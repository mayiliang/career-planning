# 路线原则与异步学习链试点

记录日期：2026-10-31。范围为 PREJS-07、JS-04、JS-05；PREJS-04、JS-01 只核对试点所需入口。本报告记录实施依据和应验证的合同；测试及真实页面证据以本轮验证结果为准，不用旧审校报告代替。

## 原则与待迁移现状

核心路线表达高级前端的能力结构，个人路线依据学习者已有基础、进度和目标推荐。按真实前置与认知负担编排；React、Vue 或任何框架没有提前或交错特权，也不要求每个人掌握两个框架。核心与专项以目标能力区分，不因所在批次推断价值。批次只是导航分组，223 个知识点、35 批次或旧的求职优先顺序均不是数量目标。

三种关系必须分开：

- **硬前置**是理解目标时确实需要的能力；尚未满足或已暂缓时要解释原因、可打开补学入口，并保留学习者自己决定当前点和恢复暂缓的权利。已具备能力的人不应被迫重学；短文的阅读记录只说明查阅，不是能力证明。
- **推荐顺序**是考虑学习成本的建议，不自动生成硬前置。批次里的相邻关系尤其不能直接视为先修依赖。
- **相关知识**用于迁移、比较或进一步探索，不构成进入当前篇的门槛。例如 JS-04 中 CS-03 的主线程分块是延伸应用，JS-05 中 TS-02 的状态建模是后续扩展。

旧限制仍存在于 `apps/server/src/services/knowledge-relations.service.ts`：`JOB_FIRST_FOUNDATION_CANDIDATES` 提前定义底座，`FRAMEWORK_ROUTE_CANDIDATES` 固定 React/Vue 交错顺序，`DEFAULT_TRACK_IDS` 参与旧默认轨道筛选，`CORE_ROUTE_BATCH_COUNT` 以 35 切分，并生成 `RECOMMENDED_KNOWLEDGE_ROUTE` / `KNOWLEDGE_ROUTE_INDEX`。`knowledge-relations.service.test.ts` 仍检查旧数量、框架顺序和文档批次表；这些检查目前用于兼容旧实现，不能被理解为新的产品原则。`learning/routes.ts` 对试点之外仍沿旧数组取下一项；`learning.service.ts`、知识点 `planWeek`、路线页和阅读器批次页继续消费旧索引或旧目录。路线文档保留批次表，明确将其标成兼容现状。

本次不机械重排全库。推广时先审读框架入口的讲义和题目，逐条列出其真正需要的 JavaScript、Web、状态、数据流及工具基础，区分跨框架对照与硬前置；再建立核心能力结构和可选择的框架目标轨，基于已有学习状态生成个人建议。需要一并迁移 `knowledge-relations.service.ts` 的候选数组、分类与索引、`learning/routes.ts` 的推荐与暂缓、学习台首次建议、详情分支、路线页、图谱和讲义目录；更新只锁死旧数量/交错顺序的测试，同时保留去重、无环、无悬空引用、记录兼容和可到达性检查。先对受影响入口和已有状态做迁移方案与页面验收，再删除旧约束；不预设后续 Issue 数量。

## 试点依赖图与阅读顺序

```text
PREJS-04（回调短文） ──▶ PREJS-07（Promise/await 短文） ──┐
                                                             ├──▶ JS-04 ──▶ JS-05
JS-01（作用域与闭包知识点） ─────────────────────────────────┘
```

箭头表示试点中说明的直接概念前置；PREJS-04、PREJS-07 是阅读辅助，不新建知识点或伪造完成状态。JS-01、JS-04、JS-05 是既有知识点。PREJS-04 向更基础的函数和变量继续链接；对已有基础可按需略读。JS-04 向 JS-05 的错误、清理与旧结果链接是后续阅读，不产生反向硬前置。JS-04 是 JS-05 的前置，边方向为 JS-04→JS-05，如图所示，无循环。推荐阅读顺序 PREJS-07 → JS-04 → JS-05 可以跨旧 B02/B03；JS-01 在实际需要时可单独打开。相关链接不增加硬门槛。

前置短文的阅读进度与知识点学习状态、练习结构检查、掌握挑战是不同证据。阅读进度可以帮助定位，不足以证明理解；用户确认学完与 M1–M4 掌握记录继续分开。当前学习中的点不应被建议偷偷切换；已学的知识点不因其基础材料尚未读完而被要求重学。一次只查阅小节不应被记成阅读整篇，超过阅读阈值也不应自动把知识点置为学完。

| --- | --- | --- | --- |
| PREJS-07 | Promise 是未来结果凭据；最小的 async/await、拒绝与接收。取消只留指向 JS-05 的说明。 | 已准备好的姓名、可手动交付的结果和一次明确拒绝；逐步区分调用者继续与当前函数等待。 | 看可预期的输出并尝试交换交付顺序；不以真实网络快慢说明顺序，不把短文当成独立考核知识点。 |

| JS-05 | 被等待的工作、错误传播、HTTP 状态、两种 finally、逐项报告、协作取消、资源归属、版本判断、重试与超时。 | 以保存、连续搜索和五项独立读取为例；可控完成顺序代替毫秒竞速，任务各自管理监听等资源。 | 普通失败继续领取；取消阻止后续领取，并等待已启动任务结束；忽略信号且永不结束的底层操作不能被 Promise 强制终止。分别观察结果槽位、资源归零及旧成功/错误/清理被抑制。 |

JS-04 的 `Promise.all` 与 `runLimited` 解释结果组合和启动控制，不承诺自动取消。JS-05 的综合任务组说明取消前检查、取消后不再启动、正常/取消时释放，以及提交前检查；该协议把取消后才观察到的任务结果报告为 `cancelled`，未启动项是 `skipped`，普通失败为 `rejected`。这些是应用报告约定，不是 Promise 的新状态。一次任务的完成与业务 UI 写入也不是同一事件。

审读时显式识别的隐藏基础包括：函数参数与回调、闭包保存版本和共享索引、数组索引与迭代、`try/catch/finally`、对象属性、`fetch`/HTTP 状态以及事件监听的注册与移除。前两项由 PREJS-04 / JS-01 承接；JS-05 的相应小节解释其余机制或给出不访问网络的模拟。CS-03、TS-02、Worker、真实服务端幂等协议是扩展或边界，不作为本试点的硬前置。后续若初级学习者仍无法独立完成任务组，应重新审查数组与异常基础或拆分练习，而不是反向添加 JS-05→JS-04。

| 资源释放、槽位归零 | JS-05「可取消的等待需要处理开始前和结束后的情况」「把领取取消和结果槽位放进同一个协议」 | JS-05 第 3、4 题断言 active、监听数归零，并在定时任务中检查 timer；取消和正常结束各有清理。 |
| 错误传播、finally 保留原结果 | JS-05「调用方等待的究竟是哪一件事」「catch 的位置决定它能处理哪些失败」「两种 finally 的返回值不要混在一起」 | JS-05 第 1、4 题定位和证伪；防止无意吞错、错误的 finally 覆盖。 |
| 旧成功、旧错误、旧 finally | JS-05「取消之后仍要判断结果是否过期」「新请求开始后旧请求的清理也可能过期」 | JS-05 第 2–4 题的连续搜索和最新请求失败变式；即使旧任务不响应取消也不能覆盖当前状态。 |
| 逐项结果、取消/网络/业务/程序错误及安全重试 | JS-05「一组工作需要先约定怎样算完成」「HTTP 失败和 Promise 拒绝需要分别判断」「区分取消与需要告知用户的失败」「重试前先问上一次可能已经做成了吗」 | JS-05 第 3、4 题检查 allSettled 的输入顺序与错误呈现；`js05-error-kinds` 用应用自定义 kind 模拟四类边界，取消优先是明确的产品策略；只对已约定安全重放的操作重试，不把客户端超时视为远端撤销。 |

新版首次任务组时间线：启动 1、2 → 完成 2，等待消费者恢复并领取 3 → 取消 → 1、3 结束；启动为 `1,2,3`，槽位为 `cancelled,fulfilled,cancelled,skipped,skipped`，第 2 项保留，峰值为 2，活动项和监听归零。普通失败继续领取；如果底层忽略信号，报告需等底层结束，并在恢复时拒绝把迟到的成功记入报告。

新版复测：启动 1、2 → 完成 1、2（每次等待消费者恢复）→ 3 普通失败 → 5 成功 → 取消仍在运行的 4；启动为 `1,2,3,4,5`，槽位为 `fulfilled,fulfilled,rejected,cancelled,fulfilled`。旧 JS-04 要求 12ms 取消后 3–5 均未启动，与其自己给出的时间线冲突：若 1 在 10ms 完成并触发领取，3 已在取消前启动。新版不沿用该错误预期；并发限制、槽位、停止领取、清理和旧结果抑制均迁到可确定的事件次序中，而非删除有效检查。真实毫秒定时只能用于观察，不能作为这两套合同的稳定答案。

## 标识、历史证据与上下文预算

保持知识点编码和数据库身份 `JS-04` / `JS-05`，旧主讲义的文件名、主锚点和 PREJS-07 旧文件入口不变。JS-04 原「取消之后仍要判断结果是否过期」小节保留为说明和通往 JS-05 同名小节的链接，原概念 `latest-result` 由 JS-05 承接。资料有实质更新，应提示新增阅读范围；不清除旧阅读进度、笔记、当前点、学完状态、掌握等级或打卡。

原两点 `strict-practice` 对应 `async-v1`，其静态题目合同快照放在 `docs/knowledge/assessment-contracts/async-v1.json`；新合同以 `strict-practice@async-v2` 保存新草稿/结果，历史提交与评分按旧合同只读展示，包含原结果、模式、检查项和后续建议。新版挑战创建时保存完整合同和机制快照，评分只使用快照；旧版评分只使用旧合同静态文件和已保存的 `sourceBasis`，不补读当前讲义；不能用当前题目静默解释旧证据。该快照对应本次变更前仓库中原合同，不声称能还原更早未留快照的任意版本。记录兼容应以包含笔记、部分阅读、已完成挑战、旧练习和暂缓状态的隔离数据库验证。

`apps/server/src/services/async-pilot-context.ts` 将两个知识点的新版合同映射到已审读的完整三级机制小节，预算为 24,000 字符，逐节保留标题、文件锚点和截断信息；预算不足或小节缺失时明确标出遗漏，不把半个代码块当成完整依据。练习验证和新挑战分别消费这些上下文；外链仅作为引用元数据，不假称其正文已经发送。非试点仍使用既有的按章节截取流程，不能把试点修复表述为全库题源已完成。应检查实际发送的请求体和降级分支；模拟模型响应只验证接口与提示词结构，不能证明真实模型理解或评分准确。无可用模型时只报告结构检查或不生成语义结论，不购买 API。
