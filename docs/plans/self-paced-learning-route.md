# AI 时代高级前端自主学习路线

更新时间：2026-08-20

这是一份紧凑的核心顺序，不是日历，也没有完成期限。当前默认路线只纳入 149 个全员必修或默认主修点，并将它们分成 35 个连续、非空的导航批次；其余 74 个专项点保留在完整知识体系中，按目标插入，不挤占主线。

## 路线原则

- 共同底座先于框架细节；只有缺失会造成概念、实现或安全断层时才设置硬前置。
- React 与 Vue 是同等优先的默认主修路线：都进入默认推荐、都覆盖组件、状态、副作用、路由、测试/性能与全栈边界。
- 同等优先不等于 API 一一对应，也不要求两个领域具有相同知识点数量；知识点只按不可替代的学习合同拆分。
- 路线页、学习台建议和知识点详情“唯一下一步”共用同一条主干索引；系统把 React/Vue 节点交错编排，避免“先学完 React 才轮到 Vue”的隐性排序。学习者仍可明确暂缓某点，但默认不会把 Vue 降为选修支线。
- 推荐顺序不自动成为硬前置；可独立学习但能相互校准的点使用 `RELATED`。
- 暂缓与放弃由用户明确操作；“已学完”由用户确认，M1～M4 由可选掌握挑战判定。
- 批次本身不是学习任务，不要求一次学完。学习者每次只推进一个具体知识点，完成后再进入唯一下一点。
- 没有关联知识点的事项，只有在系统中发布了固定输入、交付物、验证动作、通过标准和系统/AI 判定方式后，才可以成为路线任务；当前没有符合该合同的独立事项，因此不安排占位复盘、泛化项目或机动任务。

## React 与 Vue 并列框架段

| 能力阶段 | React 路线 | Vue 路线 | 共同验收重点 |
| --- | --- | --- | --- |
| 建立运行模型 | `REACT-01` | `VUE-01`、`VUE-02` | 能预测一次更新如何触发渲染，区分 snapshot 与依赖追踪 |
| 组件与状态所有权 | `REACT-02`、`REACT-03` | `VUE-03`、`VUE-04` | 输入/输出合同、派生状态、受控值、组合和焦点边界 |
| 副作用与逻辑复用 | `REACT-04`、`REACT-05` | `VUE-05`、`VUE-06` | 依赖、失效清理、迟到结果、停用/卸载与复用合同 |
| 跨组件状态 | `REACT-06` | `VUE-08` | 状态域、更新传播、持久化与服务端状态分工 |
| 异步恢复与路由 | `REACT-08`、`REACT-10` | `VUE-05`、`VUE-07` | pending/error/retry、深链、导航竞争、参数校验和服务端授权 |
| 测试与性能 | `REACT-07`、`TEST-02` | `VUE-10` | 用户行为测试、测量基线、构建产物和撤销优化的反证 |
| 框架/全栈演进 | `REACT-09`、`REACT-10` | `VUE-11` | 版本锁定、安全公告、SSR/数据边界、灰度和稳定回退 |

系统中的框架节点按下列顺序交错进入推荐路线：

`REACT-01 → VUE-01 → VUE-02 → REACT-02 → VUE-03 → VUE-04 → REACT-03 → REACT-04 → VUE-05 → REACT-05 → VUE-06 → REACT-06 → VUE-08 → REACT-08 → REACT-10 → VUE-07 → REACT-07 → VUE-10 → REACT-09 → VUE-11`

`VUE-09` 是 TanStack Query for Vue 专项。Server State 的通用原理属于 `DATA-01/02`；只有项目实际采用该库时才插入 `VUE-09`，它的选修属性不降低 Vue 主路线的优先级。

## 跨框架对照方法

| 对照关系 | 应比较什么 | 不应得出的结论 |
| --- | --- | --- |
| `REACT-01` ↔ `VUE-02` | snapshot/显式更新与代理/依赖追踪 | 把 Vue 响应式机械翻译成 `setState` |
| `REACT-02` ↔ `VUE-04` | props、事件、children/slots、受控值和所有权 | 只按语法寻找一一对应 API |
| `REACT-04` ↔ `VUE-05` | Effect/watch 的依赖、清理、竞态与恢复 | 把所有 Vue 生命周期写成 `useEffect` |
| `REACT-05` ↔ `VUE-06` | Hook/composable 的参数、返回值、清理与隐藏边界 | 把抽文件误当成逻辑复用完成 |
| `REACT-06` ↔ `VUE-08` | Context/Pinia 的状态域和传播成本 | 把服务端数据复制为全局客户端真源 |
| `REACT-08` ↔ `VUE-05` | Suspense/pending、错误捕获和重试边界 | 把 Suspense 本身当错误边界 |
| `REACT-10` ↔ `VUE-07` | URL、导航、数据加载、并发与授权 | 用客户端守卫替代服务端授权 |
| `REACT-07` ↔ `VUE-10` | 同一脚本下的性能与用户行为证据 | 只凭框架声誉判断性能 |
| `REACT-09` ↔ `VUE-11` | 当前版本、安全补丁、全栈边界和回滚 | 把一次升级或顶层版本号当成已安全 |

建议使用同一个小型业务 fixture 做两次实现，比较状态图、事件/请求时间线、错误恢复、键盘路径、测试和构建产物；不要为了“公平”堆出两份不同需求，也不要把其中一条路线写成另一条的语法翻译。

## 每个知识点的闭环

1. 打开批次中的第一个未完成知识点，不同时启动同批次的其他点。
2. 阅读该页面列出的中文主资料；英文页面只在明确标注时用于版本核验。
3. 写原始 Markdown 笔记，至少记录机制链、适用边界和一次验证结果。
4. 若页面发布了站内练习，就按它给出的固定输入、交付物、验证清单和否决项提交；系统先检查结构与证据，AI 再复核语义。
5. 用户确认“已学完”；这只表示完成本轮学习，不等于已经掌握。
6. 需要掌握证据时启动 M1～M4：资料定位、机制解释、固定 fixture 实作/诊断与单变量复测均由系统生成并保存评分。
7. 进入唯一下一点；当天结束时，只把实际学习过的点加入打卡。

## 项目与掌握证据

项目不是每个知识点的固定阶段。跨知识点项目可以作为综合证据，但不能成为未写入资料和题目的隐藏前置，也不会以“综合实践”占位项出现在 35 个批次中。

可以逐步形成复杂业务双框架切片、组件/体验平台、生产交付、可信 AI 应用四类代表证据。它们目前只是证据组合建议，不是系统已发布的独立任务；只有未来补齐固定 fixture、交付物、验证清单、否决项和系统/AI 验收后，才允许进入路线。每份证据至少包含可运行产物、测试或测量、关键决策和失败边界；“用了 React/Vue”或“页面能打开”都不足以证明高级能力。

## 完整覆盖的判断

“完全覆盖”是持续审计目标，不等于一次性学完所有专项。知识体系负责覆盖高级前端共同底座、React/Vue 同等优先的主流框架能力、AI 原生能力和生产/领导能力；个人路线负责依据目标调整节奏。体系更新时继续做主题职责、资料正文、练习/挑战、版本事实和依赖图的反向审计，不恢复固定天数课程表。
