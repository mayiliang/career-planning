# AI 时代高级前端自主学习路线与兼容分组

更新时间：2026-10-31

核心路线表达达到高级前端所需的能力结构；个人路线依据已有基础、进度与目标推荐下一步。框架不享有提前或双框架交错特权。共同能力与岗位专项按目标能力区分，数量和批次数都不是不可变指标。

当前实现正在逐步迁移：只有异步学习链试点按新原则连接，完整框架轨道和默认顺序仍沿用旧版。以下表格保留旧运行时的兼容分组，方便查阅与验证，**不是新的依赖图或学习门槛**；不能据此要求学习者先后学完两个框架。详细决策与依赖证据见[异步链试点报告](../auto-coding/route-principles-and-async-pilot.md)。

## 路线原则

- 判断概念理解是否必要，必要时建立硬前置；只适合多数初学者的先后顺序是推荐，能相互启发但不互相依赖的知识是相关连接。
- 批次是导航分组，不规定知识依赖或完成期限。内容和数据库保留 `planWeek`、B01～B35 以兼容当前入口，不把 35 视为产品目标。
- 短文是阅读辅助；阅读超过阈值只记录资料看完，不替学习者确认知识点学完，也不产生掌握证据。
- 不因缺少前置而更改当前学习点；对已暂缓的硬前置说明影响并提供查看与恢复入口，不自动解除暂缓。
- 笔记、当前学习点、已完成状态、掌握证据、打卡和阅读进度在内容调整中保留；练习合同变化区分版本。
- 不把与学习目标无关的复盘或项目变成强制任务。需要综合练习时，明确输入、过程、结果和验证证据。

## 异步学习链试点

先按需补 [PREJS-04](../knowledge/chinese-guides/javascript-scheduled-callbacks.md#prejs-04) 的回调基础，再读 [PREJS-07](../knowledge/chinese-guides/javascript-promises-and-cancellation.md#prejs-07)；结合 [JS-01](../knowledge/chinese-guides/js-01-execution-context-scope-closure.md#js-01) 的作用域基础进入 [JS-04](../knowledge/chinese-guides/js-04-async-promise-browser-event-loop.md#js-04)，最后到 [JS-05](../knowledge/chinese-guides/js-05-promise-errors-async-control-flow.md#js-05)。已有基础无需重学。JS-04 和 JS-05 分属旧 B02、B03，批次边界不改变两篇的依赖关系。

## 旧运行时的框架分组：待重构

| 能力阶段 | React 路线 | Vue 路线 | 共同验收重点 |
| --- | --- | --- | --- |
| 建立运行模型 | `REACT-01` | `VUE-01`、`VUE-02` | 能预测一次更新如何触发渲染，区分 snapshot 与依赖追踪 |
| 组件与状态所有权 | `REACT-02`、`REACT-03` | `VUE-03`、`VUE-04` | 输入/输出合同、派生状态、受控值、组合和焦点边界 |
| 副作用与逻辑复用 | `REACT-04`、`REACT-05` | `VUE-05`、`VUE-06` | 依赖、失效清理、迟到结果、停用/卸载与复用合同 |
| 跨组件状态 | `REACT-06` | `VUE-08` | 状态域、更新传播、持久化与服务端状态分工 |
| 异步恢复与路由 | `REACT-08`、`REACT-10` | `VUE-05`、`VUE-07` | pending/error/retry、深链、导航竞争、参数校验和服务端授权 |
| 测试与性能 | `REACT-07`、`TEST-02` | `VUE-10` | 用户行为测试、测量基线、构建产物和撤销优化的反证 |
| 框架/全栈演进 | `REACT-09`、`REACT-10` | `VUE-11` | 版本锁定、安全公告、SSR/数据边界、灰度和稳定回退 |

旧实现从 B04 开始按下列顺序交错编排框架节点；此顺序仅作为兼容现状记录，不是新原则：

`REACT-01 → VUE-01 → VUE-02 → REACT-02 → VUE-03 → VUE-04 → REACT-03 → REACT-04 → VUE-05 → REACT-05 → VUE-06 → REACT-06 → VUE-08 → REACT-08 → REACT-10 → VUE-07 → REACT-07 → VUE-10 → REACT-09 → VUE-11`

`VUE-09` 是 TanStack Query for Vue 专项。Server State 的通用原理属于 `DATA-01/02`；只有项目实际采用该库时才插入 `VUE-09`，应按目标和已有基础决定是否学习该专项。

## 跨框架对照方法

| 对照关系 | 应比较什么 | 不应得出的结论 |
| --- | --- | --- |
| `REACT-01` ↔ `VUE-02` | snapshot/显式更新与代理/依赖追踪 | 把 Vue 响应式机械翻译成 `setState` |
| `REACT-02` ↔ `VUE-04` | props、事件、children/slots、受控值和所有权 | 只按语法寻找一一对应 API |
| `REACT-04` ↔ `VUE-05` | Effect/watch 的依赖、清理、竞态与恢复 | 把所有 Vue 生命周期写成 `useEffect` |
| `REACT-05` ↔ `VUE-06` | Hook/composable 的参数、返回值、清理与隐藏边界 | 把抽文件误当成逻辑复用完成 |
| `REACT-06` ↔ `VUE-08` | Context/Pinia 的状态域和传播成本 | 把服务端数据复制为全局客户端真源 |
| `REACT-08` ↔ `VUE-05` | Suspense/pending、错误捕获和重试边界 | 把 Suspense 本身当错误边界 |
| `REACT-10` ↔ `VUE-07` | URL、导航、数据加载、并发与授权 | 用客户端守卫替代服务端授权 |
| `REACT-07` ↔ `VUE-10` | 同一脚本下的性能与用户行为证据 | 只凭框架声誉判断性能 |
| `REACT-09` ↔ `VUE-11` | 当前版本、安全补丁、全栈边界和回滚 | 把一次升级或顶层版本号当成已安全 |

需要比较两条框架路线时，可用同一个小型业务场景比较状态图、事件/请求时间线、错误恢复、键盘路径、测试和构建产物；对照是可选学习方法，并不要求每个人实现两套。

## 每个知识点的闭环

1. 根据当前目标选择知识点；遇到不熟悉的必要前置时，可打开上游资料并返回。
2. 阅读该页面列出的中文主资料；英文页面只在明确标注时用于版本核验。
3. 写原始 Markdown 笔记，至少记录机制链、适用边界和一次验证结果。
4. 若页面发布了站内练习，就按它给出的固定输入、交付物、验证清单和否决项提交；系统先检查结构与证据，AI 再复核语义。
5. 用户确认“已学完”；这只表示完成本轮学习，不等于已经掌握。
6. 需要掌握证据时启动 M1～M4：资料定位、机制解释、固定 fixture 实作/诊断与单变量复测均由系统生成并保存评分。
7. 根据推荐理由自行选择下一步；当天结束时，只把实际学习过的点加入打卡。

## 项目与掌握证据

项目不是每个知识点的固定阶段。跨知识点项目可以作为综合证据，但不能成为未写入资料和题目的隐藏前置，也不会以“综合实践”占位项出现在 35 个批次中。

可以逐步形成复杂业务双框架切片、组件/体验平台、生产交付、可信 AI 应用四类代表证据。它们目前只是证据组合建议，不要求每个人都做双框架实现，也不是系统已发布的独立任务；只有未来补齐固定 fixture、交付物、验证清单、否决项和系统/AI 验收后，才允许进入路线。每份证据至少包含可运行产物、测试或测量、关键决策和失败边界；“用了 React/Vue”或“页面能打开”都不足以证明高级能力。

## 完整覆盖的判断

“完全覆盖”是持续审计目标，不等于一次性学完所有专项。知识体系负责覆盖高级前端共同底座、按目标选择的主流框架能力、AI 原生能力和生产/领导能力；个人路线负责依据目标调整节奏。体系更新时继续做主题职责、资料正文、练习/挑战、版本事实和依赖图的反向审计，不恢复固定天数课程表。
