# AI 时代高级前端 48 周掌握计划

更新时间：2026-07-28

## 目标

用 48 周完成 20 个领域、190 个知识点的首次掌握和延迟复测，并形成能被代码、测试、架构记录、性能数据、部署结果和答辩共同验证的高级前端能力。

计划约束：

- 前 44 周覆盖全部 190 个唯一知识点。
- 第 45～48 周分别用于证据整合、生产演练、综合项目和盲测答辩。
- 每周 7 天都有模板，但每日 390 分钟是容量上限，不是必须填满的配额。
- 每点先完成资料、练习、项目和首考；首考完成至少 7 天后再复测。
- 到期复测优先于新内容；硬前置未通过时，不开始依赖它的知识点。

## 每日容量参考

| 时间 | 内容 | 分钟 |
| --- | --- | ---: |
| 09:00～10:30 | 资料精读与问题清单 | 90 |
| 10:45～13:15 | 机制练习、反例和排错 | 150 |
| 14:15～16:30 | 项目产出或迁移 | 135 |
| 16:45～18:00 | 首考、复测或复盘 | 75 |
|  | 合计上限 | 390 |

实际任务少于 390 分钟时不强行填充。连续三个同类知识点的实际耗时与估算偏差超过 25% 时，应按自己的历史数据调整后续计划。

## 每周执行闭环

1. 周初：查看本周知识路径和硬前置，选择一个项目锚点。
2. 每天：只推进当前学习合同，留下资料笔记、可运行实验或项目增量。
3. 首考：五类题全部完成，达到 80 分且关键项无否决。
4. 复测：系统在至少 7 天后自动安排；失败即回到薄弱阶段。
5. 周末：合并代码、证据与 ADR，更新项目资产，并写一页周复盘。

## 硬前置闸门

优先遵循以下主链：

```text
Web/JavaScript
  -> TypeScript 与框架渲染
  -> 状态、Hook、业务建模
  -> 数据、实时、性能与工程质量
  -> 发布、可观测性与生产交付
  -> AI 产品判断、隐私与安全
  -> AI 应用、Agent、MCP 与本地推理
  -> 架构演进、治理与技术领导力
```

系统不会把同一文件中的相邻知识点机械设为硬前置。只有确实会导致理解、实现或安全断层的关系才阻塞学习。

## 四个代表项目

毕业前至少形成四类证据：

- 复杂业务系统：权限、状态机、表单/表格、契约、测试和异常边界。
- 组件或平台：设计 Token、可访问性、版本治理、文档和采用率。
- 生产交付：容器、CI/CD、监控、故障注入、回滚和复盘。
- 可信 AI 应用：流式交互、RAG/工具、评估、隐私、安全、成本和降级。

可以复用现有项目，但必须补齐可运行代码、测试、架构决策和结果数据。

## 毕业标准

- 190 个知识点均完成首考和延迟复测。
- 综合项目通过功能、类型、单元/E2E、安全、性能、可访问性和部署检查。
- 能在 90 分钟内完成架构答辩，解释约束、方案、失败模式、迁移与回滚。
- 能在不看旧答案的情况下完成跨领域盲测，并对错误建立重学计划。
- 作品集中的关键结论都有代码、数据或决策记录支持。
- 能针对目标岗位说明“已有证据、仍有差距、入职后的前 90 天计划”。
