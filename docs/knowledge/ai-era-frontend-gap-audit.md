# AI 时代高级前端能力体系整改记录

更新时间：2026-08-04

## 整改结论

本轮只整改知识点主题、分类、层级映射、重复、缺失和前置关系，不以扩写正文为目标。当前真源仍为 **20 个稳定能力组、223 个唯一知识点**；全部知识点编码保持不变，已有学习记录无需迁移到新编码。

整改后的体系符合“AI 时代高级前端能力体系”主题：既保留 Web 平台、应用、工程与生产交付底座，也把 AI 应用、Agent、端侧 AI、AI 辅助研发、安全治理和技术领导力按独立分类轴纳入，而不是用“AI”替代前端基础。

## 一、层级与分类模型

### 主题层级

`总主题 -> 20 个稳定能力组 -> 文件内二级主题 -> 223 个知识点`

20 个文件是长期稳定的归档组，不再假装每个文件只能表达一个原子学科。全部知识点现已归入显式 `###` 二级主题；解析器、数据库、导入、API 与页面同步保存 `secondaryTopic/topicOrder`，不再把二级标题当成不可查询的装饰文本。

### 独立分类轴

| 分类轴 | 整改后取值 | 修正内容 |
| --- | --- | --- |
| 能力层 | `CORE / APPLICATION / SPECIALTY / LEADERSHIP` | 删除混合概念 `AI_LEADERSHIP`，补上应用层 |
| AI 关系 | `NONE / AI_ASSISTED / AI_NATIVE / AGENTIC` | AI 属性不再与能力层混用 |
| 要求级别 | `REQUIRED / TRACK_REQUIRED / ELECTIVE` | “实验性”移回成熟度，不再表示是否必修 |
| 成熟度 | `STABLE / EVOLVING / EXPERIMENTAL` | 只描述技术/规范成熟阶段 |
| 主适用范围 | 增加 `PLATFORM_SPECIFIC` | 补齐浏览器扩展、Node、桌面/移动运行时等平台限制 |
| 多重适用标签 | 框架/厂商/平台/法域可多选 | 一个知识点可同时表达多种限制 |
| 学习路线 | 4 个稳定 ID：React、Vue、Umi/Ant Design、Agent/MCP | 只表达可执行主修路线和 `TRACK_REQUIRED` 归属 |
| 主题标签 | 20 个跨领域标签 | 承接 Web 平台、无障碍、安全、媒体、跨运行时、Node/BFF、浏览器 AI、图形、增长、部署、视觉测试等检索语义 |

数据库、导入哈希、共享 Schema、服务查询、关系图、Web API、列表筛选和详情展示已同步新分类轴；迁移脚本会把旧 `AI_LEADERSHIP` 转为 `LEADERSHIP`，把旧要求级别中的 `EXPERIMENTAL` 转为 `ELECTIVE`。

## 四、缺口处理

以下三项原先只在其他知识点正文中零散出现，现已提升为明确主合同：

- 视觉回归与跨浏览器截图基线：纳入 `TEST-03` 的标题、覆盖范围、考核和通过标准。
- 客户端请求可靠性生命周期：纳入 `NET-01` 的标题、覆盖范围、考核和通过标准。
- 无障碍工程治理：纳入 `A11Y-01` 的标题、覆盖范围、考核和通过标准。

它们与现有知识点职责高度一致，因此没有新增近义编号；这样既补齐主题，也避免重复和破坏学习记录。

## 五、分类与赛道映射修正

- React/Vue/Umi 分别为应用或专精层的框架赛道；不再归入通用核心。
- Node/BFF 是应用层且平台特定；CLI/API 生成是专精选修。
- WebAssembly、运行时容器、移动原生、Docker 专项、图形/WebGPU 等使用横向主题标签；它们不再伪装成岗位路线。
- `AIAPP-05` 回归 AI 原生应用必修；`AIUI-01` 成为 Agent/MCP 主修必修。
- MCP/Agent 是 Agentic 专精能力，不再被标记为领导力。
- AI 辅助研发、AI 原生应用、Agentic 和 AI 治理分别使用独立 AI 关系与能力层组合。
- `AIMEDIA-01` 和 `AIDEV-09` 不再因引用特定工具就误标为厂商特定；具体厂商通过适配层处理。
- `ANTD-04`、`HYBRID-01`、`RUNTIME-01/02`、`MOBILE-01` 等表达真实的框架、厂商或平台限制；已删除 HYBRID/MOBILE 上没有依据的框架限制。

## 七、逐点门禁

自动校验继续覆盖 20 个能力组、223 个唯一知识点，并增加新枚举轴验证：

1. 编号、规范化标题和所属能力组唯一且可解析。
2. 每个领域至少两个不重名二级主题，每点恰好映射一个非空主题，空主题不得存在。
3. 能力层、AI 关系、要求级别、成熟度、主适用范围和多重适用标签合法。
4. 主修必修必须存在四条稳定路线之一；横向主题只能进入 `topicTags`。
5. 资料、覆盖范围、五段式考核、命题边界、通过标准和评估边界完整。
6. 硬前置端点存在、无自环、无环、无“前置 + 相关”冲突。
7. 默认路线只包含全员必修和默认主修路线，前置点不晚于依赖点。

## 八、修订后复审结论

按照与首轮相同的标准重新逐级检查后：20 个一级领域均符合总主题；全部二级主题都有知识点且领域内不重名；223 个知识点编码与规范化标题均唯一；`UX-01` 已从组件平台移入业务与产品体验领域，MCP 传输/客户端兼容和 AST 确定性改写已进入各自正确二级主题；路线与主题标签不再混用。内容门禁、迁移导入测试、全量单元测试、静态检查和生产构建共同作为复审证据。

逐点结果见[223 点主题审计矩阵](topic-audit-matrix.md)。

## 九、持续维护

- 每月复核 MCP、A2A、Agent UI、WebMCP、浏览器 AI 和安全公告。
- 每季度复核框架/浏览器版本、法规生效时间、岗位样本和生产事故暴露的能力缺口。
- 每半年复审能力组、二级主题和赛道边界，优先调整现有主合同，只有确实不可合并时才新增编号。
- 演进中或实验性内容必须保留版本、能力检测、降级和退出策略；厂商、平台或法域结论不得写成通用事实。
