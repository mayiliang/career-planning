# AI 时代高级前端知识体系查漏补全

更新时间：2026-07-21

## 结论

当前知识体系已经覆盖高级前端的主要骨架：Web 基础、TypeScript、React、Umi/AntD、业务建模、工程质量、性能、组件平台、Node/API/MCP、AI 原生应用、Agent、浏览器 AI、AI 辅助研发和职业表达。

```text

  -> AI 产品与工具系统
  -> 安全、隐私、成本、评估
  -> 团队级工程治理和业务结果
```

## 需要补齐或显式强化的 10 个方向

这些方向原本可以作为下一轮知识库扩展候选；由于学习计划尚未开始，本次已经把部署交付能力正式纳入 23 周主线。

### GAP-01 全栈渲染边界：SSR、RSC、Streaming、BFF 与 Edge

为什么重要：

React 生态正在从纯客户端应用走向“客户端组件 + 服务端组件 + Streaming + Server Actions/BFF”的混合模型。高级前端需要能判断哪些逻辑放浏览器、哪些放服务端、哪些靠边缘节点或缓存解决。

应挂载位置：

- `03-react.md`：React Server Components、Suspense Streaming、服务端边界安全。
- `06-engineering-quality.md`：部署、缓存、旧 chunk、Edge Runtime、构建产物。
- `05-business-modeling.md`：BFF DTO、鉴权、数据聚合和错误模型。

学习路径：

1. 先理解 React Suspense、Server Components、Server Functions 的信任边界。
2. 用 Next.js App Router 做一个最小页面：服务端取数、客户端交互、Streaming fallback、错误恢复。
3. 对比 Umi 中后台模式：哪些场景需要 SSR/RSC，哪些不值得引入复杂度。
4. 写一份架构取舍：性能收益、缓存策略、鉴权边界、部署复杂度和回滚方案。

项目证据：

- 给 `digitalteacher-web` 或 Career Atlas 做一个“服务端数据聚合 + 客户端交互”的原型。
- 输出一份《Umi SPA 与 Next/RSC 模式取舍说明》。

### GAP-02 数据层与缓存：Server State、失效、乐观更新和离线

为什么重要：

很多复杂前端问题不是组件问题，而是数据生命周期问题：请求去重、缓存失效、并发覆盖、乐观更新、分页合并、离线恢复和错误回滚。

应挂载位置：

- `03-react.md`：状态所有权与服务端状态边界。
- `04-umi-antd.md`：请求层、ProTable 查询、错误处理。
- `05-business-modeling.md`：幂等、一致性、异步任务。

学习路径：

1. 系统学习 TanStack Query 或同类 server state 思路。
2. 从 `gungnir-web` 找一个查询、编辑、刷新、导出组合页面，画出数据生命周期。
3. 设计缓存 key、失效策略、乐观更新、失败回滚和并发请求取消。
4. 用测试验证“快速切换筛选条件”“重复提交”“接口慢返回覆盖新结果”。

项目证据：

- 交付一个带缓存失效和竞态防护的业务页面重构记录。
- 形成《复杂列表数据层设计模板》。

### GAP-03 实时与协作协议：WebSocket、WebRTC、SSE、CRDT

为什么重要：

AI 助手、在线教学、实时批注、多人协作和长任务进度都依赖实时协议。只会普通 HTTP 请求，会限制你做 AI 产品和协作型产品的上限。

应挂载位置：

- `07-performance-h5.md`：实时连接、弱网、移动端恢复。
- `12-ai-native-frontend.md`：SSE、流式响应、增量渲染。
- `13-agents-mcp.md`：长任务进度、取消、恢复。

学习路径：

1. 对比 SSE、WebSocket、WebRTC 的连接模型、可靠性和适用场景。
2. 实现一个任务进度流：断线重连、心跳、取消、错误恢复。
3. 了解 Yjs/CRDT 的基本思想，用最小 Demo 做多人编辑或批注。
4. 写清楚：什么时候不要引入 WebSocket 或 CRDT。

项目证据：

- 给 AI 对话或导入导出任务做一个可恢复进度通道。
- 做一个多人批注/共享白板最小 Demo。

### GAP-04 数据可视化与图形系统：SVG、Canvas、WebGL、图表性能

为什么重要：

你的项目里有教学、分析、地图、趋势、图表和内容展示场景。高级前端不能只会调图表库 API，还要能处理大数据量、交互、性能、可访问性和导出。

应挂载位置：

- `07-performance-h5.md`：主线程、内存、渲染性能。
- `08-components-platform.md`：可复用图表组件、主题、文档。
- `10-career-expression.md`：可视化方案表达。

学习路径：

1. 复习 SVG、Canvas、WebGL 的渲染模型和适用边界。
2. 用 AntV/ECharts 做同一数据集的图表，对比交互和性能。
3. 实现大数据量图表的采样、虚拟化、懒渲染或 Worker 处理。
4. 验证导出、缩放、键盘访问、颜色对比和空数据状态。

项目证据：

- 从 `gungnir-web` 或教学项目中抽一个图表页面做性能剖析。
- 输出《图表组件设计与性能报告》。

### GAP-05 产品实验与增长度量：埋点、Feature Flag、A/B Test

为什么重要：

AI 功能不能只靠“感觉好用”上线。高级前端要能定义事件、实验、转化、留存、错误率、成本和质量指标，证明功能是否真的有效。

应挂载位置：

- `06-engineering-quality.md`：RUM、OpenTelemetry、发布质量。
- `12-ai-native-frontend.md`：模型评估、成本、可靠性。
- `15-ai-assisted-engineering.md`：真实提效评估。

学习路径：

1. 建立事件命名、属性、采样、脱敏和版本维度规范。
2. 实现 Feature Flag：灰度、回滚、用户分组、配置审计。
3. 为一个 AI 功能设计 A/B 测试：成功率、人工接管率、延迟、成本、满意度。
4. 每次上线必须有上线前指标、上线后观察窗口和回滚阈值。

项目证据：

- 为 Career Atlas AI 考核或 AIUI 对话功能建立指标面板设计。
- 输出《AI 功能上线实验方案》。

### GAP-06 隐私、合规与数据治理

为什么重要：

AI 时代前端会处理更多用户输入、文档、聊天记录、模型日志和工具调用记录。高级前端必须知道哪些数据不能进模型、不能进日志、不能长期保存。

应挂载位置：

- `01-javascript-browser.md`：安全基础、鉴权、CSP、WebAuthn。
- `06-engineering-quality.md`：日志、RUM、数据脱敏。
- `15-ai-assisted-engineering.md`：AI 能力治理、隐私与团队规范。

学习路径：

1. 给数据分级：公开、内部、个人信息、敏感信息、密钥。
2. 审计一次日志链路：请求、错误、埋点、模型 prompt、工具参数。
3. 设计脱敏、最小采集、保留期限、用户删除和审计机制。
4. 对 AI 功能做一次隐私威胁建模。

项目证据：

- 输出一份《前端日志与 AI 输入数据分级规范》。
- 给 `get_apidoc` 或 Career Atlas 做敏感字段过滤策略。

### GAP-07 AI 产品判断力：模型选型、体验边界和失败设计

为什么重要：

AI 时代优秀前端不是“会接模型接口”，而是能判断这个场景是否应该用 AI、该用云端还是本地、是否需要 RAG、失败时用户怎么恢复、成本是否可接受。

应挂载位置：

- `12-ai-native-frontend.md`：AI 产品 UX、评估、成本。
- `14-browser-ai-local-inference.md`：端云路由、本地推理。
- `10-career-expression.md`：技术方案和取舍表达。

学习路径：

1. 对每个 AI 需求写清楚：用户目标、非 AI 方案、AI 方案、风险和上线指标。
2. 建立模型选型矩阵：质量、延迟、成本、隐私、上下文、工具能力、可用性。
3. 设计低置信度、引用冲突、生成失败、人工接管和重试路径。
4. 用评估集而不是个人感觉决定提示词和模型版本。

项目证据：

- 为 `digitalteacher-web` 或 AIUI 写一个《AI 功能产品决策记录》。

### GAP-08 技术领导力：架构评审、迁移策略和技术债治理

为什么重要：

高级前端和普通熟练工的分界，不只在写代码速度，而在能否让团队更稳定地交付：制定标准、推动迁移、控制技术债、复盘事故、培养他人。

应挂载位置：

- `10-career-expression.md`：方案、ADR、复盘、推动。
- `06-engineering-quality.md`：门禁、发布、回滚。
- `08-components-platform.md`：平台治理、采用率。

学习路径：

1. 学会写 ADR：背景、方案、备选、取舍、影响、回滚。
2. 为一次技术迁移设计分阶段计划：试点、兼容、指标、灰度、推广。
3. 建立技术债台账：影响、成本、优先级、处理窗口。
4. 做一次代码评审复盘：哪些问题应通过工具前置阻止。

项目证据：

- 输出一份 `gungnir-web` 或 `aiui` 的技术债治理清单。
- 写一份组件平台升级或工程质量门禁方案。

### GAP-09 后端与基础设施素养：认证、队列、对象存储、CDN、数据库读模型

为什么重要：

高级前端经常要做跨端和跨系统方案。如果完全不了解后端和基础设施，就很难设计 BFF、上传下载、长任务、权限、缓存、AI 文件处理和发布策略。

应挂载位置：

- `05-business-modeling.md`：接口契约、异步任务、一致性。
- `06-engineering-quality.md`：部署、回滚、监控。
- `09-node-api-ai.md`：Node、API、工具服务。

学习路径：

1. 掌握认证会话、Cookie、Token、刷新、权限校验的端到端链路。
2. 学习队列、任务状态、对象存储、CDN 缓存和签名 URL 的基本模型。
3. 理解数据库读模型、分页、排序、搜索和一致性对前端体验的影响。
4. 用 Node 做一个最小 BFF：聚合接口、校验 DTO、统一错误、日志追踪。

项目证据：

- 重构一个导入导出或文件上传流程的前后端状态设计。
- 输出《前端视角的 BFF 与异步任务设计模板》。

### GAP-10 国际化、内容工程与知识型产品

为什么重要：

AI 教学、知识库、Markdown、PDF、视频、课程和移动分享都属于内容型产品。高级前端要能处理内容结构、国际化、搜索、引用、版本、导出和可访问阅读体验。

应挂载位置：

- `07-performance-h5.md`：内容加载、移动体验。
- `08-components-platform.md`：内容组件、主题、导出。
- `12-ai-native-frontend.md`：RAG、引用、来源可信度。

学习路径：

1. 学习 i18n、时区、数字/日期格式、RTL 基础。
2. 梳理 Markdown、公式、代码、高亮、PDF、视频批注的内容模型。
3. 做一个内容渲染安全检查：XSS、链接、外部资源、复制、导出。
4. 建立内容版本、引用和搜索索引策略。

项目证据：

- 基于 `digitalteacher-web` 写一份《AI 教学内容渲染与引用方案》。

## 官方资料校准

- React Compiler：自动优化组件更新，但仍要求理解 React 规则、性能测量和增量采用。
- React/Next 的服务端渲染与 Streaming：前端需要理解服务端组件、数据获取、缓存和 Suspense 边界。
- Vite/Rolldown：构建工具正在向更高性能的 Rust 工具链迁移，高级前端要能做迁移评估。
- Core Web Vitals：INP、LCP、CLS 仍然是性能诊断和上线质量的重要指标。
- web.dev Learn AI：AI 时代开发者的重点从“会提示词”转向系统规划、平台选择、评估和负责任构建。
- Chrome Built-in AI：浏览器内置模型、本地推理、能力检测和降级策略开始进入前端视野。
- OWASP LLM 安全：Prompt Injection、工具滥用、数据外泄、RAG 污染和 Agent 风险必须进入安全考核。
