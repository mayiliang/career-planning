# AI 输出安全与分层校验知识点讲义

## AISAFE-01 输出校验、内容安全与 Guardrails

模型生成的一段文字看起来像自然语言，却可能在下一步成为 HTML、链接、数据库筛选、工具参数、客服回复或高风险建议。只要它进入解释器、外部系统或用户决策，错误就不再只是“回答不好”，而会变成注入、越权、泄露、误导或不可恢复的业务动作。输出安全的核心不是训练一个万能分类器，而是把模型输出当作不可信输入，沿真实使用路径逐层验证，并让每一层只承担自己能证明的责任。

### 学习前先确认

- 直接前置：[SEC-01 XSS、CSRF 与 Web 信任边界](../chinese-guides/sec-01-xss-csrf-trust-boundaries.md#sec-01)。本讲直接使用“不可信数据不能获得代码、权限或身份”的通用安全模型；认证、授权、上下文编码和浏览器隔离不会因为引入模型而失效。

### 一、先从输出将被怎样使用开始

同一句模型输出在不同目标里风险完全不同。展示为纯文本时，主要担心错误事实、隐私和不当内容；写入 `innerHTML` 时还会成为脚本注入载体；作为 URL 时要限制协议、主机与跳转；作为工具参数时要重新验证主体、对象、动作和业务状态。安全设计必须从最终解释器反向推导控制，不能只盯着模型输入框。

建立输出使用清单：谁消费、进入什么上下文、是否触发副作用、最大影响范围、用户能否发现和撤销、失败时回到哪里。摘要、搜索建议、代码补丁和退款动作即使由同一模型生成，也要进入不同管道。若团队说不清输出的最终消费者，就还没有资格声明它“已过滤”。

不要把“模型拒绝了危险请求”当作唯一证据。提示可以降低风险，却不能证明每次都遵守；供应商策略会变化，检索内容也可能操纵模型。真正的安全边界位于应用拥有确定控制的位置。

### 二、Guardrail 是完整控制链而不是一个组件

**安全护栏（Guardrail）**是围绕输入、上下文、模型、输出、工具和人工流程建立的一组限制、检测与恢复机制。它可以包含数据最小化、提示隔离、结构校验、内容分类、权限判断、上下文编码、速率限制、确认、审计和人工升级。某一层漏过后，下一层仍应阻止危险影响。

护栏要按威胁和后果选择。面向公开写作的产品可能重点控制隐私、版权、骚扰和虚假来源；企业数据问答更关注租户隔离、检索授权和秘密回显；能调用工具的系统还要限制动作、参数和累计影响。统一“敏感词过滤器”无法表达这些差异。

护栏本身也会失败：分类器服务超时、策略版本不一致、规则配置未加载、日志写入失败或人工队列已满。每个控制都要定义可用性依赖、失败默认和降级界面，避免安全组件故障时反而全部放行。

### 三、结构校验只证明形状成立

**输出校验（Output Validation）**首先确认数据能被目标程序可靠解析。结构化输出进入运行时 Schema：拒绝缺字段、错误类型、未知枚举、额外危险字段、过深嵌套和超大数组。解析入口接收 `unknown`，成功后才产生可信的内部类型；TypeScript 声明不能验证网络返回。

Schema 合法不代表业务合法。`{ action: "refund", orderId: "B", amount: 1000 }` 可能类型完全正确，却引用别的租户订单、超过审批金额或处于不可退款状态。第二层要检查对象存在、当前版本、字段组合、额度、租户、角色和状态机允许的动作。

校验失败返回稳定错误类别，例如 malformed、unsupported、unauthorized、out_of_range、policy_blocked，而不是把解析栈或敏感正文回显给模型和用户。错误既要足够支持恢复，也不能泄露内部表结构、策略细节或秘密。

### 四、最终解释器决定编码与参数化方式

HTML、URL、CSS、Shell、SQL 和 Markdown 不是同一个上下文。HTML 展示优先创建文本节点或经过严格允许列表的安全渲染器；数据库查询和命令使用参数化接口，不把模型输出拼接成代码；URL 解析后限制协议、目标域、凭据与重定向。所谓“先统一转义一次”通常会在后续拼接或解码时失效。

富文本必须明确允许的元素、属性和链接协议，并在最终组合后校验。危险标记可能跨增量块拆分，逐块净化不能证明合并结果安全。代码块默认只是文本；用户主动复制或运行时进入新的高风险边界，需要独立沙箱、权限和确认。

把被删除内容悄悄变成“看起来正常”的回答也可能误导。若净化改变了关键含义，应停止当前输出，说明内容无法安全呈现，并提供重新生成、纯文本查看或人工处理等安全替代路径。

### 五、工具调用必须经过确定性授权

模型可以建议动作，但不能授予权限。服务端从当前会话身份重新取得租户、角色和资源范围，不信任模型生成的 `userId`、`tenantId` 或“用户已同意”。工具只暴露完成任务所需的最小动作，读取与写入分开，批量和不可逆操作使用更严格闸门。

参数先过 Schema，再过业务状态和授权；高风险动作绑定对象版本、审批令牌、幂等键和过期时间。用户确认界面展示真实后果与关键参数，而不是一句“是否继续”。任何参数变化都使旧确认失效，执行器也必须拒绝越权请求。

工具结果仍是不可信数据，不能因为来自内部服务就直接提升为指令。它可能含被污染的网页、订单备注或错误消息；返回模型前保留来源标签、截断敏感字段并限制下一步可调用能力。

### 六、事实、引用与计算需要可验证来源

语言流畅不能证明事实正确。可核验任务应要求来源，并检查引用真实存在、当前主体可访问、内容确实支持相邻结论、版本和时间仍适用。仅生成一个像 URL 的字符串不算引用；来源存在也不代表它支持模型的推断。

金额、日期、统计和权限判断交给确定程序或可信数据源。模型可解释计算结果，但不能自行修改输入后再声称已核对。多个来源冲突时展示差异和时间，不强行合并成确定答案。

无法验证的内容要改变产品动作：低风险创意可以标为草稿，高风险建议进入人工复核，缺少来源的事实型答案应拒绝或降级。不要用伪造的精确置信度替代证据。

### 七、内容安全需要按场景和严重度分级

内容风险可能包括暴力、自伤、仇恨、骚扰、性内容、违法协助、医疗或金融误导，也可能包括企业自己的品牌、行业和年龄限制。策略先定义类别、严重度、适用人群与允许的安全替代，而不是事后靠运营凭感觉删内容。

同一主题不一定都该拒绝。教育、新闻、求助和恶意操作的意图及细节程度不同；分类器只能提供信号，最终决定结合产品场景、用户年龄、地域规则和错误代价。高风险但模糊的样本升级人工，而不是让模型自行裁决。

拒绝要简洁、稳定且不泄露绕过细节，并尽可能保留安全方向，例如把危险操作改为防护建议或紧急求助信息。安全替代不是继续完成原危险目标的变体。

### 八、PII、秘密与敏感属性分别治理

输出前检测个人信息、认证凭据、内部密钥、私有链接和受保护属性，但不要把所有数字都当敏感数据。检测结合字段来源、数据分类和上下文：订单号可以在本人会话显示，却不能进入公共日志；身份证号即使由模型“猜出”也不应回显。

脱敏必须保持业务可用性并防止重识别。只遮住中间几位可能仍能与其他字段组合定位个人；日志、评测集、提示缓存和人工审核工具都属于数据流。阻断后记录类别、策略版本和最小摘要，不保存完整秘密作为“证据”。

模型输出包含训练数据片段或第三方内容时还要处理来源、许可与删除请求。安全扫描不能代替数据治理，但应能把可疑泄露关联到输入、检索源、模型版本和受影响请求。

### 九、分类器阈值必须用独立数据决定

分类器输出分数不是自然界的风险概率。阈值要在代表真实语言、地区、群体和攻击变化的独立标注集上选择，同时观察误报、漏报、严重样本召回、人工量和用户恢复成本。总体准确率会掩盖稀有但严重的失败。

建立阈值矩阵：低风险可提示或允许，高风险直接阻断，中间区域升级人工；不同动作可用不同阈值。公开文本和真实付款不能共享同一决策边界。标注者分歧需要仲裁规则，不能把模糊样本强行当唯一真值。

策略、模型或用户分布变化后重新评测。攻击者会改写表达，正常语言也会漂移；监控只看阻断率可能把产品故障误当安全提升。固定回归集配合新鲜盲样本，才能发现过拟合。

多语言和混合编码要单独分层抽样。把英文集上的阈值直接用于中文方言、拼音、谐音、图片 OCR 或代码注释，会同时扩大漏报与误报；规范化过程还可能改变人名、专业术语和证据。记录原始语言、检测链与规范化版本，无法可靠判断时缩小功能或升级人工，不把“不支持的语言”当作安全内容。

### 十、误拦截和申诉属于安全系统

误拦会阻断真实任务，促使用户绕过控制或转移到更不安全渠道。界面说明哪类规则触发、哪些内容已保留、可以怎样修改或请求复核；不能只显示“违反政策”并清空用户工作。

申诉进入受限人工工具，审核者看到完成决定所需的最小上下文、策略版本和来源，不自动暴露全部会话。审核结果可纠正本次决定，但不能让单个客服永久关闭全局策略。反复误拦应进入数据和规则改进，而不是靠白名单无限扩散。

攻击者也会滥用申诉探测阈值，因此限制频率、分层展示原因并审计权限。用户恢复权与防绕过不是二选一，它们共同构成可持续控制。

### 十一、失败时默认行为必须显式设计

**安全失败（Fail Closed）**表示关键安全判断不可用时，不继续执行需要该判断授权的动作。它不等于整个产品白屏：系统可以保留草稿、展示只读数据、切换人工流程或允许明确低风险功能，但不能把超时当通过。

分类器不可用、Schema 版本不兼容、授权服务超时和审计存储失败应有不同降级。高风险写操作通常停止，低风险文本可以转纯文本或延迟处理。降级状态要让用户知道发生了什么、是否已执行、如何恢复。

重试要区分无副作用检测与可能已生效动作。网络中断后的未知结果先查询幂等记录，不能因“安全服务失败”重复退款、发送或删除。

### 十二、观测与审计不能重新制造泄露

记录请求 ID、用户或服务主体、模型与策略版本、命中的规则类别、授权结果、最终动作和恢复路径。日志用于重建控制链，不保存完整提示、输出、密钥或受保护属性。必要样本使用受限加密存储、留存期限和访问审计。

指标至少包括各层拒绝、严重漏报、误拦申诉、人工等待、降级率、未知结果和策略回滚。按版本、功能和风险层观察，避免把用户 ID 或完整 URL 放入高基数标签。

告警必须对应行动：严重越权或秘密泄露立即停用相关能力，阈值漂移进入策略复核，人工队列积压触发限流。没有负责人和恢复手册的告警只是噪声。

### 十三、测试要覆盖组合和绕过

为每种输出目标建立正常、边界和恶意样本：缺失/额外字段、Unicode 混淆、超长嵌套、危险协议、事件属性、跨块标签、伪造引用、越权对象、秘密片段和内容策略绕过。每个样本写明应在哪一层被阻止以及最终用户状态。

单层通过不等于系统安全。让分类器故意放行危险 URL，验证最终 URL 策略仍拒绝；让模型生成合法结构但越权订单，验证服务端授权阻断；让净化器超时，验证界面不渲染原始 HTML。组合故障能证明纵深控制不是文档口号。

红队发现的样本经过最小化和去敏后进入自动回归，记录策略与依赖版本。修复既检查攻击被阻止，也检查正常任务没有不可接受退化。

### 十四、形成可维护的纵深防御

**纵深防御（Defense in Depth）**要求多个相对独立的控制共同限制后果，而不是重复调用三个同类分类器。结构、业务授权、解释器安全、内容风险、人工判断和运行控制各自证明不同事实；任何一层都不声称替代其他层。

为一个真实 AI 功能画出“输入—上下文—模型—输出—渲染/工具—用户”的数据流，标出每个解释器、主体和副作用。逐层写允许、拒绝、未知与恢复，再用故障注入证明分类器放行、授权不可用、输出跨块和用户申诉时仍保持边界。评审时要求证据指向具体版本，而不是展示一次成功对话。

学完后，你应能把模型输出当作不可信数据，区分 Schema、业务授权、上下文编码、事实核验和内容分类的职责；能选择阈值与人工升级，设计失败关闭、申诉、审计和回归，并解释为什么 Prompt、模型自检或单个分类器都不足以保护真实系统。继续查证可参考 [OWASP GenAI Security Project](https://genai.owasp.org/)、[Chrome 流式 LLM 安全渲染指南](https://developer.chrome.com/docs/ai/render-llm-responses?hl=zh-cn)与 [NIST 生成式 AI 风险管理框架](https://nvlpubs.nist.gov/nistpubs/ai/NIST.AI.600-1.pdf)。
