# MCP Client 发现、能力协商与兼容知识点讲义

## AGENT-04 MCP Client 发现、能力选择、缓存与兼容

一个真正可用的 MCP Client 不只是把 JSON 发给 Server。它要找到正确服务、确认当前能力、建立信任、把协议对象转换成宿主内部模型，并在服务升级、能力缺失、网络失败和恶意描述下保持可控。2026-07-28 核心规范把 `server/discover` 引入发现流程后，客户端更不应依赖一次初始化握手里永久缓存的能力；发现成为可版本化、可失效的独立读操作。

适用场景包括桌面 Host 连接本地 stdio 服务、浏览器/后端连接远程 Server，以及同一产品同时维护旧新协议实现；三者共用发现与能力原则，但身份、凭据和缓存边界不同。

### 学习前先确认

- 直接前置：[AGENT-03 MCP 传输、无状态核心与显式状态](../chinese-guides/agent-03-mcp-transport-stateless-state-versioning.md#agent-03)，用于理解独立请求、显式句柄、版本与恢复。间接前置不重复列出。

### 一、Service Discovery 回答“现在能做什么”

**服务发现（Service Discovery）**是 Client 从目标 Server 或可信目录取得服务身份、协议版本、能力、工具/资源/提示目录及必要元数据的过程。发现结果是一个带来源与时效的快照，不是永久事实。

发现前先确定 endpoint 从何而来：管理员配置、用户明确安装、受信目录或应用内置。模型、网页和工具结果给出的 URL 都是不可信候选，不能自动连接内网地址或携带用户凭据。

发现响应需要 Schema 验证、大小/数量限制和版本检查。描述文本只用于展示与模型理解，不具有授权含义，也不能改变 Host 政策。

### 二、服务身份不能只看显示名称

建立稳定 serverId、发行者、endpoint、签名/证书或安装记录，显示名称只是用户界面。两个同名服务可能来自不同主体；同一服务也可能有多个部署和版本。

远程连接验证 TLS、目标 audience、重定向策略和允许 host。stdio 验证可执行文件路径、包来源、哈希或签名及启动参数。发现到的“官方”文字不能替代供应链证据。

服务迁移 endpoint 时通过可信配置或签名元数据更新，防止 DNS、重定向和目录投毒把凭据送给攻击者。

### 三、Capability Negotiation 选择交集

**能力协商（Capability Negotiation）**是 Client 将产品所需能力与 Server 声明、规范版本和宿主策略求交集，决定启用、降级或拒绝。它不是 Server 声明什么就全部开放。

能力可以包含工具调用、资源读取、提示模板、长任务、额外输入、流式结果或扩展。Client 还要考虑用户角色、当前设备、风险策略和 UI 支持。支持能力但未授权，与根本不支持是不同状态。

用能力矩阵记录 required、optional、fallback 与 security impact。缺少必需语义时在调用前阻止；可选流式缺失可等待完整结果；缺少审批界面不能默认同意高风险动作。

### 四、目录条目是候选接口定义

工具目录包含 name、description、input/output Schema 和注解；Client 解析后映射为内部 ToolDescriptor。名称用于稳定寻址，描述用于选择，Schema 用于机器校验。三者都来自外部 Server，必须限长、过滤冲突并保持来源。

工具描述可能包含提示注入或夸大能力。把它包在不可信数据区，模型选择后仍经过 Host 白名单和服务端授权。`readOnly`、`destructive` 等注解可辅助风险判断，但不能成为唯一控制。

同名工具跨 Server 不合并成一个。内部键包含 server identity、tool name 和版本；用户界面显示来源，避免模型或用户误选。

### 五、Cache Scope 决定何时重新发现

**缓存作用域（Cache Scope）**定义发现快照可被哪个 server identity、endpoint、用户/租户、认证范围、协议版本和策略版本复用，以及何时过期。只用 URL 当 key 会把不同账号的私有能力混在一起。

缓存记录 ETag/版本、获取时间、凭据 scope、失败状态和有效期。Server 通知变化、权限改变、调用返回未知能力、部署版本切换或 TTL 到期时重新发现。安全撤销不等待普通 TTL。

离线时可显示上次目录供阅读，但执行前需在线重新授权；过期缓存不能证明工具仍存在。负缓存要短，防止一次瞬时失败长期隐藏服务。

### 六、调用前进行晚绑定验证

用户或模型选择工具后，Client 在执行前验证当前目录版本、参数 Schema、能力和权限。长时间打开的页面不能用几小时前的描述直接写数据。若工具消失或 Schema 变化，重新发现并展示差异。

参数构造区分模型提供、用户输入和宿主注入。身份、租户、幂等键和审批 token 由可信层加入，模型不可伪造。默认值由版本化 Schema 解释，不能因字段缺失猜测危险值。

结果也按声明 Schema 验证，但 Schema 合法不代表语义正确。保留原始错误类别与服务回执，避免适配器把拒绝变成空成功。

### 七、Compatibility Adapter 隔离协议差异

**兼容适配器（Compatibility Adapter）**把特定 MCP 版本、扩展或旧会话模型转换成宿主稳定的内部能力、事件和错误语义。业务 UI 依赖内部接口，不在每个组件散落版本判断。

适配器明确哪些字段被映射、丢弃或合成。旧 Server 无法提供无状态或长任务语义时，标记能力缺失；不能用内存 session 包装后宣称可跨实例恢复。未知必需语义直接失败，已声明可忽略的可选字段可保留透传。

适配器有独立版本、契约测试和淘汰日期。遥测记录实际使用比例，避免永久维护无人使用的兼容层。

### 八、错误分类驱动重新发现与恢复

网络失败先按传输策略处理；404/方法不存在可能需要重新发现；版本不支持进入兼容选择；Schema 冲突阻止调用；授权失败重新认证或缩小范围；工具业务失败交给任务层。不能遇到任何错误都刷新目录并重试。

调用响应丢失时按 operationId 查询，不因重新发现而重复副作用。Server 切换版本后在途任务继续使用句柄和原协议语义，或明确迁移失败，不能套用新 Schema 猜状态。

退避与熔断按 server identity 和错误类别隔离，一个坏服务不拖垮全部 MCP。恢复后以少量探测流量确认。

### 九、用户授权对应具体能力

安装 Server、允许连接、允许读取资源和批准某次写操作是不同授权。首次发现可以只请求最小元数据；真正调用时按工具、资源、范围和风险确认。批量授权要有可理解的边界与撤销入口。

目录变化出现新高风险工具时不自动继承旧授权。描述或名称变化也应提示可疑差异。管理员策略可以禁止某类 endpoint、工具或数据外传，即使用户希望使用。

前端展示服务来源、当前账号、所需数据和动作后果。Server 自己渲染的文案不能覆盖 Host 的可信确认区。

### 十、资源与提示同样需要来源隔离

资源 URI 解析前验证 scheme、host、路径和访问范围，防止目录遍历、SSRF 和跨租户读取。内容进入模型时保留 data provenance，并按不可信文本处理。大资源分页、限量和取消。

prompt/template 是外部模板，不是系统政策。Host 决定它处于用户内容还是工具数据层，不能让 Server 借模板提升优先级。模板参数也经 Schema 和编码。

缓存资源时 key 包含身份、版本与授权；权限撤销后清理。公开资源和私人资源不能因 URI 相同共享缓存。

### 十一、扩展采用显式 opt-in

核心之外的扩展可能提供 UI、任务或供应商特性。Client 按 namespace/version 识别，并由产品能力矩阵决定启用。未知扩展不得执行；仅展示安全的降级信息。

扩展 UI 在 sandbox、CSP 和桥接权限下运行，消息按外部输入验证。扩展任务句柄仍受 Host 身份和取消策略约束。标准化名称降低集成成本，不自动带来信任。

升级扩展先兼容接收，再启用发送；为旧客户端保留文本或只读 fallback。缺少 fallback 的关键任务应停止并解释。

### 十二、可观测性解释能力选择

记录 server identity、endpoint 类别、规范/扩展版本、发现快照版本、缓存命中、能力交集、适配器、授权结果和调用关联。正文与凭据脱敏，调试仍能回答“为什么没展示这个工具”。

指标包括发现延迟、目录大小、缓存命中/陈旧率、能力缺口、Schema 变化、适配器错误、授权拒绝、版本分布和重新发现风暴。发现成功不等于调用成功，应关联任务结果。

异常告警关注身份不匹配、目录突然膨胀、工具描述哈希频繁变化、跨账号缓存命中和未知扩展。

### 十三、兼容矩阵必须真实互测

至少覆盖当前 Client×当前 Server、当前 Client×旧 Server、旧 Client×当前 Server，以及缺能力、未知字段、工具删除、Schema 变化、权限变化、缓存过期和服务冒名。使用协议夹具还要连接真实参考实现。

断言选择正确交集、不会调用未授权工具、缓存不跨身份、降级仍可理解、旧适配器不伪造语义。模糊测试目录大小、重复名称、恶意描述、URI 和非法 Schema。

在代理、重定向、离线、Server 重启和多实例环境测试。只有本机 happy path 不能证明 Client 健壮。

### 十四、多 Server 选择需要稳定策略

多个 Server 可能提供相似工具。Client 先按管理员/用户允许列表和能力要求过滤，再考虑服务身份、数据位置、质量、健康与成本；不让模型仅凭营销式 description 选择。用户可固定首选服务，关键切换显示数据将发送到哪里。

内部工具键包含 serverId，计划一旦批准就绑定具体服务与版本。执行前若服务不可用，不自动换到另一个同名工具，因为参数、数据处理和副作用可能不同；重新适配、验证并在必要时确认。只读低风险 fallback 也要保持来源标记。

结果合并保留每个 Server 的证据和错误。一个服务成功不能掩盖另一个必需服务失败，两个矛盾结果不能由最后到达者覆盖。

### 十五、浏览器 Client 处理 origin 与凭据边界

网页发起远程 MCP 请求时，endpoint、页面 origin、Host 应用和认证服务是不同主体。CORS 允许读取响应不等于业务授权，cookie 自动携带还要处理 CSRF/SameSite。优先由可信后端代理兑换目标特定凭据，避免把长期 token 暴露给页面与第三方 Server。

重定向需重新校验 host，阻止到环回、链路本地和内网的 SSRF；DNS 重绑定、IPv6 形式和 URL 编码都纳入规范化。错误页面与认证 HTML 不能当 MCP JSON 解析。浏览器扩展或桌面桥接拥有更高能力时，消息来源和用户手势分别验证。

连接新 Server 前让用户看见真实域名、发行者、数据范围和撤销入口。卸载时清凭据、缓存、任务订阅和本地进程。

### 十六、把发现作为持续控制面

实现顺序可以是：可信 endpoint 注册、独立发现、内部描述符、能力矩阵、作用域缓存、晚绑定验证、适配器和扩展。Host 始终保留最终授权和 UI 控制，Server 只声明可提供什么。

Client 发布清单包括 endpoint 来源、服务身份、发现 Schema 与上限、能力矩阵、缓存 key/TTL/失效、调用前验证、凭据 audience、未知扩展、适配器退出和用户撤销。用恶意描述、同名 Server、权限变化、工具删除、重定向和版本切换逐项验证。发现接口成功但其中一项越权，整条能力不能进入可执行目录。

同时准备完全无 MCP、只支持核心工具、只支持旧版和扩展齐全四类环境，确认核心任务的降级文案与人工路径。兼容性不是“尽量不报错”，而是在能力不足时仍保持正确、安全和可解释。

目录 UI 还应区分已发现、已安装、已认证、已授权和当前可用；这些状态不能合成一个绿色“已连接”。用户可查看上次发现时间、版本与权限，并能主动刷新、重新认证或移除服务。

学完后，你应能设计安全的 Server 发现、身份验证、能力交集、缓存失效和版本适配，并理解为什么目录描述不能等同权限。实现前应对照 [MCP 2026-07-28 发布说明](https://blog.modelcontextprotocol.io/posts/2026-07-28/)与 [MCP 官方文档](https://modelcontextprotocol.io/)，复核当前方法和 SDK 支持情况。
