# AI 数据、变更与责任治理知识点讲义

## AIGOV-01 数据来源、模型变更、审计与责任治理

同一套资料助手昨天能正确引用政策，今天却反复给出旧规则。模型名称没有变，但运营换了提示，索引中还留着撤回的文件，服务商的模型别名也可能更新了。如果团队只记着“正在使用模型 X”，就无法解释哪个变化影响了哪些回答，更不知道该回退哪一部分。

治理把这些问题变成可以执行的管理：谁负责这项能力，来源允许做什么，哪个配置通过了评估，发生问题时怎样找到影响并停止。本讲用资料摘要与配图功能串起来源、变更、来源凭证和地区条件。读完后，你应能设计有证据约束的发布入口，而不是只写一份原则说明。

### 学习前先确认

- 直接前置：[AIPROD-02 高风险自动化与人工控制](../chinese-guides/aiprod-02-high-risk-automation-human-in-the-loop.md#aiprod-02)。先按后果和可逆性决定需要哪些人类决定与执行控制。
- 直接前置：[PRIVACY-02 跨地区数据分类与工程控制](../chinese-guides/privacy-02-cross-region-classification-engineering-controls.md#privacy-02)。用途、地区、主体角色与权利请求应进入有证据的处理规则。

### 一、登记的是一项能力，不只是一个模型

“给客服草拟内部摘要”和“自动向客户发送答复”即使使用同一模型，也有不同后果。能力登记应以稳定的功能 ID 连接用户任务、输入、输出去向、工具、副作用、适用人群、地区、负责人和停止方式。模型只是其中一个依赖。

例如 `support-summary` 的首版只读已授权工单，生成内部草稿，客服核对后保存。登记中同时写明不支持哪些任务、谁能扩大范围、模型不可用时如何回到模板。否则一次“顺手增加自动发送”的小改动，可能绕过原有风险判断。

**模型卡（Model Card）**用来说明模型的用途、评估条件、限制及相关信息。供应商卡片反映其提供的证据；应用团队还需补充在本任务、语言、资料和提示下的观察。卡片没有提供某项证据时写“未知”，不能用排行榜成绩填空。模型卡也不是安全证书或部署许可。

任务级评估应记录样本、判定规则、配置和日期，避免把测试集准确率直接当成整个产品可靠性。样本分层与留出如何使用，参照 [AIPROD-01](../chinese-guides/aiprod-01-ai-task-model-selection-value-validation.md#三先建立评分依据再收集更多答案)。

### 二、来源撤回要沿派生链找到影响

**数据血缘（Data Lineage）**记录数据从哪里来、经过什么处理、生成哪些派生物。对资料助手，一份政策文件可能派生切片、嵌入、搜索索引、缓存摘要、评测样本和用户答案。只删除原文件，不会自动清除其他位置。

来源记录至少区分获取渠道、许可或处理依据、允许用途、版本、访问范围、保留期限与撤回入口。公开可访问不等于允许训练、再发布或无限期保存；同意用于摘要也不能自动扩展为模型训练。嵌入和摘要可能继续包含可关联信息，不应因格式改变就默认匿名。

下面是合成依赖图。保存为 `lineage.mjs`，用 Node.js 22 运行，也可在现代浏览器控制台执行。它只计算需要检查的范围，不执行删除：

```js example=aigov01-lineage
const derived = new Map([
  ['source-v1', ['chunks-v1', 'eval-v1']],
  ['chunks-v1', ['index-v1']],
  ['index-v1', ['cache-v1']],
  ['cache-v1', ['answer-7']]
]);
function affected(start) {
  const seen = new Set(), queue = [start];
  for (let i = 0; i < queue.length; i += 1) {
    const id = queue[i];
    if (seen.has(id)) continue;
    seen.add(id);
    queue.push(...(derived.get(id) ?? []));
  }
  return [...seen];
}
console.log(affected('source-v1').join(' → '));
// => source-v1 → chunks-v1 → eval-v1 → index-v1 → cache-v1 → answer-7
console.log(affected('cache-v1').join(' → ')); // => cache-v1 → answer-7
```

第一项按队列遍历顺序列出影响，不表示派生物必须按这条直线处理。撤回来源后，可能要禁用检索、重建索引、失效缓存、复核答案和更换评测标签，各有责任人。已经向外发布的答案未必能直接删除，应按用途纠正或通知；法律保留义务、备份恢复和第三方副本另行判断。

血缘图记录的是已知关系。如果某个导出脚本从未登记，遍历结果不会神奇地发现它。应在实际导入、构建、缓存和导出入口记录关系，并通过代表性撤回演练查缺口。不能以“计数归零”声称所有副本已经消失。

### 三、批准必须绑定整个配置组合

决定行为的不只是模型，还包括提示、检索索引、工具、输出校验、内容政策、阈值和界面。修正一段“仅内部使用”为“直接发送”的提示，就可能改变副作用；更换索引也可能改变事实来源。变更单要说明具体差异、预计影响、证据、发布范围和回退方式。

以下实验把配置组合写成一个确定字符串，用它绑定评估与批准。保存为 `release-gate.mjs`，用 Node.js 22 运行。审批对象与时间都是模拟数据，没有真实身份或发布动作：

```js example=aigov01-release-gate
const fields = ['model', 'prompt', 'index', 'tools', 'policy'];
const key = (config) => JSON.stringify(fields.map((field) => config[field]));
const v1 = { model: 'm1', prompt: 'p1', index: 'i1', tools: 'read1', policy: 'g1' };
const evidence = { config: key(v1), passed: true, expires: 30 };
const approval = { config: key(v1), owner: 'reviewer-a', expires: 20 };
function gate(config, proof, permit, facts) {
  if (!fields.every((field) => typeof config[field] === 'string' && config[field])) return 'invalid';
  if (facts.regionDecision !== 'approved') return 'region_review';
  if (!proof.passed || proof.config !== key(config) || facts.now >= proof.expires) return 'evaluation';
  if (!permit.owner || permit.config !== key(config) || facts.now >= permit.expires) return 'approval';
  if (!facts.rollbackReady) return 'recovery';
  return 'eligible';
}
const facts = { now: 10, regionDecision: 'approved', rollbackReady: true };
console.log(gate(v1, evidence, approval, facts)); // => eligible
const v2 = { ...v1, prompt: 'p2' };
console.log(gate(v2, evidence, approval, facts)); // => evaluation
const newEvidence = { ...evidence, config: key(v2) };
console.log(gate(v2, newEvidence, approval, facts)); // => approval
console.log(gate(v1, evidence, approval, { ...facts, regionDecision: 'unknown' })); // => region_review
console.log(gate(v1, evidence, approval, { ...facts, now: 21 })); // => approval
console.log(gate(v1, evidence, approval, { ...facts, rollbackReady: false })); // => recovery
```

只改提示，旧评估就不再对应当前组合；即使补了新评估，旧批准仍然不匹配。`eligible` 仅表示这些模拟条件满足，不表示真实上线获准。字符串键不是密码学签名；真实系统还需要受控证据库、可信审批身份、不可绕过的部署入口和原子状态更新。配置里若还有模型参数或界面版本，也必须纳入相应变更范围。

临时例外要有批准者、范围、补偿措施和期限，过期后重新判断。不能把“紧急发布”作为永不失效的全局放行字段。具体人工批准机制复用 [AIPROD-02](../chinese-guides/aiprod-02-high-risk-automation-human-in-the-loop.md#四确认必须绑定即将执行的具体版本)。

### 四、灰度、回退与下线恢复不同东西

通过门禁后仍需有限试点。稳定分流、保留基线，并观察完整任务质量、严重错误、成本、等待和群体差异。监控失明时暂停扩大；只看 HTTP 成功率，看不到错误摘要或误拦截。

回退配置可以停止新影响，却不能撤回已经发出的邮件、删除外部副本或抹掉错误决定。恢复计划应分为停止新任务、恢复可用路径、确认已发生效果、补偿或通知。若旧模型已下线，回退可能只能转人工或规则，不能承诺不存在的一键恢复。

下线还要处理后台队列、定时任务、数据采集、访问权限、索引和凭据。隐藏前端按钮只改变入口，无法证明后台没有继续执行。供应商迁移也要核对能力、数据区域、留存和删除支持，接口字段相同不代表合同条件相同。

对于证据保留，既要能复盘，又要限制访问和期限。保留配置、样本版本与判定记录，不等于无限保存所有客户原文。供应商数据政策和合同变更由对应负责人核对，再映射为实际路由、采集和删除配置。

### 五、用最少必要记录重建决定

一条有用审计线应连接“来源与版本 → 模型建议 → 确定规则与人的决定 → 实际效果”。例如请求 `r7` 使用 `i1/p2/m1`，引用 `source-v1`，校验拒绝外发，最终只保存草稿。只有聊天全文无法证明哪个执行器真的发了请求；只有 token 账单又无法说明依据。

审计字段可包括能力 ID、任务 ID、主体引用、配置组合、来源版本、批准引用、结果类别、操作 ID 与时间。敏感正文在必要时进入受控证据库，普通日志只留最小摘要或引用。哈希便于发现变化，但低熵个人数据的普通哈希仍可能被猜回，不能等同匿名。

**责任归属（Accountability）**意味着有人拥有决定权、资源和响应义务。产品负责人定义用途，数据负责人处理来源与撤回，工程负责人维护执行门禁，安全和隐私角色审阅相应证据；需要专业适用判断时由有资格的人确认。不能把责任交给“模型自己判断”。

人员离职或职责变化时转移责任并复核许可。事故处置先停止扩大、保全必要证据、确定影响，再决定恢复、纠正和通知。历史错误追加纠正记录，避免无痕修改导致后续无法理解当时的决定。

### 六、来源凭证回答的不是事实真伪

**内容凭证（Content Credentials）**向用户呈现与媒体资产相关的来源、编辑、签名和验证信息。本讲依据 C2PA 2.4 规范解释这一模型，不宣称它是所有工具当前唯一支持版本。实际集成应固定验证库、规范支持范围、信任配置与错误映射。

验证至少要区分声明与资产的绑定是否成立、签名是否有效、签发者是否受当前信任配置认可。即使这些都通过，也不能证明画面里的事件真实、声明者从不说谎或内容没有风险。凭证可以记录“做过编辑”，不替用户判断编辑是否具有误导性。

| 验证观察 | 可以展示 | 不能推导 |
| --- | --- | --- |
| 绑定、签名和信任检查通过 | 此文件的来源声明可按当前配置验证，允许展开详情 | 内容事实已证实 |
| 未发现凭证 | 当前文件未找到可读取的凭证 | 不是 AI 生成、作者有意隐瞒 |
| 文件与声明绑定失败 | 当前文件无法与这份声明匹配 | 已证明恶意篡改 |
| 签名可检查但签发者未知 | 未被当前信任列表确认 | 文件必然伪造 |
| 不支持版本或验证依赖不可用 | 暂不能完成验证，保留原文件核验入口 | 无凭证或验证通过 |

不同验证库的原始状态需按实际含义映射，不能只根据一个布尔值显示绿色对勾。证书有效期、时间戳、撤销状态与验证时点要按规范处理；“证书今天过期”也不能由 UI 自行推导历史签名一定无效。

### 七、导出后的文件才是用户带走的结果

显式文字提示、文件元数据、数字水印与密码学来源凭证各有用途。文字易见但可能被裁掉，元数据便于机器识别但可能被转码移除，来源凭证需要验证绑定与信任。它们不能相互冒充，也不能以是否存在其中一种作为内容真假的检测器。

设计生成、编辑、下载、压缩、转码与再次上传的路径表。例如原图有凭证，平台转为另一格式后没有携带凭证，此时展示“导出文件未检出凭证”，同时提供原文件与验证详情。不能延续原图的验证勾号，使用户以为导出文件也已通过。

真正验证要用一份有效原文件、无凭证文件及被改变的文件，经过实际验证库和真实导出路径观察。仅把模拟状态传给一个标签函数，只能证明 UI 分支，不能证明签名验证或标识保留。本讲没有伪造证书或把字符串判断包装成 C2PA 实验。

### 八、把地区条件写成可升级的决定

地区矩阵应记录服务地区、主体角色、内容类型、生成或传播方式、适用依据、生效日期、专业复核者与所需控制。不能只存一个 `CN=true`，更不能把数据存储位置当作全部适用判断。沿用 [PRIVACY-02](../chinese-guides/privacy-02-cross-region-classification-engineering-controls.md#privacy-02) 的事实与规则分离方式。

2026-09-26 核对的中国《人工智能生成合成内容标识办法》自 2025-09-01 起施行，其适用主体见第二条；显式、隐式标识及下载导出、传播处理分别有条件和要求。工程评审应直接读取第四至六条等对应正文及适用强制性标准，不能把“都加一行 AI 生成”当作完整实现。[官方正文](https://www.cac.gov.cn/2025-03/14/c_1743654684782215.htm)用于核对具体边界，本讲不判定某项真实服务的法律适用性。

对于 EU 或其他地区，新增相应事实和当期官方依据，再由负责者判断；中国矩阵不能复制成全球规则。不明确的高影响发布先保留待审状态，给出缺少的事实和责任人，避免让开发者猜一个最宽松答案。

规则改变时新增版本和生效区间，保留旧决定当时的依据。声明遵循某项技术标准也不代表履行了全部地区义务；技术测试与专业适用审查分别留下证据。

### 九、治理要能回答一次具体事故

假设发现来源许可撤回：先停止新检索，用血缘查索引、缓存和答案；负责人确定删除、重建或纠正范围，生成新的配置组合；重新取得评估与批准后有限恢复。这个过程把登记、血缘、门禁、审计和责任连在一起。

日常观察无负责人能力、证据过期、未批准变更、撤回处理时间和无法回退比例。指标用来发现治理缺口，不用于让团队把风险类别改得更好看。一次演练成功也只证明这条路径，供应商不可用、人员缺席和跨地区变化仍需按实际风险补证据。

### 带着问题回看

- 只改提示为什么也会使模型评估和旧批准失效？
- 删除源文件之后，哪些派生物与外部效果仍可能存在？
- 来源凭证有效、缺失、无法验证分别能告诉用户什么？
