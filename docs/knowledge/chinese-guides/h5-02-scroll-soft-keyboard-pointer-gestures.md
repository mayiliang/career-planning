# 移动滚动与手势协调知识点讲义

## H5-02 滚动、软键盘、触控与手势冲突

移动交互困难通常不是某个事件没触发，而是浏览器原生滚动、嵌套容器、系统返回手势、软键盘和组件自定义手势同时争夺同一输入。粗暴 `preventDefault()`可能让一个滑块工作，却锁死页面滚动、缩放和辅助技术。本讲从滚动容器与统一指针模型出发，建立手势仲裁、键盘避让、指针取消、可访问替代和双端验证方法。

### 学习前先确认

- 直接前置：[H5-01 viewport、响应式、安全区与横竖屏](../chinese-guides/h5-01-viewport-responsive-safe-area-orientation.md#h5-01)。软键盘和浮层定位依赖布局视口、视觉视口与安全区。
- 直接前置：[BROWSER-01 DOM 渲染、事件与存储](../chinese-guides/browser-01-render-events-storage.md#browser-01)。需要先理解事件传播、默认行为、焦点和浏览器渲染。

### 一、先分清页面滚动与内层滚动

页面根滚动、弹窗列表、横向卡片和编辑区都可能是滚动容器。容器由 overflow和实际溢出共同形成；设置 `overflow:auto`但没有尺寸约束不会产生内滚动。嵌套越多，惯性、焦点滚入和恢复位置越难预测。

优先保留单一主要纵向滚动。弹层确需内滚动时，内容区负责滚动、头尾固定在同一布局，背景在打开前保存位置并在关闭后恢复。不要通过给 body永久 `overflow:hidden`留下页面无法滚动。

滚动位置属于任务状态。路由返回、键盘关闭和方向变化后要恢复有意义位置；虚拟列表用项目身份而非裸像素保存，数据插入后仍能定位。

### 二、滚动链决定边界后的运动去向

**滚动链（Scroll Chaining）**表示当前容器到达边界后，剩余滚动继续传给祖先。弹窗列表滑到顶部后带动背景页面，就是典型链传播。`overscroll-behavior`可以在指定轴和容器限制传播及过度滚动效果。

限制应尽量局部：弹层纵向列表可 contain，普通页面仍允许系统刷新或导航手势。全局 `overscroll-behavior:none`可能破坏平台习惯。不同WebView支持不一致，必要时用布局与范围明确的事件策略回退。

判断边界要考虑浮点滚动值、方向、RTL和惯性，手写 `scrollTop===0`容易误判。优先让CSS处理，只在具体手势区域补充JS。

### 三、Pointer Events 统一多种输入

**指针事件（Pointer Events）**用 pointerId、pointerType、压力、按钮和坐标统一鼠标、触摸与笔。一次手势跟踪特定pointerId，从 pointerdown开始，在 pointerup或pointercancel结束；多点输入不能共享一个全局起点。

浏览器可能因为滚动、缩放、系统手势、窗口失焦或设备变化发出 pointercancel。取消是正常终态，必须清理高亮、拖拽状态、计时器和捕获。只处理 pointerup会留下“永远拖动中”。

click仍是按钮激活的高级语义，键盘和辅助技术可触发。普通按钮不要重写为 pointerdown；自定义拖拽才使用低级事件，并保留按钮、键盘和屏幕阅读器等价路径。

### 四、touch-action 应先于 preventDefault

`touch-action`声明浏览器允许的平移和缩放，使浏览器在手势开始前仲裁。例如横向滑块可允许纵向 pan，画布可按需求限制。它比在每次 move中阻止默认行为更及时，也更易被浏览器优化。

不要为了自定义手势设置 `touch-action:none`覆盖整页，这会禁用滚动与捏合缩放。作用域缩到把手或画布，并提供放大、撤销和键盘操作。CSS改变通常只影响下一次手势，手势进行中不要依赖动态切换。

只有CSS无法表达且确实需取消默认行为时，才使用非passive监听，并记录性能影响。

### 五、passive 监听器是行为承诺

**被动监听器（Passive Listener）**向浏览器承诺回调不会调用 `preventDefault()`，浏览器可立即开始滚动。滚动观察、埋点和只读手势通常应passive；若回调中调用阻止会被忽略并产生警告。

需要阻止默认行为时显式 `{passive:false}`，但先缩小元素、事件和阶段。高频 move回调只保存最小状态，把视觉更新批到 rAF；不要同步布局或上报网络。

监听器移除要保持回调身份和capture，passive本身通常不参与移除匹配，但配置应一致可读。组件卸载、手势取消和路由离开都清理。

### 六、指针捕获保持拖拽连续

**指针捕获（Pointer Capture）**让元素在指针移出边界后继续收到该pointerId事件，适合滑块、拖拽和绘图。pointerdown后捕获，结束或取消时释放；元素移除时也重置状态。

捕获不等于阻止滚动，仍由 touch-action与默认行为决定。多指操作为每个pointer维护状态，不能一个指针释放全部。`lostpointercapture`也应作为终止信号处理。

拖拽结果先预览，松手再提交不可逆动作；跨出窗口、系统来电和设备旋转要安全取消。键盘方向键、输入框或增减按钮提供同等调整。

### 七、手势识别要有阈值与意图仲裁

点击、拖动、长按、滑动和滚动在起始阶段可能相同。设置距离、时间和主轴阈值，在未确认前不要执行副作用；一旦判定纵向滚动，横向组件停止竞争。阈值使用CSS像素并在触摸、笔和鼠标分别验证。

速度和距离可决定惯性或关闭，但动画终态必须稳定。快速反向、双指、pointercancel和低帧率会让采样稀疏，算法不能假设固定事件频率。

手势区域靠近屏幕边缘时与系统返回冲突。保留安全内边距、提供显式关闭按钮，不尝试劫持系统保留区域。

### 八、软键盘改变可见区域而非总是重排页面

键盘出现后浏览器可能缩小视觉视口、布局视口或只覆盖内容，WebView还有 adjustResize/adjustPan等模式。监听 visualViewport resize/scroll，结合焦点元素位置判断，而不是用“高度减少300px”猜键盘。

聚焦时先让浏览器原生滚入视图，再在稳定时修正，使输入框底部、错误提示和主要操作位于可见区。固定底栏根据视觉视口偏移调整，但避免每个事件强制布局。

键盘关闭、方向变化和路由离开恢复临时样式与滚动。不要在每次 resize模糊当前输入，这会让用户无法输入；不要把键盘高度当设备常量。

### 九、焦点、滚动和验证消息需要协作

表单提交失败时把焦点移到错误摘要或首个错误字段，并使用 `scroll-margin`/`scroll-padding`避开粘性头。键盘打开时错误文本可能改变布局，滚动应等待DOM更新后执行一次，防止来回跳动。

`scrollIntoView`的block选项在嵌套容器中可能同时滚动多层，先确认滚动owner。用户正在拖动时不要自动抢滚；自动滚动应由明确操作触发。

焦点可见和内容不被键盘遮住都要验证。屏幕阅读器虚拟光标与触摸事件不同，控件语义、标签和错误关联不能依赖手势代码。

### 十、弹层和 Bottom Sheet 是综合场景

Bottom Sheet同时涉及背景锁滚、内部列表、拖拽把手、键盘、安全区和焦点陷阱。结构上让把手负责拖拽、内容负责滚动；列表不在顶部时向下手势先滚列表，到顶部后达到阈值才转为关闭拖拽。

打开时保存触发元素与页面位置，设置对话框语义并把焦点移入；关闭时释放捕获、监听、视觉视口订阅和背景锁，焦点返回触发者。键盘Escape和关闭按钮始终可用。

如果内容很长或表单复杂，全屏页面可能比手势弹层更可靠。组件形态应服务任务，不为炫技制造冲突。

### 十一、滚动性能需要减少同步工作

scroll和pointermove可高频触发。监听中避免读取后立即写布局、复杂JSON和网络发送；使用passive、rAF批量和IntersectionObserver替代逐像素检查。节流仍要保证最终状态更新。

`position:sticky`和原生滚动优先于JS模拟。自定义平滑滚动尊重减少动态偏好，并允许用户输入中断。scroll-linked动画使用平台能力时仍要观察支持和主线程成本。

性能优化不能通过取消所有默认行为实现。滚动流畅但页面不能缩放、返回或选择文本仍是不合格。

### 十二、WebView 与 iOS/Android 差异必须实测

iOS Safari、Android Chrome和应用WebView在地址栏、键盘、overscroll、系统返回与视口事件上不同。记录系统、内核、宿主和键盘类型；桌面触摸模拟不覆盖输入法与惯性。

宿主可能通过原生桥报告安全区或键盘，但消息需要版本和校验。Web实现保留VisualViewport/CSS回退，不能完全依赖某个App注入。

兼容失败时优先降级为普通滚动与按钮操作。未测试平台明确标记，不用UA字符串猜全部能力。

### 十三、故障注入应覆盖中断而非只走成功路径

测试快速点按、长按后移动、双指、从边缘开始、拖出元素、pointercancel、方向切换、键盘弹出/关闭、组件中途卸载和路由跳转。记录事件序列、pointerId、滚动位置、视觉视口和最终状态。

检查背景不意外滚、内部列表可到达全部内容、输入框可见、监听不累积、捕获已释放。自动测试可断言状态与监听，真实设备录屏验证惯性、系统手势和键盘。

辅助路径同样执行：键盘完成拖拽等价操作、Escape关闭、屏幕阅读器找到名称与错误。不能以“移动端主要用触摸”排除。

### 十四、学完后应能设计输入仲裁合同

以图片排序为例，按下时只进入possible并记录pointerId；移动未越阈值仍允许点击，主轴超过阈值才捕获并进入dragging；拖动期间使用transform预览，列表自动滚动只在边缘小区域且速度有上限；pointerup按当前目标提交，cancel/lostcapture/卸载全部恢复原位。提交后焦点跟随被移动项并通过状态文本通知顺序，键盘用抓取/方向/放下或上下移动按钮完成同一动作。若排序触发远端写入，还要显示保存、失败与重试，旧请求不能覆盖新顺序。这说明手势只是输入层，业务状态和网络一致性仍需独立合同。

滚动位置恢复也应按来源处理：浏览器前进后退优先保留原生恢复，应用路由切换按列表身份保存，筛选条件改变则定位到首个有效结果，键盘关闭只修正被遮挡焦点。程序化滚动标记来源，避免scroll监听把它当用户意图反复写回。无障碍用户可能关闭动画，测试设置后立即到达终点。对于聊天、日志等自动跟随底部的界面，只有用户原本接近底部时继续跟随；用户向上阅读后出现“回到最新”，不能每条新消息抢走位置。

团队还应为手势组件保存状态表：idle、possible、dragging、scrolling、cancelled与committed分别接受哪些事件、谁拥有指针、是否允许默认滚动、退出时清理什么。用同一表检查多指、快速反向、后台、失焦和卸载，避免事件分支散落。对每次兼容补丁记录真实设备证据、影响宿主与回退，平台升级后复测并删除失效分支。用户任务验证同时包含触摸、鼠标、笔、键盘和屏幕阅读器，性能数据记录回调开销与掉帧；只有默认行为、自定义手势和替代路径都能完成任务，仲裁才算成立。

你应能区分滚动容器和滚动链，用Pointer Events跟踪多输入并正确处理cancel/capture；优先用touch-action和局部overscroll策略，理解passive承诺；能在视觉视口变化时保护焦点和操作，并为自定义手势提供键盘与语义替代。

选一个含内滚列表与表单的Bottom Sheet，在iOS和Android可靠环境执行边界滚动、键盘和中断流程，保存事件与视口证据。继续查证可参考 [MDN Pointer Events](https://developer.mozilla.org/zh-CN/docs/Web/API/Pointer_events)、[MDN Visual Viewport](https://developer.mozilla.org/zh-CN/docs/Web/API/Visual_Viewport_API)与 [MDN overscroll-behavior](https://developer.mozilla.org/zh-CN/docs/Web/CSS/overscroll-behavior)。
