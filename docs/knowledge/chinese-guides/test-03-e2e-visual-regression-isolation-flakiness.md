# 测试知识点讲义

## TEST-03 端到端测试、视觉回归、隔离与不稳定性治理

端到端测试在真实浏览器中穿过界面、网络和服务边界，能证明用户关键任务是否连接起来。它的真实性更高，成本和不确定因素也更多。成熟策略不是把所有业务规则都堆进 E2E，而是选择单层无法证明的高价值路径，控制数据与环境，并把失败证据保存到足以判断产品、测试还是基础设施问题。

### 学习前先确认

- 直接前置：[TEST-01 测试设计、预言、不变量与变异验证](../chinese-guides/test-01-test-design-oracles-properties-mutation.md#test-01)、[WEB-01 HTML 语义、表单与可访问性基础](../chinese-guides/web-01-html-semantics-forms-accessibility.md#web-01)。两份资料分别提供预言/隔离原则和用户可感知的角色、名称与焦点合同，彼此不存在递归重复。

### 一、E2E 只承担跨边界证明

**端到端测试（end-to-end test）**适合登录后完成核心任务、路由深链、文件上传下载、浏览器存储、真实布局和跨服务连接。金额计算的所有边界、解析器大量输入或组件十种错误文案不应主要依赖 E2E，因为运行慢、定位粗且环境噪声大。

选择用例时问：失败是否会阻断大量用户；是否跨越浏览器与服务；低层测试能否同等可信地证明。如果纯函数即可判断，就留在单测；若必须证明 Cookie、重定向和页面最终状态共同工作，再使用 E2E。

### 二、测试用户任务，不测试点击脚本

用例名称应是“用户能从待审批列表修改课程并看到保存结果”，而不是“点击第八行按钮”。步骤围绕业务身份定位数据，断言用户可见结果和服务端关键状态。

旅程过长会把许多失败汇聚到一个用例。把共享登录放入受控 setup，按业务阶段拆分，同时保留至少一条真实登录路径。不要让所有测试通过直接写 storage 绕过身份页面，否则认证 UI 可能完全损坏而套件仍绿。

### 三、Browser Context 提供进程内隔离

Playwright 等工具可为每个测试创建独立**浏览器上下文（browser context）**，隔离 Cookie、Local Storage 和 session。它比为每个用例启动完整浏览器快，但不会自动隔离服务端数据库、邮件箱、对象存储或共享缓存。

每个测试使用唯一租户、账号和业务 ID。并行 worker 的临时目录、端口和数据库 schema 也要区分。禁止依赖用例顺序；单独运行和随机顺序都应得到相同结果。

共享只读参考数据可以复用，任何会修改的实体都由当前测试拥有。

### 四、测试数据需要建立与清理协议

优先通过受控 API 或种子脚本创建精确状态，比在 UI 中为每个用例重复十分钟前置更快、更稳定。UI 前置本身是本次任务的一部分时才通过页面完成。

数据工厂应返回创建的 ID，清理只删除当前测试所有资源。清理失败不能覆盖原测试失败，应分别报告并留存诊断。对共享环境，可用带运行 ID 的命名空间和定期垃圾回收，避免误删他人数据。

生产真实数据不应进入测试；使用合成账号和最小权限令牌。

### 五、Locator 描述用户可见合同

**定位器（locator）**优先使用角色、名称、label 和稳定业务文本：

```ts
const row = page.getByRole('row', { name: /课程 C-008/ });
await row.getByRole('button', { name: '编辑' }).click();
await page.getByRole('textbox', { name: '课程名称' }).fill('AI 工程实践');
```

深层 CSS、XPath 和 `.nth(7)` 绑定 DOM 结构。若业务确实要求第八项，应先通过业务排序规则找到对应 ID，再验证位置；不能让数组位置成为实体身份。

locator 自带操作可行性等待和断言重试，但不会替你定义业务完成条件。

### 六、自动等待不是等待一切

点击会等待元素可见、稳定、可接收事件且启用；断言会在超时内重试。这解决渲染时序，不保证后端任务、WebSocket 消息或文件处理已经完成。

等待具体响应、状态文本、URL 或持久结果。`networkidle` 对长轮询、流式连接和埋点不可靠，固定 `waitForTimeout` 则押注速度。若后台任务有 job ID，应轮询明确状态或监听业务事件，而不是睡眠。

Promise 等待要在触发动作前注册，防止快速响应已经发生后才开始监听。

### 七、导航包含多种完成边界

链接点击可能触发文档导航、SPA 软导航、下载或新标签。分别使用 URL、页面内容、download 或 popup 事件验证。不要假设点击一定产生 `load`。

深链需直接访问并刷新，验证服务器 fallback、身份恢复和数据加载。前进后退检查 history 与状态；外部重定向则核对允许域和回跳参数，避免把测试送到真实第三方登录。

### 八、网络控制只替换不受控边界

对自己的后端可在测试环境使用真实服务，以验证接口合同；对支付、地图、邮件等第三方使用 route 拦截或沙箱，固定响应并避免外部波动。另设少量独立联调监控检查真实第三方，不把其不稳定带入每个 PR。

网络替换应保留请求 schema、延迟、错误和重试语义。直接返回理想 JSON 会遗漏鉴权、分页和异常。未匹配请求可以记录或失败，防止意外访问公网。

故障注入覆盖 401/403、500、超时、断网、重复提交和迟到响应，并断言用户有下一步。

### 九、认证状态要安全复用

setup 可以通过真实登录生成 storage state，其他用例在独立上下文加载副本。状态文件可能包含敏感 Cookie，不得提交仓库或输出到公开制品；账户权限应最小且可撤销。

状态会过期或受环境绑定。生成时记录目标环境和时间，失败时区分应用拒绝与测试凭据过期。测试不同角色时使用独立状态，不在用例中动态提升同一账号权限。

### 十、重试是诊断手段，不是稳定性证明

**不稳定测试（flaky test）**在代码和输入不变时结果偶发变化。允许重试可收集第二份 trace 并减少临时基础设施对开发的阻断，但首跑失败必须统计。

若二次通过就标绿，套件会逐渐依赖运气。按产品竞态、测试等待、共享数据、环境容量和第三方故障分类，记录发生率、owner 与修复期限。隔离区是暂时治理，不是永久墓地。

把测试改为串行或延长超时只能作为定位实验，不能自动成为最终修复。

### 十一、Trace、截图、视频和日志各有用途

**追踪包（trace）**可保存步骤、DOM 快照、网络和时间线；截图显示某时刻外观；视频展示连续过程；服务日志证明后端状态。单一证据不能回答全部问题。

CI 失败时保存首跑 trace、最后截图、浏览器 console、关键网络和服务关联 ID。制品要脱敏并设置保留期。日志太多会淹没因果，按测试运行 ID 关联并突出第一处业务偏差。

本地调试可用 headed、slow motion 或断点，但最终验证回到正常速度和 CI 环境。

### 十二、失败先分类再修改测试

产品缺陷表现为可重复的错误业务结果；测试缺陷常是错误 locator、等待或数据假设；环境故障包括服务未启动、磁盘满和浏览器崩溃；第三方故障来自不受控服务。

分类基于 trace、网络、服务健康和重复实验。不要看到 timeout 就增大 timeout，也不要看到 500 就把 route mock 掉。修复应落在拥有问题的层，并用原场景复测。

### 十三、视觉回归需要稳定基线

**视觉回归（visual regression）**比较当前截图与经评审基线，适合发现间距、字体、颜色、遮挡和响应式变化。渲染会受操作系统、浏览器版本、字体、GPU、设备像素比、locale、时区和颜色方案影响，基线与执行环境必须一致。

固定视口、字体、数据和时间，关闭不必要动画。动态头像、广告或光标优先注入稳定数据；遮罩只覆盖明确非目标区域，不能把主要内容整体抹掉。

像素阈值吸收可解释噪声，不应不断调大。每次基线更新查看 diff，并关联设计或需求决定；自动接受会让回归成为新标准。

### 十四、截图不能证明交互和无障碍

像素相同可能焦点顺序错误、按钮无名称或请求没发生；像素不同也可能是合法时间文本。视觉测试与角色/名称断言、键盘路径和业务状态测试互补。

对弹层应截打开状态、长内容和错误状态，而不只空闲页。响应式页面至少覆盖关键断点两侧和长文本。强制颜色、缩放和 reduced motion 可能需要单独场景。

### 十五、跨浏览器测试按支持合同选择

Chromium、Firefox 和 WebKit 在事件、表单、字体和新 API 上可能不同。全套所有浏览器成本高，可将关键路径运行多浏览器，详细分支主要跑一个；新平台能力按支持矩阵增加专项。

只在某浏览器失败时，先检查产品能力与 polyfill，再检查测试依赖的非标准行为。不能通过跳过整个浏览器掩盖支持合同；确实不支持时，产品应提供降级并让测试验证。

### 十六、并行与分片需要资源隔离

并行 worker 缩短时间，也暴露共享账号、端口、下载目录和数据库冲突。每项资源根据 worker 与测试 ID 命名，服务端提供幂等清理。

分片把用例分到多台执行器，合并报告时保留项目、浏览器和 retry 信息。某分片失败不能因其他分片成功而被忽略。负载导致系统容量不足时，调整测试基础设施或并发模型，并记录与生产差异。

### 十七、CI 环境要可定位和可重建

锁定浏览器与运行时，记录容器镜像或主机配置。服务启动采用健康条件而非固定 sleep；测试结束输出版本、base URL 和关键依赖。

E2E 对应明确构建制品，不能一边测试一边重新构建不同代码。若使用远端环境，保存部署 release，并防止多个分支覆盖同一地址。

### 十八、套件结构围绕风险和所有权

fixture 管理浏览器、身份和数据，page object 可以封装稳定页面语言，但不要把所有断言藏进巨型方法。测试仍应清楚显示用户任务与预期。

按领域或旅程组织，使负责团队能快速定位。公共助手改变时运行消费者检查。删除产品功能时同步删除过时测试，避免套件保留不存在的合同。

### 十九、E2E 通过仍需生产观察

测试环境无法完全复制真实流量、CDN、权限和数据规模。发布后用健康检查、关键任务合成监控和错误指标确认。E2E 是发布证据之一，不是生产正确性的永久证明。

同样，生产告警不能替代发布前测试；二者共同构成预防、检测和恢复闭环。

### 进阶：超时预算要分层而不是全局放大

测试有动作、断言、导航和整用例等不同超时。全局设为几分钟会让死锁很晚才失败，也掩盖性能退化。根据业务 SLO 和环境基线设置：普通按钮应秒级可用，后台导入可有独立长等待与进度信号。

超时时输出当时 URL、目标 locator、请求和服务健康。若 CI 资源不足导致所有动作变慢，修容量或并发；若产品本身超过用户可接受时间，不能用测试配置将其合理化。

### 进阶：下载、上传和剪贴板需要能力与文件边界

下载测试等待 download 事件，验证建议文件名、MIME 和内容摘要，并把文件保存在当前测试临时目录。不要写入用户下载目录或用绝对路径假设。上传使用合成文件，覆盖大小、类型、取消和服务器拒绝。

剪贴板、通知、摄像头和地理位置需要浏览器权限。测试只授予当前 context 所需权限，结束回收，并验证拒绝时应用有可用说明。伪造能力不能证明真实设备质量，媒体与硬件保留专门环境抽查。

### 进阶：视觉基线也要有所有权和迁移

浏览器或字体升级会产生系统性差异。先在独立变更中更新环境，抽样审查多页面，再批量更新基线；不要与功能改动混合，使评审无法区分来源。

基线文件进入版本控制并按浏览器/平台命名，废弃场景及时删除。差异报告保存 expected、actual 和 diff，评审者能从需求回到具体像素变化。动态遮罩和 stylePath 规则也属于测试代码，需要最小范围和理由。

若设计系统有意调整公共色彩、间距或字体，应由组件 owner 与受影响页面 owner 共同确认迁移范围。先在代表页面验证基线，再扩展更新；全库一次性接受差异会把局部回归混入预期变化，也失去视觉测试的审查价值。

### 学完后应能说明

你应能选择真正需要端到端证明的用户任务，通过 browser context、唯一数据和受控边界保证隔离；能使用用户可见 locator 和业务信号等待，分类 flaky 与环境失败，并保存 trace 等证据。还应能建立稳定、经评审的视觉基线，理解截图、跨浏览器与生产观察各自的证明边界。
