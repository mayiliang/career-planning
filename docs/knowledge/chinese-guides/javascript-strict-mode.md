# JavaScript 基础台阶：严格模式

## PREJS-05 严格模式

### 学习前先确认

- 直接前置：[PREJS-03 对象、属性与方法](../chinese-guides/javascript-objects-properties-methods.md#prejs-03)。函数与变量基础由它继续向下链接。本页会用到普通函数、对象方法和属性赋值。

**严格模式（strict mode）**让 JavaScript 对一部分容易掩盖错误的旧行为采取更明确的规则。脚本可以用字符串指令开启严格模式：

```js
'use strict';
```

ES Module 和 `class` 的代码天然按严格模式执行，不需要再写这条指令。

严格模式与 JS-02 最直接的关系是普通函数调用的 `this`。在严格模式里，`fn()` 不会把 `this` 自动替换成全局对象，而是保留为 `undefined`。这样，脱离对象的方法调用会更早暴露错误：

```js
'use strict';

function showThis() {
  return this;
}

console.log(showThis()); // undefined
```

严格模式还会拒绝给未声明名字赋值、删除不可删除属性等行为。它不是性能开关，也不会把动态类型的 JavaScript 变成静态类型语言。

没有严格模式时，旧式脚本中的意外赋值可能创建全局属性，使拼写错误直到很晚才暴露；严格模式会直接抛错：

```js
'use strict';

function saveTotal() {
  // totla = 3; // ReferenceError：名字拼错，且没有声明
}
```

严格模式还会让给只读属性赋值等失败操作抛出异常，而不是某些旧环境中的静默失败。这样并不保证代码正确，但能把一部分隐蔽状态错误变成靠近根因的可见错误。

`'use strict'` 只有出现在脚本或函数体开头的指令序言中才生效；把它写在普通语句之后只是一个无用字符串表达式。现代工程普遍使用 ES Module，模块本身已经严格，因此更重要的是理解严格语义，而不是到处重复写指令。

旧项目迁移时可以先在单个函数体中启用严格模式，再逐步扩大范围，但要留意行为边界。某个非严格函数调用严格函数时，被调用者按自己的函数体规则运行；严格与否并不是由调用者临时传递的。相反，把整个旧脚本一次改成严格模式，可能立刻暴露依赖隐式全局变量、重复参数名或特殊 `this` 行为的代码。正确做法是把这些报错当作原有隐患的定位线索，逐项明确变量归属与调用方式，并用回归测试确认外部行为，而不是为了消除报错而随意吞掉异常。

严格模式也不能修复所有历史行为。例如类型强制转换、浮点精度和对象可变性仍按原规则工作。把它当作更明确的运行边界，而不是“开启安全模式”的总开关。
