# 第 18—20 域中文学习讲义（审校版）

> 适用：图形、增长与国际化；身份、隐私与 AI 安全；架构、领导力与基础设施。每节均可作为首考的中文题源：先说明概念，再说明机制与产出，最后给出边界和可复核检查。法规与平台能力必须在发布时再由法务/平台负责人按适用地区、日期和产品事实复核。

<a id="graphics-01"></a>

## GRAPHICS-01

**SVG、Canvas 2D 与图形选择**

**定义与机制。** SVG 是可访问、可样式化的 DOM/场景图；Canvas 2D 是把指令立即栅格化到位图。选型看交互语义、编辑/导出、无障碍、像素级效果与更新模式，不能只按节点数下结论。**产出与边界。** 用 SVG 做可聚焦节点和文本替代；Canvas 以 DPR 缩放画布、把指针坐标反变换后命中测试，并为键盘提供同等操作。测量首帧、交互延迟、内存和导出；对象增长后用空间索引、分层或降级，不能把库默认行为当作证据。

**分步学习、例子、反例与核验。** 步骤：先列出节点是否需焦点、可编辑文本和导出，再用同一关系数据各实现 SVG 与 Canvas；例：1000 个可点击节点，Canvas 以 DPR 缩放并反算指针坐标。反例：只因节点多就选 Canvas。检查：键盘遍历、截图清晰度、命中偏移和帧时间均留记录。

<a id="graphics-02"></a>

## GRAPHICS-02

**WebGL/WebGPU 渲染管线与资源管理**

**定义与机制。** CPU 准备顶点/纹理等 buffer，shader 将顶点变换、光栅化并输出像素；WebGPU 的 device/queue/pipeline 模型不等于可无条件替换 WebGL。资源要有创建、复用、释放和 context/device lost 恢复路径。**产出与边界。** 十万点案例应按批次上传、限制重绘、记录显存与帧时间，并在丢失后重建资源；先检测支持度，回退到 Canvas/SVG。只报峰值 FPS、忽略兼容性、错误 shader 或 GPU 内存增长均不通过。

**分步学习、例子、反例与核验。** 步骤：把顶点、索引、纹理、uniform、shader、draw call 画成资源表；例：十万点按批次上传，缩放时只更新矩阵。反例：每帧重建 buffer 或把 WebGPU 当全浏览器可用。检查：记录显存、context/device lost 后重建、无 GPU 时回退。

<a id="vis-01"></a>

## VIS-01

**数据可视化语义、交互与性能**

**定义与机制。** 视觉编码应匹配数据类型：位置/长度适合比较，色相适合分类，面积和颜色不宜承载精确比较；比例尺、截断、时间区间和不确定性要显式。筛选、缩放、刷选必须保留可键盘访问的等价操作。**产出与边界。** 图表含标题、单位、来源、口径、替代数据表和不确定性说明；大数据用聚合、抽样或按需渲染。以原始数据复算关键读数，比较零线、颜色对比和筛选前后样本；好看或主题默认无障碍均不是正确性证据。

**分步学习、例子、反例与核验。** 步骤：写出字段类型、视觉通道、比例尺和读者问题；例：收入用位置与零线，类别用色相，并给出筛选后的数据表。反例：截断坐标放大差异。检查：由原始数据复算三处读数、键盘操作筛选、比较聚合前后结论。

**编码决策细化。** 先问读者是比较数值、观察变化、发现异常还是寻找分布，再选位置、长度、色相或分面；同一图内不要让面积既表示数量又被误读为长度。示例：日活趋势将缺失日期显示为断点，并把“移动平均”与原始线同时标注；反例：把累计值和当日值共用轴却不说明。验收时请另一位读者只据图回答预设问题，再用数据表核对答案、单位、筛选状态与不确定性。

**练习交付。** 给出销售额、订单数、地区和日期四列数据，先写字段字典和问题清单，再做趋势与分布两张图；图下必须有可下载表格。故障注入包括缺失值、极端值、单位改写和筛选后样本过小，验收者要能指出图中哪些结论应撤回。

**编码、交互与降级实验。** 数值比较优先以共同零点的位置或长度编码；当量级跨越很大时，改用对数比例尺前必须说明零值和负值的处理，不能静默把它们删除。时间序列若按周聚合，要在图例和替代表中同时给出聚合规则、时区和样本量；分类过多时可按值排序、分面或提供搜索，而不是用相近色相硬塞在一张图。刷选、缩放和悬浮提示只是增强：同一筛选条件必须能通过键盘控件设置，并同步更新可读数据表、标题和当前样本量；关闭脚本或读屏路径应仍能得到结论所依赖的数据。

**可复现实验。** 固定一份含 10 万行、缺失值和异常值的数据集，记录浏览器、设备档位、缩放级别、聚合阈值与渲染策略；先测原始逐点渲染的首帧、筛选响应、内存和键盘遍历，再比较分箱/抽样/按需渲染。任何降级都要保留原始数据下载入口，且在抽样后把“估计”与精确读数区分展示。反例是为了帧率只显示最近 1% 数据却继续声称整体趋势不变。验收者应能以固定随机种子重跑聚合，复核三处图上读数、筛选前后样本量和无障碍替代表，并确认性能优化没有改变预先定义的业务结论。

## ANALYTICS-01

**埋点模型、数据质量与可观测产品指标**

**定义与机制。** 事件字典为每个事件声明稳定名称、版本、owner、触发时机、属性类型和用途；身份、租户、同意和敏感字段在采集前决定。原始事件经校验、去重、时序处理和口径版本化后才计算漏斗/留存。**产出与边界。** 交付字典、采集校验、数据质量告警和从原始事件复算指标的查询；验证重复、遗漏、乱序、撤回同意与删除传播。不得为了“以后可能有用”收集个人信息，也不能用仪表盘截图代替数据链路证据。

**分步学习、例子、反例与核验。** 步骤：为注册漏斗写 event、version、owner、属性、触发条件和删除期限；例：同一订单只以 orderId 去重并允许离线补传。反例：把页面曝光和付款成功混为一件事。检查：模拟重复/乱序/撤回同意，能从原始事件重算指标。

**身份、采集与计算链路。** 事件信封至少携带 `eventId`、名称、版本、发生/接收时间、来源、匿名/用户/租户标识、同意快照和经过类型约束的属性；Schema Registry 拒绝未知字段、错单位和破坏兼容性的改动。匿名用户登录时以显式关联事件连接身份，不回写成别的账号或租户；退出、切换账号和共享设备都要切断旧上下文。离线批量重传沿用稳定 `eventId`，服务端用唯一约束幂等落库，并区分发生时间与到达时间处理迟到事件。采样必须记录策略、概率和适用事件，不能只采样漏斗分母或静默丢弃失败事件。指标定义保存版本、窗口、去重键、过滤条件和可执行查询，使仪表盘数字能追溯到原始事件。

**隐私、迁移与故障演练。** SDK 在写入持久队列前检查同意和字段 allowlist；哈希邮箱仍可能是个人信息，不能冒充匿名化。撤回同意或清除账号时，以处理清单驱动原始流、数仓、特征表、缓存和搜索副本清除，并用 tombstone 阻止旧离线批次把数据重新写回；备份按既定保留期和恢复流程验证。例：`purchase_succeeded` 升到 v2 新增币种时，先双写、双算并比较订单数和金额，再切换消费者并保留回滚窗口。反例是直接改变同名事件含义、把客户端时间当可信顺序，或关闭同意开关后仍刷新本地队列。练习输入包含重复 ID、漏记步骤、乱序/时钟偏差、账号切换、跨租户、撤回同意和版本混用；产出校验报告、隔离队列、质量告警及新旧口径差异，验收断言重复不增量、非法事件不入主表、清除后不复活且两版查询可独立复算。

## EXP-01

**Feature Flag、运行时曝光与实验配置治理**

**定义与机制。** Flag 是受控配置，不是授权：发布、实验和运维开关分别有稳定 key、类型、owner、到期和审计记录。评估上下文最小化，敏感规则与授权决策留在服务端；客户端遇到配置不可用应采用安全本地默认值。**产出与边界。** 演示稳定分组、灰度、kill switch、缓存/离线和回滚；核验不同会话不串组、旧 flag 被清除。不得下发敏感分组逻辑，亦不能以 flag 绕过权限检查。

**分步学习、例子、反例与核验。** 步骤：分别登记发布、实验、运维开关的 key、默认值、owner、到期日；例：服务不可用时新支付入口默认关闭，稳定 hash 不随刷新改变。反例：把管理员权限藏在客户端 flag。检查：审计开关变化、kill switch、过期清理和串组测试。

**评估链路。** 一次读取应按“调用方默认值 → 合并请求、会话、用户与服务上下文 → provider 解析规则 → 返回值及原因 → 曝光/审计事件”执行。实验曝光只能在用户真正看到变体时记录，预取或服务端求值不能冒充曝光。例：按 `tenantId + userId` 做稳定散列，匿名用户登录后必须声明继续原桶还是重新分桶；反例是以随机数逐次求值，使刷新后串组，或把邮箱、疾病等敏感属性完整下发到浏览器。

**练习与验证。** 给出一个配置服务间歇超时、缓存旧值、规则误发布的 fixture，实现超时上限、最后已知值、版本校验、安全默认值与紧急停用；分别注入离线、错类型、旧客户端和跨租户上下文。验收需保存求值 key、配置版本、变体、原因、时间、owner 与回滚记录，并证明授权接口在开关打开时仍拒绝无权限请求。清理练习还要删除代码分支、配置项、仪表盘与文档，不能只把 flag 永久关闭。

<a id="exp-02"></a>

## EXP-02

**A/B Test、统计推断与实验护栏**

**定义与机制。** 可证伪假设先定义随机单位、主指标、护栏、样本量/停止规则与分流；结果同时报告效应量、区间、不确定性和 SRM。相关趋势不构成因果，反复窥探、污染和多重比较会夸大结论。**产出与边界。** 交付预注册方案、分流日志、样本质量检查、分析报告和上线/停止决定；复算分流比例与关键指标。单次 p 值、事后挑指标或统计显著都不足以证明业务值得上线。

**分步学习、例子、反例与核验。** 步骤：实验前固定随机单位、主指标、护栏、样本量与停止规则；例：以用户为单位比较结算转化，同时监测退款率。反例：每天看 p 值并在显著时停止。检查：SRM、污染、效应量/区间、多重比较和复现脚本齐全。

**推断细化。** 报告先冻结“曝光即进入实验”的资格规则，随后按随机单位连接曝光、转化和护栏事件；不能把只看到按钮而网络失败的用户误当已处理。示例：A 组 10,000 人、B 组 10,000 人，除转化率外同时报告绝对差、区间和退款率；如果 B 的转化略升却使退款护栏越界，应按事前规则停止。反例：在十个分群中挑出唯一显著者宣布成功。复核时保存分流 hash、剔除规则、SQL/脚本和决策记录，使独立人员能从原始事件重跑。

**练习交付。** 给一张含用户、分组、曝光、成交、退款时间戳的 CSV；先声明去重键与观察窗，再输出组别样本数、转化率、绝对差、置信区间和护栏结论。把提前停止、漏记曝光、跨组登录和节假日促销分别作为四个故障注入，逐项说明是否仍可下结论。

**资格、曝光与复算账本。** 分流事件只说明“被分配到哪组”，不能自动证明用户有机会接受处理；曝光事件要由可见变体或实际生效动作产生，并与资格规则、分流版本、时间戳和稳定用户键连接。分析前冻结去重、观察窗、排除（如机器人、内部员工、已退款订单）和意向分配或实际处理口径；两种口径不得互换后挑选更漂亮的结果。固定 CSV 中故意放入已分流但未加载页面、加载失败、跨设备登录和重复曝光记录，验收者应能复算每个剔除人数并解释 SRM、护栏或污染何时让结论失效。

## I18N-01

**本地化、文本方向与可翻译 UI**

**定义与机制。** 国际化是让产品承载语言、复数、性别、日期和方向规则；翻译只是其中一步。使用 BCP 47、消息 key/上下文、`lang`、语义 `dir`、逻辑 CSS 属性和字体回退，而非字符串拼接或全局 CSS 镜像。**产出与边界。** 用伪本地化、阿拉伯语和复数语言测试文本扩展、缺失 key、RTL、图标方向与排序；翻译可发布和回退。机器翻译质量不能替代前端工程验收。

**分步学习、例子、反例与核验。** 步骤：把“你好，{name}”改为带上下文的消息，分别配置语言与方向；例：阿拉伯语订单页以逻辑 margin 和 dir=rtl 布局。反例：用 CSS transform 镜像整个页面。检查：伪本地化、复数、缺失 key、长文本、数字与图标方向。

<a id="i18n-02"></a>

## I18N-02

**Temporal、时区、日历、数字与货币**

**定义与机制。** `Instant` 是时间线时刻，`PlainDateTime` 是墙上时间，`ZonedDateTime` 绑定时区；显示由 locale/日历/CLDR 决定。金额换算与格式化分离，DST 缺失或重复时刻必须选定策略。**产出与边界。** 明确 API 传输的 instant/offset/时区契约，针对 DST、跨日历、货币小数位和服务端无时区字符串做测试；检测 Temporal 支持并限定 polyfill。只在本机时区或手写日期格式通过不算完成。

**分步学习、例子、反例与核验。** 步骤：存储 instant 和 IANA 时区，显示时才用 locale 格式化；例：纽约 DST 重复的 01:30 要求用户选早/晚偏移。反例：把无时区字符串当全球同一时刻。检查：跨日历、货币小数位、DST 缺失/重复和服务端契约测试。

<a id="seo-01"></a>

## SEO-01

**技术 SEO、抓取索引与内容可发现性**

**定义与机制。** 发现、抓取、渲染、索引和展示是不同阶段；状态码、robots、canonical、sitemap、语言链接和可见正文必须一致。结构化数据描述已展示的内容，不能承诺排名或 AI 回答收录。**产出与边界。** 为列表/详情/筛选/多语言制定 URL、重定向、canonical、sitemap、元数据和 JSON-LD 校验；发布后用日志与 Search Console 查抓取、收录和可归因转化。Lighthouse、一次 URL 检查或黑帽策略不是证据。

**分步学习、例子、反例与核验。** 步骤：为详情页给出 200 状态、canonical、sitemap 和可见正文；例：筛选参数只保留可索引组合，其余 noindex 或规范化。反例：JSON-LD 描述页面没有的评分。检查：发布前爬虫模拟、重定向链、孤儿页和 Search Console 观测。

<a id="content-01"></a>

## CONTENT-01

**内容模型、CMS、Markdown/MDX 与搜索**

**定义与机制。** 内容模型定义字段、版本、引用和生命周期，页面模型只决定呈现；不可信 Markdown/HTML/MDX 必经 AST 解析、白名单净化和链接校验。编辑、存储、构建、索引和回滚有独立状态。**产出与边界。** 实现可版本化文章、引用/slug 校验、安全渲染、内部搜索与发布/回滚记录；验证 XSS、坏链接、重复 slug 和索引滞后。不可直接执行不可信 MDX。

**分步学习、例子、反例与核验。** 步骤：定义文章 schema、版本、slug、引用和发布状态；例：Markdown 先转 AST、白名单净化后再渲染，索引任务记录版本。反例：执行作者提交的 MDX。检查：XSS、失效引用、slug 冲突、回滚和索引滞后均有自动用例。

**内容流水线。** 编辑器提交的是受 schema 约束的内容记录；服务端先校验字段、引用、唯一 slug 和权限，再生成不可变版本。构建器读取指定版本，把 Markdown 解析成 AST，对链接、图片与允许的节点做白名单转换，随后生成页面和搜索文档；发布指针最后原子切换。例：文章正文已发布但搜索索引任务失败时，页面仍标注当前版本，后台重试相同幂等任务；反例是搜索库先写成功、正文事务回滚，导致用户搜到不存在页面。

**安全与练习。** 即使作者可信，粘贴的 HTML、远程图片、iframe、协议链接和 MDX import 也必须按不可信输入处理；只转义 `<script>` 不能阻止 `javascript:` URL、事件属性或危险组件。给定两个同 slug 草稿、循环引用、坏锚点、索引延迟和恶意 Markdown fixture，要求输出校验错误、净化后的 AST、发布/回滚日志及索引状态。验收从原始版本重建页面和索引，比较内容哈希、引用完整性、权限边界与删除传播，证明展示层不能绕过内容模型。

<a id="editor-01"></a>

## EDITOR-01

**复杂编辑器、输入法与 AI 创作界面**

**定义与机制。** 编辑器以 AST/事务为内容真相，浏览器输入事件、composition、Selection/Range、剪贴板和 DOM patch 必须可映射；AI 改写是可取消的异步建议，不能覆盖用户后续输入。**产出与边界。** 实现跨块选择、中文 IME、净化粘贴、按意图撤销、序列化恢复和 AI diff 接受/拒绝；在不同内核与输入法注入竞态、粘贴 XSS、锚点过期和大文档压力。工具栏或 `execCommand` 可用不等于模型正确。

**分步学习、例子、反例与核验。** 步骤：把输入事件转换为 AST 事务，再据事务更新 DOM/撤销栈；例：中文拼音 compositionend 前不提交，AI 改写以稳定 range 呈现 diff。反例：流式文本直接覆盖用户新输入。检查：IME、粘贴 XSS、跨块选择、撤销和过期锚点。

## COMPAT-01

**Baseline、渐进增强与跨浏览器真机测试**

**定义与机制。** Baseline 只描述功能在目标浏览器的可用范围，不能取代项目支持矩阵；渐进增强以核心任务可用为先，再为已检测能力加速或增强。**产出与边界。** 交付支持矩阵、能力检测、无功能/低网/触摸/键盘回退和真机证据；每个增强路径须有安全失败行为。UA 嗅探或开发机单浏览器测试不是兼容性证据。

**分步学习、例子、反例与核验。** 步骤：先定义核心任务和目标设备，再以能力检测启用增强；例：不支持 View Transition 时仍可完成导航。反例：按 UA 推断全部能力。检查：Chromium/Firefox/WebKit、触摸、键盘、低网和真实手机保留证据。

**支持矩阵与分层降级。** 先以用户地区、设备占比、辅助技术、网络条件和业务损失建立支持矩阵：把登录、支付、提交、保存等核心任务列为必须可用，把动画、离线预取或高阶编辑列为可选增强。机制是先渲染语义化 HTML 与基础交互，再用特性检测添加增强；检测失败时保持原任务路径，而不是显示空白、循环重试或把用户导向“不支持浏览器”。例如 `CSS.supports`、`'serviceWorker' in navigator` 和 API 调用后的错误分支分别保护样式、离线与权限能力；反例是仅以 UA 字符串判断 Safari 版本，或用 polyfill 掩盖低端设备内存回收。

**跨浏览器与真机实验。** 为冻结的测试页面记录 Chromium、Firefox、WebKit 及至少一台 iOS/Android 真机的版本、输入方式、网络档位和结果。实验依次在键盘与读屏、触摸滚动、中文 IME、慢网/断网、权限拒绝和新 API 缺失下完成同一核心任务；把截图、trace、控制台错误、耗时和降级路径写入可复核矩阵。失败边界是“自动化视口通过”却在真机软键盘遮挡、低网超时或触摸命中偏移中失效。通过证据不仅是项目绿灯，还要证明增强关闭后核心任务仍完成，且各浏览器差异已有 owner、缓解措施与复测日期。

## IDENTITY-01

**Cookie、Session、Token 与浏览器身份边界**

**定义与机制。** Cookie 是浏览器携带规则，session 是服务端状态，bearer token 是持有即能使用的凭据；三者的签发、绑定、轮换、吊销、退出、跨域和多设备生命周期不同。第三方 Cookie 受限时，CHIPS/Storage Access/FedCM 等仅在明确支持和用户交互下评估。**产出与边界。** 绘制凭据数据流，配置 Secure/HttpOnly/SameSite、CSRF 防护、刷新轮换与服务端撤销；验证 XSS/CSRF、过期、登出和设备丢失。不能把 token 放在任意前端存储就视为安全，也不可把试验 API 当普适方案。

**分步学习、例子、反例与核验。** 步骤：画浏览器、后端、身份提供方的 cookie/token 流；例：会话 cookie 使用 Secure、HttpOnly、SameSite，并在状态变更处校验 CSRF token。反例：把长寿命 bearer token 放 localStorage。检查：固定会话、登出、轮换、第三方阻断和多设备撤销。

## IDENTITY-02

**OAuth 安全最佳实践、OIDC 与 PKCE**

**定义与机制。** 生产基线是授权码流加 PKCE；`state` 绑定授权请求，OIDC 的 `nonce` 防重放，ID token 必校验 issuer、audience、签名和时效。scope 最小化，重定向 URI 精确注册，资源服务器独立验证访问令牌。**产出与边界。** 演示发起、回调、code 交换、会话建立、刷新/撤销与账户绑定；攻击测试覆盖回调篡改、code 注入、token 混淆和 open redirect。草案或“能登录”不等于符合当前安全 BCP。

**分步学习、例子、反例与核验。** 步骤：生成 verifier/challenge 和 state，回调精确匹配后交换 code；例：验证 ID token 的 issuer、audience、签名、exp 和 nonce。反例：客户端接受任意 redirect URI。检查：mix-up、授权码注入、重放、错误 audience 和刷新撤销。

**协议分步。** 浏览器先创建高熵 `code_verifier`，仅把其 S256 challenge、随机 `state` 和 OIDC `nonce` 带到授权端；回调必须先验证本地保存的 state，再由受信后端以 verifier 交换一次性 code。客户端根据发现文档选择精确 issuer/JWKS，但发现结果也要固定允许的 issuer，不能让攻击者提供任意元数据。验证 ID Token 时同时检查算法、签名、issuer、audience/azp、exp、iat 与 nonce；访问令牌只发送给其目标资源服务器，不能用 ID Token 调 API。

**失败与验证。** 例：同一浏览器打开两个登录页时，每个事务都有独立 state/nonce，较晚回调不能覆盖另一事务；反例包括通配 redirect URI、接受隐式流片段、日志记录 code/token、仅解码 JWT 不验签、把 OAuth scope 当应用角色。练习用伪造 issuer、替换 code、重复回调、错误 audience、过期 JWKS 缓存和刷新令牌重放测试实现；验收记录失败类型而不泄露凭据，并证明退出会撤销服务端会话，刷新令牌轮换能识别旧令牌再次使用。

**密钥、会话与账号边界。** JWKS 缓存必须支持授权服务器正常轮换：遇到未知 `kid` 可限次刷新密钥集，刷新后仍不匹配就拒绝，绝不能降级为不验签；同时限制允许的签名算法，防止算法替换。应用会话应在服务端重新生成标识，设置安全 Cookie，并把认证完成、令牌刷新和本地权限变化分别记入不含令牌正文的审计事件。账号关联只能依赖已经验证的稳定主体标识和受信 issuer，不能只凭相同邮箱自动合并，否则不同身份源的同名地址会造成账号接管。

**端到端练习。** 为两个允许的身份源建立测试矩阵：正常登录、用户取消、回调超时、密钥轮换、旧 code 重放、刷新令牌被窃后再次使用、issuer 混淆和邮箱碰撞。每个失败用例都要断言“没有建立会话、没有错误关联账号、没有把敏感值写入日志”；成功用例则核对最小 scope、资源服务器 audience、本地角色重新读取和退出后的会话失效。这样验收的是完整信任链，而不是登录按钮最终跳回页面。

## PRIVACY-01

**数据最小化、同意、留存与用户权利**

**定义与机制。** 数据处理先定义目的、合法基础、必要字段、敏感度、接收方和期限；同意应可理解、可撤回且不以非必要处理绑架服务。权利请求影响主库、日志、缓存、索引和备份的传播策略。**产出与边界。** 建数据清单/流图、同意记录、保留/删除作业、访问更正导出接口和验证日志；审查字段必要性和第三方。隐私声明、一次删除 UI 或只删主表都不能证明闭环。

**分步学习、例子、反例与核验。** 步骤：把每个字段映射到目的、合法基础、保存期限和接收方；例：用户删除请求同时进入主库、缓存、搜索索引和备份到期队列。反例：收集“以后可能有用”的精确位置。检查：撤回后停止处理、导出可读、第三方删除回执。

**权利闭环细化。** 处理清单要区分控制者/处理者、在线主库与异步副本，并把保留期限转换为可执行删除任务而非自然语言承诺。示例：用户撤回营销同意后，前端立即停止 SDK 发送，服务端取消受众队列并留下处理时间戳；反例：只隐藏开关但继续上传设备标识。验证时以测试账号发起访问、导出、更正、删除和撤回，核对缓存、搜索、分析仓库和供应商回执，记录无法即时删除的法定保留理由。

**练习交付。** 为“保存搜索历史”画浏览器、API、分析服务和备份之间的数据流，给每条箭头标目的、权限和期限。分别演练未同意、撤回、账号注销和供应商失败四种路径；验收输出应包含用户可见状态、服务端审计条目与待重试删除队列。

**可复现实验。** 建立只含测试账户的删除演练：先写入搜索词、设备标识和偏好，再制造缓存命中、索引延迟及供应商回执超时。机制是由同一请求标识把撤回事件扇出到各处理者，并以幂等删除作业重试；适用于可定位副本的常规业务，不适用于法律保留、不可逆聚合或无法重新识别的匿名统计。失败反例是把“请求已受理”当作“所有副本已删除”。验证证据应同时包含用户端状态、每个副本的计数变化、失败队列、供应商回执与最终复查时间。

## PRIVACY-02

**跨区域合规、数据分级与前端工程控制**

**定义与机制。** 按用户所在地、处理者、数据类型、处理目的、接收方和部署地建立适用矩阵；区分个人/敏感/重要数据与去标识化，不把任何地区规则泛化为全球规则。前端把告知、同意、权限、埋点、日志和 AI 输入映射到后端处理记录，法律解释由法务确认。**产出与边界。** 交付数据分级、跨境路径、单独同意/撤回、未成年人和自动化决策交互清单，并在发布前以当前官方法源复核。不能把技术加密或匿名化标签本身当作全部合规结论。

**分步学习、例子、反例与核验。** 步骤：按地区/主体/数据/接收方/部署地填写适用矩阵；例：敏感信息的单独同意与跨境传输路径在 UI 和处理记录中一致。反例：默认勾选或把匿名化名称当法律结论。检查：未成年人、自动化决策、日志和 AI 输入由法务复核。

## AIPROD-01

**AI 任务定义、模型选择与价值验证**

**定义与机制。** 先量化用户任务、错误成本、可验证性、延迟、成本、隐私、公平与人工基线，再判断生成 AI 是否优于规则、搜索、传统模型或“不做”。模型能力是条件性的，必须为不确定或失败设计降级。**产出与边界。** 交付任务卡、候选方案矩阵、离线/在线评测、成功与护栏指标、试点停止条件；核验样本代表性和人工复查。演示效果或模型榜单不能证明价值。

**分步学习、例子、反例与核验。** 步骤：先写用户任务、人工基线、错误成本和验收样本，再比较规则、检索、模型和不做；例：知识问答以可引用答案率和人工纠正时长评测。反例：只用模型排行榜选型。检查：离线集、灰度、成本/延迟/公平护栏和停止条件。

**评测细化。** 任务卡必须给出输入分布、可接受输出、不可接受伤害、人工兜底时间和数据敏感级别；先用固定留出集比较基线，再在小流量下观察真实行为。示例：客服摘要以“关键信息遗漏率、人工改写分钟数、敏感信息泄漏数”而非文笔评分决定是否上线；反例：只展示三条精挑样例。每次模型、提示词或检索库变化都重跑同一集，并记录成本、延迟、拒答和人工升级率。

**练习交付。** 同一需求分别给规则、检索增强、生成模型和人工流程估算，记录开发/运行成本与风险。将十条真实失败样本按“可恢复、需人工、禁止输出”标注，要求候选系统给出可追溯结果；若无法满足引用或时延护栏，就写出不采用 AI 的决定。

**可复现实验。** 以同一份冻结的工单集进行盲测：将规则、检索、模型和人工结果交给不知道方案来源的复核者，分别记录任务完成率、事实错误、人工修订分钟数、P95 延迟、单任务成本和敏感信息命中数。机制是把价值判断绑定到预先定义的功能单位和停止阈值，而非把模型输出流畅度当成质量；适用于目标可观察、可抽样复核的任务，不适用于无法安全评估或伤害不可逆的决策。反例是试点只展示成功案例。验证时保留输入版本、模型/提示词/检索版本、原始评分和复算脚本，任一护栏越界即回退人工或规则基线。

## AIPROD-02

**高风险自动化分级、失败 UX 与 Human-in-the-loop**

**定义与机制。** 自动化等级由影响、可逆性、数据敏感度、错误代价和检测能力决定；高风险场景选择禁止自动化、人工复核、强确认、双人审批、撤销和申诉。人必须有足够上下文、时间和否决权，而非只点击确认。**产出与边界。** 交付风险矩阵、失败状态、置信度/限制说明、升级路径、审计和恢复演练；用代表性错误案例核验。把责任转给用户或把人工当橡皮图章不通过。

**分步学习、例子、反例与核验。** 步骤：按伤害、可逆性、敏感度、错误可检测性分级；例：报销建议可草拟，付款必须人工确认并可撤销。反例：把确认按钮放在没有依据的页面。检查：拒绝、升级、申诉、双人审批和故障恢复路径。

**控制闭环。** 每个自动化等级要对应允许动作、所需证据、确认人角色、超时、撤销窗口和升级渠道。模型先生成结构化建议，确定性规则检查金额、账户、地域和权限；风险超过阈值或证据缺失时进入人工队列，审批决定与依据写入不可变审计记录，执行器只接受已验证的审批令牌。例：招聘工具可以提取履历字段，但不得因模型分数自动拒绝候选人；反例是让审核者只看到“模型建议通过”，没有原始事实、限制或冲突项。

**练习与验证。** 为退款、医疗信息摘要、营销文案和付款四类任务分别给出自动化等级及理由，再实现付款流程的预览、强确认、双人审批、取消、超时和申诉。故障注入包括模型高置信错误、审批人越权、重复点击、执行后回执丢失和人工队列不可用。验收必须证明未审批不能执行、同一审批不能重放、用户能看到当前责任人与下一步，并用代表性失败样本测量人工推翻率、恢复时间和漏审伤害，而不是只统计点击确认率。

## AISAFE-01

**输出校验、内容安全与 Guardrails**

**定义与机制。** 模型输出是不可信输入：先用 schema、类型、范围、业务权限和上下文编码约束，再决定是否显示、执行或调用工具；内容审核和分类器有阈值、误报与漏报，需人工升级和持续监测。**产出与边界。** 测试恶意 URL/HTML/命令、越权字段、虚假引用、PII/秘密和拒绝恢复；记录策略版本与申诉。仅靠 prompt、过滤关键词或直接执行模型输出均不安全。

**分步学习、例子、反例与核验。** 步骤：模型 JSON 先过 schema，再做业务权限、URL 协议和输出编码；例：工具调用只允许枚举动作和当前用户可见资源。反例：把模型生成 HTML 直接 innerHTML。检查：恶意链接、越权参数、秘密回显、误拦截申诉和策略版本。

**分层校验。** 第一道校验确认语法与 schema；第二道检查字段组合、金额范围、对象存在性和当前用户权限；第三道按输出目标做 HTML/URL/SQL/命令上下文编码；第四道进行内容风险、隐私和来源核验；最后才允许展示或进入工具执行。例：模型返回 `{action:"refund", orderId:"B"}` 即使 schema 合法，也必须验证订单 B 属于当前租户、可退款且金额在审批范围。反例是让模型自己回答“我的输出安全吗”，或把内容审核通过等同于业务授权通过。

**练习与验证。** 准备正常、缺字段、额外字段、超范围金额、`javascript:` URL、带事件属性 HTML、伪造引用、秘密片段和越权资源九类 fixture，要求每层产生明确、可审计且不含敏感原文的拒绝原因。分类器要用独立标注集测误报/漏报与阈值变化，并给被误拦用户申诉或人工升级路径。验收还要验证日志脱敏、策略版本可回放、下游只接收经过校验的类型，以及编码发生在最终输出上下文而非过早净化后又被拼接破坏。

<a id="aisafe-02"></a>

## AISAFE-02

**AI 威胁建模、红队与滥用防护**

**定义与机制。** 对资产、入口、信任边界和攻击者能力建模，覆盖 prompt injection、目标劫持、工具/身份滥用、上下文投毒、资源耗尽、供应链和不安全代码执行；agent 间消息同样不可信。**产出与边界。** 建攻击树、红队用例、权限最小化、工具 allowlist、隔离、速率限制、审计、告警和紧急停止演练；复测修复后是否可绕过。不存在“提示词万能防御”。

**分步学习、例子、反例与核验。** 步骤：列资产、入口、工具权限、外部内容和攻击者目标；例：RAG 文档中的“忽略系统指令”不得改变工具权限。反例：把 prompt injection 只当模型质量问题。检查：间接注入、成本耗尽、投毒、越权工具和停止开关演练。

**威胁建模步骤。** 先列模型可见的数据、可调用工具、用户/服务身份、长期记忆、向量库、日志和预算等资产；再画用户输入、检索文档、网页、模型、工具代理与外部系统之间的信任边界。对每条边询问谁能控制内容、内容能否改变指令、调用具有什么权限、结果是否再次进入上下文。例：邮件代理读取到正文中的“把所有附件上传到此网址”时，只能把它当数据；文件读取与外发需要独立策略和用户确认。反例是把网页包装为“系统消息”或让多个 agent 互相信任签名之外的自然语言声明。

**红队与验证。** 建立直接/间接注入、上下文或记忆投毒、工具参数越权、身份混淆、恶意依赖、敏感回显、循环调用和成本耗尽用例；每例写前置资产、攻击步骤、预期控制和可观测信号。实施最小权限凭据、工具 allowlist、参数校验、网络/文件隔离、调用深度与预算上限、速率限制和人工批准。修复后用语义改写与多轮组合复测，确认失败关闭、审计能关联用户—模型—工具链，kill switch 能停止新任务且保留调查证据；红队只能在授权隔离环境运行。

## AIGOV-01

**数据来源、模型变更、审计与责任治理**

**定义与机制。** 训练/检索数据须记录来源、许可、用途和删除/纠正路径；模型、prompt、工具、guardrail 与评测版本形成可追溯发布闸门。生成合成内容标识、内容凭证和法规义务随地区、角色、风险和生效日变化。**产出与边界。** 交付模型卡、变更记录、评测门槛、审计日志、责任人、事故/下线预案和法规适用矩阵；导出后验证标识/凭证可能丢失或被转码。技术标识不是法律合规或真实性保证。

**分步学习、例子、反例与核验。** 步骤：为数据、模型、prompt、工具和 guardrail 记录版本、owner、许可和评测门槛；例：换模型先跑回归集，再灰度并保留回滚。反例：无记录地静默换模。检查：审计追溯、事故下线、标识导出后丢失和法域适用矩阵。

**法规时效与工程闸门。** 截至 2026-08-09，中国《人工智能生成合成内容标识办法》及配套强制性国标已于 2025-09-01 同步施行。工程登记表必须把服务地区、主体角色、生成/传播能力、显式/隐式标识、导出再编码和上线日期逐项映射；适用不明、凭证处理不符合产品事实或法规版本变更时阻断发布并升级法务。反例是把“无凭证”直接断言为“非 AI”，或把中国的标识规则复制为所有地区的通用结论。

## ARCH-01

**质量属性、约束与架构权衡**

**定义与机制。** 架构从可测质量属性、业务约束、风险与权衡出发：性能、可靠性、安全、可演进性与成本常互相牵制。质量场景要明确刺激、环境、响应和度量。**产出与边界。** 交付约束清单、质量场景、方案比较、容量/故障证据和复查日期；以压测、演练或原型验证高风险假设。技术名词堆砌或单一“最佳架构”不是结论。

**分步学习、例子、反例与核验。** 步骤：把“快”改写为“峰值 500 并发下 p95 小于 300ms”，再列成本和可靠性冲突；例：缓存降低延迟却可能返回旧权限。反例：罗列云厂商支柱不写刺激。检查：压测、故障演练、剩余风险和复查日期。

## ARCH-02

**技术方案、ADR 与架构评审**

**定义与机制。** ADR 记录背景、可行选项（含维持现状）、决定、代价、未决风险、owner、指标与复查；评审的目标是暴露假设并定义验证，不是为既定方案背书。**产出与边界。** 交付可复核 ADR、反对意见、试验、迁移/回滚与退出条件；面向技术和非技术受众陈述不确定性。文档长度、职位或投票不能替代证据。

**分步学习、例子、反例与核验。** 步骤：先写问题、非目标和约束，再比较含维持现状的三案；例：ADR 记录为何不选微前端以及复查触发器。反例：先定结论再编选项。检查：证据来源、反对意见、原型、迁移闸门、回滚和 owner。

**评审实验。** 每个候选项都必须对同一约束给出可证伪预测：例如“SSR 边缘缓存方案在指定地域与冷缓存下满足 p95，且月成本不超过预算”。把证据分成实测、估算和未知，给未知项指定 owner、截止时间和停止条件。评审中至少保留一条反对意见及其回应；若原型显示高风险假设不成立，应回到候选比较而不是靠例外批准。练习交付三份 ADR：维持现状、渐进迁移、替换方案，并附原型记录、用户/运维影响、回滚触发器与复查日期；验收者能从结论追溯到原始约束和实验数据。

**场景、反例与验证证据。** 适用场景是存在多个真实可行方案、且错误决策会影响交付或运行风险的变更；小型可逆实现不应为了形式强写 ADR。具体示例：把结算页从单体渲染拆为 BFF 时，同时测首字节时间、错误率、缓存命中、部署复杂度和客服恢复流程。反例：先宣布“必须微前端”，再把其他候选故意写得不可行；或者只比较一次压测便忽略故障、成本与组织能力。验证应保存输入数据、原型版本、基准命令、结果摘要、反对意见、决策人和下一次复查的触发条件，使新成员也能复做并挑战结论。

## ARCH-03

**渐进迁移、Strangler 与兼容层**

**定义与机制。** 迁移从可观测的垂直切片开始，利用路由、兼容/防腐层、双读写或影子流量逐步替换；每阶段有一致性策略、闸门、回滚和旧路径删除日期。**产出与边界。** 建现状基线、切片地图、差异审计、阶段验收和回滚演练；验证共享状态、双写漂移与回滚。只列里程碑、人日或永不删除兼容层不合格。

**分步学习、例子、反例与核验。** 步骤：选一个可观测垂直切片，先镜像流量再小流量切换；例：新订单页双读旧/新接口并差异审计。反例：无删除计划的永久兼容层。检查：基线、漂移、回滚、数据修复和旧路径下线证据。

## ARCH-04

**技术债识别、优先级与偿还治理**

**定义与机制。** 债务可来自架构、代码、依赖、测试和运维；用发生概率、影响、利息、机会成本和升级窗口排序，而非把偏好或告警数直接等同债务。**产出与边界。** 台账含证据、owner、触发条件、策略、容量预算、验收与收益复验；主版本升级需兼容测试和回滚。长期 fork、无主依赖和只追关闭数量均为失败信号。

**分步学习、例子、反例与核验。** 步骤：债务项写证据、概率、影响、利息、owner 和处理时限；例：停止维护的依赖在安全窗口内升级并保留回滚。反例：把代码风格偏好当高优债务。检查：兼容测试、容量预算、删除旧路径和收益复验。

## ARCH-05

**框架选型、生命周期与跨框架迁移**

**定义与机制。** 比较框架、元框架和组织能力对产品形态、渲染/部署、支持寿命、性能、无障碍、安全、可逆性与总成本的影响；结论有有效期。**产出与边界。** 同一约束下给出含维持现状的三案矩阵、验证原型、支持矩阵、垂直迁移和回滚/删除条件；监测双运行期体积和共享状态。流行度和个人熟悉度不是可测约束。

**分步学习、例子、反例与核验。** 步骤：以同一业务约束比较现状、框架/元框架和 Web Components；例：先验证 SSR 缓存与团队运维能力，再决定迁移。反例：按招聘热度选框架。检查：支持矩阵、双运行体积、共享状态、回滚和删除条件。

**适用性与验证原型。** 组件技术、框架与元框架不是同一层选择：先分别验证渲染边界、数据/路由约定、构建部署、设计系统互操作和团队维护能力，再计算双运行期包体、培训、可观测性与退出成本。示例：为同一详情页做“维持现状、渐进接入、完整替换”三个最小原型，统一测冷启动、无障碍关键任务、错误恢复和发布回滚；若 Web Components 能满足跨框架交付却不能覆盖数据获取/部署约束，只能作为一个实现部件而非自动胜出的架构。反例是用招聘热度或单一 demo 帧率取代支持寿命、owner 与删除日期。验收要保存版本矩阵、原型结果、停止阈值和下一次复查信号。

**场景与实验交付。** 适用场景包括需要长期维护的多团队产品、SSR/边缘部署迁移或设计系统跨应用复用；不适用场景是一次性活动页或不存在持续 owner 的技术试验。实验以同一业务流程作为输入：登录、列表、详情、错误页面和键盘任务都在三案中执行，记录构建时间、传输体积、可访问性缺陷、事故恢复步骤和两周内维护工时。失败反例是双框架期没有退出日期，或为了避免迁移风险永久维持两套状态。通过验证需要能重跑原型、解释差异、在护栏越界时回滚，并在支持期限或团队能力变化时重新评审。

## LEAD-01

**技术路线、跨团队推动与影响力**

**定义与机制。** 领导力把问题、共同决策、授权、反馈、依赖和结果度量连成可持续能力，不是职位或个人英雄。路线图有基线、结果指标、干系人与升级路径；委派要给上下文、权限、检查点和安全试错空间。**产出与边界。** 制定两季度路线、决策/依赖图和成长计划，校准评审样例，证明另一位工程师已独立交付并成为 owner。会议、文档或满意度数量不是影响力证据。

**分步学习、例子、反例与核验。** 步骤：把路线拆为结果指标、依赖、决策人和升级点；例：委派性能预算治理，提供上下文、样例评审和逐步放权，最终由受托者独立发布。反例：负责人替团队做完所有难题。检查：基线/结果、继任者交付、反馈行动项和依赖复盘。

**授权实验与结果证据。** 把“培养能力”拆成可观察假设：受托者是否能独立解释取舍、处理一次故障、完成发布并在复盘后更新标准。先给出业务背景、权限范围、不可越过的安全护栏和每周检查点，再逐步移除审批依赖；负责人只在风险触发器出现时升级。示例：把性能预算治理从单人脚本转为两名工程师轮值，比较发布前违规率、恢复时间和知识覆盖，而不是会议数量。反例是把任务分配后仍由负责人重写全部实现，或只用满意度问卷宣称影响。验收保留独立交付、评审校准、依赖冲突解决和继任 owner 的证据。

**适用场景与验证。** 适用场景是跨团队依赖、关键路径质量治理或人员单点风险；不适用场景是用路线图替代日常管理责任，或没有授权空间时虚构“委派”。具体实验：让第二位工程师主导一次发布，从发现指标异常、协调依赖、决定回滚到复盘改进均由其负责，负责人只按预设升级阈值介入。失败反例是关键人休假后计划停摆、review 标准因团队不同而冲突、或把一次分享算作能力迁移。验证材料应包括基线、任务边界、决策日志、独立交付记录、故障恢复时间、后续 owner 与复查日期；只有结果和能力都可持续时才算领导力影响。

## BACKEND-01

**SQL、事务、索引与前端数据模型**

**定义与机制。** 关系模型用主外键、唯一和检查约束阻止非法状态；索引服务于真实查询与执行计划；事务隔离、锁与乐观并发决定 API 的冲突/一致性语义。**产出与边界。** 为审核流建模、实现稳定游标分页、解释索引和冲突处理，并测试丢失更新、慢查询与分页漂移。ORM 能运行、偏移分页在静态数据中正常都不是证据。

**分步学习、例子、反例与核验。** 步骤：先用约束表达不变量，再按查询写索引和并发策略；例：审核流以 createdAt/id 游标分页，更新用版本号避免丢失。反例：offset 分页在插入后仍假定稳定。检查：执行计划、并发写入、唯一冲突和 API 错误语义。

**事务细化。** 先把业务不变量写成数据库约束，例如“同一订单同一审批阶段仅一条有效决定”，再选择悲观锁或带版本号的条件更新。示例：两个审核员同时提交时，第二个 `UPDATE ... WHERE version = ?` 影响零行，API 返回可解释的冲突而非静默覆盖；反例：先查后写且没有事务/版本条件。验证用并发脚本制造竞争、用 `EXPLAIN` 对照索引、在插入新行后检查游标分页无重复无漏项，并检验前端重试语义。

**练习交付。** 对订单审批写出表、约束、两条查询和索引理由，并给前端四种状态：正常、冲突、稍后重试、不可恢复错误。把执行计划中全表扫描、两个并发批准和插入新记录后的翻页作为验收 fixture；所有响应必须能说明当前数据是否已提交。

**隔离层例子。** 把“创建审批”封装为一次事务：插入决定、更新当前状态、写审计记录必须同成同败；只把耗时通知放到事务提交后的队列。若读副本延迟，前端不能立刻把旧读数解释成写入失败，应显示一致性状态或从主库确认。验收还应覆盖死锁重试次数与超时后的用户提示。

## BACKEND-02

**消息队列、异步任务与幂等消费**

**定义与机制。** 队列常见至少一次投递，消费者须用幂等键/唯一约束、状态机、退避上限、死信和重放处理重复与未知结果；202 应指向可查询的任务资源。**产出与边界。** 实现可恢复导出任务、可见失败/取消、刷新后状态恢复与死信处置；注入重复、乱序和毒消息。轮询显示成功不代表端到端恰好一次或后台可靠。

**分步学习、例子、反例与核验。** 步骤：提交时创建任务和幂等键，消费者以唯一约束去重并记录状态；例：导出重复投递只生成一个文件，失败进入死信。反例：相信队列端到端恰好一次。检查：重复、乱序、超时、取消、重放和刷新恢复。

## BACKEND-03

**对象存储签名、生命周期与 CDN 服务边界**

**定义与机制。** 预签名 URL/Policy 应最小权限、短时且绑定对象/租户；分片上传要初始化、校验、重试、完成确认和未完成清理。CDN 缓存键、变体和失效决定私有内容是否暴露。**产出与边界。** 演示断点续传、摘要、MIME/处置验证、恶意文件扫描、私有下载和缓存失效；注入重复分片/旧对象。单文件直传成功和客户端 MIME 声明不算安全。

**分步学习、例子、反例与核验。** 步骤：服务端签发限时对象键，客户端分片上传并以摘要确认；例：私有合同文件下载前再次鉴权，CDN 不缓存带用户权限的响应。反例：信任客户端 MIME 或永久 URL。检查：断点、重复片、病毒扫描、未完成清理和缓存失效。

## CLOUD-01

**云交付拓扑、平台协作与 Kubernetes 素养**

**定义与机制。** 容器镜像经 Pod/Deployment、Service/Ingress 成为服务；配置/密钥、健康探针、资源、伸缩和滚动发布分别有职责。静态托管、Serverless 和 Kubernetes 的运营成本应与规模匹配。**产出与边界。** 为 SSR/BFF 写最小部署，演练就绪/存活探针、配置漂移、资源不足、滚动更新与回滚；密钥不进镜像或日志。能应用 YAML 不等于生产正确。

**分步学习、例子、反例与核验。** 步骤：从镜像、Deployment、Service 到 Ingress 画控制链；例：SSR 服务 readiness 只在依赖可用后成功，滚动更新保留可回滚版本。反例：把 liveness 当业务就绪。检查：资源上限、配置漂移、密钥泄漏、探针失败和回滚演练。

**交付细化。** 最小清单应把镜像标签、Deployment 副本、资源 requests/limits、Service 端口、Ingress 路径、ConfigMap/Secret 引用和 rollout 策略逐项写明。示例：新版本先以一个副本启动，readiness 探针确认 SSR 能访问必要依赖后才加入负载；若探针连续失败，暂停 rollout 并回退到上一个 revision。反例：健康接口永远返回 200，或把密钥写入镜像环境文件。验收用一次配置漂移、一次资源耗尽和一次回滚演练，保存事件、日志、版本和恢复时间。

**平台边界。** 应用团队负责镜像、资源需求、健康语义、配置引用和回滚验证；平台团队负责集群、入口策略、证书、观测与配额，双方以可交付契约协作。示例：BFF 因下游限流而返回 503 时，readiness 可以暂时摘流而非无限重启；反例：把所有故障都交给自动扩缩容。**练习交付。** 给出一份 SSR/BFF 发布清单，模拟错误 Secret、错误端口、CPU 限额和旧版本回退，逐项比对发布事件、探针、日志、指标和用户可见结果。

**故障判读与证据。** 发布失败时先按控制链定位：镜像拉取失败看镜像名和凭据；Pod 未就绪看事件、应用日志和依赖连通性；Service 无端点看 selector；Ingress 失败看路由、证书和上游状态。不要把 CrashLoopBackOff 一概归因为“集群问题”。完成一次演练后写明触发时间、受影响请求、检测信号、人工决策、回滚 revision、恢复时间与防复发动作；这些记录才可证明团队理解交付拓扑。

**容量与变更练习。** 为峰值流量设定 CPU、内存、并发和延迟预算，并说明为什么仅增加副本不能修复慢依赖。提交变更前比较当前 revision 与目标 revision 的镜像摘要、配置差异和资源差异；发布中若错误率或 p95 延迟跨越护栏，立即暂停并恢复已验证版本。验证人应能从仪表盘、事件流和一次真实请求串起“部署、发现、路由、处理、回滚”的完整证据。

## SUSTAIN-01

**Web 与 AI 可持续性、能效与碳感知工程**

**定义。** 可持续性工程是在满足同一用户任务和质量约束的前提下，减少设备、网络、存储和数据中心的资源消耗，并避免把成本转移给别的参与者或未来版本。比较前必须先写出“功能单位”，例如“一名用户成功完成一次带图片理解的申请”，再声明系统边界是否包含终端制造与寿命、资源传输、缓存、云端推理、数据留存和失败重试。传输字节、CPU/GPU/NPU 活跃时间、内存峰值、设备温升、推理次数、云成本与碳排相关但不等价；它们只能作为注明条件的代理证据，不能被换算成无误差的碳结论。

**机制与决策流程。** 先冻结设备档位、网络、缓存冷热、模型和任务成功标准，记录页面资源、媒体字节、主线程与加速器工作量、内存、端到端时间、推理调用和失败重试；服务端另记录模型、地域、批处理、缓存命中与计算用量。然后按“避免无价值工作→减少数据和计算→复用结果→把非紧急工作移到合适时间或位置→选择更小且够用的模型”的顺序提出方案。每项优化都保留基线、变更、版本、测量窗口和不确定性，不能只展示最好的一次结果。

**适用与不适用条件。** 高流量页面、重媒体流程、频繁轮询、长时间本地推理和可延后的批任务适合建立能效预算。碳感知调度只适用于有可信地域/时间信号、允许延期且不会损害安全和用户完成率的工作；登录确认、无障碍辅助、医疗告警等即时或关键任务不能为了指标被任意延迟。没有可信能耗或碳强度数据时，只报告可复核的字节、工作量、用量与体验变化，不制造“减碳百分比”。本地推理也不天然优于云端：它可能减少传输和数据暴露，也可能加快电池老化、占满低端设备或重复下载大模型。

**边界、失败与反例。** 图片压缩若导致用户反复放大或重新上传，缓存若造成过期数据和额外刷新，小模型若降低准确率并触发更多重试，都会把单次节省变成总量反弹。把云账单下降、请求转到客户端、购买新设备或删除监测数据当成可持续性成功，都是边界偷换。优化不得牺牲可访问性、隐私、安全、可靠性、内容质量或硬件寿命；采购、硬件制造与地区电力结构超出前端直接测量能力时必须透明披露。

**验证与产出。** 为媒体加 AI 的代表任务在快、中、慢三档设备以及冷/热缓存下重复测试，报告中位数与高分位、成功率、字节、计算/推理用量、峰值内存、温升或电量等可用代理、成本和误差来源。至少实施三类独立优化，并用同一功能单位比较前后；同时注入弱网、低电量、缓存失效、模型降级和重试风暴，确认用户仍可完成任务。发布后同时监控单次消耗与总调用量，防止“每次更便宜”诱发使用量增长；只有收益可复现且体验、隐私、可靠性无退化时才通过。
