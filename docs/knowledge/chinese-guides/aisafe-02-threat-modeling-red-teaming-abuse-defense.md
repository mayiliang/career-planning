# AI 系统威胁建模与滥用防护知识点讲义

## AISAFE-02 AI 威胁建模、红队与滥用防护

传统 Web 应用的攻击面主要由代码、协议和配置决定；AI 系统又加入了可被自然语言影响的模型、外部检索、长期记忆、工具和其他 Agent。攻击者不一定突破服务器，只要让不可信内容改变模型目标、借用高权限工具或把秘密带到可见输出，就可能完成攻击。安全团队因此不能只测试“模型会不会说坏话”，而要沿完整数据和权限链理解资产、边界、攻击能力、控制与残余风险。

### 学习前先确认

- 直接前置：[AISAFE-01 输出校验、内容安全与 Guardrails](../chinese-guides/aisafe-01-output-validation-content-safety-guardrails.md#aisafe-01)。红队之前必须先能区分结构、授权、解释器、内容分类、失败关闭和人工升级，否则只会收集越狱对话，却不知道哪个工程边界应负责阻断。

### 一、威胁建模从真实资产和后果开始

**威胁建模（Threat Modeling）**是在实现与变更过程中系统识别资产、参与者、信任边界、攻击路径、控制和残余风险的方法。资产不仅是模型权重或 API 密钥，还包括用户数据、检索库、长期记忆、提示资产、工具权限、审批令牌、预算、品牌信誉和用户对结果的信任。

先写损失事件：跨租户文档泄露、未授权付款、错误记忆持续影响后续会话、模型端点被批量滥用、生成代码逃逸沙箱或攻击沿 Agent 链扩散。损失事件比“存在 Prompt Injection”更接近决策，因为同一种攻击在只读摘要和可转账系统中的风险完全不同。

为每项资产记录所有者、敏感度、允许主体、影响范围、可检测性和恢复方式。没有 owner 的资产无法分配控制，没有恢复方式的系统也无法定义风险是否可接受。

排序时把可达性、所需权限、最大影响、传播速度、可发现性和恢复成本分别记录，不用单一“高/中/低”掩盖依据。能批量外发但容易检测的风险，与只影响一个对象却不可逆的风险需要不同控制。分数只帮助排队，最终接受或停止仍由有权负责人结合任务价值与证据决定。

### 二、画出数据流和信任边界

数据流图至少包含用户、前端、应用服务、模型供应商、检索源、记忆、工具代理、外部系统、日志、审核者和其他 Agent。每条边标注数据内容、身份、协议、方向、持久化和谁能控制。自然语言从受信服务返回，并不自动可信：邮件正文、网页、工单和数据库备注都可能由攻击者写入。

信任边界是身份、权限或控制者发生变化的位置。浏览器到 BFF、租户检索到共享模型、模型到工具执行器、Agent A 到 Agent B、沙箱到宿主网络都要独立认证、校验和授权。把所有内部组件放在一个网络里不代表它们拥有同等信任。

同时画控制流：哪段内容被当指令、谁选择工具、谁最终批准、执行结果怎样再次进入上下文。很多 AI 攻击不是数据被读取一次，而是数据经模型解释后获得了本不该拥有的控制权。

### 三、定义攻击者能力而不是想象万能黑客

攻击者可能只控制一条用户消息，也可能能发布会被检索的网页、共享被污染的文档、注册恶意工具服务器、操纵下游 Agent，或持有普通租户账号。不同能力决定可行路径和测试边界。内部员工、供应链维护者、被盗服务账号和匿名用户不能合并成一个角色。

列出攻击前提、所需访问、期望目标、成功证据和可重复成本。例如“攻击者可向公共知识库提交文档；系统每小时索引；回答 Agent 可读文档但付款工具需服务端批准”。这比一句“测试间接注入”更能指导控制。

还要考虑非恶意故障：供应商返回异常结构、检索排序错误、记忆过期、网络重放和人工误批可能产生与攻击相似的后果。安全机制应按影响阻断，而不是只识别攻击者意图。

### 四、Prompt Injection 攻击的是目标与权限链

**提示注入（Prompt Injection）**指攻击者通过直接输入或被系统读取的外部内容，试图改变模型应遵循的目标、泄露上下文或诱导调用能力。直接注入来自用户消息；间接注入藏在网页、邮件、文档、图片文本、工具结果或其他 Agent 消息中。

不可信内容必须保留来源和数据身份，不能被包装成系统指令。模板分隔符、引用标签和提示语有帮助，但模型仍可能受内容影响；真正边界由最小权限、工具策略、参数授权、输出限制和用户确认构成。即使模型“被说服”，它也不应拥有完成危险动作的权限。

测试不要只用固定句子“忽略之前规则”。使用语义改写、多语言、编码、长上下文、分步诱导、工具错误消息和跨轮记忆；同时检查正常文档中的命令式语言不会被大量误拦。

### 五、Excessive Agency 放大一次判断错误

**过度代理（Excessive Agency）**发生在系统给模型过多功能、过宽权限或过高自主性，使错误或注入能造成不必要后果。一个只需查询订单的任务不应获得退款、导出全部客户和外部发送权限；一次生成建议不应自动循环执行上千个对象。

减少功能范围、对象范围、凭据权限、自主步骤和累计影响。读取与写入工具分开，工具名称和说明明确副作用，参数在服务端绑定当前主体和租户。批量、外发、删除、付款及权限变更要求独立策略和更强确认。

把模型置信度用于扩大权限是危险的。权限来自用户、角色、业务状态和批准，不来自生成文字。复杂 Agent 应由确定状态机限制允许转移，模型只在受控节点提出候选。

### 六、身份混淆与跨租户泄露必须单独建模

一次调用里可能同时存在用户身份、应用服务身份、模型供应商账号、工具服务账号和代理身份。日志里看到 `userId` 不证明工具实际以该用户权限执行；来自模型的身份字段更不能作为授权依据。执行器从认证上下文读取主体，并把租户与资源范围绑定到调用。

检索层先授权后召回，不能先从全局库取文档再让模型“不要泄露”。向量相似度不是访问控制。缓存键、嵌入索引、会话历史和评测记录都需要租户边界，错误键可能让合法请求获得别人的结果。

委派必须说明谁代表谁、允许哪些动作、持续多久、能否再委派。Agent 间传递自然语言“我已获批准”没有授权效力；使用可验证令牌、范围、对象版本和审计链。

### 七、记忆与检索投毒会跨请求持续

短期上下文污染只影响当前调用，长期记忆、知识库和缓存投毒会影响未来用户。写入前验证来源、主体、用途和敏感度，区分用户事实、模型推断、外部文本和系统结论；高影响记忆需要人工或确定规则确认。

检索语料记录来源、版本、许可、抓取时间和删除路径。新内容先进入隔离与评测，异常增长、隐藏指令、跨租户标识和来源突变触发审核。索引删除后还要传播到缓存、摘要和派生数据。

读取时把记忆当数据并显示可纠正来源。用户纠正不能被旧摘要再次覆盖；模型生成的“事实”也不能循环写回成为下一次检索的权威证据。

### 八、工具与代码执行需要沙箱和出口控制

代码生成与执行把自然语言风险带入操作系统。沙箱限制文件、进程、网络、CPU、内存、时间和输出；使用临时工作区、只读依赖和非特权身份。沙箱不可用时拒绝执行，不能退回宿主机“临时跑一下”。

网络出口采用允许列表并防止访问元数据服务、内网管理面和任意回调。文件路径规范化，禁止穿越、符号链接逃逸和共享敏感目录。依赖安装、脚本钩子和构建工具本身属于供应链攻击面。

工具结果限制大小、类型和后续解释。超长 stdout、二进制、终端控制序列和恶意错误文本不能直接进入模型或 UI。代码执行审计保存摘要与隔离证据，不收集无关用户文件。

### 九、资源耗尽既是成本风险也是可用性风险

攻击者可发送超长上下文、制造递归工具调用、触发大规模检索、生成巨大输出或让多个 Agent 相互等待。每个请求设置输入、输出、工具次数、深度、并发、时间和费用预算；预算在可信协调层计算，模型不能自行提高。

限制要按用户、租户、会话、模型和全局资源组合。单次调用都低于上限，累计一千次仍可能耗尽配额。队列使用背压、优先级和公平调度，紧急任务也不能无限饿死普通用户。

到达预算时进入明确终态，保留已完成工作并说明如何继续，不让循环以“再试一次”绕过。成本异常关联具体调用链和版本，避免只看到供应商月账单。

### 十、供应链覆盖模型、数据、工具与策略

模型版本、SDK、提示模板、嵌入模型、解析器、向量数据库插件、MCP Server、浏览器扩展和红队数据集都可能被替换或污染。维护来源、版本锁定、摘要、签名、权限和变更审批；第三方更新不能绕过回归直接进入生产。

自托管模型也依赖权重来源、推理镜像和运行参数。模型卡与许可证说明用途边界，却不证明制品未被篡改。下载后验证摘要，构建和部署保留可追溯材料。

供应商故障或能力退化要有降级与退出路径。切换模型可能改变拒答、工具格式和上下文限制，因此必须重跑安全集，不能把“接口兼容”当行为兼容。

### 十一、多 Agent 系统要限制级联和信任传播

每个 Agent 都有目标、可见数据、工具和身份，彼此消息视为外部输入。协调器验证消息 Schema、来源、任务 ID、预算和允许的下一步；下游 Agent 不继承上游全部权限。共享记忆区按主体和任务隔离。

攻击链可能从恶意网页影响浏览 Agent，再让研究 Agent写入错误记忆，最后诱导执行 Agent 外发数据。故障隔离要在每条边限制信息和能力，防止一个节点的目标劫持自动变成全链权限。

检测循环、重复委派、目标漂移和异常扇出。协调器能暂停新步骤、取消子任务并标记未完成；人工接管看到完整链路，而不是只看到最后一句回答。

### 十二、红队是可重复实验而不是表演

红队用例写清资产、攻击者能力、初始状态、输入与变式、期望控制、成功条件、允许范围和清理方式。只在授权隔离环境执行，不攻击真实第三方、生产用户或未获授权系统。高风险动作以模拟工具和假数据验证。

覆盖直接/间接注入、数据泄露、工具越权、身份混淆、记忆投毒、供应链、代码逃逸、资源耗尽和多 Agent 级联。每个发现记录到具体信任边界和控制缺口，严重度看真实影响、可达性、规模与恢复成本，不只看提示是否“越狱”。

修复后用语义改写、组合步骤和新鲜盲样本复测，同时验证正常任务。通过一次固定攻击只证明那条字符串被拦，不证明攻击类别消失。

红队基础设施本身按高敏系统管理：测试提示、越权样本、假凭据和漏洞记录限制访问，执行账户与生产分离，所有外部调用使用模拟端点或明确允许列表。每次演练设时间窗、负责人、停止条件和数据清理，发现真实用户信息立即中止并升级。报告区分可复现事实、推测影响和未验证路径，避免为了展示严重性而扩大授权范围。

### 十三、检测、响应与 Kill Switch 必须演练

**紧急停止（Kill Switch）**是在风险超过容忍度时阻止新任务、取消可取消工作、撤销凭据或关闭某项能力的受控机制。它必须位于可信执行或协调层，不能依赖已经被操纵的模型主动停止。停止范围可以按工具、租户、模型或全局分级。

触发信号包括越权拒绝激增、秘密泄露、异常调用深度、成本飙升、跨租户命中和供应链告警。停止后保留调查证据、标记未知执行结果并保护用户草稿；恢复需要负责人、修复证据、回归和渐进放量。

定期演练凭据已过期、队列积压、执行器离线和负责人缺席。按钮存在但无法阻断后台重试，或停止后丢失审计，都不算有效机制。

### 十四、把残余风险带回产品与交付决策

控制不能消除全部风险。对每条主要威胁记录现有控制、测试证据、剩余概率与影响、负责人、复测期限和接受理由。残余风险超过预算时缩小能力、增加人工、停止上线或选择不使用 AI；不能用“模型以后会更好”代替决定。

威胁模型随工具、数据、模型、地区、用户和业务规模变化而更新。代码评审检查边界变化，发布门禁运行安全回归，生产信号反馈新攻击，事故复盘补充用例。这样威胁建模才是工程循环，不是一张上线前画完就过期的图。

学完后，你应能为含检索、记忆、工具或多 Agent 的系统画出资产与信任边界，区分注入、过度代理、身份混淆、投毒、供应链和资源耗尽；能设计最小权限、沙箱、预算、故障隔离、红队集和紧急停止，并用残余风险决定发布、降级或退出。继续查证可参考 [OWASP GenAI Security Project](https://genai.owasp.org/)、[OWASP LLM06:2025 Excessive Agency](https://genai.owasp.org/llmrisk/llm062025-excessive-agency/)、[MITRE ATLAS](https://atlas.mitre.org/)与 [NIST 生成式 AI 风险管理框架](https://nvlpubs.nist.gov/nistpubs/ai/NIST.AI.600-1.pdf)。
