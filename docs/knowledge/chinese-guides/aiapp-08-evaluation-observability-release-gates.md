# AI 系统评估、生产观测与发布门禁知识点讲义

## AIAPP-08 模型评估、生产可观测与回归门禁

AI 功能具有统计波动，最终答案相同也可能经过不同检索、工具和审批路径。传统单元测试仍然必要，却不能单独回答“新模型是否让真实任务更好”“是否以越权或更高成本换来分数”。成熟评估把产品目标拆成可判断样本和评分器，把生产 trace 变成可回放证据，并用预先约定的发布门禁管理模型、提示、检索和工具变更。

### 学习前先确认

- 直接前置：[AIPROD-01 AI 任务定义、模型选择与价值验证](../chinese-guides/aiprod-01-ai-task-model-selection-value-validation.md#aiprod-01)，用于建立真实任务、非 AI 基线和失败成本；[OBS-01 前端可观测性、SLO 与隐私](../chinese-guides/obs-01-frontend-observability-slo-alerting-privacy.md#obs-01)，用于理解事件、trace、指标、告警和数据最小化。两条路径分别承担产品目标与观测基础。

### 一、Evaluation 验证明确主张

**评估（Evaluation）**是在固定系统、输入分布、运行条件和评分规则下，收集足够证据判断一个具体质量或风险主张。它不是随便问几次模型，也不是用排行榜替代产品任务。

先写主张，例如“退款问答在当前政策集上，关键结论有可访问引用且严重错误率不高于阈值”“写工具在无有效批准时执行次数为零”。主张决定样本、运行次数、评分器和否决项。一个总分无法同时代表事实、安全、延迟和成本。

评估对象要明确到系统版本：模型及快照、推理设置、提示、检索索引、工具、策略、SDK、上下文预算和 harness。只记录模型名，无法解释差异来自哪里。

### 二、从失败分类建立测试面

先收集真实任务和错误，再把失败拆成可行动类别：理解错误、结构错误、无依据主张、错引、检索漏召回、越权工具、参数错误、未停止、恢复失败、隐私泄露、超时和成本超限。类别对应负责人和修复层。

分层评估模型输出、RAG、工具、会话和 Agent 轨迹。最终文字正确但读取了无权文档仍失败；工具结果正确却执行两次仍失败；有礼貌的拒绝如果本可安全完成任务也可能是过度拒绝。

把正常、边界、对抗和故障样本都纳入。真实流量分布用于估计体验，严重低频风险单独加权与设零容忍门槛，不能让大量简单样本稀释。

### 三、Gold Set 是版本化证据资产

**黄金样本集（Gold Set）**包含输入、允许上下文与工具、预期事实或评分量表、风险标签、来源、评审记录和版本。它不是永恒真相，政策和产品变化后需要复核与迁移。

训练、提示优化、开发调试和最终留出集分离。样本泄漏会让分数高估泛化；允许浏览的 Agent 还要检查答案是否可直接在公开数据中找到。合成样本可扩展边界，但不能取代真实失败分布。

每条样本有稳定 ID 和变更历史。争议样本记录多个合理答案、裁决与适用条件，不强行压成唯一字符串。删除或修改样本也保留理由，防止只留下容易通过的题。

### 四、确定性评分优先证明确定事实

Schema、枚举、引用 ID、权限、调用次数、状态转移、预算和副作用都能由代码断言。能确定判断的部分不要交给模型裁判，因为代码评分可复现、便宜并能直接指出失败字段。

结构相同不代表语义正确，因此确定性检查与人工/语义评分组合。工具轨迹先断言只调用允许工具、参数和顺序，再评价结果是否有帮助。RAG 先检查引用属于允许集合，再评引用是否支持主张。

评分器本身也有测试：正例、负例、边界和变异样本。若删除授权检查后评估仍通过，门禁没有保护目标。

### 五、Model as Judge 需要校准

**模型裁判（Model as Judge）**使用模型依据明确 rubric 对开放输出评分，适合规模化辅助语气、完整性和部分语义质量，但会受位置、长度、措辞、身份、同源偏好和版本漂移影响。

先由领域人员标注代表样本，再计算裁判与人工的一致性、每类错误、混淆和不确定区。隐藏候选身份、随机成对顺序，要求引用 rubric 证据；对高风险、分歧和阈值附近样本人工复核。

裁判模型、提示、rubric 和温度全部版本化。更换裁判需要重新校准，不能把分数变化误认为待评系统变化。同一模型给自己的回答单次打分不能作为独立上线证据。

### 六、多次运行揭示方差和尾部风险

非确定系统在相同输入上可能不同。关键样本运行多次，报告成功概率、最差类别和置信区间，而不是只选最好回答。高温创意任务关注分布与用户选择，高风险工具任务关注任何一次越权。

固定可固定的环境：模型快照、数据、工具桩、时间、网络、预算和随机参数。不可固定因素记录下来，使比较解释得通。运行次数根据差异大小和风险决定，不机械套一个数字。

比较版本使用配对样本和相同 harness。平均提升可能隐藏某语言、租户或风险层退化，必须分层报告并看实际样本。

### 七、Trace 连接一次运行的完整轨迹

生产 trace 用匿名 request/run ID 关联输入类别、提示与模型版本、上下文选择、检索、工具提议与结果、审批、token、延迟、成本、错误和用户恢复。它回答“这次具体发生了什么”，不等于跨样本评估。

记录结构化决策和外部证据，不要求暴露隐藏思维。原始提示、私有文档和工具结果按目的采样、脱敏、访问和留存；重放使用冻结副本或模拟工具，不能再次产生真实副作用。

缺少关键字段的 trace 标为不可回放，不能悄悄从当前配置补齐。版本、来源和策略快照让历史事件仍可解释。

### 八、离线评估与线上观测互相补足

离线集合可重复、适合变更比较，却可能偏离新流量；线上指标真实，却含选择偏差、反馈缺失和环境变化。上线前离线门禁，灰度中观察任务完成、安全、恢复、延迟和成本，线上失败经人工确认后进入回归集。

用户点赞不是唯一质量标签：满意用户更愿反馈，失败用户可能直接离开。结合任务完成、编辑量、撤销、人工接管、投诉和来源打开等信号，但不把代理指标当真值。

异常出现时从线上 trace 回放到冻结环境，区分模型、数据、工具、配置和外部服务变化。未经授权的真实会话不能直接复制到测试环境。

### 九、Release Gate 把证据变成决策

**发布门禁（Release Gate）**在变更进入下一环境前检查预先定义的质量、安全、成本和可靠性阈值。它绑定评估集、评分器、样本版本和审批人，失败默认阻断或要求有期限的显式例外。

门禁包含硬否决与权衡项：越权调用、跨租户泄露和不可撤销重复副作用可以零容忍；轻微语气与成本可在预算内权衡。总体提升不能抵消硬否决失败。

例外记录依据、影响范围、负责人、补偿控制、到期和复查。灰度、回滚和停用阈值与门禁同源；指标越线时自动缩小流量或回退，不等人工凭感觉解释。

### 十、评估数据也需要治理

样本来自生产时，先确认用途、同意或合法基础、最小化、去标识、访问和留存。秘密、个人敏感信息和客户专有内容不因“用于质量”就可无限复制。供应商评估服务的数据政策同样核验。

标注工具按角色只展示必要字段，导出受控并记录访问。删除请求传播到原始 trace、样本、向量、缓存和派生摘要；必要的审计保留范围与法律依据分开说明。

合成数据也可能复现训练样本或偏见，需要来源和质量检查。评估集不是安全数据垃圾桶。

### 十一、观测指标要能驱动行动

同时看成功、拒绝、人工接管、恢复、错误类别、延迟分位、token、费用、缓存、工具调用和安全阻断。按功能、版本、语言、风险和租户类型分层，避免全局平均掩盖。

SLO 以用户任务和可恢复性定义，例如“有资格任务在预算内完成或给出明确安全降级”，不只是接口 200。告警要有负责人、查询、止损和回滚手册；模型波动不应成为忽略告警的理由。

高基数用户 ID、完整 URL 和提示不进入指标标签。需要调查时通过受控 request ID 访问最小 trace。

### 十二、评估 Agent 要看轨迹而非结尾

Agent 评估记录目标、计划、工具、参数、权限、证据、预算、停止和恢复。最终文件正确也可能经过越权读取或无限重试；最终失败也可能在关键缺权限时正确停止。

轨迹评分混合确定性规则、任务环境断言和人工质量。工具桩模拟响应丢失、重复、迟到和权限撤销，检查状态机；真实外部系统只在隔离、授权环境下运行。

多 Agent 还检查上下文隔离、交接 Schema、预算传播和冲突仲裁。增加 Agent 数不能直接算能力提升，必须扣除协调成本和新增失败面。

### 十三、故障注入校验评估本身

故意让引用来自过期文档、工具伪成功、授权被撤销、trace 缺字段、裁判偏爱长答案、成本翻倍和模型拒绝。确认对应评分器失败、门禁阻断且报告能定位层次。

再注入正常但风格不同的回答，防止 rubric 只奖励模板。对模型裁判交换候选顺序、改写表面措辞、隐藏模型身份，观察稳定性。对数据集做重复、污染和标签冲突检查。

回归报告保存原始配置哈希、样本和评分版本、聚合方法、失败列表与批准。只保存一个 0.86 分数无法复核。

### 十四、统计设计避免对噪声过度反应

比较版本前固定主要指标、切片、样本和停止规则。报告样本量、置信区间或重复运行分布，不把 20 个样本里多对 1 题当稳定提升。对随机模型使用同输入多次运行，区分平均质量、方差和最坏可接受行为；高风险安全断言通常要求零容忍，而不是被平均分稀释。

同一测试集被频繁调 prompt 会产生评测过拟合。保留开发集、回归集和受控隐藏集，线上异常再转成匿名化候选，经审核后加入新版本。测试集版本变化与模型变化分开比较，避免基准变容易后宣称提升。

对成对比较随机答案顺序并遮蔽版本信息。人工标注者获得明确 rubric、边界样例和冲突升级路径；测量一致性并抽查疲劳。模型裁判的偏好按语言、长度、风格和自身模型族切片校准。

### 十五、发布策略把不可逆风险降到最低

通过离线门禁后仍采用 shadow、内部用户、少量流量和逐步扩展。shadow 不执行真实副作用；在线实验按用户稳定分流，不能同一会话在模型间跳动。新版本的缓存、摘要和长期任务带版本，回滚时知道哪些产物需重建或隔离。

停止条件不仅看平均错误率，还看权限违规、引用失配、重复工具动作、成本爆炸和特定人群退化。告警触发自动熔断到上一安全版本或无 AI 路径，并保留现场证据。回滚本身定期演练，不能只存在文档中。

发布结论记录采用的评测集、运行配置、阈值、批准人、已知缺口和观察窗口。例外具有期限与负责人，后续数据不足不能自动变永久放行。

### 十六、评测服务也要防污染与越权

生产样本进入评测前脱敏、按目的授权并冻结版本。评测执行器使用模拟或只读工具，任何网页/工具结果中的指令不能要求读取额外数据。模型裁判只见必要候选与 rubric，不获取用户身份和无关敏感上下文。

评分、标注和人工覆盖都保留来源；修改 gold label 创建新版本。权限撤销或样本删除传播到数据集、缓存和报告。这样评测不会成为绕过生产访问控制的第二条数据管线。

### 十七、形成持续学习闭环

从产品主张与真实失败出发，构造黄金样本和分层评分；运行后保存可回放 trace，门禁决定发布；灰度收集受控证据，确认的新失败回到集合。每次循环都能说明改了什么、改善哪类失败、牺牲什么以及如何回退。

一份可审计发布报告至少写明产品主张、样本版本与切片、运行次数、模型/提示/工具配置、主要与安全指标、统计不确定性、人工分歧、门禁结果、例外、灰度范围和回滚触发。报告链接可回放 trace 与失败样本，但按权限脱敏。这样下一次升级能比较相同事实，而不是依赖“团队感觉新模型更好”。

门禁系统自身的代码、阈值和权限也进入版本控制与测试，不能由待评模型修改评分逻辑或选择只对自己有利的样本。

评测失败要能定位到可行动 owner：数据、检索、提示、模型、工具、UI 或策略；否则总分下降只会引发无方向调参。

学完后，你应能设计覆盖模型、RAG、工具和 Agent 轨迹的评估体系，校准人工与模型评分，保护评估数据，并让发布决策与线上观测连续。可参考 OpenAI 的 [Evals API](https://platform.openai.com/docs/api-reference/evals)与 Anthropic 的 [Agent 评估工程说明](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents)核验具体实践，但评估主张必须来自自己的产品风险与任务。
