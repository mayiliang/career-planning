# PRECS-01 输入规模、基本操作与增长趋势

这是一份只补一个台阶的前置短文：怎样把“数据变多了，程序会怎样”变成可以讨论的问题。它不要求你先会复杂度符号。

## PRECS-01

### 先把问题中的量说清楚

程序接收的内容通常不止一种。搜索页有商品数量、关键词长度和筛选条件数；关系图有节点数和边数；文本处理有字符数与段落数。分析之前，先选出真正影响工作的那个量，把它叫作**输入规模（input size）**。

字母 `n` 只是输入规模的代号，并不天然等于“数组长度”。例如：

- 扫描一份名单时，`n` 可以是记录数；
- 检查一张关系网时，通常要同时考虑节点数 `V` 和边数 `E`；
- 分页请求全部数据时，成本可能同时受页数和每页条数影响。

如果没有先定义 `n`，后面的“O(n)”就没有明确含义。

### 什么叫基本操作

为了比较工作量，需要选一个会重复发生、并且足以代表主要成本的动作，这叫**基本操作（basic operation）**。它可以是一次数字比较、一次集合查询、一次字符检查，也可以是一次更昂贵的 DOM 测量或对象序列化。

下面的函数有 `n` 个元素时，条件 `value > 0` 会被判断 `n` 次：

```js
function countPositive(values) {
  let count = 0;
  for (const value of values) {
    if (value > 0) count += 1;
  }
  return count;
}
```

“循环只有一层”只是线索，真正有用的是说明哪项操作发生了多少次。一个循环内部若又调用了会扫描整个数组的 `find`，总工作量就不再只是表面上的一层遍历。

### 看增长，不只看一次耗时

设备速度、浏览器版本和后台负载都会改变一次测量的毫秒数。更稳定的问题是：输入从 `n` 增大到 `2n` 后，操作次数大致怎样变化？这种随规模变化的形状叫**增长趋势（growth trend）**。

- 工作量几乎不变，说明它与 `n` 的关系很弱；
- 工作量大约翻倍，常见于一次完整遍历；
- 工作量大约变成四倍，常见于“每个元素再与所有元素比较”；
- 工作量增长很慢，可能来自不断把候选范围减半。

这里讨论的是趋势，不是承诺实际时间一定按同一倍数变化。缓存、内存分配、编译优化和输入分布都会影响真机结果。

### 测量值与结论不是一回事

一次 `performance.now()` 得到的是某次运行的**样本（sample）**。样本可能受偶然因素影响，因此可靠测量通常会固定输入生成方式、先让代码预热、重复多次，并保留原始数据。分析者再根据问题选择中位数、百分位数或最坏样本。

先记住三个边界：

1. 操作次数的推导解释“为什么会增长”；
2. 真机样本显示“在这个环境中实际多快”；
3. 单次快速不能证明规模扩大后仍然快速。
