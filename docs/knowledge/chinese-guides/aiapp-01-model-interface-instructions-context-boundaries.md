# AI 应用模型接口与上下文边界知识点讲义

## AIAPP-01 AI 产品运行时的模型接口、指令与上下文边界

从浏览器向某个模型地址发送消息，很容易做出演示，却不足以形成可维护产品。真实系统要处理身份、密钥、供应商能力差异、上下文预算、不可信数据、取消、限流、拒绝、未知结果、版本、评测和回滚。高级前端或全栈工程师的任务不是把所有 SDK 包成同名函数，而是建立一个只承诺应用真正需要、能在运行时验证且能随供应商变化安全退化的边界层。

### 学习前先确认

- 直接前置：[AIPROD-01 AI 任务定义、模型选择与价值验证](../chinese-guides/aiprod-01-ai-task-model-selection-value-validation.md#aiprod-01)。先确认用户任务、非 AI 基线、失败成本、评测和停止条件，才能决定运行时需要哪些模型能力；本讲不替尚未证明价值的功能寻找技术理由。

### 一、先定义应用合同再选择供应商字段

应用合同从用户任务出发，声明输入内容类型、输出形态、允许工具、最大延迟、取消语义、错误类别、数据地区和审计字段。只把当前功能需要的交集暴露给业务层；推理过程、私有采样项或供应商特有缓存若没有稳定语义，不进入通用合同。

同名字段也可能不同。消息角色、工具选择、结构化输出、停止原因、用量、图像和推理模式在各家接口中不天然等价。适配器显式转换、拒绝或降级，并把能力缺失返回为可判断状态，不能静默丢弃高优先级指令或工具约束。

合同还要定义未知字段和演进。响应增加新结束原因时安全保存原值并降级展示；输入收紧要经过版本迁移。把厂商 SDK 类型直接传播到页面会让全站与单一版本耦合。

内部响应采用内容块而不是假设永远只有一段文本：文本、引用、图片、工具提议、拒绝说明和用量各有明确类型与来源。业务层只处理已声明块，未知块保留观测并安全忽略或中止；不能把工具 JSON 拼进 Markdown 后再靠正则提取。结构化结果到达后仍做 Schema 与业务校验，引用链接仍检查访问权限，内容块合同只解决表示，不自动授予信任。

### 二、Provider Adapter 是防腐层而不是 URL 开关

**供应商适配器（Provider Adapter）**把应用内部请求映射为某个模型服务支持的消息、参数、流事件、工具和错误，同时保留不可映射差异。它负责运行时校验、超时与取消、能力检查、错误分类、用量和版本元数据，不负责业务授权或提示内容本身。

适配器输入包含稳定 request ID、任务类型、模型能力需求、内部消息、预算和 AbortSignal；输出是成功、拒绝、可重试暂态、配额、取消、无效响应或未知结果。原始响应仅在受控调试存储短期保留，业务层消费经过校验的内容块。

多 Provider 测试使用固定假实现：一个不支持工具，一个流式格式不同，一个 429，一个超时后服务端可能仍完成。断言内部状态和用户恢复一致，而不是要求生成文字相同。

适配器还应隔离 SDK 生命周期与连接资源。客户端实例复用要按凭据、地区和网络配置分区；流读取结束、取消或异常时释放 reader、计时器和监听器。供应商 SDK 自动重试必须关闭或纳入统一策略，否则应用以为只调用一次，底层却可能重复发送高成本请求或副作用工具。

### 三、Capability Negotiation 在调用前失败

**能力协商（Capability Negotiation）**把任务需求与供应商、模型和当前端点实际支持的角色、媒体、工具、结构化输出、流式、地区和上下文限制比较。缺少必需能力时在请求前拒绝或选择明确降级，避免发送后才发现语义被破坏。

例如任务要求服务端强制 JSON Schema，只有“尽量输出 JSON”的模型不满足；需要工具调用时，文本模拟 `<tool>` 不能冒充原生结构化能力；需要图像输入时，丢掉图片只发送说明文字会改变任务。可选能力则能降级，如隐藏 token 用量或使用非流式回答。

能力表来自官方文档、运行时探测和契约测试，并带版本与缓存期限。模型别名指向内容变化时重新探测；探测失败按上次可信结果的期限决定拒绝或安全降级，不默认“应该支持”。

路由策略只能在满足任务必需能力的候选之间选择，再比较质量、地区、延迟、成本与容量。故障切换不是遇错便换下一家：不同供应商的数据边界、拒绝策略和副作用格式可能不同，切换前重新做策略与能力检查。高风险任务若没有等价候选就转人工或停止，不能为了可用率降到不满足合同的模型。

### 四、消息角色表达来源和控制权

内部消息模型至少区分应用策略、用户目标、助手历史、工具结果和外部上下文。高优先级策略由服务端受控资产产生，用户和检索内容不能声明自己是系统消息。供应商没有 `developer` 等对应角色时，适配器只有在能保持语义时映射，否则拒绝使用该能力。

工具结果是外部数据，即使由内部服务返回也可能含用户控制文本或提示注入。保留 source、trust、tenant、contentType 和截断信息，组装时以数据边界包裹，不让其中一句“忽略规则”改变权限。

历史助手消息也不是永恒真相。模型过去生成的错误不能因进入历史就提升可信度；事实性状态从业务系统重新读取，旧建议只作为会话内容。

### 五、Context Window 是有限而有风险的工作集

**上下文窗口（Context Window）**是一次模型调用可处理的输入与输出 token 总空间，具体限制和计数随模型与编码器变化。它不是长期记忆，也不是把越多资料塞进去越好。无关内容增加成本、延迟、冲突和注入面，重要指令还可能被淹没或截断。

预算从输出上限、必需策略、当前任务、工具 Schema 和必要上下文反向分配。每项候选记录来源、相关度、时效、敏感度和 token 估算；先删除重复和低价值，再对可验证内容摘要。永不从中间任意截断结构化块、代码边界或关键免责声明。

超预算是正常状态。界面提示缩小范围、选择文件或分阶段处理；服务端记录哪些内容被纳入、摘要或排除。不能悄悄丢掉用户附件后生成看似完整答案。

### 六、Token 预算与成本必须按任务核算

token 是模型计费和容量单位，不等于字符或词。中文、代码、JSON 和图片在不同模型中的计量不同；离线估算用于预规划，供应商返回用量用于结算和观测。模型未返回用量时标记未知，不伪造精确数字。

设置输入、输出、工具回合、总时长和费用预算，并按用户、租户与功能累计。缓存命中也要验证身份、提示版本、模型版本、数据时效和权限；跨用户复用生成结果可能泄露上下文。

成本指标按“一个有效完成任务”计算，包含失败重试、检索、工具、存储、评测和人工复核。单次调用便宜但完成率低，整体可能更贵。

### 七、采样参数控制分布而非事实可靠性

temperature、top_p、seed 和惩罚项是供应商特定的生成控制。通常不同时随意调多个采样旋钮；即使 seed 固定，模型、基础设施和并发变化也未必保证字节级复现。参数记录到版本证据，但不能当事实正确控制。

结构化、计算和高风险任务优先通过 Schema、工具和来源验证降低自由度；创意任务可允许更多变化，并用多样性和用户选择评估。把 temperature 设为 0 不会消除幻觉、偏见或注入。

输出上限与停止条件要防止截断。达到长度限制时状态是未完成，界面提供继续或缩小任务，不能把半截 JSON 或句子保存为成功。

### 八、Prompt Asset 是可发布、可回滚的配置

**提示资产（Prompt Asset）**是带 owner、用途、角色、变量 Schema、示例、语言、兼容模型、版本、评测、发布与回滚信息的受控指令模板。它不是散落代码中的魔法字符串，也不应由浏览器携带秘密。

变量使用结构化装配，明确数据边界，避免字符串替换让用户内容闭合分隔符或伪装角色。few-shot 示例应代表真实边界并有来源、期限；示例过多会占用上下文并将旧政策固化。

提示变更像代码发布：审阅差异、运行留出评测和安全集、灰度观察、绑定模型版本并保留回退。只让同一模型自评新提示不构成独立证据。

### 九、上下文组装需要可解释的优先级

组装器接受任务、受信策略、用户输入、授权检索、会话摘要和工具结果，按确定规则排序、去重与裁剪。事实资料保留来源和时间，冲突不由最后出现的文本自动获胜。敏感内容在进入第三方模型前经过目的、地区和最小化判断。

检索先按当前主体授权，再排序和取回；不能从全局数据取出后靠提示要求模型保密。摘要引用原消息 ID 与版本，用户修正后旧摘要失效。工具 Schema 只包含本任务可用动作，减少模型选择面。

保存上下文计划而非无节制保存全文：纳入项、排除原因、token 分配、来源版本和策略决定。这足以复盘大多数问题，同时降低隐私风险。

### 十、请求状态必须区分拒绝、失败与未知

一次调用可建模为 received、policy_checked、context_assembled、in_flight，最终进入 succeeded、rejected、retryable_failed、cancelled、invalid_response 或 unknown。状态单向、带请求序号与时间；同一 UI 消息可发起多次尝试，但每次尝试身份独立。

拒绝是模型或策略明确不执行，暂态失败可能重试，无效响应是到达但不符合合同，unknown 表示客户端未确认服务端结果。只读生成在用户确认后可重试；带工具副作用的未知结果先查询业务幂等记录。

页面显示与状态一致：拒绝给安全替代，限流给可行动等待，取消保留草稿，未知不冒充失败或成功。日志记录脱敏错误类别和供应商 request ID。

### 十一、取消、超时和重试由端到端共同实现

AbortSignal 从页面传到 BFF、供应商请求和可取消工具；组件卸载或新请求出现时标记旧尝试失效，迟到结果不得覆盖新内容。客户端停止读取不一定终止服务端计算，因此预算和审计仍要按实际状态处理。

连接超时、首 token 超时、整体超时和工具超时分别设置。重试使用退避、抖动、最大次数和 Retry-After，避免所有客户端同时冲击服务。非幂等工具不由模型接口层自动重放。

取消后用户可以保留已生成草稿，但它必须标记未完成；继续生成建立新尝试并引用原版本，不能把两个流无序拼接。

### 十二、密钥、数据地区与日志属于服务端边界

模型 API 密钥保存在服务端或受控边缘运行时，使用最小权限、短期轮换和供应商配额。浏览器包、源码映射、错误报告和网络响应不得包含密钥。前端通过自己的会话与 BFF 通信。

请求发送前决定哪些个人、企业和跨地区数据允许进入哪个端点。供应商“不用于训练”是合同属性之一，不代替本方的数据目的、告知、留存和权利流程。日志默认不保存完整提示和回答。

支持调试时使用受限采样、去敏、短期存储和访问审计。用户删除请求传播到会话、缓存、评测候选与供应商可控存储。

### 十三、可观测性连接质量、成本与发布

记录模型/提示/策略/适配器版本、任务、状态耗时、输入输出用量、缓存、工具、错误类别和用户恢复。指标看成功完成率、拒绝、unknown、TTFT、总延迟、成本、人工修订和严重错误，而不只看 HTTP 200。

高基数字段进入 trace 或日志，指标使用任务与错误分类。供应商 429、响应 Schema 漂移、能力探测变化和特定群体退化各有可行动告警。模型输出原文不能成为普通标签。

发布事件标注配置组合，比较灰度与基线。监控失明、评测越界或 unknown 激增触发停止扩大和回退。

### 十四、用契约矩阵验证可替换性

为两个真实或假 Provider 建矩阵：角色、媒体、工具、结构化输出、流式、上下文、用量、取消、限流、拒绝与错误。对每个必需能力运行正常、缺失、超预算、取消、429、无效结构、模型下线和未知结果测试。

再验证 Prompt v1→v2、模型 A→B 和地区端点切换：业务层不读取供应商私有字段，能力不等价时拒绝或明确降级，旧版本能回放并回滚，用户状态与审计保持完整。一次成功补全只证明网络可用，不证明产品运行时成立。

学完后，你应能从任务合同设计供应商适配器和能力协商，理解消息来源、上下文与 token 预算，治理提示资产，并把请求状态、取消、重试、隐私、观测和版本回滚连接起来；能够解释为什么“统一一个 URL 和 messages 数组”既不能保证可替换，也不能保证安全。继续查证可参考 [DeepSeek Chat Completions API](https://api-docs.deepseek.com/api/create-chat-completion/)、[NIST AI RMF](https://www.nist.gov/itl/ai-risk-management-framework)与所选供应商的当期官方模型和数据政策；上线前必须重新核验具体能力与限制。
