# AI 会话状态、上下文组装与隐私知识点讲义

## AIAPP-12 会话状态、上下文组装、压缩与持久化隐私

聊天窗口里看到的消息、发给模型的消息、工具事件、流式临时态和摘要并不是同一种数据。把它们塞进一个数组可以快速演示，却会在刷新、并发、重试、租户隔离和删除时崩溃。成熟会话系统区分事实、派生与草稿，使用服务端身份、顺序和版本恢复，并在有限上下文中保留关键约束而不是无限保存全部历史。

### 学习前先确认

- 直接前置：[AIAPP-02 流式响应、SSE 与增量渲染](../chinese-guides/aiapp-02-streaming-sse-incremental-rendering.md#aiapp-02)，它递归包含模型接口和隐私目的基础；[IDENTITY-01 认证、会话与浏览器边界](../chinese-guides/identity-01-session-cookie-token-browser-boundaries.md#identity-01)，用于理解用户、租户和服务端授权。间接前置不重复列出。

### 一、Conversation State 分成多种记录

**会话状态（Conversation State）**是恢复一次对话任务所需的服务端事实、用户草稿、UI 派生、模型上下文和工具事件的集合。它们具有不同可信度、所有者和生命周期，不能混成一条消息列表。

原始用户消息是事实记录，助手输出是生成候选，工具结果有外部来源，执行状态由服务端账本决定，UI 卡片与折叠状态是派生视图，未发送草稿属于用户设备。摘要是可重建派生，不得覆盖原文。

先定义每类谁能写、谁能读、保存多久、能否删除和怎样版本化。这样一个 UI bug 不会改变业务事实，一次摘要错误也不会重写历史。

### 二、服务端身份决定会话归属

会话由不可猜 ID、tenantId、owner/participant、创建来源和策略管理。API 从认证上下文取得主体，不接受客户端传来的 userId 决定访问。不存在与无权访问的响应避免泄露存在性。

共享、协作和客服接管使用显式角色与范围，记录授予、撤销和到期。公开分享创建独立、最小化快照，不把内部会话 ID 直接暴露。供应商 thread ID 只是下游引用，不能替代应用授权。

切换账号、租户或权限后清理本地缓存和连接，重新验证所有打开会话。标签页里旧凭据不能继续追加。

### 三、追加日志优于覆盖数组

服务端为每条持久消息分配单调序号或版本，客户端提供唯一 clientMessageId 用于去重。追加采用原子约束 `(tenant, conversation, clientMessageId)`，重复投递返回原记录，不生成第二条消息。

编辑、重新生成和分支创建新版本并引用父消息，不静默覆盖历史。工具事件和助手流关联 run ID；确认完成前的 token 保存在临时流或事件表，终态后归并为消息块。

删除可以是可审计状态转换与后台清理，不允许并发追加在删除后复活会话。服务端版本控制所有合法迁移。

### 四、Optimistic Concurrency Control 发现竞争

**乐观并发控制（Optimistic Concurrency Control）**在写入时比较预期版本与当前版本，冲突时拒绝并要求合并，而不是通过锁住整个会话避免并发。它适合标签页、重新生成和多人协作。

客户端提交 baseVersion、父消息或 If-Match；服务端原子验证。不同分支可以并存，同一草稿冲突展示差异。最后写入者获胜会让一个标签页悄悄删除另一个的消息或摘要约束。

冲突重试重新读取当前状态和权限，不能原样循环。工具副作用不因消息写冲突而重放，二者有独立幂等键和状态。

### 五、流式事件与持久事实分离

流事件有 run、message、sequence 和 terminal。客户端只应用连续序号，重复忽略，缺口等待或重新同步；终态后迟到 token 不再拼接。刷新按已确认水位线恢复，不从 DOM 猜完成内容。

用户取消时保留已确认文本并标记 incomplete/cancelled；服务端若继续产生迟到结果，依据 generation ID 隔离。用户开始编辑后旧 run 失效，不能覆盖草稿。

持久化可以保存最终消息与必要事件水位线，不一定永久保存每个 token。调试采样遵循隐私，完整敏感流不进入普通日志。

### 六、Context Assembly 是有预算的选择

**上下文组装（Context Assembly）**按当前任务、优先级、来源、可信度、时效和 token 预算，从策略、消息、工具状态、检索和记忆中选择一次模型调用的工作集。它不是简单取最后 N 条。

系统策略、当前用户目标、未完成工具事实和关键约束优先；近期对话提供局部语境；外部资料带来源和数据身份。无关寒暄、重复内容和已失效工具结果可省略。任何排除、摘要和截断都可观测。

上下文窗口不是长期记忆。能放更多 token 不代表应把全部历史、敏感数据和过期事实发送；内容越多，成本、冲突和注入面越大。

### 七、摘要保留来源与不变量

摘要包含覆盖消息范围、生成版本、源序号、模型/规则版本、关键事实、未决事项和不可丢约束。它是候选派生，激活前通过 Schema、来源完整性与关键约束回归。

分层摘要可以把旧轮压缩为章节，再组合任务摘要；重要事实也可结构化保存。不要反复摘要摘要而失去原始来源。用户修改事实时产生新版本并标记旧结论失效。

摘要不能获得比原文更高权限。源消息删除或变为无权时，派生摘要同步失效或重建，不能成为泄露旁路。

### 八、Summarization Drift 会悄悄改变任务

**摘要漂移（Summarization Drift）**是压缩过程中遗漏、泛化、反转或编造约束，使后续行为偏离原会话。反复压缩、长链推断和模型版本变化都会放大。

为关键约束建立机器可检查表示，例如预算、禁止工具、日期、主体与未决选择。压缩前后运行问答或规则回归；失败时继续用上一有效摘要、原文窗口或请求用户确认，不能激活新摘要。

随机抽样人工对照原文，按语言、任务和长度观察。摘要接受率高不代表质量好，可能是检查缺失。

### 九、草稿、本地缓存和离线体验

未发送草稿可存在 IndexedDB 等本地存储，带会话、账号、版本和过期。它改善刷新与离线，但不成为服务端已确认消息，也不能拥有最终租户授权。

恢复时分别显示服务端原文、摘要和本地草稿。账号变化或会话被删后，旧草稿不自动上传；给用户复制或安全清除选择。敏感草稿考虑设备共享、加密和较短留存。

离线发送排队在重连后重新认证、校验 baseVersion 和幂等键。过期请求进入冲突，不静默追加到已改变的任务。

### 十、分支与重新生成保持可追溯

重新生成不是覆盖助手消息，而是从同一父状态创建新 run/branch。每个分支记录使用的上下文、模型、提示和工具事实，用户选择采用哪一版。后续消息明确父分支。

工具副作用不能随重新生成重放。已执行结果作为只读事实进入新分支，若用户希望另一个动作需创建新提议和确认。分支删除也要处理关联草稿、摘要和附件。

合并分支要比较事实与用户编辑，不能用模型自动挑选后覆盖。冲突显式呈现或人工决定。

### 十一、隐私生命周期从收集到删除

记录每类消息、附件、摘要、供应商副本、日志和备份的目的、访问、地区、保留和删除。聊天内容不因为用户主动输入就可永久用于训练或个性化；用途分别同意与控制。

导出包含用户可理解的原文、时间、来源和必要元数据，不泄露其他租户或内部秘密。删除先立即停止可用，再清理主记录、索引、缓存、摘要、附件和下游副本，保存最小回执。

备份有明确延迟与不可即时清除边界，恢复备份时重放删除 tombstone，防止已删会话复活。供应商留存与删除能力纳入产品说明。

### 十二、上下文安全防止历史升级权限

过去助手消息可能错误，工具结果可能含注入，用户引用的“系统规则”仍是用户文本。组装时保留角色、来源和信任，不把摘要或记忆提升为高优先级策略。

敏感信息按当前任务裁剪，跨租户过滤在检索前。历史里曾有权看到的数据在权限撤销后不继续发送模型。日志和评测也遵循同一边界。

模型输出中的会话 ID、owner 和权限字段都是候选，不用于访问控制。服务端只信认证和持久化记录。

### 十三、可观测性与回放

一次调用关联 conversation、branch、run、消息水位线、摘要版本、上下文项来源、模型/提示和工具状态。记录哪些内容被纳入、压缩或排除，不保存超出目的的全文。

指标包括追加冲突、重复去重、流缺口、恢复成功、摘要回归失败、上下文超限、跨租户拒绝、删除传播和供应商失败。恢复成功要确认用户看到正确版本，不只是接口 200。

回放使用冻结消息、摘要和模拟工具，不再次执行副作用。缺少版本快照时明确不可复现。

### 十四、附件与工具制品有独立生命周期

消息中的附件、生成文件、网页快照和工具制品不应以内联大文本永久复制。服务端保存 assetId、所有者、内容哈希、MIME、扫描状态、版本、权限与过期；消息只引用。下载使用短期授权，预览经过安全转换，不能信任扩展名。

附件更新创建新版本，旧消息继续指向当时版本或明确显示已失效。上下文组装只提取任务所需片段并保留页码/位置；模型无权遍历同一存储桶的其他文件。工具生成制品的信任级别和来源进入后续提示。

删除会话时按共享关系决定是否删除制品；共享项目引用不能被一个会话误删，私人附件也不能因另一个引用而永久保留。派生 OCR、缩略图、索引和供应商上传副本一并追踪清理。

### 十五、多设备同步使用版本与水位线

每个客户端维护已确认 serverVersion、消息水位线和本地草稿版本。同步先拉服务端变化，再合并未发送操作；重复 clientMessageId 去重。不要用本地时间排序，设备时钟可能漂移，服务端序号负责确定事实顺序。

已读位置、折叠与滚动通常是设备偏好，可选择同步；消息、分支和审批是服务端事实。把两类分离，避免手机改变折叠状态触发桌面会话版本冲突。推送只作为变化通知，收到后仍从服务端取可信快照。

离线队列展示待发送与失败项，用户可以编辑或删除。重连后身份变化、会话归档或父版本冲突时不自动上传，提供复制到新会话等安全选择。

### 十六、供应商 thread 与应用会话解耦

某些模型服务提供 thread、response 或缓存 ID。应用把它们视为下游优化引用，记录 provider、区域、创建目的与版本，不能用其 ID 决定本地用户权限或成为唯一历史。供应商故障或迁移时，本地事实仍可重建请求。

切换供应商要重新评估角色映射、工具事件、留存、删除和上下文格式。无法迁移的供应商状态明确终止，不把旧 ID 发给新服务。删除请求跟踪下游回执和延迟。

### 十七、故障注入验证会话不变量

用两个标签页并发追加、重复 clientMessageId、刷新中的流、旧 generation 迟到、摘要遗漏禁止工具、租户 B 请求 A 会话、权限撤销、删除后离线重连和供应商超时。逐项断言顺序、授权、草稿和删除。

测试 `summary-v2` 漏掉关键约束时不激活；删除后本地草稿不冒充服务端原文；重复消息只有一个序号；冲突保留双方。输出事件时间线、版本表、用户可见状态与清理回执。

架构评审应画出消息、事件、草稿、摘要、附件、索引、供应商副本和备份的数据流，逐项标出事实/派生、主体、版本、权限、留存和删除。随后走查刷新、并发、账号切换、权限撤销与供应商故障，确认所有页面来自同一服务端事实，而不是各自缓存的偶然一致。

上线迁移需要冻结或双写窗口、计数与哈希对账、旧客户端兼容和回滚。若旧数据缺少来源或租户，不能用默认 owner 猜测归属；隔离、请求用户确认或只读保留更安全。恢复备份后重放删除和撤销事件，再开放读写。

会话数据模型还要支持法务保留与普通删除的明确边界：保留由有权限流程创建、最小化范围并限制日常检索；到期后继续删除。不能用“可能需要审计”无限保存全部聊天，也不能让保留副本继续参与上下文、个性化或评测。

对每个下游处理方维护数据处理清单和删除能力。供应商更换时停止旧写入、验证导出/删除回执并清理凭据，避免历史 thread 成为无人负责的永久副本。

会话导出要保持角色、时间、分支、附件与来源关系，同时避免包含内部提示、密钥和其他参与者无权数据；导入仍按不可信输入重新校验。

学完后，你应能区分 UI 消息、模型上下文、工具事实、摘要和长期记忆，设计可并发追加与恢复的服务端模型，控制摘要漂移，并把导出、删除和供应商副本纳入完整隐私生命周期。
