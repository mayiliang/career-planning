# 跨区域隐私工程知识点讲义

## PRIVACY-02 跨区域合规、数据分级与前端工程控制

跨区域系统不能只在页脚增加不同地区的政策链接。数据从哪个主体产生、由谁决定目的、在哪些地区收集和存储、经过哪些处理方、是否能被境外人员访问、怎样返回结果，都会影响适用路径。工程目标不是替法务作结论，而是让这些事实可见、可配置、可阻断、可验证。

### 学习前先确认

- 直接前置：[PRIVACY-01 数据最小化、同意、留存与用户权利](../chinese-guides/privacy-01-data-minimization-consent-retention-rights.md#privacy-01)。本讲直接使用处理活动、数据清单、目的、保留、权利请求、处理方和删除传播。

### 一、跨区域分析从四类事实开始

第一类是主体事实：用户常住地、服务地区、年龄、员工/消费者等角色。第二类是处理者事实：哪个法人或组织决定目的，哪些供应商受托处理，是否共同决定。第三类是数据事实：个人信息、敏感信息、重要数据和数量规模。第四类是流动事实：收集、远程访问、传输、存储、备份和支持发生在哪里。

IP 推断、账户地区、设备语言和付款国家都可能不准确。地区识别要记录来源、置信度和用户可更正方式；高风险路径不能仅凭一个前端 locale 决定。

把四类事实放入适用性矩阵，交给隐私/法务确认规则。工程配置引用已批准结论的版本，而不是在代码里散落 `if (country === 'CN')` 后假设问题解决。

### 二、先区分地区、部署区与法律角色

用户在某地、服务器在某地、公司注册在某地和供应商员工从某地访问，是四个不同维度。CDN、日志平台、客服工具、云备份和模型 API 都可能产生额外处理位置。

“选择境内区域”不保证数据不会出境：控制台支持、跨区故障转移、集中可观测性、全局密钥管理和远程运维仍需检查。反过来，跨境也不必然禁止，可能存在不同合规路径与豁免条件，必须依据当前事实和专业结论。

工程图应标注逻辑处理者、物理/云区域、可访问人员、复制与故障转移，而不仅画一个数据库图标。

### 三、分类与分级解决不同问题

**数据分类（Data Classification）**回答数据属于什么类别，例如公开内容、账号标识、敏感个人信息、凭证、重要数据候选。分级回答一旦被泄露、篡改、不可用或非法利用会有多大影响，从而决定保护强度。

分类标签可以驱动日志脱敏、DLP、加密、地区路由、访问审批和保留。分级可以决定双人审批、专用密钥、网络隔离、恢复目标和审计频率。二者有关联，但不能只用“高/中/低”替代法律数据类别。

未知数据默认进入保守等级，直到 owner 与专业人员确认。字段名和文件扩展名只是信号；自由文本、附件、截图和模型输入需要内容与上下文共同判断。

### 四、分类应贯穿 schema、事件和对象

在 schema 或数据目录为字段声明 `dataClass`、purpose、retention、regionPolicy 和 owner。事件总线定义 payload 分类，日志库禁止高敏字段，上传对象携带服务端可信元数据，不能只相信客户端标签。

派生数据继承或重新评估来源风险。摘要可能仍含敏感事实，embedding 可能支持相似检索，缩略图可能暴露证件。不能因为转换了格式就自动降级。

分类变更要能传播。若原本普通字段开始允许自由输入，旧日志、指标、导出和供应商都需重新检查。自动扫描发现冲突并通知 owner，高风险冲突阻断发布或摄取。

### 五、数据驻留是可验证的系统属性

**数据驻留（Data Residency）**描述数据被存储或处理的地理位置约束。要实现它，需要区域化入口、计算、数据库、对象、缓存、队列、日志、密钥、备份与支持流程，而不是只设置主库 region。

区域路由在可信服务端依据已确认租户策略决定，前端 region 参数只能是提示。请求到错误入口时应拒绝或安全重定向，不得先上传数据再纠正。异步任务携带不可篡改的区域/策略标识。

基础设施清单与云配置持续对账：允许区域、复制目标、备份位置、监控出口和管理员角色出现漂移时告警。定期用合成标记追踪真实路径，证明数据没有进入禁止区域。

### 六、跨境流动不只指网络请求

**跨境数据传输（Cross-border Data Transfer）**可能包括主动 API 传输、跨区复制、境外远程查询、集中支持、日志聚合、供应商处理和备份恢复。具体规则如何定义由适用法律与专业意见决定，工程清单应先完整呈现事实。

数据流记录发送方、接收方、地区、数据类别、目的、数量、频率、协议、加密、保存、后续转移和合规路径。没有接收方和目的的“发到云上”无法审查。

临时排错也属于处理。工程师不能把生产附件下载到个人电脑或发到聊天工具来绕过正式路径；需要受控跳板、短期授权、脱敏数据和审计。

### 七、中国规则需要按当前官方文本核验

《中华人民共和国个人信息保护法》自 2021 年 11 月 1 日施行，规定个人信息处理原则、敏感个人信息、跨境提供、个人权利和处理者义务等。工程设计可以据已确认要求实现告知、单独同意、影响评估、权利和安全措施，但具体适用仍取决于角色与事实。

《促进和规范数据跨境流动规定》于 2024 年 3 月 22 日公布并自公布之日起施行，对数据出境安全评估、标准合同、认证及若干免予情形作了衔接和调整。不能沿用更早阈值表，也不能看到“豁免”就省略告知、安全保护或其他仍适用义务。

《网络数据安全管理条例》自 2025 年 1 月 1 日施行，覆盖网络数据处理的一般要求、个人信息、重要数据、跨境与平台义务。法规和配套指南可能继续变化，发布前要按官方最新文本与具体行业规则复核。

### 八、阈值和路径必须配置化、版本化

法律阈值可能涉及处理者类型、数据类别、累计数量、时间窗口、自贸区规则和重要数据认定。不要把几条数字硬编码在前端，也不要让工程师依据模糊输入自动作法律结论。

合规规则服务读取已审批配置：适用版本、生效日、地区、主体角色、条件、所需路径和证据。业务请求只得到 allow、deny 或 review-required，以及可对用户表达的原因类别。

配置变更经过双人审查、测试和渐进发布，保留旧版本以重放历史决定。服务不可用或输入缺失时，高风险传输默认阻断并生成升级单；低风险本地功能可按预先批准的降级策略继续。

### 九、前端负责知情选择与诚实状态

前端在数据离开预期边界前展示必要告知和选择，说明数据类型、目的、接收方类别、是否跨区域、可选性和撤回入口。默认值遵循已确认规则，不用预勾或模糊按钮诱导。

但前端不能成为唯一闸门：请求可被伪造，配置可加载失败，旧客户端仍存在。服务端根据权威主体、地区、分类、同意/依据和规则版本再判断。

页面要区分“正在核验”“允许”“需要确认”“被阻断”“等待人工复核”。配置未加载时不能假装本地允许；同时给出不上传数据的替代路径或保存草稿方式，减少用户损失。

### 十、同意与跨境路径不是同一个开关

某些场景可能需要单独同意，但同意并不会自动满足所有跨境条件；某些处理依据也可能不是同意。系统把用户选择、适用路径、影响评估、合同/认证/评估状态和安全措施分别记录。

撤回后停止基于同意的未来传输，并触发下游处理与删除流程。若仍有其他法定义务需保存，应进入受限状态并向用户清楚表达，而不是继续全部用途。

同一用户的不同功能、数据类别和接收方可能有不同状态。一个全局 `crossBorderConsent=true` 容易过度授权，也无法支持后续变更。

### 十一、重要数据候选必须进入人工确认

重要数据依赖主管部门、地区和行业目录及危害判断，不能由前端开发者仅凭字段名称决定。系统可以用规则和扫描标记候选，但在未确认时走保守路径。

候选记录包含来源系统、数据类别、规模、地区、业务用途、潜在影响和 owner，提交安全与法务复核。收到明确目录或认定后更新分类、出境路径、风险评估和报告控制。

“未被识别为重要数据”与“确定不是重要数据”不同。证据不足时不应自动跨区，也不应在产品文案中给出确定法律结论。

### 十二、供应商与子处理方必须纳入区域图

供应商评估不仅看总部所在地，还看服务区域、数据副本、运维访问、子处理方、模型训练、遥测和事件响应。合同 region 承诺需要用技术配置、访问日志和删除回执验证。

API client 按租户/区域选择 endpoint 和凭证，禁止自动 fallback 到未批准全局端点。供应商故障时可以在本区排队、降级或停止，不得为了可用性静默跨境。

子处理方变更触发影响评估与必要通知。定期从供应商控制台和账单资源清单对账，避免测试项目或新功能使用默认全球区。

### 十三、日志和可观测性常是隐藏跨区通道

集中日志、崩溃录屏、性能追踪和 APM 常默认发送 URL、请求体、用户 ID、附件名或模型提示。它们可能绕开主业务的区域路由与保留策略。

在采集端按分类删除或转换字段，使用区域化 collector，限制采样和保存，禁止 Authorization、Cookie、签名 URL 与原始敏感正文。日志 schema 审查与业务 schema 同等重要。

告警信息只包含定位所需摘要，值班人员通过受控系统按需访问；不要把生产样本复制到全球聊天群。跨区域排障使用合成数据或审批的最小片段并记录销毁。

### 十四、加密不改变流动事实

传输加密和静态加密降低窃听与介质暴露，但数据到达接收方后仍会被解密处理，因此不能把“已加密”当作不发生跨境或不属于个人信息。

密钥应按区域和用途隔离，访问受最小权限、轮换和审计。全局 KMS、集中密钥管理员或跨区备份密钥可能形成额外访问路径，需要纳入图中。

端到端或客户端加密可缩小服务方可见范围，但会影响检索、审核、恢复和权利请求。只有威胁模型、密钥恢复与元数据边界完整时才是有效控制。

### 十五、发布闸门应默认拒绝未知高风险事实

每次发布计算依赖：新字段是否分类，新供应商是否批准，目标地区是否允许，处理路径是否有效，告知/同意是否部署，保留和删除是否可执行，官方规则复核是否仍在有效期内。

**隐私工程控制（Privacy Engineering Control）**指能够在系统中执行并产生证据的约束，例如区域路由拒绝、字段级脱敏、基于目的的权限、保留任务、删除传播和供应商 allowlist。政策文档本身不是运行控制。

闸门输出可审计决定与配置版本。紧急豁免有明确风险、批准人、范围、到期时间和补救任务；到期自动失效，不能成为永久后门。

### 十六、故障模式要按“宁可不传”设计

地区配置加载失败、分类服务超时、同意状态不一致、供应商 endpoint 不可达或法律复核过期时，高风险上传进入 blocked/review-required，而不是使用默认全球配置。

对用户提供本地草稿、稍后重试、删除附件或选择已批准本区功能。错误文案不泄露内部阈值，也不把“法规阻断”说成用户网络问题。

异步队列在策略恢复后重新评估当前规则，不能沿用入队时已经过期的 allow；如果用户已撤回或数据超期，任务应丢弃并执行删除。

### 十七、多区域架构需要删除与权利一致性

用户请求访问、导出、更正或删除时，系统必须找到所有区域、灾备、日志、索引和供应商副本。全局目录可以只保存最小路由元数据，避免为了定位反而集中复制内容。

删除工作流按区域扇出并收集回执，部分失败保持 pending 并告警。区域不可用时记录尚未完成范围，恢复后优先处理；不能因主区成功就向用户宣称全局完成。

跨区灾备恢复先加载当前权利和 tombstone，再开放流量。演练需要证明已删除数据不复活、撤回状态不倒退、地区路由不因故障切到未批准区域。

### 十八、建立可复现的合规证据链

用合成 CN/非 CN 主体、普通/敏感数据、境内/跨区处理方和不同配置版本构造矩阵。验证网络目的地、数据字段、服务端决定、日志脱敏、队列路线、删除传播和 UI 状态。

负向实验包括：地区配置缺失、用户拒绝可选传输、附件被升级为敏感、供应商切换区域、日志 SDK 尝试发送原文、规则版本过期和未知重要数据候选。预期高风险流被阻断且生成可追踪升级记录。

生产持续对账 DNS/endpoint、云资源区域、访问主体、供应商清单、出境数量和权利积压。证据包含时间、版本、输入事实、决定、执行结果和 owner，能够让工程、安全与法务复查。

### 十九、法律资料的阅读方式与边界

官方全文用于确认条文、发布日期和生效时间，讲义用于建立工程模型，两者互不替代。阅读法规时先定位适用范围、定义、处理原则、跨境条件、权利、义务和例外，再由专业人员结合主体与业务事实作解释。

讲义中的日期和路径是 2026 年 8 月 31 日复核快照。发布前应重新打开官方来源，检查新法律、部门规章、行业规则、自贸区政策、指南和执法口径；任何过期快照都不能自动放行。

系统界面不要对用户显示“已完全合规”这种无法证明的总括结论。更诚实的表达是某一处理活动已完成指定版本的复核，所需控制已验证，并保留适用性与例外记录。

### 学完后应能说明

你应能用主体、处理者、数据和流动四类事实构建跨区域矩阵，区分分类、分级、驻留、远程访问与跨境传输；能把已确认的法律路径转化为版本化规则、服务端闸门、区域路由、日志控制、供应商治理和权利传播；也能在未知、高风险或规则过期时停止传输并提交专业复核，而不是用前端开关或加密口号代替适用性判断。
