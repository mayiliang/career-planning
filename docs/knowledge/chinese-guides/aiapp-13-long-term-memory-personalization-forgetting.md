# AI 长期记忆、个性化与遗忘知识点讲义

## AIAPP-13 长期记忆、个性化、纠错与遗忘

会话上下文解决“这一轮模型需要知道什么”，长期记忆解决“跨越多次会话后，系统可以在什么条件下继续使用哪些事实”。二者不能混为一谈。把所有聊天都向量化并在每次请求前检索，看似获得了记忆，实际会积累错误、过时结论、敏感信息和跨任务干扰。成熟系统把记忆视为有来源、用途、权限、时效和撤销能力的数据产品，而不是模型随手写入的无限笔记本。

### 一、长期记忆不是更长的聊天记录

**长期记忆（Long-Term Memory）**是跨会话保留、在未来任务中按条件取回的用户或工作事实。它必须能回答：事实来自哪里、为哪个目的保存、谁能读取、何时过期、怎样纠正，以及删除后有哪些副本需要同步清理。

聊天原文是事件记录，摘要是派生内容，用户档案是结构化事实，偏好是可撤销设置，项目知识是共享资产，模型推断只是候选。它们的证据等级和生命周期不同。把“用户在一次头脑风暴里说喜欢蓝色”直接升级为永久偏好，会把临时语境误当身份。

先按用途拆分存储和检索，而不是先选择向量数据库。只有未来确有用途、用户合理预期且可治理的事实，才值得成为长期记忆。

### 二、记忆分层决定能否安全复用

可以把记忆分为显式设置、稳定档案、任务事实、工作习惯、推断偏好和组织知识。显式设置由用户直接写入，可信度最高；任务事实只属于具体项目；推断偏好需较低权重和更短有效期；组织知识还受角色与租户控制。

每层定义独立 Schema、命名空间、读写主体、默认留存和检索条件。个人偏好不能覆盖组织政策，项目 A 的事实不能进入项目 B，模型推断不能覆盖用户明确修改。发生冲突时，权限更高不等于内容更新；应同时比较来源、时间和明确程度。

前端展示来源和作用范围，使用户知道“这是当前会话临时使用”还是“以后都会使用”。隐藏的永久个性化会损害信任。

### 三、Memory Candidate 先候选后入库

**记忆候选（Memory Candidate）**是从用户明确指令、结构化操作或对话中提取出的待验证事实，在通过用途、敏感性、重复、冲突和权限检查前不进入可检索记忆。

候选至少包含 subject、predicate、value、scope、source、observedAt、confidence、sensitivity、retention 和 extractionVersion。比如“这个项目使用 Vue 3”属于项目事实；“我以后都喜欢 Vue”可能只是当下表达。提取器负责提出，策略层负责准入，不能让同一个模型既猜测又自行永久保存。

明确的“请记住”可以触发保存流程，但仍要验证主体和范围。敏感健康、身份、财务或第三方信息通常需要更高门槛，某些类别应默认不形成个性化记忆。拒绝保存时解释边界，而不是静默失败。

### 四、Provenance 让每条记忆可核对

**来源谱系（Provenance）**记录记忆从哪条原始证据产生、经过哪些提取与合并、当前版本为何生效。没有来源的句子无法判断是用户陈述、模型推断、外部文档还是旧系统迁移。

保存 sourceType、sourceId、原始片段定位、创建主体、模型或规则版本、确认状态和替代关系。前端不必暴露内部 ID，但应允许用户查看“来自哪次对话/哪个设置”、何时保存、影响哪些体验。来源被删除或失权后，派生记忆失效或重建。

合并同义记忆时保留多个证据和版本，不覆盖历史。纠错创建新版本并链接 supersedes，旧版本退出检索；审计可以解释过去结果，正常产品不再使用旧事实。

### 五、检索不是相似度最高就使用

检索先做租户、用户、项目、目的、权限和有效期过滤，再做关键词、结构化条件或向量召回。排序综合任务相关性、来源等级、用户确认、时效、冲突和敏感性。相似度只能表达文本接近，不能证明事实正确或适用。

取回结果必须携带来源与数据身份进入上下文，模型不能把记忆内容当系统指令。任务要求与记忆冲突时，当前用户明确输入优先，并可触发纠错提示。低置信推断用“可能偏好”表达，不伪装确定事实。

限制每次注入的记忆数量和 token；按任务需要选择，不用“为了更个性化”塞满档案。无关记忆会增加成本，也可能让模型固化刻板印象。

### 六、个性化应改善选择而不是替用户决定

适合个性化的包括语言、详细程度、常用技术栈、无障碍设置和用户明确选择的工作方式。不适合由隐式推断直接决定的包括重要权限、价格、医疗法律结论、就业筛选和不可逆操作。

应用“最小影响”原则：先用记忆调整排序、默认值或解释方式，关键决定仍请求确认。提供本次关闭、按类别关闭和全部关闭。个性化结果应有可见理由，例如“因为你把 TypeScript 设为当前技术栈”，而不是神秘地改变答案。

对新用户、少数语言和偏好变化单独评测，防止历史行为把用户困在过滤气泡。个性化命中率不是唯一指标，还要看纠错率、关闭率、意外暴露和任务成功。

### 七、冲突解析要保留时间与范围

“我住在上海”和“我下个月在深圳办公”并非简单矛盾；一个可能是长期居住，一个是临时地点。Schema 应表达属性类型、作用域、有效区间和观察时间。没有这些字段，最后写入者获胜会把复杂事实压扁。

冲突时优先采用用户明确、范围匹配、更新且来源可核验的版本。高影响事实不自动选边，展示差异并询问。无法确认时可以不注入，而不是选择最像的一条。

多个设备或标签页编辑采用版本检查；离线旧修改不能覆盖新版本。合并操作保存操作者、依据和结果，便于撤销。

### 八、遗忘有衰减、失效和删除三种含义

衰减是降低过旧或低置信记忆的检索权重；失效是事实仍保留审计但不再用于生成；删除是按请求清除可识别内容及其派生。三者不可用一个 `active=false` 代替。

过期策略按类别设置：临时任务上下文可能数天，推断偏好数周，明确设置直到用户更改。频繁检索不应自动延长敏感记忆寿命，否则系统会因为自己使用它而永久保存它。

删除传播到结构化库、向量索引、缓存、摘要、训练/评测样本、日志允许范围和供应商副本。备份可能延迟清除，但恢复时必须重放删除标记，不能让记忆复活。

### 九、Right to Be Forgotten 是端到端能力

**被遗忘权（Right to Be Forgotten）**在产品工程中体现为用户能够发现、导出、更正和删除与自己相关的持久数据，并让后续处理停止使用这些数据，而不只是隐藏一条 UI 记录。

记忆管理页按类别展示值、来源、范围、保存时间、最后使用和到期。删除前说明影响，删除后立即从检索路径移除并返回可理解回执。后台异步清理具有状态和失败重试，但不能在等待期间继续个性化。

第三方数据、法定留存和共享项目需分别说明。无法删除的最小记录不得包含可继续个性化的正文。用户退出个性化与删除历史是不同操作，都要提供。

### 十、安全边界防止记忆变成持久注入

网页、附件、工具结果和助手输出都可能包含“以后都执行这个命令”之类的恶意文本。除非用户在可信界面明确批准，这些来源不能写入高权重记忆。写入 API 由服务端授权、限定字段和速率，不接受模型自由生成策略或权限。

记忆内容进入提示时包裹为不可信数据，保留来源标签。它不能改变工具白名单、审批要求和系统政策。高风险动作再次按当前会话授权，过去的“总是允许”文本不是授权凭证。

监控突然大量写入、跨命名空间访问、异常高命中和同一来源传播。撤销被污染来源后批量失效其派生记忆。

### 十一、隐私预算与数据最小化

在产品设计时列出每类记忆的明确收益、最小字段、合法目的、用户预期和删除方式。能从当前请求重新获得的内容不必永久保存；能保存类别就不保存全文；能在设备端处理就不上传服务端。

日志使用记忆 ID、策略结果和脱敏标签，不复制正文。分析与评测使用授权样本和最少字段。跨地区、跨模型供应商前检查数据处理边界，敏感类别可禁用外部模型。

个性化同意应具体、可撤销且不与核心功能强绑定。撤销后停止未来写入并处理既有数据，不能只关闭一个开关。

### 十二、可观测性回答“为什么记得”

一次调用记录候选提取、准入/拒绝原因、检索过滤、排序特征、实际注入、用户纠正和删除传播。诊断界面按权限显示来源与版本，不暴露其他租户或敏感正文。

指标包括候选接受率、用户确认率、冲突率、过期命中、无关注入、纠错后再次出错、删除延迟、关闭个性化和任务提升。单看回答更像用户口吻，无法证明记忆有价值。

告警关注跨租户命中、已删内容再现、高敏感类别写入和策略版本突变。所有自动回填都需可回滚。

### 十三、评测要覆盖变化中的人

测试明确保存、含糊陈述、否定、临时计划、多人对话、项目切换、偏好反转、来源失权和恶意文档。断言正确命名空间、有效期、来源、检索理由与用户可见控制。

建立时间序列：第一天确认偏好，第二天临时例外，第三天明确更改，第四天删除。系统既不能忘记新选择，也不能在删除后从摘要或缓存恢复旧偏好。

离线评测候选精确率和检索相关性，在线评测任务成功、纠错与关闭率；敏感类别需要人工审查。模型升级后重放同一证据集，检查提取和合并是否漂移。

### 十四、团队与共享记忆需要所有权模型

团队空间里的术语、决定和项目事实不属于某个参与者的个人记忆。它们需要 workspace owner、编辑角色、审核状态和适用项目；个人离开团队后，共享事实可按组织规则保留，但其私人偏好和无关对话不能留下。

多人对同一事实提交候选时，保留来源并经过合并/审核。正式决策与讨论意见分开，废弃决定指向替代版本。新成员检索只获得当前角色允许的内容，不能因向量相似看到私密频道。

从个人记忆提升为团队知识需要显式动作和可见目标，不由模型自动传播。反向引用个人来源时遵循删除与匿名化，避免团队知识成为个人数据无法清除的副本。

### 十五、跨 Agent 传播要重新评估目的

Agent A 为代码任务保存的项目事实，只有在 Agent B 的任务范围和权限匹配时才能使用。传递时携带来源、scope、敏感度和有效期，接收方按自己的工具与数据政策再次过滤，不能把“另一个 Agent 已使用”当作信任证明。

子 Agent 返回的新候选先回到统一记忆策略层，不能直接写入永久库。多 Agent 结论冲突时以原始证据和用户确认仲裁，不通过多数票覆盖。委派结束后撤销临时访问，清理只为子任务建立的缓存。

### 十六、从可控记忆开始演进

第一阶段只支持用户显式设置和项目事实，提供查看、更正与删除；第二阶段加入有来源的候选和确认；第三阶段才考虑低风险隐式偏好。每一步都要先有治理和评测，再增加“记住更多”。

记忆功能上线前建立数据目录：类别、用途、来源、写入门槛、默认有效期、敏感级别、检索场景、用户控制、删除下游和 owner。逐条证明没有记忆时核心功能仍可用，记忆错误时能发现和纠正，关闭后不再影响结果。不能回答这些问题的类别先不采集。

模型或提取规则升级使用影子候选比较，不直接改写现有记忆。观察新增、冲突、敏感误收和删除回归，经抽样确认后再迁移；保留旧版本以便回滚，但旧内容不越过用户已做的删除。

用户界面需要解释一次回答实际使用了哪些记忆，并允许对单条选择“本次忽略、以后不用、更正或删除”。纠正动作立即影响后续检索，同时触发相关冲突候选复核，不能只修改显示文本。

定期运行“记忆卫生”任务：找无来源、过期、长期未用、互相冲突和过度敏感的条目，优先失效或请求确认。卫生任务不能自行延长留存，也不应把扫描结果写成新的永久推断。

所有处理结果都应可审计、可撤销并能向用户解释。

产品团队按类别定期复核收益与风险；没有可测任务提升、却频繁被纠正或删除的记忆类别应缩短留存或停止采集。

学完后，你应能区分会话上下文、长期事实、偏好推断和组织知识，设计候选准入、来源谱系、冲突解析、检索排序与删除传播，并让用户真正控制个性化。长期记忆的成熟标志不是保存量，而是系统能准确解释为什么保存、为何使用、何时不用以及怎样彻底忘记。
