# Linux 文件系统与安全操作知识点讲义

## LINUX-01 文件系统、权限与安全命令

Linux 运维事故常不是命令不会写，而是没有看清命令作用在哪个对象、路径如何解析、当前身份拥有什么权限，以及通配符或链接把范围扩大到哪里。高级工程师在修改前建立对象和权限模型，先做只读定位与预览，再用最小变化执行并保留恢复证据。本讲从文件对象、路径、权限与可逆操作建立基础。

适用场景例如开发机文件整理、服务目录权限设计、制品发布、日志归档和受控清理；共享生产环境必须先按本讲的预览、边界和恢复流程执行。

### 学习前先确认

本讲没有站内直接前置；示例从路径、文件对象和普通用户身份开始解释。请在临时目录或专用练习机执行，不要在生产目录实验递归修改和删除。

### 一、先理解目录树与挂载边界

**文件系统层级（Filesystem Hierarchy）**把设备和文件系统挂载到一棵以 `/` 为根的目录树。路径看起来连续，不代表数据位于同一磁盘；`/`, `/home`, `/var`, `/srv` 或容器挂载点可有不同容量、选项和故障域。

常见用途：`/etc` 放系统配置，`/var` 放变化数据与日志，`/tmp` 放临时数据，`/usr` 放系统提供的程序与共享内容，`/srv` 可承载服务数据。发行版与组织约定会不同，先用 `findmnt`, `df`, `lsblk` 查实际布局，不凭目录名推断。

相对路径依赖当前工作目录；绝对路径从 `/` 开始。脚本在 cron、systemd 或 CI 中的当前目录可能不同，关键路径使用明确绝对路径或从脚本位置安全计算，并验证最终目标仍在允许范围。

### 二、文件名只是目录项

目录保存名称到 inode 的映射，inode 保存类型、权限、所有者、时间和数据块等元数据。重命名同一文件系统内的文件通常只改变目录项，因此可用原子 rename 发布完整文件；跨文件系统移动则可能变成复制后删除。

普通文件、目录、符号链接、设备、FIFO 和 socket 行为不同。`ls -l` 首字符提示类型，`stat` 给出 inode、模式、时间和设备。批量操作先按类型过滤，避免把 socket、挂载点或链接当普通文件。

文件名可含空格、换行、前导短横线和通配字符。命令参数用 `--` 结束选项，变量加引号，批量列表用 NUL 分隔。`for f in $(ls)` 会拆词且丢失边界，不可用于可靠脚本。

### 三、权限位依赖对象类型

**权限位（Permission Bits）**按 owner/group/other 三组给出 read/write/execute。对普通文件，r 是读取、w 是修改、x 是作为程序执行；对目录，r 是列出名称、w 是增删目录项、x 是穿越并访问已知名称。

删除文件主要取决于父目录的 w+x，不取决于文件自身是否只读。因此“文件 444 就不会被删”是错误结论。访问 `/a/b/c` 需要沿途目录可穿越；用 `namei -l` 查看整条路径权限，不能只看末端文件。

内核先按进程有效用户和组选择一组权限，不会把 owner/group/other 相加。root 有广泛能力，但仍受只读挂载、不可变属性、MAC 策略和网络文件系统限制。验证最小权限应切换到实际服务用户执行读写，而不是只看管理员命令成功。

### 四、所有者、组与协作目录

文件有 UID/GID，名称只是本机映射。跨主机复制或容器挂载时相同数字可能代表不同名称。用 `id`, `stat -c '%u:%g'` 和目录服务配置确认真实身份。

共享目录优先建立专用组，设置合理 group 权限和 setgid 目录位，使新文件继承组。不要用 `chmod -R 777` 解决协作；这扩大所有本机用户权限，也未解决默认新文件模式。

sticky 位用于多人可写目录，限制删除他人文件，典型为 `/tmp`。setuid/setgid 可改变执行身份，风险高，应最小化并审计。修改 owner/group 前记录原值和受影响清单。

### 五、umask 决定新对象默认收敛

**默认权限掩码（Umask）**从程序请求的创建模式中移除权限。常见基线文件从 666、目录从 777 开始再应用掩码；它不会给普通文件自动增加执行位，也不会回溯修改已有文件。

交互 shell、systemd unit、容器和应用进程可有不同 umask。部署脚本不要假设登录环境；显式设置安全值并验证生成结果。协作服务常用组可写配合 `umask 002/007`，敏感文件使用 077，但具体由访问模型决定。

ACL、默认 ACL 可进一步改变结果；程序也可在创建后 chmod。排查时同时看 `umask`, `getfacl`, unit 配置与实际 `stat`。

### 六、符号链接与硬链接不是复制

**符号链接（Symbolic Link）**保存目标路径，可跨文件系统、可指目录，目标移动会悬空。相对链接按链接所在目录解析，适合 `/srv/app/current -> releases/42` 这类可迁移发布结构。用 `readlink`, `readlink -f`, `namei` 检查。

硬链接是同一 inode 的另一个名称，通常不能跨文件系统或链接目录。删除一个名称只减少链接计数，直到最后名称和打开引用消失才释放数据。备份与去重工具可能使用硬链接，修改内容会影响所有名称。

递归工具是否跟随符号链接各不相同。跟随可能越过目标目录或形成环；不跟随又可能只归档链接本身。每次明确预期并在临时树验证。修改 `current` 发布链接可先创建新链接再原子 rename，避免短暂不存在。

### 七、读取与定位遵循从宽到窄

先用 `pwd`, `ls -la`, `stat`, `file`, `findmnt` 确认位置和类型；用 `find` 按类型、名称、时间、大小和文件系统限制查找。查目录容量用 `du`，查挂载剩余用 `df`，二者含义不同；已删除但仍被进程打开的文件会造成 df 高而 du 找不到。

阅读文本可用 `less`, `head`, `tail`; 跟随日志时注意轮转。搜索内容用 `rg`/`grep`，二进制和权限拒绝要单独处理。命令输出很大时先限制目录与条件，不把整个系统递归扫进终端。

每个诊断记录命令、时间、身份、主机、路径和关键结果。只保存结论会失去复核能力；保存全部敏感内容又有泄露风险，应脱敏并限制访问。

### 八、可靠处理特殊文件名

shell 展开发生在命令收到参数之前。未引用 `$path` 会拆词和 glob；`*` 默认不含点文件且在无匹配时可能原样传递。避免从字符串拼整条命令，使用参数数组或工具原生选项。

`find ... -print0` 配合支持 NUL 的消费者保留边界；`find -exec ... {} +` 也可安全分组。以 `./-danger` 或 `--` 处理前导短横线。不要解析 `ls` 的展示输出作为数据接口。

对用户提供路径，先解析绝对路径并验证位于明确根目录，检查符号链接策略，再执行。字符串前缀比较要防 `/srv/app-old` 冒充 `/srv/app`，使用路径组件语义。

### 九、复制、移动和发布要考虑原子性

复制前检查源类型、目标容量、权限、扩展属性和是否需要保留 owner/time/link。普通 `cp` 默认行为未必满足备份；根据需求使用归档模式并验证。

写配置或制品时先在同一目录/文件系统生成临时文件，fsync 需求按风险决定，校验完整后 rename 到目标。这样读者看到旧或新完整版本，不会读到半写入。跨文件系统不能假设 rename 原子。

发布目录可版本化为 `releases/<id>` 且只读，验证后切换 `current` 链接；回滚切回旧版本。可变 uploads/logs 不应混入制品目录，以免归档、删除和权限边界混乱。

### 十、归档先检查范围再信任

创建 tar 前从明确工作目录使用相对路径，避免把绝对系统路径写入归档。排除规则要验证，归档完成用 `tar -tf` 列出并抽样解压到新临时目录。

备份成功不等于可恢复。记录工具版本、压缩、owner/权限策略、链接处理、加密和校验摘要；定期恢复演练。数据库活跃文件不能仅复制目录，应使用一致性快照或数据库备份机制。

解压不受信归档要防路径穿越、绝对路径和链接覆盖，在隔离目录检查清单。不要以 root 直接把未知归档覆盖系统。

### 十一、删除与递归修改必须逐步收敛

删除前先用完全相同条件打印目标、计数、计算总量并人工核对；关键数据先备份或移到隔离/回收区。把允许根路径硬编码或配置为已验证绝对路径，拒绝空、根目录、home/workspace 根和意外挂载点。

避免 `rm -rf "$dir"/*`：点文件遗漏、变量错误和 glob 范围都危险。使用受控 `find` 条件、深度、文件系统边界和逐批操作；首次用 dry-run。递归 chmod/chown 同样可能跟随链接或破坏服务身份。

生产变更定义停止条件、批次、可恢复性和第二人复核。完成后重新列目标、检查服务和磁盘，不以退出码 0 证明业务正确。

### 十二、磁盘与 inode 都可能耗尽

文件系统可因字节用尽或 inode 用尽失败。`df -h` 与 `df -i` 分开检查。大量小缓存可耗尽 inode，即使仍有容量；稀疏文件表观大小与实际占用不同。

定位增长按挂载点逐层 `du`，避免跨入其他文件系统。已删除打开文件用 `lsof +L1` 查，正确做法是让进程重开日志或受控重启，不直接操纵 `/proc` 作为常规方案。

日志轮转需与应用协作，测试 rename/copytruncate 行为、权限和压缩。磁盘告警要留恢复余量，不能等 100% 才处理。

### 十三、ACL、属性与安全模块

POSIX ACL 可给额外用户/组权限，`ls -l` 的 `+` 提示存在；mask 可能限制条目。扩展属性、不可变标志、SELinux/AppArmor 和挂载 `noexec/nosuid/ro` 都会改变简单 rwx 推断。

权限排错按身份、路径每级、基本位、ACL、挂载、安全模块和应用自身检查。不要看到 Permission denied 就直接开放 777；先找具体拒绝层，做最小改动并记录。

安全上下文错误应按策略和部署流程修复，不用永久关闭强制访问控制。跨发行版命令与策略可能不同，保存系统版本。

### 十四、shell 命令的观察与退出码

命令无输出不等于成功；检查退出码与预期结果。管道默认可能只返回最后命令状态，脚本需要理解 pipefail。输出到文件时重定向由 shell 先打开目标，可能在命令失败前截断，关键文件使用临时文件和原子替换。

`sudo cmd > file` 的重定向仍由当前 shell 执行，权限可能与预期不同。与其绕过，不如明确哪个进程以什么身份打开文件。命令历史可能记录敏感参数，秘密通过受控文件描述符或秘密系统提供。

建立 before/after 快照：路径解析、stat、ACL、挂载、摘要与服务读写测试。这样才能证明修改生效且未越界。

### 十五、练习与故障注入

在临时目录创建含空格、换行、点文件、前导短横线、硬链接、相对/绝对软链接和悬空链接的树。用普通用户和共享组验证读、写、穿越、创建、重命名和删除，解释每个结果。

设置 `umask 027`、默认 ACL、只读 release 和组可写 uploads；用 `namei -l`, `stat`, `getfacl` 形成证据。构建 tar，检查不含绝对路径与敏感目录，再恢复到新目录。

故意制造 inode 接近耗尽、打开后删除的日志和 current 悬空链接，按只读诊断恢复。所有删除练习限定临时绝对目录，先打印清单，并写出如果路径解析异常时的停止条件。

命令说明页和发行版默认可能随版本变化。保存 `uname`、文件系统类型、核心工具版本与 locale；同名工具在 GNU、BusyBox 和 BSD 系统的选项与输出不一定相同。自动化不要解析面向人的彩色表格，优先机器接口或固定格式，并在目标系统测试。

对跨主机操作，还要确认远端身份、实际 shell、路径和文件系统，而不是把本机验证结果直接外推。传输完成后比较摘要、大小、权限和链接语义，并在消费者身份下读取。若归档跨越不同 UID/GID 体系，先定义映射与恢复规则，避免名称看似相同而数字身份错误。

### 十六、最终复核

任何文件操作前回答：实际身份与组是什么；最终绝对路径和挂载点是什么；对象类型及链接策略是什么；权限由哪些层决定；特殊文件名如何保留；操作是否跨文件系统；最坏范围多大；如何预览、恢复和验证。

Linux 基础的高级之处不是记住更多命令，而是理解名称、inode、身份、路径和挂载如何共同决定结果。先验证对象，再执行最小变化；保留恢复和复核证据，才能把一次命令从“看起来成功”提升为可控工程操作。
