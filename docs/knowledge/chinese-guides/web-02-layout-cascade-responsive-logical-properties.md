# Web 基础知识点讲义

## WEB-02 CSS 布局、层叠、响应式与逻辑属性

CSS 布局问题很少只靠“再加一个宽度”解决。元素最终尺寸来自格式化上下文、内在尺寸、可用空间和最小/最大约束；样式是否生效还受层叠来源、优先级和作用域影响。理解这些机制，才能解释长文本为什么撑破 Grid、`z-index:9999` 为什么仍在下面、sticky 为什么突然失效。

### 学习前先确认

- 直接前置：[WEB-01 HTML 语义、表单与可访问性基础](../chinese-guides/web-01-html-semantics-forms-accessibility.md#web-01)。本讲默认页面已有合理 DOM、原生控件与焦点顺序；HTML 语义和弹窗协议由该讲说明。

### 一、正常流是布局基线

块级元素在块方向依次排列，行内内容在行盒中换行。脱离正常流的 absolute/fixed 元素不再为周围内容预留位置；float 和多栏又有自己的规则。

先在无定位、无固定高度的正常流中确认内容可读，再增加 Grid、Flex 和叠层。大量绝对定位通常把不同文本长度、缩放和语言变化变成坐标碰撞。

布局调试先问当前元素属于哪个格式化上下文、包含块是谁、可用 inline/block size 从哪里来，而不是先改 margin。

### 二、盒模型决定声明尺寸包含什么

默认 `content-box` 的 width 不含 padding 和 border；`border-box` 让声明尺寸包含它们。全局常设置：

```css
*, *::before, *::after { box-sizing: border-box; }
```

margin 不属于盒尺寸，相邻块 margin 还可能折叠。用 gap 表达 Flex/Grid 子项间距通常比给每项外边距更稳定。

百分比、min/max 和自动尺寸要结合包含块计算。`height:100%` 只有祖先块尺寸可确定时才有预期效果；用固定视口高度包正文容易在移动键盘和动态地址栏下裁剪。

### 三、内在尺寸解释“为什么缩不下去”

内容具有 min-content 和 max-content 等**内在尺寸（intrinsic sizing）**。长单词、URL、表格和不可缩图片会提高最小宽度。Flex/Grid 子项默认 `min-width:auto`，常采用内容最小尺寸，导致容器出现横向溢出。

```css
.panel,
.panel__title {
  min-inline-size: 0;
}

.panel__title {
  overflow-wrap: anywhere;
}
```

先允许子项缩小，再定义长内容换行。`max-width:100%` 不一定覆盖自动最小尺寸。图片和媒体可使用 `max-inline-size:100%; block-size:auto`，但表格可能需要滚动容器或重排。

### 四、Flexbox 解决一个主轴的分配

**弹性布局（flexbox）**先确定主轴和交叉轴，计算 flex base size，再按 grow/shrink 和可用空间分配。`flex:1` 是多个值的简写，不只是“宽度相等”。

工具栏、导航和一行控件适合 Flex。使用 `flex-wrap` 让内容换行，并验证 DOM 顺序与视觉顺序一致。`order` 只改变视觉排列，键盘与读屏通常仍按 DOM，不能用它修语义顺序。

对固定侧栏和可伸正文可用 `flex:0 0 16rem` 与 `flex:1 1 auto; min-inline-size:0`。若空间不足，需要明确折行、折叠或切换布局，不让按钮被挤到不可用。

### 五、Grid 同时管理行和列

**网格布局（grid layout）**适合二维轨道、区域和对齐。`fr` 分配剩余空间，但轨道的自动最小值仍可能受内容影响：

```css
.layout {
  display: grid;
  grid-template-columns: minmax(0, 1fr) 18rem;
  gap: 1rem;
}
```

`minmax(0,1fr)` 常用于允许主轨道小于 min-content。卡片网格可用 `repeat(auto-fit, minmax(min(100%, 18rem), 1fr))`，让列数随空间变化且窄容器不溢出。

Grid 的隐式轨道会在项目超出显式范围时创建。调试“多出一列”要查看项目定位和 implicit grid，不只改模板列数。

### 六、Flex 与 Grid 可以嵌套

页面整体用 Grid，工具栏内部用 Flex 很自然。选择依据是当前层的约束：需要沿一个轴分配还是对齐二维区域，而不是“项目统一只用一种”。

嵌套时每层都可能产生新的最小尺寸、overflow 和包含块。DevTools 布局覆盖可以显示轨道和 gap，但最终仍要检查 computed size 与内容。

### 七、响应式从内容断点出发

**媒体查询（media query）**可根据视口、输入能力、颜色方案、打印和用户偏好应用样式。断点应在内容开始拥挤、行长失衡或任务不可完成处出现，而不是只照几个设备型号。

采用窄屏基线，再在空间足够时增强：

```css
.shell { display: block; }

@media (min-width: 60rem) {
  .shell {
    display: grid;
    grid-template-columns: 14rem minmax(0, 1fr);
  }
}
```

断点两侧都验证，并拖动中间宽度寻找“无人测试区”。组件在主栏和侧栏可用空间不同，容器查询的架构方法由 WEB-03 继续讲解。

### 八、视口单位有动态变体

移动浏览器地址栏和键盘会改变可见区域。传统 `100vh` 可能比当前可见高度大；现代 `svh`、`lvh`、`dvh` 分别表达小、大和动态视口，但仍要保留内容滚动和兼容基线。

全屏应用可用 `min-block-size:100dvh`，不要给正文固定高度再隐藏 overflow。安全区 inset 用于刘海和系统 UI，不是任意 padding。

测试横竖屏、软键盘打开和浏览器缩放，不能只看桌面响应模式截图。

### 九、逻辑属性适应书写模式

**逻辑属性（logical properties）**用 inline/block 表达相对文字方向的尺寸和边距：`inline-size`、`block-size`、`margin-inline`、`padding-block`、`inset-inline-end`。

它们让 LTR、RTL 和 `vertical-rl` 更容易共享规则。逻辑属性不自动镜像图标含义或业务顺序，方向箭头、时间线等仍需语义判断。

避免同一层同时声明冲突的物理和逻辑属性，除非清楚层叠结果。国际化验证使用真实长文本、RTL 和竖排，而不是只切 `dir` 看空页面。

### 十、层叠先比较来源和重要性

**层叠（cascade）**决定同一元素同一属性最终采用哪个声明。大致考虑相关性、来源/重要性、层、优先级、作用域近接度和出现顺序。选择器权重不是第一步。

浏览器 user agent、用户和作者样式有不同来源；动画与过渡也进入层叠。用户的重要样式能覆盖作者重要样式，是可访问性定制的一部分。

调试时在 computed 面板查看胜出和被覆盖规则，确认 media/support 条件是否匹配。不要一开始增加 `!important`。

### 十一、优先级按选择器结构计算

ID、class/属性/伪类、类型/伪元素形成不同权重。`:where()` 权重为零，适合低权重基线；`:is()`、`:not()` 和 `:has()` 的参数会影响权重。内联样式和 important 还有更高层规则。

架构上保持低且可预测的权重，使用组件边界和 layer，而不是不断加父选择器。权重竞赛使复用和主题覆盖困难。

出现顺序只在前面层次都相同时决定，不应把“后写的一定赢”当通则。

### 十二、层叠上下文限制 z-index 比较范围

**层叠上下文（stacking context）**把一组后代作为整体参与父级排序。定位配合 z-index、opacity、transform、filter、isolation 等可创建新上下文。

子元素 `z-index:9999` 也无法越过祖先在父上下文中的整体层级。先沿祖先找创建条件，再区分被其他层覆盖和被 overflow 裁剪。

真正模态可使用 `dialog.showModal()` 进入 top layer，但语义、焦点和关闭恢复仍由应用负责。top layer 不是安全隔离。

### 十三、包含块决定定位坐标

absolute 元素相对最近建立定位包含块的祖先；fixed 通常相对视口，但 transform 等祖先可能改变它；sticky 在滚动容器和阈值内表现。

sticky 失效常因没有可滚动空间、祖先 overflow 建立了另一个滚动容器、容器高度或 grid stretch。先识别滚动容器和边界，不要只提高 z-index。

定位弹层还要考虑视口碰撞、滚动和焦点。CSS 锚点定位属于现代增强，WEB-03 会讨论其回退边界。

### 十四、overflow 同时影响裁剪与滚动

`overflow:auto/scroll/hidden/clip` 会改变滚动、裁剪和格式化行为。为消除一条横向滚动简单给 body `overflow-x:hidden`，可能隐藏真实内容和焦点。

从最宽元素向上查原因：固定宽度、transform、长内容、Grid 最小值或负 margin。仅目标区域确实需要滚动时建立可命名容器，并确保键盘可达、滚动条可见。

滚动锁定弹窗要保存位置、处理 scrollbar 布局变化和 iOS 行为，优先采用成熟协议。

### 十五、文本、缩放和字体是布局输入

中文、英文长词、数字、URL 和不同字体宽度不同。浏览器缩放 200% 时可用空间减少，固定高度和截断更易失败。不要用省略号隐藏表单错误或关键操作。

用 `ch` 控制阅读行长、`clamp()` 建立有界流式字号，并尊重用户字号。字体加载前后可能布局偏移，提供合理 fallback 和尺寸匹配。

实际内容测试包括空、极长、多语言和动态错误，而不只设计稿短文。

### 十六、响应式不应破坏 DOM 与焦点

窄屏把侧栏移到抽屉时，确认 DOM 顺序、打开按钮、焦点进入/归还和背景交互。不要通过 CSS 把视觉顺序与键盘顺序完全相反。

隐藏内容区分 `display:none`、visibility、透明和屏外定位，它们对布局、焦点和可访问树不同。不可见交互元素不应仍能 Tab 到。

断点变化中保存用户输入和滚动，避免重建组件造成草稿丢失。

### 十七、打印和强制颜色需要独立样式

打印去除 sticky 导航、交互按钮和无意义阴影，允许内容自然分页，并避免卡片标题与正文分离。背景色可能不打印，信息不能只靠颜色。

强制颜色模式会替换作者颜色，边框和焦点使用系统颜色或可适配声明。reduced motion 降低非必要动画，不要让内容依赖滚动动画才能出现。

这些不是“少数用户特殊版”，而是检验结构是否稳健的方式。

### 十八、布局调试采用逐层证伪

1. 检查页面级 scrollWidth 与 clientWidth；
2. 找到超出视口的具体元素；
3. 查看格式化上下文、内在尺寸和包含块；
4. 临时关闭 min-size、transform、overflow 或定位作单变量对照；
5. 在目标视口、长文本和缩放下复测；
6. 保存 computed rule 与修复前后截图。

DevTools overlay 和规则禁用是实验，不是最终修复。找到机制后在正确层修改，并检查没有破坏其他断点。

### 十九、建立多视口与内容矩阵

至少覆盖窄、中、宽和断点邻近宽度；加入长标题、表单错误、弹层打开、200% 缩放、RTL/竖排和打印。每种断言无页面级横向溢出、关键操作可见、焦点可达。

截图发现视觉变化，DOM/键盘测试证明交互，computed style 解释层叠。三类证据组合比“我看着正常”可靠。

### 进阶：布局稳定性也是性能和可用性

图片无尺寸、字体切换和异步插入横幅会让内容移动。为媒体提供 intrinsic width/height 或 aspect-ratio，为延迟内容预留合理空间，并使用匹配度较高的 fallback 字体。不要为消除指标固定一个会裁剪真实文本的高度。

布局偏移需结合用户输入判断：用户点击前按钮移动最危险。性能工具给出受影响节点，随后追到资源和尺寸机制。视觉回归可以发现静态差异，真实加载 trace 才能证明时间中的移动。

### 进阶：containment 要说明隔离代价

CSS `contain` 可限制布局、绘制或尺寸影响，提高浏览器优化机会，也会改变包含块、溢出和内在尺寸。不要给所有组件统一 `contain:strict`；先确定希望隔离哪一维，并验证弹层、sticky、焦点与打印。

容器查询建立的 size containment 也会影响尺寸贡献，这正是 WEB-03 需要从可用基线逐步增强的原因。优化后保留无 containment 对照和用户指标，收益不明显就撤销复杂度。

### 学完后应能说明

你应能从正常流、盒模型和内在尺寸解释 Flex/Grid 项为何溢出，使用 `minmax(0,1fr)`、`min-inline-size:0` 和合理换行建立稳健布局；能按层叠、优先级、层叠上下文和包含块定位样式问题。还应能用内容断点、逻辑属性、缩放、打印和多语言验证响应式，而不是只适配几个设备宽度。
