# Vue 知识点讲义

## VUE-01 Vite 脚手架、SFC 与项目结构

能运行 `npm create vue@latest` 只是项目的起点。高级开发者需要知道脚手架生成了什么、开发服务器与生产构建为何不同、单文件组件怎样被编译、模块别名如何在运行时与类型系统中保持一致，以及哪些配置最终会暴露给浏览器。

### 学习前先确认

- 直接前置：[TS-03 泛型、约束、`keyof` 与索引访问](../chinese-guides/ts-03-generics-constraints-keyof-indexed-access.md#ts-03)、[WEB-01 HTML 语义、表单与可访问性基础](../chinese-guides/web-01-html-semantics-forms-accessibility.md#web-01)、[JS-06 ES Modules 与模块边界](../chinese-guides/js-06-es-modules-module-boundaries.md#js-06)。它们分别提供 TypeScript、HTML 与模块运行模型。

Vue 响应式、组件 props 和路由都在后续知识点展开。本讲只建立可运行、可检查、可发布的 Vue 项目边界。

### 一、脚手架是一组可审阅的选择

本讲区分**依赖预构建（dependency pre-bundling）**、**环境变量（environment variable）**与**生产构建（production build）**：它们分别属于开发启动、配置注入和部署产物，不能混为同一件事。

Vue 官方脚手架会询问 TypeScript、Router、Pinia、测试、代码质量等选项。选择某项意味着增加依赖、配置、目录和验证命令，不意味着项目自动获得相应工程能力。

创建后先读 `package.json`：

```json
{
  "scripts": {
    "dev": "vite",
    "build": "run-p type-check \"build-only {@}\" --",
    "build-only": "vite build",
    "type-check": "vue-tsc --build"
  }
}
```

`dev` 启动开发服务器，`type-check` 检查 Vue/TypeScript，`build` 生成部署制品，`preview` 只是在本地预览制品。开发页面能打开不能替代类型检查和生产构建。

截至 2026-08-30，官方快速上手页给出的 Node.js 前提会随工具链更新；实际项目应把允许版本写进 `engines`、版本管理文件或 CI 镜像，不要把“我电脑上的 latest”当团队合同。

### 二、Vite 开发与生产走不同路径

开发时，Vite 利用浏览器原生 ES Modules 按需提供模块，并对变更执行**热模块替换（hot module replacement）**。生产时，构建器解析完整依赖图，转换、分块、压缩并输出带 hash 的资源。

因此两种环境可能出现不同问题：

- 只在开发环境存在的环境变量或代理；
- 动态导入路径在构建时无法静态分析；
- 文件名大小写在 Windows 可用、Linux 部署失败；
- `base` 配置错误导致子路径资源 404；
- 某个依赖开发时按需转换，生产打包时暴露 CommonJS/ESM 边界问题。

发布前必须直接服务 `dist` 并走真实深链、刷新和资源加载，而不是只检查开发服务器。

### 三、SFC 把同一组件的关注点放在一起

**单文件组件（single-file component）**（SFC）通常由 `<template>`、`<script setup>` 和 `<style>` 组成：

```vue
<script setup lang="ts">
interface Props { name: string }
defineProps<Props>()
</script>

<template>
  <section aria-labelledby="welcome-title">
    <h2 id="welcome-title">你好，{{ name }}</h2>
  </section>
</template>

<style scoped>
h2 { margin-block: 0; }
</style>
```

浏览器并不认识 `.vue` 文件。构建插件会解析各区块，把模板编译为渲染函数，把脚本转换为模块，并处理样式。`scoped` 样式通过编译生成属性选择器限制匹配范围，它不是 Shadow DOM，也不是安全隔离；全局样式、继承、CSS 变量和 Teleport 仍可能跨边界影响结果。

### 四、`script setup` 是编译语法而不是生命周期钩子

`<script setup>` 的顶层代码会成为每个组件实例的 `setup()` 内容；导入、局部变量和函数可直接在模板使用。编译器宏 `defineProps`、`defineEmits`、`defineSlots`、`defineModel` 不需要导入，也不是运行时普通函数。

模块级普通 `<script>` 则只在模块求值时执行一次。把每个请求或实例必须隔离的可变数据放到模块级，可能让多个组件甚至 SSR 请求共享状态。要明确区分：

- 模块生命周期：随模块加载，通常进程内共享；
- 组件实例生命周期：每次挂载创建；
- 响应式生命周期：由 effect scope 和组件卸载管理。

### 五、目录按职责而不是文件类型无限堆叠

小项目可从下列结构起步：

```text
src/
  app/          应用装配、路由、全局 Provider
  features/     按业务能力组织的页面、组件、状态和请求
  components/   真正跨业务复用的展示组件
  services/     外部接口适配与运行时校验
  styles/       全局 token、reset 与主题
  main.ts       浏览器入口
```

只有一个文件时不必建立多层目录；当一个能力有页面、组件、状态和测试时，把它们就近组织通常比全局 `components/`、`stores/`、`utils/` 更容易演进。目录名不能替代模块公共 API，跨 feature 引用应通过明确入口，而不是深入内部路径。

### 六、别名必须在构建器与类型系统中一致

```ts
// vite.config.ts
resolve: {
  alias: { '@': fileURLToPath(new URL('./src', import.meta.url)) }
}
```

TypeScript 也需要能解析同一别名，通常由脚手架的 `tsconfig.app.json` 或继承配置完成。仅在 Vite 配置别名会出现“运行能用、编辑器报错”，只在 TypeScript 配置则可能“类型通过、构建找不到”。测试工具、Node 脚本和 lint 解析器也需要同一合同。

别名适合稳定源码根，不应掩盖层间违规。大量 `@/features/a/internal/...` 说明模块边界仍未设计好。

### 七、环境变量进入客户端后就是公开数据

Vite 通过 `import.meta.env` 暴露构建环境信息。默认只有特定前缀（通常 `VITE_`）的自定义变量会进入客户端代码：

```ts
const apiBase = import.meta.env.VITE_PUBLIC_API_BASE;
```

“环境变量”不等于秘密。只要值被注入客户端 bundle，用户就能在脚本、source map 或网络请求中看到。数据库密码、服务端 API 密钥和签名私钥必须留在可信服务器；前端只能获得公开配置或短期、受限的用户凭证。

环境变量是字符串，布尔值、数字和 URL 都要显式解析并在启动时验证。缺少配置应尽早失败，不能默默拼出 `undefined/api`。

### 八、静态资源有导入资源与公共资源两条路径

从源码导入的图片进入依赖图，可获得 hash、优化和缺失检查：

```ts
import logoUrl from './logo.svg';
```

`public/` 下的文件通常按原名复制到根路径，适合必须保持固定文件名的图标、验证文件等。不要写 `public/logo.svg` 作为运行 URL；部署在子路径时还要考虑 `base`。大量业务资源放进 `public` 会绕过依赖追踪和缓存失效策略。

### 九、开发代理不是生产网络架构

开发服务器可把 `/api` 代理到本地后端，从而避免开发阶段的跨域配置。但构建后的静态文件不带这台代理；生产环境必须由反向代理、同源 BFF 或正确的 API 地址承担。

不要因为开发代理可用，就把内部服务地址、未认证接口或私密端口暴露给浏览器。CORS 只是浏览器读取响应的规则，不是服务端授权。

### 十、类型检查与模板编译是独立门禁

普通 `tsc` 不一定理解 `.vue` 模板中的类型关系，Vue 项目通常使用 `vue-tsc`。构建工具为了速度可能只转译 TypeScript，不执行完整类型检查，所以 `vite build` 成功不一定代表类型正确。

CI 至少应分别运行：依赖锁定安装、类型检查、单元/组件测试、生产构建和必要的 E2E。若并行运行，要保证各步骤都使用同一锁文件和生成类型。

### 十一、生产构建要检查产物而不只看退出码

构建成功后检查：

- `dist` 中是否意外包含秘密、内部 URL 或 source map；
- 首屏与按需 chunk 是否符合预算；
- 动态导入是否形成预期分块；
- CSS、字体和图片路径在真实 `base` 下能加载；
- 深链刷新是否由服务器回退到入口 HTML；
- 旧 HTML 与新 hash 资源并存时是否有安全发布策略。

静态预览只能证明本地文件可服务，不能证明 CDN 缓存、反向代理、认证或回滚正确。部署合同会在后续工程与发布知识点继续深化。

### 十二、依赖升级从锁文件和制品出发

顶层 `vue`、`vite` 或插件版本不能代表真实依赖树。升级前记录 Node、包管理器、锁文件、浏览器基线和构建结果；升级后检查解析出的具体版本、弃用警告、bundle diff 和 E2E。遇到安全公告时，应核对受影响的实际传递依赖，而不是只把 `package.json` 的范围改大。

脚手架输出是某个时刻的推荐起点，不是永久架构。保留最小可回滚变更，避免同时升级框架、构建器、测试工具和业务功能而无法定位失败来源。

### 十三、从入口追踪一次页面出现

浏览器请求 HTML，HTML 加载模块入口，入口创建 Vue 应用并挂载到 DOM 容器。随后 Vite 提供或构建模块，SFC 模板被编译为渲染函数，组件实例建立响应式依赖，最后 Vue 把计算出的 DOM 更新提交给浏览器。

这条链上任何一层都可能失败：HTML 容器 ID 不匹配、入口未加载、模块解析错误、SFC 编译错误、运行时异常或样式资源 404。按链排查比反复重装依赖更有效。

### 十四、HMR 是开发反馈机制，不是状态正确性保证

Vite 的热模块替换（Hot Module Replacement）尽量只替换发生变化的模块，Vue 插件还会尝试保留可安全保留的组件状态。这能缩短反馈时间，但保存的是开发时便利，不是应用的持久化合同。修改组件结构、生命周期或模块导出后，状态可能被重置；某些副作用若没有清理，还可能在多次热更新后叠加。

因此调试怪异状态时要做一次完整刷新作为对照。定时器、事件监听和模块级单例必须有明确清理，不能依赖 HMR 帮你恢复。生产构建没有同样的热更新边界，关键行为仍要以冷启动和真实导航验证。

### 十五、Scoped CSS 解决选择器范围，不解决组件语义

`<style scoped>` 会通过编译后的属性选择器限制样式命中范围，但继承、CSS 自定义属性、teleport 内容、深度选择器和全局重置仍可能跨越组件边界。它也不会自动给颜色、间距和层级建立一致设计语言。

基础 token 和全局语义样式放在明确入口，组件样式跟随组件，跨组件覆盖要有可搜索的约定。遇到样式不生效时检查生成选择器、DOM 实际位置与层叠优先级，不要不断增加 `!important`。

### 进阶：依赖预构建与源码转换解决的是不同成本

开发服务器通常先把 CommonJS 或包含大量小模块的依赖预构建为浏览器友好的 ESM，并缓存结果；项目源码则按请求即时转换。依赖变化、配置变化或锁文件变化可能使缓存失效，因此“第一次慢、之后快”与生产 bundle 大小不是同一指标。

遇到只在某台机器出现的解析问题，记录 Node、包管理器、锁文件、Vite 缓存状态和实际解析路径，再用可控清缓存作为诊断步骤。不能把删除所有缓存和重装依赖当永久修复；应找到不一致的入口、条件导出或插件顺序。

### 学完后应能说明

你应能解释脚手架选项的工程后果、Vite 开发与生产的差异、SFC 和 `script setup` 的编译/实例边界、别名与环境变量的真实责任、公共资源与导入资源的差别，并给出一套从类型检查到产物预览的发布前验证链。
