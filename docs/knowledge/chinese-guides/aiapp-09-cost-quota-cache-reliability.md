# AI 成本、配额、缓存与可靠性知识点讲义

## AIAPP-09 成本、配额、缓存与可靠性

AI 调用把 token、模型容量、检索、工具和媒体处理都变成按请求变化的运行成本。一个演示只要能返回答案，生产系统还要在并发、限流、价格变化、超时和供应商故障中维持任务边界。真正的成本优化不是少发几个字符，而是用完整账本、预算、缓存、重试和降级，让每个成功任务的质量、费用与风险都可解释。

### 学习前先确认

- 直接前置：[AIAPP-01 模型接口、指令与上下文边界](../chinese-guides/aiapp-01-model-interface-instructions-context-boundaries.md#aiapp-01)，用于理解供应商用量、能力和错误适配；[NET-01 浏览器网络、Fetch 与可靠性](../chinese-guides/net-01-browser-network-fetch-reliability.md#net-01)，用于理解超时、取消、重试与 HTTP 状态。两条路径相互独立。

### 一、Cost Ledger 记录真实消耗

**成本账本（Cost Ledger）**把一次任务的模型输入、输出、推理、缓存、媒体、检索、工具、存储、网络和人工费用关联到模型、版本、租户、功能、请求与价格快照。它服务结算、预算、优化和异常调查。

调用前 token 估算只用于保护上下文和预算，最终以供应商用量与账单为准。供应商未返回某项就标记未知，不伪造精确值。价格表带币种、生效时间、地域和计量单位，不能把当前网页价格写成永不变化的代码常量。

成本按“有效完成任务”观察：失败重试、检索、工具、评估和人工复核都计入。单次模型更便宜却导致更多失败或人工处理，单位成功成本可能更高。

### 二、预算与配额是累计边界

为单次调用、一次任务、用户、租户、功能和日/月设置输入、输出、工具步数、时间和费用预算。软阈值用于提示和降级，硬阈值由服务端原子执行，不能依赖浏览器计数。

高并发下“先查余额再扣减”会竞态超支。采用预留、结算、释放：请求开始原子预留上界，完成后按实际结算并释放差额，失败和超时有回收流程。保留应急额度和有审计的临时提升，不允许无限透支。

预算耗尽是产品状态。界面说明已完成部分、为何停止、何时恢复、是否可缩小范围或切换非 AI 路径。不能悄悄降低质量、删除附件或换到不满足隐私要求的模型。

### 三、Rate Limit 保护瞬时容量

**限流（Rate Limit）**约束单位时间内请求、token、并发或其他资源速率，防止瞬时流量压垮供应商和自己的服务。它与累计预算不同：一个用户可以没超月费却在一秒内发出百次请求。

在浏览器、BFF、租户、供应商和工具层分别限流，但服务端规则是最终边界。队列设置最大长度、等待期限与取消，不能无限堆积。按风险与交互分配容量，保留关键操作和人工恢复通道。

429 处理遵守供应商语义与 `Retry-After`，没有建议时使用指数退避、随机抖动、单次上限和总预算。所有客户端同时按固定时间重试会形成惊群。

### 四、超时要分阶段而非一个数字

区分排队、连接、首 token、流间空闲、工具、总任务和用户等待时限。首 token 慢与生成停顿需要不同诊断；浏览器取消也要传播到 BFF 和供应商，否则用户离开后后台仍消费费用。

超时不是业务失败证据。只读模型请求可以安全丢弃迟到结果，写工具可能已经执行，必须按操作 ID 查询。SDK 自动重试纳入统一策略，避免底层与上层叠加成指数调用。

记录每阶段开始、结束、取消来源和供应商 request ID。只看总时长无法判断是队列、网络、模型、工具还是渲染问题。

### 五、Cache Key 定义可复用语义

**缓存键（Cache Key）**包含决定结果语义与权限的所有必要维度：租户/主体范围、模型与版本、系统提示、工具和 Schema、采样参数、输入规范化、检索数据版本、安全策略、语言和时效。遗漏任何关键维度都可能返回陈旧或越权结果。

字节响应缓存适合完全相同、确定性较强的只读请求；语义缓存把相似问题映射到旧答案，风险更高；供应商上下文缓存复用公共前缀的计算。三者命中条件和失效语义不同，不能只看一个 hit rate。

个性化、高风险、实时或含私有数据的任务默认不跨用户共享。命中后仍执行当前授权、内容安全和来源新鲜度检查。用户删除、权限撤销、提示/模型/索引变化触发关联失效。

### 六、上下文缓存不是答案缓存

供应商上下文缓存通常复用相同前缀 token 的计算，回答仍重新生成，命中与计价取决于具体实现。它不保证生成一致、事实新鲜或权限隔离。DeepSeek 当前官方文档描述其上下文硬盘缓存命中规则，接入时要按返回 usage 核验，而不是假设所有 Provider 相同。

前缀设计把稳定公共指令放前面、用户私有或变化内容放后面，但不能为命中率泄露数据或延迟政策更新。提示资产版本、安全规则和工具 Schema 改变时应自然失效。

缓存收益同时看费用、首 token、任务完成和存储/隐私风险。命中率高却不断复用过期政策不是优化。

### 七、重试只处理明确暂态失败

网络中断、部分 429 和 5xx 可能可重试；无效参数、权限拒绝、内容策略、上下文超限和不支持能力通常不可重试。错误适配器先分类，再决定退避、切换、人工或停止。

每次重试消耗总次数、时间、token 和费用预算，携带同一逻辑 request ID 与新的 attempt ID。最终报告包含所有尝试，不能只记录成功一次而隐藏放大成本。

流式响应已交付部分内容时，重试需要新 run 或协议支持的续传；直接拼接两个生成会产生重复与语义跳变。写工具沿独立幂等和查询链处理。

### 八、Circuit Breaker 阻止级联故障

**熔断器（Circuit Breaker）**在某依赖持续失败或超时时暂时拒绝新调用，让系统快速降级并给依赖恢复空间。它按供应商、模型、地域和能力分区，避免一个端点拖垮全部功能。

状态通常为 closed、open 和 half-open；阈值基于足够样本、错误类别和时间窗口。内容拒绝与用户取消不应计入供应商故障，模型质量下降也需要独立门禁而非仅靠 HTTP 熔断。

half-open 用少量受控请求探测，成功达到条件后恢复。熔断状态可观察且有人工覆盖期限，不因部署重启全部忘记。

### 九、Fallback 必须重新验证完整合同

换 Provider 或模型前重新检查能力、数据地区、隐私、Schema、工具、上下文、质量、延迟和费用。能够返回文本不代表等价支持工具或结构化输出。高风险任务没有合格替代时应停止或人工处理。

降级层次可包括更小上下文、非流式、只读、缓存的明确旧结果、规则系统或人工。每层告诉用户差异，并使用对应评估与预算。不能用低价模型静默处理本应隔离的数据。

多个 fallback 仍受总重试和费用预算，防止供应商链全部尝试后成本翻倍。路由决策记录原因和版本。

### 十、并发隔离和背压保护全局可用性

按租户、功能和供应商建立并发池，长任务不能占满日常交互槽位。队列过长时早拒绝或建议稍后，而不是让所有请求超时。浏览器输入去抖只改善体验，不是服务端容量控制。

流式下游慢时执行背压，合并 UI 更新并限制缓冲；用户离开后取消上游。工具并发还要遵守外部系统配额与副作用顺序，不因模型一次提出多个调用就全部并行。

容量演练模拟热点租户、批量任务、供应商降额和长输出，观察排队、公平性、取消和预算，而非只测平均 QPS。

### 十一、安全与隐私不能为缓存和降级让路

缓存、日志和成本账本只保存必要元数据与脱敏摘要。提示、秘密、个人数据和工具结果按目的与留存治理。访问账单和 trace 也需租户隔离。

语义缓存可能把相似私密问题关联起来，供应商缓存可能在其基础设施保留前缀；使用前核验政策和地区。删除请求传播到缓存、索引、日志允许范围和导出。

限流错误不应回显其他租户用量或供应商密钥。成本告警包含聚合与请求 ID，不把敏感输入放进通知。

### 十二、成本与可靠性指标放在同一视图

看成功率、拒绝、429、超时阶段、取消、重试放大、熔断、fallback、缓存命中、token、单位成功成本、预算拒绝和账单差异。按模型、版本、功能、风险和租户类型分层。

低成本若伴随任务失败、编辑量或人工升级上升，不算优化。高缓存命中若来源过期率上升，需要立即失效。目标是满足质量和风险门槛后的成本最小化。

预估与实际账单定期对账，差异超过阈值调查漏记计量、价格变化、隐式重试和工具费用。预算依赖准确账本。

### 十三、故障注入验证整条策略

模拟 429+Retry-After、连接超时、首 token 超时、流中断、5xx、永久参数错、响应丢失、缓存跨租户、价格切换和供应商降额。断言重试次数、等待、费用、用户状态和安全边界。

让主 Provider 无工具能力但 fallback 只支持文本，确认系统拒绝工具任务而非伪装；让缓存命中旧政策，确认版本失效；让两个请求并发预留最后额度，确认只有一个成功。

保存时间线、账本、缓存决策、熔断状态和用户提示。单次最终成功不能掩盖此前十次昂贵重试。

### 十四、请求路由同时考虑能力、健康与预算

路由器先按结构化输出、工具、多模态、上下文长度和地区等必需能力过滤，再比较质量基线、当前健康、延迟与成本。价格低但缺少所需语义的模型不是 fallback；健康实例也不能突破租户预算。路由决策带 policyVersion 和原因，便于回放账单与质量变化。

供应商切换会改变 token 计算、角色映射、Schema 严格度、错误类型和内容政策。适配器统一内部合同，并在上线前用同一评测集验证。中途流断开不能把剩余请求切到另一模型后无痕拼接；要明确结束、重试整次候选或让用户选择。

对高价值请求可保留少量备用容量，对批处理使用低优先队列和截止。路由器发生故障时采用保守固定路径或停止，不让每个调用端自行随机挑供应商。

### 十五、缓存一致性围绕业务失效事件

除了 TTL，还应由权限撤销、文档发布、用户修改、模型/提示升级、工具版本和安全事件主动失效。失效消息可能重复或延迟，所以缓存项验证 namespace 与版本水位线；读取发现过旧就 miss，不等待后台最终清理。

缓存 stampede 使用请求合并、租约或随机过期抑制，但不能让不同用户共享在途敏感结果。stale-while-revalidate 只适用于允许陈旧的只读内容，并在 UI 表明时间；授权、价格、审批和操作状态不应返回陈旧成功。

缓存未命中率上升可能是正确的安全失效，也可能是 key 漂移。观测需关联失效原因、节省 token、额外延迟与质量，不能单纯追求命中率。

### 十六、形成可运营的调用平台

从一次用户任务画出估算、预算预留、排队、调用、缓存、重试、结算和指标。为每种错误定义是否重试、是否切换、用户看见什么、怎样回放；用价格和配额变化证明配置可更新与回滚。

容量评审用峰值并发、输入/输出分布、缓存命中、重试放大和供应商故障计算，而不只用日均 token。为关键功能定义降级优先级和保留容量，为批处理定义截止与可暂停点。每次价格、模型、提示或上下文策略变化都重新跑单位成功任务成本，避免省单价却因质量下降和重试增加总成本。

账单对账按供应商、模型、请求类别和时间窗汇总，再与内部 ledger 比较；差异超过阈值时停止自动优化结论并调查缺失回执、重复请求或计价版本变化。

预算告警同时给出已用、预测、主要来源和可执行措施；只报“额度不足”会让团队通过临时加钱掩盖重试风暴或上下文膨胀。

学完后，你应能建立真实成本账本，区分预算与限流，设计正确缓存键、重试、熔断和 fallback，并用单位成功任务而非单次 token 评价优化。具体接口可参考 DeepSeek 的 [Token 用量](https://api-docs.deepseek.com/zh-cn/quick_start/token_usage/)、[限速](https://api-docs.deepseek.com/zh-cn/quick_start/rate_limit/)与[上下文缓存](https://api-docs.deepseek.com/zh-cn/guides/kv_cache/)，HTTP 等待语义可核验 [Retry-After](https://developer.mozilla.org/zh-CN/docs/Web/HTTP/Reference/Headers/Retry-After)；这些都是版本事实，不是跨供应商通用保证。
