# RAG 检索、引用与来源可信度知识点讲义

## AIAPP-06 RAG、引用与来源可信度

检索增强生成把模型回答连接到可更新、可授权的外部证据，但“搜到几段文字再交给模型”远不是完整系统。资料可能过期、冲突、无权访问或被注入；相似片段可能不支持最终主张；一个可点击链接也可能只是装饰。成熟 RAG 要把来源治理、切分、权限过滤、检索、重排、引用绑定、拒答和删除传播连成可回放的证据链。

### 学习前先确认

- 直接前置：[AIAPP-01 模型接口、指令与上下文边界](../chinese-guides/aiapp-01-model-interface-instructions-context-boundaries.md#aiapp-01)。它递归包含 AI 任务价值与隐私目的基础，本讲在此之上处理外部证据怎样进入上下文，不重复列出间接前置。

### 一、RAG 的目标是受约束的证据使用

**检索增强生成（Retrieval-Augmented Generation）**在生成前从外部资料中选择与任务相关且当前主体可访问的证据，并让回答的关键主张回指这些证据。它适合知识经常变化、答案需要出处或资料按租户授权的任务。

RAG 不会把模型变成数据库，也不保证事实正确。检索可能漏掉正确资料，排序可能把过期内容置顶，模型可能忽略证据或拼出不被任何来源支持的结论。系统要分别评估每个阶段，而不是只看最终文字流畅度。

先定义答案合同：哪些主张必须有引用，允许哪些来源，时效如何判断，冲突时怎样展示，无答案时是否拒答，以及用户能否查看原文。没有这些规则，top-k 与提示优化没有稳定目标。

### 二、来源入库前先做治理

每个文档记录来源 URI、标题、所有者、许可、租户、权限标签、发布时间、版本、生效区间、语言、内容哈希和删除状态。爬取成功不代表允许用于模型，公开可见也不代表允许缓存或二次分发。

解析过程保留章节、段落、表格和代码边界。页眉、导航和重复模板应剔除，但不能丢失影响含义的标题、脚注与单位。OCR 和格式转换标记质量，不把识别错误当原文事实。

更新采用新版本并让旧版本退出在线索引，必要时保留受控历史用于审计。删除、权限撤销和许可变化要传播到原文、索引、缓存、摘要、评测集和引用页面；只删数据库一行会留下可召回副本。

### 三、Chunk 是可引用的最小证据单元

**切分片段（Chunk）**是保留足够语义与来源上下文、可以独立检索和引用的文档单元。切得太小会失去条件、主语和单位，太大则混入无关内容、浪费上下文并降低定位精度。

按标题层级、段落、表格、代码块和语义边界切分，保留父章节与相邻关系。重叠只用于维持跨边界语义，不能制造大量重复命中。表格行需要表头，列表项需要前导语，代码片段需要语言和文件位置。

每个 chunk 有稳定 ID、文档版本、位置、原文和哈希。模型只能引用本次检索返回的 ID，页面用 ID 从受信服务解析链接与摘录，不让模型自由生成 URL。

### 四、Embedding 是召回信号而非事实判断

向量嵌入把文本映射到数值空间，便于语义相似检索。相似度说明表达接近，不说明来源权威、当前有效或真的支持问题。关键词、字段过滤、图关系和规则检索可与向量互补。

索引配置带 embedding 模型、版本、维度、预处理和距离度量。更换模型通常需要重建或双索引验证，不能把不同空间的向量直接混用。语言、代码和短标识符在不同模型上表现不同，应按真实查询评估。

查询可先做拼写和意图归一化，但保留原问题并限制扩写。模型生成的查询可能泄露敏感内容或扩大范围，进入检索前仍执行租户、用途和字段策略。

### 五、权限过滤必须早于模型可见

权限与租户过滤在候选进入模型上下文之前执行，并在打开引用时再次核验。先跨租户召回再从界面隐藏，已经把秘密送进提示、日志或缓存。过滤条件来自受信身份，不接受模型生成的 userId 或 tenantId。

复杂 ABAC 可先用授权服务生成允许范围或安全过滤表达式，再检索；若底层向量库无法可靠过滤，高敏感资料采用物理分区或两阶段受控查询。排序缓存键包含主体或权限范围，不能跨用户共享私有结果。

权限可能在会话中撤销。长回答生成前、引用展开和工具执行时重新核验关键资源；被撤销片段从当前上下文和后续重试移除，界面说明来源已不可用。

### 六、Reranking 结合相关性、时效和权威性

**重排（Reranking）**对初步召回候选重新评分和筛选，使进入上下文的片段更贴近问题与来源策略。它可以使用交叉编码器、模型评分或确定规则，但要保留每种信号与版本。

相关性之外还要考虑来源等级、生效时间、文档状态、重复度、覆盖多样性和冲突。官方旧政策可能比新公告语义更像问题，却不应优先。高分博客也不能自动压过当前规范。

重排输出不是事实裁决。候选互相冲突时保留双方及时间，让回答明确差异或转人工；不要用平均分合成一个不存在的政策。阈值以下进入“证据不足”，而不是为了填满 top-k 降低标准。

### 七、上下文装配保留数据身份

进入模型的每段证据带 citation ID、来源、日期、权限范围和清晰边界，并声明内容只是数据，不能修改系统指令或工具权限。分隔符和提示能帮助模型，但真正控制仍是最小权限、输出验证和服务端授权。

去除重复片段，按任务覆盖选择少量高价值证据；保留问题所需的例外和条件，不能只截取结论句。token 不足时减少来源或请求缩小范围，不能悄悄去掉反例后给出确定答案。

检索内容中的 HTML、脚本、提示和链接都不可信。显示时按上下文编码，工具不会执行片段中的指令，日志不保存超出目的的全文。

### 八、Citation Grounding 绑定主张与证据

**引用落地（Citation Grounding）**检查回答中的可核验主张是否由相邻引用的具体片段支持。引用存在只证明有一个链接，不能证明它支持数字、条件和因果结论。

把答案拆成原子主张，为每条记录 citation ID、支持范围和是否完全支持。引用应定位到段落或表格行，让用户看得到上下文、版本和时间。多个主张不能都挂一个宽泛首页。

模型提出的引用映射是候选。服务端验证 ID 来自本次允许集合、来源仍可访问、摘录哈希和版本匹配；必要时用确定规则或独立评审检查蕴含。无法验证的主张删除、改成不确定或明确无证据。

### 九、无答案和冲突是正常产品状态

区分没有命中、命中相关度低、来源过期、来源冲突、权限不足和系统不可用。它们给用户的下一步不同：改写问题、选择时间、申请访问、查看冲突或稍后重试。

拒答应保留已经确定的范围，例如“当前可访问资料没有 2026 年价格，找到的是 2025 版本”，比笼统“我不知道”更有帮助。但不能通过错误详情泄露无权文档存在、标题或数量。

请求澄清时只问能改变检索范围的关键条件。模型编一个假设后继续回答，会把缺信息伪装成事实。

### 十、缓存需要包含身份与资料版本

查询、候选、重排和最终答案可以分层缓存。键至少包含规范化问题、租户/权限范围、索引版本、过滤规则、模型与提示版本、语言和时效。公开答案与私有答案分区。

命中缓存仍检查当前权限和来源有效期。源文档更新、删除、许可变化或索引切换时失效关联缓存；语义缓存尤其要防止相似问题跨主体复用。缓存内容带引用映射，不能只保存一段失去来源的文本。

供应商上下文缓存只改善成本，不自动提供应用级新鲜度或用户隔离。是否允许使用要根据数据目的和供应商政策判断。

### 十一、评估要拆开召回、排序和生成

为真实查询建立分层集合：有答案、无答案、跨语言、过期、冲突、跨租户、拼写错误、长尾术语和注入。标注允许来源、相关片段、必须支持的主张和应拒答条件。

召回看正确证据是否进入候选，排序看它是否进入有限上下文，生成看主张、引用和无答案处理。最终答案正确也可能引用错源；检索正确也可能被模型歪曲。指标按失败类型报告，不用一个综合分掩盖。

评测集与提示优化、训练数据隔离；来源变化后更新标注并保留历史版本。人工复核高风险与冲突样本，模型评分只作经校准辅助。

### 十二、可观测性服务于可回放诊断

一次查询关联匿名 request ID、主体范围、索引与 embedding 版本、过滤摘要、候选与分数、重排版本、进入上下文的 chunk、回答主张和引用。敏感正文按目的最小化，不把完整私有文档复制进通用 trace。

指标包括检索空结果、权限过滤、过期命中、引用覆盖、错引、拒答、缓存命中、更新传播和删除延迟。相关度突然提高也可能是重复 chunk 或权限过滤失效，需要结合来源分布判断。

用户反馈先由人工确认错误类型，再把去敏样本加入回归。点击引用不等于引用正确，只能作为一个行为信号。

### 十三、故障注入验证证据链

建立两租户、旧新两个版本、冲突条款、无答案问题和含“忽略规则”的网页片段。依次验证旧版退出、跨租户片段不进入候选和日志、冲突同时展示、无答案不编造、注入只能作为引用数据。

再让引用 URL 失效、索引更新延迟、重排服务超时和权限中途撤销。系统应安全降级到可解释状态，不静默使用陈旧缓存或扩大搜索。断言答案—主张—chunk—原文版本链可重建。

删除测试追踪原文、向量、缓存、摘要和下游副本回执。只验证搜索不到不足以证明删除完成。

### 十四、查询理解与多跳检索不能隐藏假设

用户问题常包含时间、主体、比较维度和隐含术语。查询理解先抽取这些约束并保留原问题，再生成可追踪的关键词、过滤条件和同义词；模型改写只是候选，不能把“当前版本”丢掉或擅自增加地区。若实体不唯一，先澄清或并列检索，不用最高相似结果替用户选主体。

复杂问题可能需要多跳：先找到产品版本，再查对应兼容表，最后定位迁移规则。每一跳都记录子问题、使用证据和产生的新查询，后续查询只能使用已验证实体。中间证据不足时停止；不能把第一段模型推断当事实继续检索，最后用长链条掩盖不确定性。

混合检索结合精确关键词、结构字段、向量和关系，但合并前统一权限与版本。关键词适合 ID、错误码和专名，向量适合语义近似，结构过滤约束租户、语言、日期和状态。权重通过评测调校，不能让一个高分覆盖强制过滤。

### 十五、文档更新需要可重复的索引流水线

抓取、解析、去重、分块、Embedding、索引和发布都具有版本。新索引在隔离命名空间构建，检查文档数、失败列表、权限、抽样块和检索回归后原子切换；失败时保留上一有效版本。就地逐条覆盖会让用户在几分钟内查询到新旧混合语义。

稳定 documentId 与 chunk lineage 连接版本；文本移动或重新分块后，旧引用能说明已过期并跳到当前文档，而不是指向错误段落。删除先从检索可见集合移除，再清缓存、向量、副本和派生摘要。权限变化的失效优先级高于性能缓存。

增量更新按内容哈希避免重复计算，但解析器、分块器或 embedding 模型变化时必须触发相应重建。迁移期间查询请求绑定一个 indexVersion，回答的所有引用来自同一可解释快照。

### 十六、面向不同语言与格式保持证据等价

同一政策可能有中文、英文、PDF 与网页版本。建立 canonical document 和 edition 关系，排序考虑官方指定权威语言、发布日期和地区。翻译是派生来源，不能无提示替代原文；关键主张可同时给原文定位与译文说明。

表格、代码、图片 OCR 和脚注需要结构感知解析。把表格逐行打散会丢失列标题，把代码按自然段切分会破坏定义。为不同 block type 保存坐标、标题路径与页码，引用 UI 能回到用户看得懂的位置。解析失败的页面不悄悄进入索引。

### 十七、形成可治理的检索系统

先以一个真实问题画出入库、权限、召回、重排、上下文、生成、引用和展示，给每层定义输入、能证明的事实和失败状态。把来源更新、权限撤销和无答案作为日常状态，而不是上线后的例外。

评审一个 RAG 方案时，逐项要求语料清单、权限过滤位置、索引版本、无答案阈值、主张到证据映射、删除传播和分层评测。若团队只能展示几个看起来不错的回答，却不能重放查询、定位 chunk 或证明越权资料未被召回，系统仍停留在演示阶段。生产发布还需指定数据 owner、更新频率、失效 SLA 和用户纠错入口。

对答案页面抽样反查每个引用，确认链接仍有效、定位范围仍支撑主张、用户当前仍有权限；发现失效时回收缓存和派生答案，而不只修复索引后台。

用户纠错应进入资料 owner 的复核队列，确认后更新源文档或失效索引；不要把一次点赞直接改成全局事实权重。

学完后，你应能解释相似度、权威性与证据支持的差别；能设计可授权、可版本化的 chunk 与引用链；能分别评估和诊断召回、重排、生成，并在没有足够证据时给出诚实可恢复的体验。
