# 领域 13–14 校订中文讲义：Agent/MCP 与浏览器本地 AI

> 本讲义是领域 13、14 的中文必读材料。每节均按“定义—机制—例子/反例—边界与失败—验证”组织；协议和浏览器版本状态以各知识点列出的官方原文为准（核验日：2026-08-04）。实验性 API 只能能力检测后作为渐进增强，不能当作跨浏览器承诺。

## MCP-01

**端到端验收补充。** 以订单场景实现 `orders://{id}`、`get_order`、`cancel_order` 与 `refund_reply`：读取只返回当前用户可见字段，写操作要求幂等键和审批，模板只接收经过 Schema 校验的参数。分别注入未知字段、越权 URI、超大 Resource、把订单文本伪装成指令、相同幂等键重复写入、业务拒绝和 JSON-RPC 参数错误。断言前四种不泄露或执行，重复写入返回首次结果，业务拒绝以结构化正常结果表达而协议错误才使用错误响应；再核对审计记录含用户、能力版本、参数摘要和访问范围。

MCP 中 Host 负责用户界面、同意和安全策略，Client 是 Host 内连接一个 Server 的协议端，Server 暴露能力。Tool 是模型可执行的动作；Resource 是可寻址、可读取的上下文；Prompt 是可发现的参数化消息模板。例：`orders://123` 是 Resource，`cancel_order({id})` 是 Tool，`draft_refund_reply({orderId,tone})` 是 Prompt；把订单读取也做成有副作用 Tool 会丢失缓存、授权和语义边界。

先声明并发现能力，再对输入、输出和错误作 JSON Schema 校验；Tool 的写入/删除风险、只读提示和幂等语义要写入契约。业务状态不藏在传输会话中：创建购物篮返回 `basketId`，后续调用显式带回。协议错误（无效 JSON-RPC、未知方法、Schema 不合格）与业务结果（余额不足、订单不可取消）必须分开。验证：各实现 Tool、Resource、Prompt 一项，注入未知字段、权限拒绝、重复写入和错误原语，并证明只有允许的文件/网络范围被访问。

一套最小 Server 可声明 `tools/list` 中的 `get_order`、`cancel_order`，Resources 中的 `orders://{id}`，Prompts 中的 `refund_reply`。`get_order` 的输入只接受订单 ID，`cancel_order` 还要求幂等键和审批；输出 `structuredContent` 要与 output Schema 一致，业务拒绝以正常结果表达，JSON-RPC 参数错误才是协议错误。Host 负责提示用户和策略，Client 只负责协议连接，Server 不应替用户猜测授权。

练习：把“查订单、退单、退款说明模板”正确归类，写出三个 Schema 和错误表；注入未知字段、错误枚举、同一幂等键、越权 URI、超大 Resource、模型把 Resource 文本当指令。提交工具调用记录、权限拒绝证据和断言只读请求不会改变订单的测试；反例是把所有动作塞进 `run` Tool 或把业务会话藏在传输状态。

## AGENT-01

**定义与运行机制。** Agent 运行协议是把一次目标执行建模为可持久化的有限状态机：`created → planning → executing → verifying → completed`，并允许转入 `waiting_input`、`waiting_approval`、`failed`、`canceled` 或 `stopped`。每次状态迁移都写入 `runId`、前一状态版本、触发事件、预算余量和不可变的操作标识；执行器只接受与当前版本匹配的迁移，避免两个恢复进程同时继续同一步。`planning` 只能产生候选动作，`waiting_input` 不得消耗工具预算，终态不得重新开启执行。这样“模型还在思考”不是进度，“HTTP 超时”也不是成功或失败，而是必须按操作标识核查的未知结果。

例如整理下载目录时，先产生只读清单和移动预览，用户批准后才写入。移动调用携带 `operationId`；响应丢失时先查询该 ID 的最终记录，而不是再次移动。验收脚本应注入最后一步耗尽预算、相同动作连续出现、工具返回 500、用户取消和刷新恢复，断言每条轨迹都给出停止原因，恢复后不产生第二次移动。审计界面只显示目标、动作摘要、证据、预算与原因，不展示隐藏推理或把它当作可执行指令。

Agent Loop 是“观察当前状态—选择或规划下一动作—执行—验证结果—更新状态”的受预算状态机，不是 `while(true)`。状态至少含目标、已完成步骤、下一动作、证据、步数/时间/费用预算和取消原因。例：检索失败两次后改用人工澄清；反例是每次失败都原样重试直到耗尽 token。

每个循环检查目标已达成、最大步数、截止时间、总成本、重复动作、不可恢复错误和人工审批；任一条件触发时写入可恢复快照并停止。恢复只从已记录状态继续，不能重放有副作用调用。验证：绘制状态转换，使用固定工具结果测试成功、重复、超预算、取消、工具超时和目标不可达，产出审计日志与“停止而未达成”的明确解释。

实现时把运行记录固定为：`{runId, goal, phase, step, budget:{maxSteps, deadline, maxCost}, lastAction:{name,argsHash,result}, evidence[], stopReason}`。每轮先读取记录与用户权限，`observe` 只产生事实；`plan` 产生一个经 Schema 校验的候选动作；策略层在 `act` 前检查预算、授权、幂等键和审批；`reflect` 把结果归类为成功、可重试、不可重试或需要输入。伪代码：`if (now>deadline || step>=maxSteps || cost>maxCost) stop('budget'); else if (sameActionTwice(lastAction)) stop('loop'); else if (needsApproval(action)) waitApproval(); else execute(action)`。工具返回网络超时仅代表未知结果；写操作必须先以幂等键查结果，不能直接重放。

例：订票的检索、选择、补充护照号、付款是不同状态；缺少信息进入 `waiting_input`，付款前进入 `waiting_approval`，成功才是 `completed`。反例是把“模型仍在思考”当进度，或付款请求超时后再次扣款。练习：实现三步文件整理任务的上述状态、取消信号与事件日志；注入连续相同动作、工具 500、已提交但响应丢失、用户拒绝和刷新。提交状态转移表、每项预期/实际以及证明终态后不再调用工具的自动化测试。

## AGENT-03

**定义与协议机制。** 无状态 MCP 传输是让每个请求自带可验证的协议版本、请求 ID、认证上下文和业务 handle；handle 是随机不可猜的服务端键，按用户与租户重新授权，不能把权限编码到客户端可改字段。请求先由网关按 `Mcp-Method` 路由，再由服务端核对 header 与 JSON-RPC body；临时补充输入的 `requestState` 还要防篡改、设过期时间并绑定原请求，它不是跨实例共享内存的替代物。

可执行验证：以两个无共享内存实例处理同一 `basketId`，依次篡改 `Mcp-Name`、断开客户端、重放同一幂等键、把请求路由到另一实例，并让旧版 adapter 断线。预期是每种非法输入有确定拒绝，合法重放返回同一业务结果，且不用 sticky session 才能正确。扩容、滚动发布与单实例故障各跑一次该矩阵；若失败，修复显式 handle 或持久状态，而非用进程内 session 掩盖问题。

MCP `2026-07-28` 的 HTTP 核心是无状态、自包含请求；版本和客户端能力随请求元数据传递，`initialize`/`initialized` 与 `Mcp-Session-Id` 属于旧会话协议。HTTP 请求的 `MCP-Protocol-Version`、`Mcp-Method`、`Mcp-Name` 必须和 JSON-RPC body 一致，便于路由、限流和缓存。业务仍可有状态，但用显式 handle 或持久化存储承载。

例：负载均衡把两次 `tools/call` 分给不同实例，均以 `basketId` 读取同一业务记录；反例是依赖实例内 Map 中的会话而导致刷新或扩容丢状态。MRTR 通过 `InputRequiredResult` 返回请求状态，客户端携带用户输入重新发起原请求。兼容 2025 时隔离在 legacy adapter，不把旧会话当新主线。验证：分别跑 stdio、2026 无状态 HTTP 与 2025 适配分支，检查 header/body 冲突、断线重试、重复副作用、任意实例落点、Origin/Host/认证拒绝。

最小 HTTP 调用为 `POST /mcp`，头部含 `MCP-Protocol-Version: 2026-07-28`、`Mcp-Method: tools/call`、`Mcp-Name: add_item`，body 含 `{"jsonrpc":"2.0","id":"r-7","method":"tools/call","params":{"name":"add_item","arguments":{"basketId":"b-1","sku":"p-9","idempotencyKey":"k-2"}}}`。网关可按头路由，但 Server 必须比对头和 body；不一致立即拒绝。持久服务按 `basketId` 读取业务状态、按幂等键回放结果；stdio 虽无 header，仍需版本、请求 ID、取消和显式状态。

MRTR 先返回 `input_required`、可序列化 `requestState` 与输入 Schema；Host 显示确认页，Client 带 `inputResponses` 重新提交。拒绝、过期均是明确结果。练习：用两个无共享内存实例处理同一 basket，依次制造 header/body 冲突、断线、写入重放；提交请求样本、实例日志、数据库幂等记录和 2025/2026 契约矩阵。

## AGENT-04

**定义与发现机制。** 服务发现是 Client 获取对端协议版本、能力与缓存提示的协商过程，不是授权事实：实际调用仍由 Server 重新鉴权、校验 Schema 与限额。缓存键至少包含 `serverId + userScope + version`，并保存取得时间、游标和 TTL；私有结果绝不能跨用户复用。能力更新时，正在执行请求使用启动时快照，新请求才采用新发现结果，避免同一任务中途切换契约。

测试可让第一页与第二页重复一项、cursor 循环、TTL 过期、中途收回权限、Server 声称有工具却返回不支持。客户端应只展示一次已授权项、清除失效缓存、停止恶意无限分页并给出“本服务不支持此操作”的降级说明。记录命中率、发现失败、版本无交集、取消耗时与分页异常；在 2025 连接低于预设阈值且回归通过后，才删除 legacy adapter。

Client 先获取 Server 的能力和版本，再按交集调用 Tool、Resource、Prompt 或扩展；`serverInfo`/`clientInfo` 是描述信息，不是信任依据。列表和资源读结果的 TTL/cache scope 决定缓存新鲜度和能否跨用户共享。未知能力安全忽略，关键能力缺失要给出可操作降级提示。

例：发现 Tasks 扩展不存在就执行同步小任务或让用户稍后重试；反例是把“Server 名称相同”当作同等授权。分页需记录游标和去重，取消需沿请求链传递。验证：建立 2025/2026、能力存在/缺失、过期缓存、页重复/漏页、版本不交集和取消的矩阵；每个格子都有期望 UI、请求和审计记录。

启动序列是：从可信配置读取服务地址和允许版本；发现能力或发首个协商请求；验证响应 Schema、版本、扩展和 cache scope；将 Tool/Resource/Prompt 以 `serverId + userScope + version` 分别缓存；按 `ttlMs`、通知或刷新失效。缓存保存获取时间与游标，不能跨用户复用 private 数据。服务声称工具存在而调用返回不支持时，清除缓存并给出降级提示，不无限重试。

例如第一页返回 `{tools:[...],nextCursor:"c1",ttlMs:60000,cacheScope:"private"}`，Client 只对同一用户复用，读取下一页时记录 `c1` 并检测重复游标。练习：假 Server 依次返回缺 Tasks、陈旧 TTL、重复 cursor、未知字段、2025 session 与 2026 元数据；提交能力快照、命中/失效日志、分页不变量测试和 legacy adapter 退出条件。

## AGENT-05

**定义与审批机制。** Human-in-the-loop 是在含糊目标、权限扩大、外部影响或不可逆动作前由真实用户决定继续、编辑或拒绝。风险由服务端按可逆性、金额、外部受众、权限变化、敏感数据和批量范围评分，Agent 只能申请而不能自批。令牌绑定 `requestId`、工具、规范化参数摘要、用户/租户、策略版本、范围和过期时间；执行器重新计算摘要并检查撤销、权限与价格。收件人、路径、金额或附件一变，旧批准立即作废。低风险只读可自动执行，发送、删除、支付和发布必须先展示真实影响与可取消后果。

以邮件、删除和支付做故障演练：浏览器双击、批准后撤销、审批过期、服务端价格变化、重放请求和网络断开。断言无匹配批准时执行器调用次数为零；断线后先按幂等键查询，不再次外发。批量操作还应显示总数、筛选条件和影响上限，超过上限拆成可分别批准的请求。验收报告列出策略版本、风险理由、用户决定、实际副作用与回滚证据。

Human-in-the-loop 将人放在含糊目标、权限扩大、外部影响或不可逆动作前，而不是逐步弹窗。审批绑定动作、真实参数、目标、影响范围、有效期和风险级别；改参数后旧批准作废。MRTR/elicitation 的用户输入与原请求和 request state 关联，拒绝、超时、撤回都是正常终态。

例：删除三个文件必须展示路径和数量，可编辑范围或拒绝；反例是“始终允许所有删除”或模型高置信度绕过确认。验证：为删除、发送、支付、发布做低/中/高风险策略，测试参数变更、断线重试、拒绝、一次/范围授权、撤销和审计，确保未获批准的调用从未抵达执行器。

审批令牌绑定不可变摘要：`approval={requestId,actorId,tool,canonicalArgsHash,risk,expiresAt,scope,policyVersion}`。执行器重新计算参数摘要，检查用户/租户、过期、策略和撤销；不同即作废重问。低风险只读可自动执行；发送、删除、支付、发布显示目标、金额/数量、数据去向、影响与取消后果。范围授权只能限制动作、资源和时限，不能等价“永久信任”。

MRTR 中 Server 返回 `input_required` 时尚未执行，Host 收集确认或编辑参数；执行后断线先按幂等键查询，避免重复。练习：为四类工具制作风险表和审批 UI，生成编辑、过期、拒绝、撤销、重复点击、超时六例；交付审计事件和断言“无有效批准时执行器调用次数为零”的测试。

## AGENT-06

**恢复与取消补充。** 任务表为 `taskId`、创建摘要、幂等键、状态、进度序号、产物引用、取消标记和过期时间建立唯一约束；worker 只接受递增进度，终态不可回到工作态。创建时先按幂等键查旧任务，刷新后只按 handle 查询，不从连接内存猜测仍在运行。取消只是请求到达，worker 在安全检查点写入终态；取消与完成竞争时以一次原子状态转换裁定，并保存原因。验证服务重启、乱序更新、重复创建、不可重试 Schema 错误和部分产物，证明相同键只产生一个任务且取消后没有新的写入。

长任务以稳定 task handle 表示，并具有持久状态、进度、产物、取消、过期和幂等键。Tasks 是可协商扩展；`tools/call` 可返回 task，客户端用 `tasks/get`、`tasks/update`、`tasks/cancel` 驱动，不依赖连接内存；`tasks/list` 已移除。取消是请求，必须继续观察终态。

例：代码分析在刷新后按 task id 恢复进度；相同 idempotency key 不重复创建。反例是把浏览器连接断开直接标记任务失败。验证：运行分钟级任务，覆盖刷新、重复提交、服务重启、进度乱序、取消竞争、可重试/不可重试失败和部分产物，检查状态机不变量与幂等证据。

任务记录至少含 `taskId`、创建请求摘要、状态、进度序号、产物引用、取消标记、幂等键、更新时间和过期时间。创建时先按幂等键查找旧任务；轮询/订阅只接受序号更大的状态；终态不可回到工作态。`tasks/cancel` 只表示请求已送达，Worker 需在安全检查点停止并写入 canceled/failed/completed 之一。刷新后 Client 用 task handle 查询，不从内存假定仍在跑。

练习：实现代码扫描任务，从 queued 到 working 到 completed/canceled/failed，保存三次进度和一份产物；注入两次创建、取消与完成竞争、服务重启、进度乱序和不可重试 Schema 错误。交付状态表、数据库唯一约束、取消传播日志、刷新恢复录屏和断言相同键只创建一条任务的测试。

## AGENT-07

**定义与协作机制。** 多 Agent 协作是由协调者维护版本化工作图、让各角色通过受控 Artifact 交接，而不是自由聊天树：每个节点声明输入版本、允许来源与工具、输出 Schema、证据要求、预算、依赖和完成定义；边只传受控 Artifact 引用，不广播整段对话。研究者不能写生产文件，实现者不读取敏感原对话，评审者没有写工具。子 Agent 输出一律是不可信数据，合并前仍验证来源、Schema、权限和版本。

验收用一个三节点 DAG 注入恶意交接文本、递归超过两层、预算耗尽、两个实现者改同一文件和相互冲突的引用。父节点取消后，未开始子节点不启动，运行中节点收到取消，完成产物标注可用性与版本；评审阻塞时发布节点不得启动。保存每个节点的成本、工具、证据、停止传播和冲突仲裁记录，证明不会因最后发言或越权文本而静默覆盖结果。

多 Agent 只适合职责可分、交付物明确且合并价值大于协调成本的任务。每个角色拿到最小输入、工具权限、输出 Schema、预算和停止条件；协调者对最终结论负责。通过版本化任务单、证据链接和产物交接共享必要信息，不广播完整对话。

例：研究者给出带出处的结论、实现者只收到经审查需求、评审者只读验证产物。反例是递归委派、把网页/子 Agent 文本当高权指令，或用 MCP Sampling 作为新系统的模型调用主线。验证：注入循环委派、提示污染、预算耗尽、冲突结论和角色越权，证明能停止、隔离、仲裁并追溯。

交接单可固定为 `TaskEnvelope {taskId,role,goal,allowedSources,allowedTools,inputArtifacts,outputSchema,evidenceRequired,maxSteps,maxCost,parentTrace}`。协调者只传最小材料：研究者不能写生产文件，实现者不能读敏感原对话，评审者不能调用写工具。输出是带出处的结构化产物，不是下一位的系统指令；协调者把它当不可信数据，验证 Schema、来源、版本、权限再合并。父状态维护总预算、并发、递归深度、去重键和最终责任人。

例如角色结论冲突时，评审比较证据等级并标注待人工裁决，不能由最后发言者覆盖。练习：实现带 DAG 的协调器，注入恶意交接文本、非法 Schema、递归超过两层、预算耗尽和冲突引用；提交最小权限清单、交接记录、聚合规则及敏感字段未广播的测试。

## AGENT-11

**跨组织信任补充。** 在信任目录中明确对端域名、issuer、签名键、允许 skill、最大 scope、数据分类、协议版本与任务时限。Card 只用于发现，认证后才暴露敏感能力；Artifact 传受权引用而非裸 URL，下载前再次检查当前授权。每一跳验证消息的 `taskId`、`contextId`、租户、顺序、回调地址、签名、受众、时间戳和重放标识，状态只能单向推进。

用报价协作验证：公开 Card 只列能力，OAuth 后的扩展 Card 才显示价格输入；用户补充信息创建新消息或 Task，不覆写旧终态。故障集中放入伪造域名、过期证书、重复 webhook、状态回退、取消后到达 Artifact 和租户交换 URL，全部应拒绝并留下隔离审计。Card 缓存过期或身份材料轮换时重新验证；失败时仅保留本地审计，不继续请求、下载或转交数据。

A2A 面向跨应用/组织的 Agent 协作：Agent Card 用于发现能力与接口，Task/Message/Artifact 表示任务生命周期和交付物；MCP 面向 Host 与工具/上下文的连接。远端自称能力不等于已获信任，发现、认证、授权和每次高风险执行均要独立验证。

例：客户 Agent 创建异步翻译 Task、订阅状态并取得可追溯 Artifact；反例是仅凭未签名 Card 授权跨租户数据访问。验证：实现 Card、创建/流式/取消任务和 Artifact，测试重复消息、乱序状态、回调重放、伪造 Card、版本/扩展不交集和逐跳授权。

A2A 链路为：Client 从受信域或目录读取 Agent Card，验证地址、协议、认证方案、签名/来源与缓存新鲜度；选择双方接口和扩展；带凭证发送 Message；即时结果返回 Message，需跟踪则返回 Task；Task 通过状态或 Artifact 更新流式/异步交付。`contextId` 关联对话，`taskId` 标识工作，Artifact 有独立 ID、部件、来源和访问控制。每一跳都重新认证授权，Card 文字不是授权。

例：采购 Agent 的公开 Card 只含技能，报价接口在 OAuth 后经扩展 Card 暴露；`input-required` 时用户确认数量，取消后 Task 终态且后续回调被拒绝。练习：实现 Card、Message/Task、状态流、取消和 Artifact 下载；制造伪造 Card、过期缓存、重复消息、状态倒退、回调重放、scope 不足和版本不交集，提交逐跳认证日志与状态机测试。

## AGENT-08

**定义与选择机制。** 工具契约是用于发现、选择和安全执行 Tool 的名称、描述、输入输出 Schema 与副作用声明。Tool 名称采用“动词+对象”，描述写明前置条件、禁止条件、影响、返回值与错误分类；每个版本维护有效、最小、无效和最大输入样例。Resource URI 先做 scheme 白名单、规范化、授权、根目录、字节数、页数和总耗时限制；Prompt 保存模板版本与参数来源。高风险 Tool 应提供 dry-run 或预览，并把真实执行绑定同一参数摘要和资源版本。

建立意图评测集，含相似名称、缺参、无需调用、恶意描述、陈旧缓存和旧 Client。修改描述或 Schema 后跑回归，统计副作用误调用率、拒绝正确率与越权率，而非只看命中率。若预览后资源改变，Server 返回冲突并要求重新读取；例如 `delete_invoice` 的旧预览不能在发票金额或归属改变后继续执行。测试通过的条件是这些负例均不误写、不泄露 URI，也不把 Resource 文本解释成系统指令。

工具可发现性来自准确动作名称、适用条件、输入输出 Schema 和明确副作用。复杂输入拆为可组合工具；字段描述含单位、格式、范围、枚举和互斥关系。2026 Tool Schema 使用 JSON Schema 2020-12：输入根为 object，输出与 `structuredContent` 可为受验证的 JSON 值；外部 `$ref` 不自动解引用，验证深度和时间设上限。

例：`findCustomer` 与 `updateCustomerEmail` 分离，后者有确认和幂等键；反例是 `doCustomerThing` 加数十个可选字段。验证：以 20 条含易混意图的固定集统计选错、漏调用、误调用和参数错误；再测 TTL、分页、取消、超大参数、路径穿越和旧客户端未知字段。

工具契约应说明调用时机、副作用和可验证输入输出。例如 `search_orders({query,maxResults<=50})` 是只读；`refund_order({orderId,amountCents,reason,idempotencyKey})` 必须声明资金影响、审批和不自动重试。Schema 使用枚举、范围、格式、互斥、`additionalProperties` 与 `$defs`；服务端执行前后都校验。外部 `$ref` 不自动解析，验证器限制深度、节点数与耗时，避免攻击者让请求取远程文档或耗尽资源。

Resource 是稳定 URI 的受权读取，Prompt 是版本化参数模板，不能藉 Tool 描述扩大权限。列表带 cursor、`ttlMs`、cache scope，调用可取消。练习：给十个易混接口重写契约，建立应调用/不应调用/参数拒绝集；故意加入隐藏副作用、外部 `$ref`、`../../secret` 和 20MB 参数，提交拒绝位置、错误信息与 20 条意图测试统计。

## AGENT-09

**可回放观测补充。** 每次运行建立 trace、span、runId、toolCallId 与业务 handle 的关联；事件按 `observed → planned → authorized → executed → verified → stopped` 记录时间、版本、延迟、重试和错误类别。日志不写原始密钥、完整提示或敏感 Resource，改存脱敏摘要与访问控制引用。告警区分模型选择错误、策略拒绝、外部超时和业务失败，不能把 HTTP 状态码混作结果。回放使用固定输入、策略和工具录制件并禁用真实写工具；注入跨租户 trace、重复 span、丢失结果和过期关联，断言可定位失败而不泄露数据或二次执行。

可观测性将一次执行中的目标、步骤、模型、工具、审批、错误、成本和结果以 trace/span、请求 ID、task ID 关联。日志保留离散上下文，指标观察聚合趋势，追踪连接执行链；三者都先脱敏并按权限、采样与保留期治理。MCP Logging 已弃用，新系统以 OpenTelemetry 或 stdio stderr 作为替代。

回放默认只读展示版本化输入、决策与已记录工具结果，绝不重放有副作用调用。验证：从一条用户请求追到失败 span，并从异常指标找到版本；确认 token、密钥、个人信息和原文件不被写入；在隔离环境用替身工具重跑评估。

一次运行用 `traceId` 串起 Host、Client、Server 与下游；每个 step/span 记录开始结束、模型和工具版本、参数摘要、结果分类、token/成本、审批和错误码。日志记录可搜索事实，指标汇总成功率/延迟/介入率，追踪显示因果链，三者不应无差别复制 Prompt 或文件。采集前按字段白名单脱敏，按用户权限、采样率、区域与留存期治理。

练习：让一次 `tools/call` 在下游超时，提交能从 UI 请求找到 span、再找到版本和错误分类的证据；再用替身工具作只读回放。制造 secret、身份证号、超长工具结果和错误 traceparent，证明它们被掩码、截断或拒绝；反例是调试模式写全量对话，或回放时再次执行退款。

## AGENT-10

**定义与授权机制。** Agent 运行隔离是把身份认证、令牌交换、逐工具授权和受限执行环境分层：Host 代表用户发起，Server 依据当前用户、租户、资源、scope 与策略版本在每次调用重新判定。令牌只在服务端安全存放，最小 scope、短有效期、受众绑定与撤销检查缺一不可。网络工具限制协议、DNS 重解析、私网地址和重定向以防 SSRF；文件工具规范化路径并限定根目录，不能把模型给出的 URL、文件名或 Resource 文本当作可信控制指令。验证伪造 issuer、过期/撤销令牌、跨租户 ID、环回地址、路径穿越与提示注入，全部拒绝且审计不含秘密。

Agent 安全覆盖身份、授权、输入、执行、输出和审计。OAuth/OIDC 验证 issuer、audience、scope、state/nonce 和 PKCE，不把上游 token 原样透传；Server 每次按用户、资源、动作重新授权。文件和 URL 先规范化再按允许根、协议、主机、解析地址、重定向和大小限制。

Tool 描述、Resource、Prompt、网页和结果均是不可信数据；模型看到的文本不是权限。例：删除工具需服务端重新校验所有者和路径，反例是浏览器传 `isAdmin` 或字符串前缀白名单。验证：覆盖 issuer/audience 混淆、SSRF/DNS 重绑定、路径/符号链接逃逸、注入、越权、重复副作用、撤销和紧急停止，并保存拒绝证据。

请求路径是身份认证、令牌验证、服务端策略、参数规范化、隔离执行、结果过滤和审计。OAuth/OIDC 校验 `iss`、`aud`、签名、过期、state、nonce、PKCE 和 scope；令牌仅给目标服务和短时用途，不能透传。文件先解析真实路径并限制授权根与符号链接；URL 限协议、主机、解析 IP、端口、重定向和字节数，阻断内网 SSRF 与 DNS 重绑定。密钥不进入 Prompt、浏览器包或普通日志。

练习：为 `readFile`、`fetchUrl`、`sendEmail` 写策略表和拒绝测试，输入 `../../secret`、localhost URL、重定向到内网、错误 audience、过期 token、恶意 Tool 描述和重复 key。提交策略命中日志、撤销后的拒绝证据、最小 sandbox 允许表与紧急停止测试；反例是模型说“管理员已批准”就直接执行。

## WEBAI-03

## WEBAI-11

回退结果也要可观测：UI 保存 `requestedBackend`、`actualBackend`、模型哈希、输入形状、开始/结束时间和 reasonCode；只有数值校验通过才缓存输出。用户可在设置中关闭云端回退，此时不支持的算子应返回可理解错误而非秘密上传数据。发布前以固定金样本比对版本升级前后的分类与错误路径。

**定义与推理机制。** WebNN 是用 operand、常量和算子图表达神经网络计算、再交给浏览器选择可用后端执行的 Web API，不等于“有 GPU 就一定更快”。应用先用 feature detection 创建 context，再按可用后端建立 graph，把模型的输入形状、数据类型、算子集合和版本写入能力快照。选择顺序应由产品政策决定，例如优先 WebNN，失败后退 WebGPU/Wasm，最后给出云端或关闭功能的明确选择；不要依据 UA 字符串猜测。编译图与权重缓存按模型哈希、设备能力和后端隔离，设备丢失、编译失败或形状变化时释放旧资源并重新协商。

举例：图像分类的预处理产生 `float32[1,224,224,3]`，构图阶段声明 `conv2d → relu → softmax`，执行前验证输入字节数和输出类别数。故意把不支持的量化算子、动态形状、错误布局和失效设备放入矩阵，预期不静默给出旧结果，而是记录后端、失败码和实际回退。验收在至少两种后端上比较固定样本的 top-k、一致性阈值、首次编译时间、推理延迟、内存峰值和取消时延；无障碍 UI 同时解释当前是否本地执行、数据是否离开设备以及可用的人工替代路径。

例：同一统一运行时先尝试 WebNN，再选 WebGPU/Wasm/云端；反例是教授已移除的 NPU/GPU/CPU 枚举或把成功创建 context 当成算子可执行。验证：为每个后端测模型图支持、数值误差、首次/稳态延迟、内存和降级，测试不支持算子、设备偏好无效、图缓存失效和输入布局错配。

## WEBAI-04

消息协议应只传可克隆数据和版本化 Schema，Worker 对每一条消息校验来源、大小和 job 状态；收到未知 job 或取消后的结果直接丢弃。主线程以测试桩重复投递 progress/complete 事件，确认 UI 不倒退、不重复完成，也不会因一个坏任务阻塞其余队列。

**任务池与所有权实战。** 主线程只负责交互、状态渲染和可访问提示；模型、Wasm 实例、OffscreenCanvas 与大数组由一个明确 owner Worker 持有，避免每个组件复制权重。主线程发送带 `jobId`、输入版本、优先级、截止时间和取消信号的消息，Worker 以有限并发队列执行并回传递增进度；队列达到上限时合并同类预览、丢弃可重算任务或显示“稍后重试”，而不是无限堆积。transferable 的 ArrayBuffer 转移后主线程不能继续读取，SharedArrayBuffer 仅在满足隔离条件时使用。

实现一个缩略图标注队列：输入文件经校验后把像素缓冲转给 Worker，结果以 `jobId + inputVersion` 回来，过期版本直接丢弃。模拟 Worker 崩溃、页面隐藏、连续输入、慢设备和取消竞争；崩溃时清空不可恢复队列、重建 worker 并只恢复可幂等任务，绝不把旧结果覆盖新输入。验收采集队列长度、复制字节、取消时延、崩溃恢复数和 INP；以键盘操作、读屏状态和主线程长任务阈值验证本地 AI 没有让交互或无障碍退化。

AI 任务池把预处理、embedding、推理和后处理移出主线程；消息携带版本、task id、所有权、优先级、进度和取消。大张量优先 Transferable，转移后发送方不可再用；队列设并发、批处理与背压，Worker 崩溃须使任务进入确定终态或重试。

例：交互查询优先于索引重建，队列满时合并或拒绝低优先任务；反例是无限创建 Worker、重复 clone 模型或组件卸载后继续更新 UI。验证：测 INP、复制字节、峰值内存、吞吐；注入 detached buffer、乱序、双所有者、取消、崩溃和低端设备，确保重启/降级可用。

## WEBAI-05

制品清理采用 LRU 前先排除 active、正在下载和被运行引用的版本；删除操作在下一次启动重新核对清单。任何来源 URL、哈希或版本不匹配都让下载进入隔离状态，用户只能查看诊断或删除，不能手动“强制激活”。

**模型制品状态机实战。** 将模型下载拆为 manifest 校验、分片写入、哈希核验、原子激活、运行引用和回滚六步。manifest 包含模型版本、分片大小、哈希、总大小、最小运行时和签名/来源；分片写入临时命名空间，全部校验后才将 active 指针切到新版本。配额不足、断网或单片损坏时保留上一个可用版本并删除不完整临时数据，不能把半个模型标记为可用。读取侧取得版本快照，更新不得影响正在执行的推理。

测试造出错误哈希、重复分片、超过配额、两标签页并发下载、激活中关闭页面与旧版本仍被引用。预期是同一版本只下载一次，第二标签页订阅进度或复用结果；损坏制品不可激活，激活失败回滚且不丢失旧模型。记录存储估算、已用空间、下载来源、模型哈希、激活时间和清理原因；提供“清除本地模型”并在删除前说明离线能力会消失。用断点续传与刷新恢复证明状态来自持久清单而不是内存标志。

模型制品下载是“清单/来源信任—临时分片—摘要校验—原子激活—旧版回滚”的状态机。Cache API、IndexedDB、OPFS 各有用途，均可能受配额或驱逐；摘要证明完整性，签名或受信清单才证明来源。激活前必须验证版本、大小、哈希、兼容性和分词器/配置组合。

例：下载写入 OPFS 临时名，全部校验后更新当前指针；反例是 HTTP 200 后直接覆盖当前模型，或清空全部存储来“解决”迁移。验证：模拟 Range 错位、断点、损坏、空间不足、驱逐、双标签竞争、半激活、旧 Service Worker 和回滚不兼容；用户可见大小、网络、版本与删除入口。

## WEBAI-06

索引更新以批次号提交：新批次完整写入并通过抽样查询后才成为 current，失败批次保留诊断但不参与检索。向量距离只是排序信号，不是事实证明；回答层必须要求模型引用返回的 documentId，并把无足够命中的问题导向澄清或人工搜索。

**本地向量索引实战。** 文档入库先规范化文本、记录来源与许可、分段并生成 embedding；每条记录写入 `documentId`、chunkId、模型/维度版本、向量、文本摘要、时间戳和删除标志。索引与 embedding 必须同版本：模型或维度变化时建立新命名空间、双读验证后切换，不能把不同维度直接混检。查询先对问题使用相同模型编码，再做 top-k、阈值和可选重排，并返回引用而不是把检索片段当可信指令。敏感文档按用户/租户分库或查询过滤，删除请求同时清除原文、向量和派生缓存。

用一千篇文档和二十个带标准答案的查询评估召回、精确率、延迟、索引体积和冷启动时间；再注入重复导入、模型升级中断、相同文本跨租户、过期删除与恶意文档中的“忽略前文”文字。验收要求重复导入不倍增、升级可回滚、跨租户零命中、删除后不可检索，且界面能展示命中来源、分数与“本地索引可能过期”的提示。IndexedDB 事务提交前不得报告成功，失败后由可重放队列恢复。

本地语义搜索把文档经固定模型/预处理版本变为向量，归一化后以相似度检索 top-k，并保存文档、向量、索引和模型版本的关联。IndexedDB 持久化必须处理事务、升级、删除与配额；模型或分词变更后旧向量不可静默混用。

例：Worker 分批生成 1000 条向量，增量更新只重算变化文档；反例是 UI 线程做全量编码或按“看起来相关”验收。验证：固定至少 20 条有标注查询，报告 recall@k/MRR 或明确的任务指标、首载和更新时间，覆盖删除传播、模型变更、索引损坏、取消、离线和隐私边界。

## WEBAI-07

权限状态在每次新任务重新读取；曾允许不等于持续允许。设备标签、地理信息和人脸等元数据默认不进入模型输入，确有用途时单独征得同意并设置短期删除。用浏览器自动化检查拒绝权限后仍可浏览、重新授权后不复用旧媒体、关闭页签后摄像头指示灯熄灭。

**媒体 AI 隐私链路实战。** 摄像头、麦克风和文件选择都必须在用户手势后请求，并在采集前说明用途、保留时长、是否上传和可撤销方式。媒体先在本地缩放、裁剪或抽帧，按任务最小化传入模型；对象 URL、VideoFrame、AudioData、轨道和 Worker 缓冲在完成、取消、页面隐藏与错误时显式关闭或 revoke，避免内存与设备占用泄漏。上传不是本地推理的默认回退：网络、同意、数据分类和服务端授权都满足才允许，失败时保留本地草稿或给人工流程。

实现“照片描述”流程：检查 MIME、尺寸和方向，生成缩略图后给模型，结果附带输入版本和置信度；原始照片不得写入日志。故障集含权限拒绝、设备拔出、超长视频、伪造 MIME、处理期间切换文件、网络从在线变离线和取消后迟到结果。断言旧结果不能覆盖新文件，取消后不再上传或保留媒体句柄，云端请求只含已同意的最小数据。验收同时测量首帧到结果、峰值内存、释放计数、权限提示可访问性和离线降级文案。

多模态 AI 输入的生命周期是用户意图与授权—采集/选择—格式/尺寸/时长限制—抽帧/分段/降采样—预览确认—本地推理或明确上传—结果与删除。MediaDevices/文件输入都可能包含敏感内容和元数据；本地处理不等于不会被日志、缓存、第三方脚本或用户选择错误泄露。

WebCodecs 用于帧级处理，不负责容器/播放；帧、轨道、对象 URL 要在成功、错误、取消和卸载时 `close()`/stop/revoke。例：视频只抽样低分辨率帧后请求上传确认；反例是默认上传原片或无限向 decode queue 投帧。验证：权限拒绝、设备切换、格式不支持、后台限流、队列增长、重复上传、元数据残留和低端降级均有用例。

## WEBAI-08

端云路由按任务质量、输入敏感度、用户同意、能力、模型状态、预期延迟、网络、成本和功耗代理作可解释决策；Network Information API 只是提示，不能当网络可用或带宽保证。所有后端使用统一输入/输出、错误、取消和版本契约，避免回退改变业务语义。

例：敏感短文本优先本地；本地模型不可用时征得同意才发云端，否则给非 AI 路径。反例是仅按 `effectiveType` 自动上传敏感数据，或“本地失败”静默换成不同模型输出。验证：写决策表及理由码，注入错误能力探测、弱网/断网、权限变化、超时、云端配额、模型不匹配和回退，比较结果与隐私承诺。

## WEBAI-09

离线 AI 作业由可离线应用壳、版本化本地数据、任务队列和结果 outbox 组成。每项有稳定 ID、输入快照/版本、状态、幂等键、重试策略和冲突规则；联网后后台同步只是优化，必须有用户可见的手动恢复。模型缺失或过期时可只读、轻量模型或排队，不能伪造已完成。

例：离线笔记摘要先保存请求，联网后按幂等键上传，服务端返回冲突供选择；反例是覆盖云端新版本、把未发送当成功或依赖唯一的 Background Sync。验证：离线创建、刷新、重复投递、同步中断、模型变更、冲突、浏览器不支持/拒绝后台同步和用户删除都可复现。

## WEBAI-10

建立发布门槛表，将设备档位、模型版本、浏览器能力、网络条件和每项预算写成机器可读基线；采样异常要保留而非只上报聚合值。发生降级时结果旁显示可展开诊断，内容包括未满足的能力或预算、已采取的回退和重试入口，避免把性能问题伪装成模型“无回答”。

**本地 AI 体验预算实战。** 为设备档位设定首个可交互、INP、长任务、峰值内存、耗电/温升代理和推理延迟预算；能力探测、模型下载、编译与推理分别埋点，不能用平均值掩盖弱设备。调度器在输入、滚动、读屏焦点或低电量时让出主线程，批处理以可取消小片执行；若连续超预算，自动降低分辨率、缩短上下文、改用小模型或停止本地功能，并把实际原因告诉用户。结果区域用语义状态和实时区域播报，不以闪烁动画代替进度。

以快、中、慢三档设备跑同一图像和文本任务，记录 p50/p95 延迟、INP、长任务数、内存、下载量、取消时延和回退原因；再注入 reduced-motion、键盘仅操作、读屏、断网、低存储和模型编译失败。验收要求焦点不跳失、取消可达、错误可理解、人工替代路径始终存在，且“本地处理”声明只在确未上传时出现。性能回归超过阈值即阻断发布，并保存可复现的输入、设备档位和版本快照。

本地 AI 性能不止一次“跑通”：分别记录下载、预热、首 token/首结果、稳态 tokens/s、端到端延迟、峰值内存、长任务、功耗代理和失败率，区分冷启动与稳态。能耗代理不是精确碳排，需说明设备、任务和测量边界。交互中支持暂停、取消、降级和明确进度。

无障碍方面，流式状态按语义节流给读屏器，键盘可暂停/取消，动画尊重 `prefers-reduced-motion`，不能把连续 token 刷新强行播报。验证：在三档真实设备、前后台和高负载下复测；报告预算、P50/P95、内存、可访问检查和回退，低端结果不达标时降低模型或交给人工路径。

## WEBAGENT-01

WebMCP 是已打开网页给浏览器 Agent 的结构化页面工具提案，不等于远程 MCP Server 或 MCP App。Chrome 149 的 Origin Trial 提供命令式 JavaScript 和声明式 HTML 表单 API；工具声明名称、描述、JSON Schema 和页面状态，调用在可见标签页进行，不能无头运行。它是渐进增强，非支持浏览器仍需语义 HTML 和人工流程。

工具只在适用页面状态注册，失效即撤销；副作用要幂等、可取消，并在页面显示真实影响和高风险确认。受源隔离与 `tools` Permissions Policy 限制，跨源 iframe 需显式 `allow="tools"`，但仍不绕过业务鉴权、CSRF 或反欺诈。验证：实现搜索与结算两类工具，测试陈旧状态、重复购买、隐藏副作用、描述注入、跨源越权、页面关闭和 API 不可用；确认人工、键盘和读屏路径未退化。
