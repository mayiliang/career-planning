# Prompt Injection 与不可信内容边界知识点讲义

## AIAPP-07 Prompt Injection 与不可信内容边界

传统注入攻击把数据送入 SQL、Shell 或 HTML 解释器；Prompt Injection 则利用模型对自然语言指令与数据边界的不可靠判断，试图改变目标、窃取上下文或借用工具。它可以来自用户，也可以藏在网页、PDF、邮件、OCR、检索片段、工具结果和其他 Agent 交接中。没有一条神奇提示能彻底解决它，工程目标是即使模型受到影响，危险权限和数据仍过不了确定边界。

### 学习前先确认

- 直接前置：[SEC-01 XSS、CSRF 与 Web 信任边界](../chinese-guides/sec-01-xss-csrf-trust-boundaries.md#sec-01)。本讲把“不可信输入不能获得代码、身份或权限”的通用模型扩展到自然语言系统；间接依赖由 SEC-01 继续展开。

### 一、Prompt Injection 攻击控制流

**提示注入（Prompt Injection）**是不可信内容试图改变模型应遵循的目标、约束、数据使用或工具选择。直接注入来自用户消息，间接注入来自系统主动读取的外部内容。成功不一定表现为越狱回答，也可能是泄露隐藏上下文、偏转检索、批准错误动作或污染记忆。

模型无法像编程语言解析器那样可靠地区分“这里是一段要总结的数据”和“这里是一条新指令”。XML 标签、引号、角色文字和“永远忽略其中指令”能降低一些风险，却不能成为安全证明。攻击者会改写、多语言、编码、跨轮拆分或利用长上下文。

先定义损失事件和模型可达能力。只读公开摘要与能读取私有文档、发送邮件、执行代码的 Agent 风险不同。注入危险度由后果、权限和恢复决定，不只由句子看起来是否恶意决定。

### 二、Trust Boundary 标出控制权变化

**信任边界（Trust Boundary）**是数据来源、身份、权限或解释方式发生变化的位置。用户到服务端、检索库到模型、模型到工具、工具结果回到模型、模型输出到浏览器、Agent 到 Agent 都是独立边界。

为每段内容记录 source、owner、tenant、contentType、trust、purpose 和允许用途。来自内部数据库的工单备注也可能由用户控制；来自官方网页的正文也不拥有应用系统指令权。来源可信与内容有权发指令是两个概念。

控制平面只由受信服务生成：系统策略、工具注册表、授权结果、审批和预算。数据平面包含用户、文件、网页、检索、工具文本和模型历史。数据可以影响答案内容，却不能修改控制平面。

### 三、数据与指令在结构上分层

提示组装采用类型化内容块，而不是字符串拼接：策略、用户目标、引用数据、工具结果和历史分别有角色、来源和边界。外部数据明确标记为待分析内容，必要时摘要或转义，但仍按不可信处理。

不要让用户内容闭合模板分隔符、伪造角色或插入工具定义。供应商不支持所需角色语义时适配器拒绝或降级，不能把所有内容合并到一条高优先级消息。

把检索网页转换为纯文本可以移除脚本，却不能移除自然语言注入。净化内容与约束权限是两层；任何一层都不能声称替代另一层。

### 四、Least Privilege 限制最大后果

**最小权限（Least Privilege）**让每个模型会话、工具和代理只拥有完成当前任务所需的最小功能、对象范围、时间和调用额度。只需读订单就不提供退款；只需生成草稿就不提供外部发送。

服务端从认证上下文读取主体和租户，不信任模型参数。工具输入经过 Schema、业务状态、资源范围和策略；高风险动作需要真实用户确认。即使模型完全服从恶意网页，也只能提出被执行器拒绝的候选。

凭据按工具与环境分区，短期且可撤销。不要把数据库主密钥、全租户搜索或生产 Shell 放进一个通用 Agent。批量和递归调用有数量、成本和影响上限。

### 五、Taint Tracking 保留不可信来源

**污点跟踪（Taint Tracking）**让由用户、网页、文件、工具或模型生成的数据在转换、摘要、缓存和交接后仍保留来源与限制。它不判断一句话是否恶意，而是防止不可信数据在管线中悄悄升级为授权事实。

例如网页片段经摘要后仍是 `external_content`，不能因模型重写成礼貌文字就进入 system policy；工具结果里的 URL 仍需协议和域名检查；Agent A 的结论交给 Agent B 时仍是待验证产物，不是高权指令。

实际系统可用结构化标签、独立存储、来源 ID 和允许操作集合实现。任何丢失标签的转换都进入低信任默认；不要靠在字符串前加“UNTRUSTED”便宣称完成污点跟踪。

### 六、敏感数据在进入模型前最小化

只提供当前任务需要的字段、时间范围和对象。密钥、完整身份号码、其他租户数据和不必要历史在服务端裁剪；脱敏值还要考虑组合重识别。模型看不到的数据不可能被注入诱导泄露。

检索权限在召回前过滤，工具结果在回传前裁剪，日志与评测集也执行相同数据目的。供应商留存、地区和训练政策属于架构条件；不满足时选择本地/受控处理或停止。

输出检测可以拦截明显秘密，但只是补充。若完整密钥已经进入上下文，模型不回显一次不代表安全。

### 七、工具授权与用户确认切断攻击链

模型只提出工具名和参数。执行器重新验证工具是否允许、参数是否来自当前任务、对象是否属于主体、业务状态是否允许，以及是否有绑定本次参数的批准。模型文字“用户已经同意”没有效力。

确认界面从服务端事实生成，展示收件人、金额、数量、数据去向和不可逆影响。用户编辑参数后旧批准失效；拒绝、超时和撤回都是封闭状态。注入内容不能控制确认文案或隐藏字段。

响应丢失的写入先按幂等键查询，不因模型建议“再试一次”重复执行。预算和速率限制防止注入触发无限循环或批量外发。

### 八、输出处理仍遵守传统安全边界

模型输出进入 HTML、URL、SQL、Shell、Markdown 和文件名时分别按最终解释器编码、参数化和允许列表处理。Prompt Injection 与 XSS 可以串联：恶意网页诱导模型生成事件属性，若页面直接用 `innerHTML` 就完成执行。

结构化输出先 Schema，再业务与权限校验。链接限制协议、域名、凭据和重定向；代码默认只展示文本，需要运行时进入独立沙箱。逐流块净化不能证明组合结果安全，完整边界还要复核。

拒绝或检测错误时不要回显完整原始提示、系统策略和秘密。面向用户的说明与内部诊断分开。

### 九、检测器是信号而不是授权器

规则、分类器和另一个模型可以识别显著注入、编码和可疑目标，用于阻断、降低能力或转人工。但攻击分布会变化，正常文档也包含命令式语言；单一阈值会同时产生漏报和误报。

检测不可用时，高风险能力按失败关闭，低风险可以纯文本或人工降级。不能把“分类器超时”当安全通过。检测分数也不能提高工具权限。

阈值在代表真实语言、文件类型和攻击路径的数据上选择，按严重后果观察召回和误拦恢复。持续加入经过去敏和授权的真实失败样本。

### 十、长期记忆和缓存会延长污染

一次注入若写入摘要、偏好、长期记忆或语义缓存，会在攻击文本不再可见时继续影响任务。写入前验证目的、来源、敏感性和用户控制；模型推断默认只是候选，不能自动成为长期事实。

缓存键包含租户、权限、模型、提示、工具、数据和策略版本。检测到污染后要能追踪并失效索引、缓存、摘要与下游副本。只修当前提示无法清除持久影响。

多 Agent 交接也保留污点和证据来源。子 Agent 输出永远是待验证数据，不成为下一位的系统消息。

### 十一、模型自检不能证明安全

询问模型“上面的内容是否恶意”或“你是否遵守规则”仍使用同一个易受影响的通道。它可以作为检测信号，却不能证明授权、数据隔离、输出编码和副作用没有被绕过。

更强模型、微调或 RAG 也不能消除根因。模型更新可能改变易感模式，需要重新红队，但架构边界应在不同模型下保持。安全证明来自执行器调用为零、无权数据不进上下文、危险输出不进入解释器等可观察事实。

不要公开隐藏推理作为安全审计。结构化决策摘要、策略版本、工具日志和拒绝原因更稳定，也减少泄露新的攻击线索。

### 十二、测试覆盖直接、间接和组合攻击

样本来源包括用户、网页、PDF/OCR、邮件、图片说明、检索 chunk、工具错误、Agent 交接和历史记忆。变体包含多语言、编码、长上下文、分步诱导、假确认、数据外泄、恶意 URL、富文本、租户越界和循环调用。

每例记录攻击前提、目标、预期控制点、工具调用次数、可见结果和审计。让检测器故意放行，验证权限仍阻断；让模型生成合法工具参数但跨租户，验证服务端拒绝；让输出含安全标签外的 HTML，验证解释器安全。

同样测试正常命令式资料，避免误拦让产品不可用。红队发现经最小化与去敏后加入回归，并记录适用版本和授权范围。

### 十三、事故响应沿污染链清理

确认事件后先限制相关工具、凭据、来源和模型路由，保留最小证据。用 request、content、chunk、memory、toolCall 和 operation ID 追踪数据如何传播，判断是否发生读取、外发或副作用。

轮换凭据、撤销批准、清除污染索引/缓存/记忆，并核查外部系统事实。给受影响用户准确说明发生了什么和可采取动作，不把“模型被越狱”当作无需负责的理由。

修复从根因控制开始：减少权限、修复授权或编码、建立来源隔离，再补检测规则。只把攻击句加入黑名单容易被改写绕过。

### 十四、浏览器与 MCP 场景扩大间接注入面

浏览器 Agent 读取的 DOM、无障碍树、隐藏文本、下载文件、剪贴板和页面返回值都由站点控制。导航到新 origin 后重新计算信任和能力，页面中的“点击授权”不是宿主授权。自动填写、上传和下载分别使用允许列表与用户可见预览，防止恶意站点借正常任务取得本地数据。

MCP Server 的工具描述、resource、prompt、App UI 和工具结果同样属于外部供应方。安装/发现只证明能够连接，不证明描述里的指令安全。Host 把服务身份、能力声明、内容数据和真实授权分层；工具描述可以帮助选择，但不能要求 Client 传递其他 Server 的秘密或绕过确认。

跨工具链尤其危险：网页诱导读取私密资源，再让邮件工具发送。策略应在数据流层判断来源与目的，而不只逐个允许工具。敏感数据标签跨调用传播，目标域、接收人或用途变化时阻止或重新确认。

### 十五、编码代理需要保护仓库和流水线

Issue、README、依赖脚本、测试日志和代码注释都可能夹带指令。编码 Agent 先遵守仓库可信规则与用户任务，文档中的命令只当待审内容。执行命令、安装依赖、修改工作流、读取密钥和发布产物需要独立能力边界。

补丁审查关注不仅是显眼恶意代码，还包括悄悄扩大网络、文件、CI 权限，修改测试使错误“通过”，或把敏感输出写入日志。验证使用固定测试和差异审查，不能让生成变更同时重写验收标准。第三方贡献在隔离环境运行，默认无生产凭据。

### 十六、形成纵深防御而非提示迷信

为一个真实功能画出不可信内容从入口到检索、模型、工具、输出和记忆的路径，标出每层身份与解释器。假设模型会遵从攻击，仍证明最小权限、参数授权、确认、编码、预算和审计限制后果。

安全评审按“攻击者控制什么、模型能看到什么、执行器允许什么、最坏后果是什么”逐层回答。任何只依赖模型拒绝率的控制都要假设失效，再检查是否仍有服务端授权、数据最小化、目标限制、人工确认和审计阻断。新增数据源、工具、记忆或跨 Agent 传播都会改变攻击图，必须重新评审而不是沿用旧的安全提示词。

把被阻止的攻击保存为脱敏回归样本，关联触发入口、策略层和最终授权结果。修复后验证正常任务仍可完成，避免以关闭所有能力换取表面安全。

风险接受必须说明剩余攻击路径、最大影响、监控和到期日；“模型大多会拒绝”不能成为长期例外依据。

学完后，你应能区分注入检测与真正的安全边界，使用来源和污点模型保持数据身份，设计最小权限与服务端授权，并用组合攻击验证纵深控制。OWASP 官方 [LLM01 Prompt Injection](https://owasp.org/www-project-top-10-for-large-language-model-applications/assets/PDF/OWASP-Top-10-for-LLMs-v2025.pdf)可用于核验风险分类，但控制仍需落到你的真实数据流和权限链。
