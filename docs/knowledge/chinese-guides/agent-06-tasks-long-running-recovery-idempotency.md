# Agent 长任务、恢复、幂等与取消知识点讲义

## AGENT-06 长运行任务、Task 句柄、恢复与可观测进度

超过一次请求生命周期的任务，不能靠保持浏览器标签页、SSE 连接或进程内 Promise 来维持。网络会断，进程会重启，用户会离开，任务仍可能在外部系统继续。可靠长任务把目标、步骤、幂等、进度、结果和取消持久化为显式对象，使任意实例都能恢复，也使用户看到的状态与真实执行一致。MCP 2026-07-28 的 Tasks 扩展提供了相关协议方向，但业务正确性仍由应用负责。

### 学习前先确认

- 直接前置：[AGENT-01 Agent 循环、规划、停止与恢复](../chinese-guides/agent-01-loop-planning-stopping-recovery.md#agent-01)，用于理解状态机与检查点；[AGENT-04 MCP Client 发现、能力与兼容](../chinese-guides/agent-04-mcp-client-discovery-compatibility.md#agent-04)，用于理解任务能力发现、版本和授权。间接前置不重复列出。

### 一、Long-Running Task 是持久业务对象

**长运行任务（Long-Running Task）**是无法可靠地在单个同步请求内完成、需要跨连接或进程继续推进的工作对象。它包含主体、目标、输入快照、状态、版本、预算、策略、步骤、结果引用、到期和审计。

长不只指耗时几小时。需要人工审批、等待外部 webhook、排队资源或可恢复上传的任务，即使计算很短，也应采用长任务模型。反之，一次几秒的纯计算若可安全重做，不必引入复杂工作流。

HTTP 202 或“后台处理中”只是响应，不是模型。任务必须有可查询终态、失败原因和资源所有权。

### 二、Task Handle 让连接与任务解耦

**任务句柄（Task Handle）**是服务端签发的不可猜引用，客户端用它查询、订阅、继续输入、取消或取得结果。句柄绑定主体、租户、任务类型与范围，每次使用重新授权。

创建响应返回 taskId/URI、初始状态、版本、建议轮询时间和可用操作。不要把数据库序号直接暴露，不能让句柄本身成为永久 bearer 权限。公开分享应创建独立、限权引用。

句柄在多实例、重启与部署后仍能解析。路由依赖持久数据库或分区规则，不要求同一连接回到同一进程。

### 三、状态机区分等待、运行和未知

状态至少表达 queued、running、input_required、approval_required、waiting_external、succeeded、failed、cancel_requested、cancelled 和 expired。终态不可被迟到 worker 改回运行。迁移以数据库条件更新或事务保证。

unknown 通常是调用某个外部副作用的结果未知，不应作为整个任务随意终态。任务进入 reconciling，先对账该步骤。blocked 表示需要外部改变，需给原因和唤醒条件，不能与失败混合。

状态字段外保存 reasonCode、可恢复性和用户行动。自然语言消息可本地化，但程序逻辑依据稳定代码。

### 四、队列交付通常是至少一次

多数队列可能重复交付，worker 崩溃后消息会重新可见。因此处理器必须假设同一步会执行多次。消息包含 taskId、stepId、expectedVersion 和 attempt，不把完整敏感上下文复制到队列。

worker 先声明租约或原子迁移，读取当前状态，再执行。重复消息发现步骤已完成就确认，不重做。租约有心跳和过期；长外部调用不能仅靠进程锁。

消息丢失可由 outbox、扫描器或调度器修复。数据库提交任务状态与发布下一事件若非原子，需要事务 outbox 防止“状态更新但没有消息”。

### 五、Idempotency Key 绑定逻辑动作

**幂等键（Idempotency Key）**是同一逻辑副作用在重试、重复消息和恢复中复用的稳定标识。它的作用域包含租户、工具、业务动作和任务步骤；相同 key 不同参数必须拒绝。

在调用外部系统前持久记录 intent 与参数哈希，调用后保存回执。超时先用 key 或业务标识查询，不立即再发。若外部系统不支持幂等，使用本地唯一约束、预留/提交协议或转人工，但不能承诺恰好一次。

用户点击“再执行一次”是新逻辑动作，生成新 key；页面重复提交同一次创建则复用。key 生命周期覆盖最迟重试和消息积压。

### 六、进度来自完成事实

百分比只有在工作量可测时才有意义，例如 100 个文件已验证 37 个。开放式推理不能用 token 数伪造 73%。改用阶段、已完成项、当前等待、可核验证据和最后更新时间。

进度事件带 taskVersion/sequence，客户端去重和补缺；断线后先取快照，再订阅新事件。SSE/WebSocket 是通知通道，数据库状态是事实来源。进度写入限频，避免自身压垮存储。

总量变化时说明基准变化，不让百分比倒退得毫无解释。并行子任务按实际权重聚合，不能简单平均。

### 七、Checkpoint Recovery 按步骤对账

检查点恢复（Checkpoint Recovery）从最近持久安全边界加载任务目标、已完成步骤、在途意图、外部回执、预算和下一状态，再逐项确认而非从头重跑。恢复逻辑与正常逻辑共享同一状态迁移规则。

worker 崩溃在“外部成功、数据库未记录”之间是最危险窗口。重启后查询外部幂等记录或资源状态，确认成功再补写本地；无法确认则 unknown/reconciling，不能重复。

部署升级后检查 workflowVersion。兼容迁移保留旧步骤语义；无法安全转换的任务暂停并给用户选择，不使用新默认值继续。

### 八、轮询、推送与 webhook 各有边界

Client 轮询简单可靠，应尊重 `Retry-After`、状态变化频率和退避。事件流降低延迟但会断线，需要水位线。外部 webhook 需签名、时间窗、防重放和事件 ID 去重，收到回调不直接信任业务完成，可再向源系统查询。

推送失败不改变任务状态。多个标签页订阅同一任务，各自恢复，不触发额外执行。服务端限制订阅数和事件保留，过旧游标返回完整快照。

不要用每秒轮询掩盖缺少唤醒机制；waiting_external 可由调度器或 webhook 激活。

### 九、Cooperative Cancellation 诚实报告边界

**协作式取消（Cooperative Cancellation）**是任务收到取消请求后停止安排新步骤、向可取消的在途操作传播信号，并在安全点收敛到 cancelled 或已完成，而不是假设能瞬间回滚一切。

cancel_requested 与 cancelled 分开。已经发送的邮件、支付或发布可能完成；最终结果列出完成、未开始、取消成功、未知和需补偿项。重复取消幂等，完成任务不能被改写成取消。

取消需要授权和版本检查。管理员强制停止、用户取消和系统超时具有不同原因与后续清理策略。

### 十、输入与审批可暂停任务

任务需要用户输入时保存表单 Schema、原因、当前提议、有效期和 continuation token。进程释放资源，状态持久等待。输入提交校验 taskVersion 与权限，过期后重新观察。

approval_required 还要绑定不可变动作快照和审批范围。Task 扩展提供承载方式，不替代 Host 的可信确认与服务端执行校验。

用户不回应时按策略提醒、过期或取消，不无限占用额度。敏感凭据使用专门认证通道。

### 十一、公平、配额与背压

调度按租户、任务类型、优先级和资源池限制并发，防止一个大任务饿死交互请求。优先级有上限和老化，不能由模型任意设置“最高”。

创建前预估并保留预算，执行中记账；额度不足进入可解释状态。队列积压时拒绝或延后新任务，不接受后再永远排队。下游限流时全局协调退避，避免每个 worker 独立重试形成风暴。

大结果存对象存储并使用短期授权引用，不塞入队列或任务行。设置留存与清理。

### 十二、可观测性跨越任务寿命

记录 task、run/step、workflowVersion、状态迁移、queue message、worker attempt、外部 operation、幂等 key、checkpoint、进度和结果。trace 跨数小时需要稳定关联，采样不能丢失错误与终态。

指标包括排队时长、执行时长、等待用户、重复消息、租约过期、恢复成功、未知结果、取消延迟、积压年龄、任务过期和每租户公平性。成功响应 202 不计任务成功。

提供用户可见时间线和运维诊断，但正文、凭据与第三方数据按权限最小化。

### 十三、故障注入验证恢复

在创建后、外部调用前、外部成功后、本地提交前、发布下一消息前和终态通知前分别杀死 worker。重复投递、乱序事件、租约竞争、数据库短暂失败、队列延迟、webhook 重放和版本升级都要覆盖。

断言每个副作用最多一个业务结果、状态单向收敛、进度可恢复、取消不虚报、过期输入不执行。两个 worker 竞争同一步时只有一个获得合法迁移。

浏览器刷新与断网后用户仍能看到同一 task，而不是创建新任务。真实外部写操作用沙箱或模拟器验证。

### 十四、任务结果需要提交、发布和过期语义

计算完成不一定等于用户可见完成。任务可能先产生候选制品，经过病毒扫描、Schema、质量或人工审核后才发布。区分 processing、validating、ready、published；只有产品定义的终态才显示完成。结果引用带内容哈希、版本、MIME、大小和权限。

下载链接短期有效，但任务记录可重新签发给有权用户。结果过期后任务保留最小元数据和清理状态，UI 提示重新生成的成本与条件。删除任务不应误删被其他对象引用的共享制品，引用计数或所有权由服务端管理。

部分结果需合同化：哪些分片成功、哪些失败、能否使用、是否允许补跑。不要把一个 ZIP 存在当全部文件正确，发布前以 manifest 和校验结果验收。

### 十五、定时、周期与依赖任务形成任务图

定时任务记录计划时区、下一触发、错过执行策略和去重窗口。应用重启后不能把所有错过时刻无限补跑；按业务选择跳过、合并或补一次。夏令时和用户时区变化显式处理。

任务依赖图只有前置到达允许终态才激活后继；失败、取消和过期按边策略传播。循环依赖在创建时拒绝。并行子任务使用独立幂等键和产物，父任务聚合前验证版本；一个子任务重试不重做兄弟节点。

周期任务每次运行有独立 runId，共享 scheduleId。暂停计划阻止未来 run，不伪装取消已运行任务。修改计划创建版本，旧触发消息到达时因版本不匹配被忽略。

### 十六、数据库清理也必须可恢复

长任务会积累事件、进度、日志和制品。按合规与用户需求分层保留：终态摘要较久，细粒度事件较短，敏感正文最少。归档与删除本身是幂等后台任务，记录水位线和失败重试。

清理不能删除未完成任务的幂等记录，否则迟到重复消息会再次执行；去重窗口结束前保留必要参数哈希与终态。备份恢复重放删除与取消标记，防止旧任务重新入队。容量告警在影响队列前触发。

### 十七、用显式任务替代长连接幻想

先实现持久 Task、严格状态机、查询与幂等，再增加队列、事件流、用户输入、取消和跨版本恢复。每一步都能在没有原连接和原进程时继续，是可靠性的基线。

任务发布门禁应展示状态迁移表、数据库约束、队列重复测试、每个副作用的对账方法、跨版本恢复、取消传播、结果权限和清理策略。在创建、执行、回执和终态提交之间逐点制造崩溃，确认只有一个业务结果且用户最终能获知真实状态。容量评审还要覆盖积压年龄、租约风暴和下游限流。

客户端契约也需独立测试：刷新、换设备、重复提交、旧游标、过期句柄和权限撤销都返回可解释状态；UI 不因事件流中断新建任务，也不因本地取消立即宣称服务端 cancelled。最终结果从查询接口核验。

运维可按 taskId 查询时间线、当前 owner、租约、最后心跳和外部 operation，但诊断权限不自动授予查看任务敏感正文。

学完后，你应能设计长任务对象、任务句柄、至少一次队列下的幂等处理、可信进度、检查点恢复与诚实取消，并解释为何 SSE、后台 Promise 或 HTTP 202 都不能独自保证任务完成。协议实现前应复核 [MCP 2026-07-28 发布说明](https://blog.modelcontextprotocol.io/posts/2026-07-28/)中的 Tasks 扩展状态。
