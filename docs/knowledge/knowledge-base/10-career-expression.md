# 10 项目表达、技术方案与职业影响力

所有“通过”均需满足[统一考核规则](00-assessment-rules.md)。职业能力也必须用真实产出和他人可验证反馈考核。

## CAREER-01 项目复盘与 STAR/问题-方案-结果表达

- [ ] 自评已掌握
- [ ] 已通过严格考核
- 学习资料：[项目经验资产库](../project-assets.md)、[Google Technical Writing](https://developers.google.com/tech-writing)、[GitHub Profile README](https://docs.github.com/en/account-and-profile/how-tos/profile-customization/managing-your-profile-readme)、真实提交、Issue 和上线结果。
- 严格考核：选择一个项目做 5 分钟陈述；覆盖背景、个人责任、难点、方案、取舍、结果和反思；接受 5 个连续追问并核对证据。
- 通过标准：无流水账和夸大；个人贡献可验证；至少一个量化或可观察结果；追问时前后事实一致。

## CAREER-02 架构图与系统边界

- [ ] 自评已掌握
- [ ] 已通过严格考核
- 学习资料：[C4 Model](https://c4model.com/)、[Mermaid C4 Diagrams](https://mermaid.js.org/syntax/c4.html)、目标项目路由、权限、请求、服务、组件和部署结构。
- 严格考核：画出 Context、Container 和关键 Component 图；10 分钟讲解数据流、依赖、部署和失败边界；现场增加一个外部系统。
- 通过标准：不同层级不混杂；箭头和职责清楚；图与代码一致；变更后能解释影响范围。

## CAREER-03 技术方案、ADR 与取舍

- [ ] 自评已掌握
- [ ] 已通过严格考核
- 学习资料：[Google Design Docs](https://www.industrialempathy.com/posts/design-docs-at-google/)、[ADR](https://adr.github.io/)、历史技术方案。
- 严格考核：针对组件库、状态管理或微前端写方案；至少比较 3 个选项；包含约束、风险、迁移、监控和回滚；进行 20 分钟答辩。
- 通过标准：决策由目标与约束推出；拒绝项有证据；失败与退出策略完整；不是先选技术再找理由。

## CAREER-04 故障复盘与问题定位表达

- [ ] 自评已掌握
- [ ] 已通过严格考核
- 学习资料：[Google SRE Postmortem](https://sre.google/sre-book/postmortem-culture/)、[Google SRE Incident Response](https://sre.google/sre-book/managing-incidents/)、真实线上问题、日志和修复提交。
- 严格考核：根据零散现象还原时间线、影响、根因、促成因素、修复和预防；区分事实、推测与待验证项。
- 通过标准：根因有证据链；不归咎个人；改进项有 owner、优先级和验证方式；能回答“为什么监控没提前发现”。

## CAREER-05 代码评审、沟通与技术推动

- [ ] 自评已掌握
- [ ] 已通过严格考核
- 学习资料：[Google Code Review Guide](https://google.github.io/eng-practices/review/)、[Google Writing Review Comments](https://google.github.io/eng-practices/review/reviewer/comments.html)、真实 PR 讨论和团队规范。
- 严格考核：评审一份含业务、类型、性能、安全和测试问题的 PR；区分必须修改/建议/疑问；模拟与不同意见作者沟通。
- 通过标准：发现全部高风险问题；评论具体、可执行且有依据；不纠缠无关风格；能在质量与交付之间给出分级方案。

## CAREER-06 面试、教学与技术影响力

- [ ] 自评已掌握
- [ ] 已通过严格考核
- 学习资料：[本知识掌握清单](README.md)、[求职执行计划](../../plans/frontend-career-plan.md)、[MDN Soft Skills Curriculum](https://developer.mozilla.org/en-US/curriculum/getting-started/soft-skills/)、[Google Technical Writing](https://developers.google.com/tech-writing)、自己已经通过的考核证据。
- 严格考核：进行 60 分钟模拟面试，包含基础、React/TS、系统设计、项目和反问；随后用 20 分钟向他人讲授一个知识点并现场答疑。
- 通过标准：技术题总分至少 80；不会时明确边界并给出验证路径；项目表达有证据；听众能复述核心模型并完成一道迁移题。

## 领域综合考核

- [ ] 已通过领域综合考核
- 任务：围绕一个代表项目完成项目复盘、C4 图、关键 ADR、故障案例、简历描述和 60 分钟模拟面试，并让一位不了解项目的人复述其业务与技术价值。
- 通过标准：全部材料事实一致；至少两轮外部反馈后修订；模拟面试达到 80 分；所有关键结论能定位到代码、数据或文档证据。
