## COMP-01 组件职责、API 与组合设计

- [ ] 自评已掌握
- [ ] 已通过严格考核
- 学习资料：[React Thinking in React](https://zh-hans.react.dev/learn/thinking-in-react)、[React 组件属性](https://zh-hans.react.dev/learn/passing-props-to-a-component)、[WAI-ARIA APG](https://www.w3.org/WAI/ARIA/apg/)、`aiui` 现有组件 API。覆盖范围：组件职责、受控/非受控状态、组合、默认值、事件、可访问语义、版本兼容和逃生口；本地 API 只作为待评审样例，不作为规范来源。
- 严格考核：首考题 1（资料定位）：只允许使用《React Thinking in React》《React 组件属性》《WAI-ARIA APG》和题目提供的 `aiui` API，定位职责、状态、组合和语义边界；首考题 2（机制解释）：解释数据所有权、受控状态、组合和可访问交互的因果链；首考题 3（最小产出）：为复杂业务组件设计 Props、事件、插槽、状态、错误和键盘 API，并用 3 个差异场景验证；首考题 4（受限排错）：评审布尔参数爆炸、实现泄漏、焦点丢失和破坏性默认值；首考题 5（学习复述）：说明组件 API 如何长期演进。命题边界：本地 API 是待评审样例而非规范来源。
- 通过标准：主场景简单、扩展场景可组合、非法组合可被类型阻止；能明确哪些需求不纳入组件。评估边界：不得用未列资料或题目未点名的框架/项目场景作为主要评分依据。
