# 前端知识体系：从碎片学习到结构化掌握

更新时间：2026-07-13

## 核心原则

学习前端不能按文章、课程、面试题碎片堆叠。你需要的是一个稳定的知识操作系统：

```text
知识地图 -> 学习路径 -> 项目验证 -> 输出表达 -> 复习机制
```

每学一个知识点，都必须回答 5 个问题：

1. 它属于知识地图里的哪个位置？
2. 它解决什么真实问题？
3. 它在我的哪个项目里出现过？
4. 我能不能用代码或图解释它？
5. 过一周后我还能不能讲清楚？

如果一个知识点不能挂到体系里，它就很容易遗忘。

## 可勾选知识库与严格考核

总体知识树负责说明“要学什么”，[前端知识掌握清单](knowledge-base/README.md)负责真正执行。目前已经细化为 92 个可独立考核的知识点，每个知识点都包含：

- `[ ] 自评已掌握`：读完指定资料、完成示例，不看资料也能独立复述和应用。
- `[ ] 已通过严格考核`：完成闭卷问答、编码/排障或项目任务，首次考核和 7 天复测均达到通过线。
- 学习资料：优先使用官方文档、标准和当前项目真实代码。
- 严格考核：至少达到 3-5 年前端面试难度，关键领域要求可运行代码或项目产出。
- 通过标准：明确分数、边界、自动测试或可验证证据，不能凭主观判断勾选。

考核统一执行[评分、否决与复测规则](knowledge-base/00-assessment-rules.md)，每次结果使用[考核记录模板](knowledge-base/assessment-record-template.md)留档。

示例：

```text
知识点：useEffect 依赖数组
所在体系位置：框架与应用开发 -> React -> Hooks
一句话定义：useEffect 用于把组件渲染结果同步到外部系统，依赖数组决定同步逻辑何时重新执行。

它解决的问题：接口请求、订阅、定时器、DOM/外部系统同步。
常见场景：重复请求、闭包旧值、清理函数、依赖遗漏。
在我的项目中的例子：列表筛选条件变化后重新请求；AIUI 消息滚动到底部；H5 页面监听路由或 SDK 状态。

底层原理：render 后执行副作用；每次 render 都有自己的闭包；依赖变化触发清理和重新执行。
常见误区：把所有状态派生逻辑都放进 effect；为了消除 lint 警告随意删依赖。
最佳实践：优先在 render 阶段计算派生状态；外部同步才用 effect；复杂逻辑抽自定义 Hook。
```

## 知识之间的关联方式

你要用“链路”学习，而不是孤立学习。

### React 状态链路

```text
JS 闭包
  -> React render
  -> state snapshot
  -> Hooks 依赖
  -> 组件状态设计
  -> 性能优化
  -> 项目中的复杂表单/AI 聊天/列表查询
```

### TypeScript 业务建模链路

```text
联合类型
  -> 状态枚举
  -> 操作权限
  -> UI 按钮可见性
  -> 接口请求参数
  -> 审核流页面
```

### 中后台业务链路

```text
业务对象
  -> 状态机
  -> 权限模型
  -> 表单/表格/详情
  -> 接口契约
  -> 异常边界
  -> 可复用模板
```

### H5 性能链路

```text
浏览器渲染
  -> 资源加载
  -> 首屏指标
  -> 移动端网络
  -> 图片/视频/地图/SDK
  -> DevTools/Lighthouse
  -> 优化方案
```

### 工具化链路

```text
重复人工操作
  -> 抽象输入输出
  -> Node/CLI
  -> schema 校验
  -> OpenAPI/YAML 解析
  -> 类型生成
  -> MCP/AI 工作流
```

## 学习顺序

不要按“哪个热门学哪个”。按依赖关系学。

### 第一层：基础内功

先补这些，因为它们支撑后面所有内容：

- JavaScript 执行机制
- 异步与事件循环
- TypeScript 类型系统
- 浏览器渲染、网络、缓存、安全
- CSS 布局与响应式

### 第二层：应用开发

再系统化你每天用的技术：

- React 组件、状态、Hooks、性能
- Umi/Max 路由、运行时、权限、请求
- AntD/AntD Mobile 表单、表格、弹窗、移动组件

### 第三层：业务建模

这是你从中级到高级的关键：

- 业务对象
- 状态机
- 权限模型
- 接口契约
- 表单/表格/详情模板
- 异常边界

### 第四层：工程质量

这是高级前端的分水岭：

- 构建
- 包管理
- 测试
- CI/CD
- 性能监控
- 发布与回滚

### 第五层：平台和工具

这是资深/负责人方向：

- 组件库
- 低代码/配置化
- 微前端
- Node/CLI
- MCP
- AI 辅助研发

## 复习机制

为了避免遗忘，每个知识点至少复习 4 次：

| 时间 | 动作 |
| --- | --- |
| 当天 | 写笔记和代码示例 |
| 第 2 天 | 不看笔记复述一遍 |
| 第 7 天 | 用项目案例重新解释 |
| 第 30 天 | 用面试题或方案题验证 |

复习时不要重读原文，要做输出：

- 画图
- 写代码
- 讲给自己听
- 写面试答案
- 回到项目里找例子

## 掌握程度评估

每个知识点可以标一个自评等级，但自评等级不能代替严格考核：

| 等级 | 标准 |
| --- | --- |
| 陌生 | 只听过名词 |
| 理解 | 能看懂解释 |
| 能用 | 能在项目里照着用 |
| 能讲 | 能结合项目讲清楚现象、原理、方案 |
| 能设计 | 能做技术选型、抽象方案、指导别人使用 |

你的目标不是所有知识都到“能设计”。不同知识有不同目标：

- 高频基础：至少到“能讲”。
- 主战场技术：React、TS、Umi、AntD、H5 至少到“能设计”。
- 加分技术：Node、MCP、AI、低代码先到“能用/能讲”。

只有首次考核和 7 天复测都达到 80 分，且没有触发否决项，才允许勾选“已通过严格考核”。已经勾选的知识点在月度抽测中低于 80 分，应取消勾选并重新学习。

## 每周学习闭环

每周只围绕一个主题，按这个节奏走：

```text
周一：建立概念
周二：补原理
周三：找项目案例
周四：写代码或方案
周五：整理面试表达
周六：做一个综合产出
周日：复盘和复习
```

每周必须产出一个“知识卡片包”：

```text
本周主题：

核心概念：
项目案例：
代码示例：
常见问题：
面试表达：
下次复习日期：
```

## 今天开始怎么做

知识与考核体系已经建好，今天可以直接开始：

1. 阅读[统一考核规则](knowledge-base/00-assessment-rules.md)。
2. 从[知识掌握清单](knowledge-base/README.md)选择 1 个知识点，建议从 `TS-02` 或 `REACT-01` 开始。
3. 完成指定资料和自己的代码示例，确认能独立复述、应用后，只勾选“自评已掌握”。
4. 至少间隔 24 小时，再按该知识点的任务进行首次闭卷考核。
5. 用[考核记录模板](knowledge-base/assessment-record-template.md)记录分数和证据，7 天后复测通过再勾选“已通过严格考核”。
