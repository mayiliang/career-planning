# AI 时代高级前端能力体系

更新时间：2026-08-18

本体系把高级前端定义为：能够在复杂约束下，从产品判断、架构设计、实现验证到生产交付，对 Web 与 AI 用户体验结果负责的人。

## 结构层级

知识体系采用稳定的四级主题结构：

1. 总主题：AI 时代高级前端能力体系。
2. 一级：20 个稳定能力组；用于内容归档和保留知识点、学习记录的长期地址。
3. 二级：各文件中的主题分组，例如“Web 标准与可访问性”“质量门禁与测试体系”“生成式与 Agent UI”。
4. 三级：223 个可独立学习、验证和维护的知识点。

能力层、要求级别、AI 关系、成熟度、适用范围、学习路线和主题标签不是父子层级，而是知识点的独立分类轴。同一能力组中的知识点可以落在不同能力层、路线或横向主题中，不能用文件编号推断必修性。

## 分类轴

| 维度 | 取值 | 回答的问题 |
| --- | --- | --- |
| 能力层 `capabilityLayer` | 核心 / 应用 / 专精 / 领导力 | 在高级前端职责中承担什么层次的能力 |
| AI 关系 `aiRelation` | 非 AI 专属 / AI 辅助 / AI 原生 / Agentic | AI 在该能力中是工具、产品核心还是行动主体 |
| 要求级别 `requirementLevel` | 全员必修 / 主修必修 / 选修 | 是否进入通用路线或特定岗位路线 |
| 成熟度 `maturity` | 稳定 / 演进中 / 实验性 | 技术、规范或生态处于什么发展阶段 |
| 主适用范围 `portability` | 可迁移 / 框架 / 厂商 / 平台 / 法域特定 | 列表中的主要迁移限制是什么 |
| 适用标签 `applicabilityTags` | 框架、厂商、平台、法域可多选 | 是否同时受多种环境约束 |
| 学习路线 `trackIds` | `react`、`vue`、`umi-antd`、`agent-mcp` | 主修必修点属于哪条可执行路线 |
| 主题标签 `topicTags` | 安全、无障碍、平台工程、浏览器 AI 等 20 类 | 跨一级领域检索相近能力，不承担路线语义 |

“实验性”只属于成熟度，不再混入要求级别。“AI 原生”不再等同领导力；AI 应用实现可以是应用层，Agent 协议可以是专精层，AI 治理可以是领导力层。平台特定能力与框架、厂商或法域限制可以同时标记。

默认核心路线由“全员必修 + `react`、`vue` 与 `agent-mcp` 主修必修”动态计算，当前 149 个主干知识点压缩为 35 个连续批次。批次只用于紧凑导航，不绑定自然周，也不生成无知识点的占位任务。React 与 Vue 在框架阶段交错编排并享有同等推荐优先级；这表示入口、要求级别和完整能力闭环同等，而不是强行让两者具有相同 API 或知识点数量。Umi、图形、跨运行时、端侧推理等完整保留在按目标选择的专项路线中。

## 四类能力层

### 核心能力

- Web 语言和平台：JavaScript、TypeScript、计算机基础、HTML/CSS、浏览器、网络、请求可靠性、调试、安全、可访问性治理和兼容性。
- 工程底座：Git、模块与依赖、通用质量门禁、测试方法、发布证据和供应链基线。
- 身份隐私：浏览器身份边界、数据最小化和隐私生命周期。

### 应用能力

- 框架与业务：React/Vue/Umi 学习路线、业务状态、权限、表单、接口、错误和可恢复体验。
- 生产应用：性能、移动 Web、Node/BFF、渲染、Server State、实时消息、离线和部署交付。
- AI 应用：模型接口、流式 UI、结构化输出、Tool Calling、Generative UI、RAG、评估、成本、会话和记忆。
- AI 辅助研发：规格上下文、验证、评审和团队工作流。

### 专精能力

- 组件平台、设计系统、微前端、嵌入式 SDK、浏览器扩展、小程序、桌面容器、跨平台原生、CLI/API 工具。
- WebAssembly、图形与可视化、专业媒体、实验分析、内容/SEO、国际化、多人协作、本地优先、GraphQL、边缘运行时。
- MCP、Agent、浏览器本地 AI、Agent UI 协议、安全专项、容器运行和云交付专项。

### 领导力

- 架构质量属性、ADR、渐进迁移、技术债和框架生命周期治理。
- 技术路线、跨团队推动、平台采用、AI/数据治理、合规决策、能效与可持续性。

## 关键主题边界

- `A11Y-01` 负责 WCAG、测试和持续工程治理；`UX-01` 负责一般可用性与任务体验。
- `NET-01` 负责浏览器请求全生命周期可靠性；`DATA-01/02` 负责 Server State 缓存、写入和冲突。
- `TEST-03` 负责 E2E、跨浏览器视觉基线和关键路径；无障碍测试仍归 `A11Y-01`。
- `AIAPP-05` 负责协议无关的 Generative UI；`AIUI-01` 负责 AG-UI、A2UI 与 MCP Apps 的互操作实现。
- `MCP-01` 负责 Host/Client/Server 和 Tools/Resources/Prompts 核心模型；`AGENT-03` 负责传输、会话和恢复兼容。
- `AGENT-10` 负责身份、授权、工具权限与运行隔离；`AISAFE-02` 负责系统级威胁建模、红队和滥用防护。
- `COLLAB-01` 负责 CRDT、OT、Presence 和收敛；`REALTIME-01` 负责传输可靠性，`MEDIA-02` 负责 WebRTC 媒体采集。
- `RUNTIME-01` 负责扩展、小程序和受限 Web 容器；`MOBILE-01` 负责跨平台原生前端。

## 顺序与前置关系

推荐顺序不自动成为硬前置。只有缺失会造成概念、实现或安全断层时，才建立 `PREREQUISITE`。可以相互启发但可独立学习的关系使用 `RELATED`。

已明确降级为“相关”的典型关系包括：高级 Git 与通用调试、类型状态机与权限模型、发布流水线与具体部署、React Suspense 与通用流式 SSR、PWA 与离线 AI 作业、文本流式 UI 与本地推理/实时语音、组织级 AI 治理与媒体工作流、RAG 与本地语义搜索、MCP 与通用 Generative UI。

硬前置图必须满足：端点存在、无自环、无环、同一知识对不同时标记为前置和相关；默认路线中的前置点必须不晚于依赖点。

## 掌握与维护边界

一个知识点要形成可靠掌握证据，至少要能定位资料、解释机制和失败模式、完成最小实现或诊断、给出适用边界，并通过首考和延迟变式复测。统一规则见[考核规则](knowledge-base/00-assessment-rules.md)。

该体系不枚举所有库、云厂商或短期热门功能。新增独立知识点必须形成明确的高级前端职责、不可被现有点自然覆盖的主题边界和可复核产出。演进中、实验性、厂商/平台/法域特定内容按核验日期持续复查。
