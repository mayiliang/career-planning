## 读者先得到什么

一篇主讲义应帮助读者建立可以解释代码的模型。开篇用真实的困惑说明学习理由，在解释术语之前给出足够的直觉；用独立可运行的例子呈现结果，再把结果与原因连起来。少见边界放在核心解释之后，参考资料放在文末并说明用途。

MDN 的 [学习内容写作指南](https://developer.mozilla.org/en-US/docs/MDN/Writing_guidelines/Learning_content)区分循序学习与详尽参考，强调学习目标和亲手尝试；[写作风格指南](https://developer.mozilla.org/en-US/docs/MDN/Writing_guidelines/Writing_style_guide)强调清晰、具体的表达与相关链接。本项目借鉴这种组织方法，中文正文与示例重新创作，不逐句翻译 MDN，不复制其整套例子，也不把资料改写成站内考题讲解。

同一个重要概念只设一个主要解释入口。在别处需要它时，先给一句当前语境所需的提示，再链接到对应小节。允许从多个角度提及同一概念，但不要维护多份各自演化的“完整定义”。读者可以顺序学习，也可以沿引用补充背景后返回。

## 前置和相关引用分开管理

“直接前置”表示进入当前讲义之前应具备的基础，只写在 `### 学习前先确认` 中，以 `- 直接前置：` 开头。已经能沿另一个直接前置找到的上游资料，不再重复列出。前置图必须无环。

“相关知识”解释当前概念与其他知识的联系，可以相互引用，不用于阻挡学习路线。例如，JS-01 的闭包指向 JS-03 的对象共享，JS-03 也可以返回 JS-01 的绑定说明；它们是补充理解的关联，不能因此生成循环前置要求。

链接统一使用相对于讲义目录的地址，例如：

```text
../chinese-guides/js-03-types-equality-copy-immutability.md#赋值之后谁和谁共用对象
```

小节链接使用实际标题生成的锚点。注册为目录概念的小节在站内打开时会保留完整讲义，只定位到对应标题，阅读记录仍使用 `js-03` 等主入口。原有 `/知识资料文件/小节锚点` 形式的站内概念链接也会转到对应完整文章。未登记的小节沿用旧的章节提取行为，不能靠随意改写地址掩盖坏链接。

从已登记的小节链接进入时，阅读器保留整篇正文并进入查阅状态，不把直接跳转的位置保存成整篇阅读进度。选择“从头阅读本篇”后，恢复正常阅读记录。通过整篇入口开始阅读时，原有的阅读进度规则保持有效。

改小节标题之前，要同时检查正文引用和目录。当前不维护任意标题的永久别名；若已有对外分享的深链接需要保留，应明确补充迁移规则。

## 中文表达的具体做法

先写“谁做了什么、结果怎样”，再引入术语。把连续几个抽象名词拆成可观察的动作：例如“两个变量指向同一个对象，改属性会影响两边”，比“对象身份关联产生共享可变状态”更容易读懂。

保留已经广泛使用或翻译后更别扭的英文，例如 `this`、Promise、Proxy、Reflect、receiver、trap。第一次出现时用中文解释它在当前代码中做什么，之后保持同一种叫法。普通句子中的代码名用行内代码；只对值得辨识或发音的关键术语加粗，避免每个英文变量旁边都出现播放按钮。

段落之间要有因果关系，不连续堆“注意”“边界”“约束”。标题描述这一节帮助读者解决的问题。表格用于比较可并列的规则，提示块用于少量会改变判断的重要前提；不要用大段清单代替讲解。自然中文不等于把精确条件省掉，特别是严格模式、生产者与消费者错误、属性描述符和资源关闭的边界。

## 示例就是可以核对的内容

已登记主讲义的每个 JavaScript 代码块都带唯一标识；可独立执行的示例把变量、模拟资源和调用在块内定义，不需要猜测前一段有没有运行。预期输出使用 `// =>`；复杂调用顺序可以把输出按实际顺序统一列在代码块末尾。

````text
```js example=js01-example-name
const count = 2;
console.log(count + 1); // => 3
```
````

标识只用于维护，阅读器的代码栏仍只显示语言。示例以现代浏览器为执行环境，异步示例显式等待完成。异常示例捕获并展示错误，不在后台留下未处理异常；涉及资源的例子优先使用内存模拟，不向读者的真实服务发请求。需要真实浏览器能力时标记 `runtime=browser`，例如 B02 的 Blob Worker 往返，并在 finally 中清理 Worker、定时器和临时 URL。带标识的 Nginx 配置以 `runtime=project` 登记，阅读器提供 Nginx 高亮；登记不代表已在 Nginx 实机执行。带标识的 Dockerfile 以 `runtime=project` 登记，只提取来源、不作为 JavaScript 执行；阅读器补充 Dockerfile 与 INI 高亮。带标识的 Bash 片段以 `runtime=project` 登记，和 PowerShell 一样不进入通用 JavaScript 执行器；没有标识的历史命令说明保持原有行为。需要展示平台差异时，单独声明前提和结果，不能让示例依赖某个未说明的控制台习惯。

`learning-material-examples.mjs` 从实际正文提取代码和预期输出。`check-curated-materials.mjs` 复用有超时限制的独立 worker，核对 B01 至 B35 的通用示例；浏览器专用示例和框架项目按实际环境另行核对。这验证的是示例与标注是否一致，无法替代对概念、语言质量和知识覆盖的审校。

## 修改后的核对顺序

1. 对照知识点范围逐项检查解释入口，确认重要知识没有被更流畅的文风一起删掉。
2. 从零阅读每个示例：输入是什么，预期看到什么，哪个改动能揭示规则，读者是否拥有全部定义。
3. 核对官方来源；遇到 MDN、规范或不同引擎结果不一致时，记录版本与实际行为，收窄结论。
4. 更新目录、正文引用和知识点资料说明。只更新当前批次的发音资源。
5. 运行 `pnpm content:check`，检查内容结构、直接前置、概念归属、小节链接、示例输出与发音一致性。
6. 系统面向桌面，检查本次改动涉及的桌面章节导航、交叉引用与浏览器专用示例。以内容和引用核对、必要构建为主；只有关键功能有改动或发现问题时才增加针对性检查，不默认扩展移动端适配或完整测试套件。

执行时先批量读取本批旧稿、范围与已有前置，只核对直接相关的官方变化；写完并自查后统一运行内容检查和必要构建。代表性桌面阅读与完整实验集中核对取消、状态、输入和导航；已有检查通过且没有新问题时不重复整套流程，不另写与正文脱节的测试副本。

字符数下限只用于发现意外截断，不作为内容质量评分。完整检查同时包含可追溯的概念入口与实际运行结果，也需要编辑者通读中文。B01 至 B35 当前采用这种管理方式；推广到后续批次时，先逐批审校内容，再加入目录，不能批量套模板后就标记完成。

## B03 的多文件与类型示例

JavaScript、TypeScript 代码都保留在正文，不另外维护一份手写示例源码。ES Modules 示例用相同 example 标识组成一组，每个代码块声明 `runtime=browser file=文件名.mjs`，组内必须有 `main.mjs` 入口；读者可见的正文同时标出文件名和 HTTP 加载方式。一组文件作为一个示例核对，不能把其中的 import/export 当成普通函数体执行。

TypeScript 示例使用 `ts example=唯一标识`。现有内容检查先在内存中为每段创建独立模块，用项目 TypeScript 5.7.2 和 strict、noUncheckedIndexedAccess、exactOptionalPropertyTypes 核对真实源码，再转换并比对运行输出。预期非法写法用 @ts-expect-error 标明，并解释原因；不执行的错误函数只服务于观察诊断，不让学习页面留下未处理异常。编译通过不能替代语义审校，尤其显式类型谓词可能错误地承诺真假分支。

| 知识点 | 主要讲解入口 | 特别核对的边界 |
| --- | --- | --- |
| JS-05 | 外层提前结束、return await、两种 finally、取消与旧清理 | Promise.finally 的普通返回值不替换原结果；try/finally 中 return 会覆盖；超时不等于远端回滚 |
| JS-06 | 八组多文件程序、依赖图、循环失败与拆分 | 静态导入是绑定；普通解构是取值；循环读取未初始化 const 会失败；导入缓存不等于业务初始化幂等 |
| TS-01 | 静态视图与实际值的对照、明确的类型错误、完整解析入口 | strict 不自动开启索引和精确可选属性两项；as、readonly 不验证或冻结；结构赋值不删字段 |
| TS-02 | 分支可能性表、真假反例、守卫、穷尽检查与请求状态机 | 谓词的 false 分支也必须正确；保留旧数据刷新可以是合法状态；类型不证明异步提交资格 |
