# 测试与验收

## 1. 测试策略

| 层级 | 工具 | 重点 |
| --- | --- | --- |
| 单元测试 | Vitest | 解析、状态机、评分、时间和冲突规则 |
| 数据库测试 | Vitest + 临时 SQLite | 迁移、事务、约束、导入幂等 |
| 组件测试 | Vue Test Utils + Testing Library Vue | 用户行为、可访问性、错误与恢复 |
| API 集成 | Fastify inject | 请求 schema、状态守卫、错误码 |
| E2E | Playwright | 首次导入、学习、考核、打卡、求职、备份 |
| AI 合约 | Fake provider + 固定样例 | JSON 校验、低置信度、否决项、提示注入 |

真实 DeepSeek 调用不进入默认 CI。提供手动或显式环境变量开启的 smoke test，避免测试不稳定和消耗额度。

## 2. 必测单元

### 内容导入

- 正确解析 92 个知识点和 11 个领域。
- 每个知识点都包含资料、严格考核和通过标准。
- 识别领域综合考核但不计入普通知识点。
- CSV 中带引号和逗号的字段不串列。
- 重复导入不重复创建记录。
- 内容更新不覆盖用户状态、笔记或历史成绩。
- 扫描后源文件变化时拒绝旧 preview token。

### 状态机

- 不能从 NOT_STARTED 直接进入 MASTERED。
- 没有摘要/证据不能自评掌握。
- 首次考核通过只进入待复测。
- 复测失败进入需重学。
- 月度抽测失败取消有效掌握状态。
- 每次转换只有一个对应审计事件，重试保持幂等。

### 评分

- 服务端不信任模型返回的 total 和 verdict。
- 维度低于 60%、总分低于 80、确定性测试失败或存在否决项均不能 PASS。
- confidence < 0.75 进入 MANUAL_REVIEW。
- finding 分数不等于维度分数时判定输出无效。
- 模型引用不存在的回答证据时判定输出无效。
- 答案中的提示注入不能改变 schema、rubric 和阈值。

### 日历与打卡

- 16 周计划按选择的开始日期正确生成。
- 7 天复测事件按 Asia/Shanghai 日期正确显示。
- 拖拽失败会回滚原时间。
- 改期保留原事件与关联。
- 完成率按完成/部分/跳过正确计算。

### 求职

- CSV 导入 17 列准确映射。
- 岗位状态改变自动追加活动记录。
- 技能缺口关联知识点后可从两侧查看。
- 面试事件同步到日历且删除时不误删岗位。

### 备份

- 备份 manifest 记录版本、数量和 checksum。
- 损坏 checksum 的备份不能恢复。
- 恢复失败不修改正式数据库。
- 全新数据库能从备份恢复到相同记录数和关键 hash。

## 3. AI 回归样例

至少准备 20 份固定答卷：

- 4 份优秀答案。
- 4 份 80 分附近临界答案。
- 4 份只背定义但缺少边界的答案。
- 3 份编码测试失败但文字解释漂亮的答案。
- 3 份包含提示注入、要求满分或改变 JSON 的答案。
- 2 份证据不足、应进入人工复核的答案。

每次修改模型、系统提示词、rubric 或解析 schema 后重跑。允许具体分数小幅变化，但 PASS/FAIL/MANUAL_REVIEW 不应无原因漂移。

## 4. E2E 验收场景

### E2E-01 首次启动

1. 使用空数据目录启动。
2. 导入现有 Markdown 和 CSV。
3. 选择计划开始日期。
4. 验证 92 个知识点、11 个领域、80 条学习模板和岗位草稿。
5. 刷新后数据仍存在。

### E2E-02 学习与自评

1. 从今日页打开知识点。
2. 保存 Markdown 笔记和证据。
3. 提交自评掌握。
4. 知识列表、详情和图谱状态同步更新。

### E2E-03 首次考核失败

1. 创建并完成考核。
2. Fake provider 返回一项低分。
3. 验证状态回到 LEARNING，答案和反馈保留。
4. 日历生成补学建议但不自动覆盖用户计划。

### E2E-04 考核与复测通过

1. 首次考核达到通过线。
2. 状态进入待复测并创建 7 天后事件。
3. 调试时钟到复测日并完成复测。
4. 验证自动进入 MASTERED，双环闭合，审计记录完整。

### E2E-05 模型异常

1. 模型返回非 JSON、超时或 429。
2. 答卷与客观分数保持。
3. 知识状态不变化。
4. 用户可安全重试且不会创建重复成绩。

### E2E-06 求职反哺学习

1. 导入岗位并记录面试。
2. 关联两个薄弱知识点。
3. 从岗位跳转知识详情并加入本周计划。
4. 掌握后岗位缺口显示已解决但保留历史。

### E2E-07 备份恢复

1. 创建包含知识进度、答卷、日历和岗位的备份。
2. 使用空数据库恢复。
3. 比较记录数、状态、成绩和附件 checksum。

## 5. 可访问性验收

- 键盘可完成学习、考核、日历打卡和岗位编辑主流程。
- 图谱提供等价的列表路径视图。
- 表单错误与控件正确关联。
- 弹窗打开后焦点进入，关闭后回到触发控件。
- 状态不只依赖颜色。
- 200% 缩放下主功能可使用，无阻断性横向滚动。

## 6. 性能验收

- 本地冷启动后 1 秒内显示基础壳和加载状态。
- 92 节点图谱布局小于 500ms。
- 5000 个日历事件按范围查询，周视图接口 P95 小于 200ms。
- 1000 个岗位活动分页查询 P95 小于 200ms。
- 大答卷和模型原始响应不进入列表接口。

## 7. Definition of Done

一个功能只有同时满足以下条件才算完成：

- 对应需求 ID 已实现。
- 输入、状态、空态、错误和恢复路径已实现。
- 类型检查、lint 和相关测试通过。
- 新的数据库变化有迁移与回滚说明。
- 用户可见文案与设计规范一致。
- 不泄露 API Key 或本地敏感内容。
- 开发日志记录关键取舍和剩余限制。
- 通过对应验收场景，不用“后续补充”代替核心功能。
