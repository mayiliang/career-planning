# 产品需求

更新时间：2026-08-20

## 1. 产品目标

把“AI 时代高级前端能力体系”变成可长期使用的自主学习工作台：知识范围完整、资料可核验、学习顺序可解释、笔记可沉淀、练习可在站内完成、掌握证据分级，并允许用户按工作路线选择与暂缓。

## 2. 核心原则

1. 不按天强制排课。学习强度由用户当天实际时间决定。
2. “学过”和“掌握”分离。用户确认资料与笔记完成；系统只根据挑战证据判定掌握。
3. 理论与实践同等重要，但题型服从知识特性，不给纯理论点硬塞代码题。
4. 资料优先中文。英文一手资料只能作为明确标注的版本核验材料，不是独立必读或隐含题源。
5. 用户数据优先。AI 只能生成新版本，不能静默覆盖原笔记或改变掌握状态。
6. 分支尽量少。唯一后续直接推进；只有一段连续路线结束时才让用户选方向。
7. 默认路线优先主要内容。149 个主干知识点压缩成 35 个非空批次；批次不绑定自然周，也不生成无知识点的复盘、项目或机动任务。

## 3. 用户闭环

```text
选择/恢复知识点
  -> 设为当前学习
  -> 阅读资料与示例
  -> 在 Markdown 笔记中记录
  -> 可选：站内练习、AI 整理
  -> 用户标记已学完
  -> 快速进入唯一后续或选择下一方向
  -> 可选：M1～M4 掌握挑战
  -> 当天按实际学习内容打卡
```

## 4. 功能需求

### 学习台

- 只显示一个明确的“当前正在学”知识点。
- 未设置当前点时，建议起点与路线参考使用同一推荐算法，并展示该点第一项必做活动的任务、固定输入、交付物、完成判定、预计投入和直接开始入口。
- 已学完的当前点仍可用于打卡与进入下一个点，直到用户切换。
- 打卡可选择多个知识点，记录 Markdown 总结、实际分钟、精力和难度。

### 知识详情

- 展示知识主题、领域、学习状态、掌握等级、学习方式、中文资料和通过标准。
- 资料与笔记都使用统一现代 Markdown 渲染。
- “已学完”按钮要求存在笔记，只改变学习状态，不改变 M 等级。
- 有练习时必须给出输入、输出要求、完成判定、资料定位和站内提交入口。
- 代码练习必须能在站内编辑、执行、查看输出并验证；不在宿主机执行不可信代码。

### 笔记中心

- 知识点笔记自动进入笔记中心，按知识体系顺序默认排序。
- 支持搜索、领域过滤和自定义排序。
- Markdown 支持表格、图形、公式、代码、任务、脚注、提示块和 thinking。
- 原始笔记、AI 候选稿、已采用稿和版本历史分别保存。
- 编辑时立即写入浏览器本地草稿，并在短暂防抖后自动保存到服务端；刷新、网络失败或切换页面不得静默丢失未保存文字。
- AI 整理流式显示进度、thinking 与候选正文；中止、超时或降级不覆盖原文。

### 掌握挑战

| 等级 | 含义 | 典型证据 |
| --- | --- | --- |
| M0 | 未评估 | 没有系统证据 |
| M1 | 初步理解 | 能解释概念、作用和边界 |
| M2 | 引导应用 | 在提示、提纲或脚手架下完成 |
| M3 | 已掌握 | 独立完成适合该知识点的理论或实践挑战 |
| M4 | 稳定掌握 | 至少 7 天后独立完成变式挑战 |

- 挑战完全可选，失败不撤销“已学完”或降低既有等级。
- 难度逐级增加；帮助从解释题意到完整思路逐级展开并记录独立程度。
- 题目必须标注知识点、明确输入输出和回答格式，并可由所列资料直接定位或按给出的推导步骤推出。
- 已存在进行中的挑战时直接恢复并给出清晰说明，不显示上游英文错误。
- 答题前必须检查 AI 是否已配置且可连接，并说明会发送题目合同、学习资料、作答和帮助记录，不发送 API Key；预检失败时不创建新答卷。

### 求职与个人数据

- 岗位可手动创建；CSV 支持常用中英文表头、引号与多行字段，先本地解析，再由服务端逐行预览，存在无效行时整批不写入。
- 备份恢复必须先校验文件，展示当前数据量、恢复后数据量、差异和警告，再由用户确认。
- 用户可导出并重新导入可阅读 JSON；内容使用固定白名单，不包含 API Key 和知识库正文。导入必须校验版本、字段、计数、引用和知识点匹配情况，先展示差异，再自动备份并以事务写入；失败时不得留下部分结果。

### 路线与分支

- 路线页、学习台建议和详情下一步共用同一主干索引；React 与 Vue 在默认框架段交错推进并享有同等优先级。
- 每个核心批次只包含 4～5 个真实知识点，批次仅用于导航；具体学习任务来自知识点页的资料、站内练习和掌握挑战。
- 非知识点任务必须先在系统中发布固定输入、交付物、验证清单、否决项和系统/AI 验收方式；没有该合同就不进入路线。
- `CONTINUE`：有唯一直接后续，系统只显示该点。
- `TRACK_CHOICE`：当前连续线路结束，展示每个方向的内容、领域和剩余规模。
- 未选择不等于放弃，之后可以再次推荐。
- 暂缓点/支线不会立即再次推荐；若它不是硬前置则继续后续，若是硬前置则明确说明阻塞原因。
- 用户可从知识体系恢复暂缓内容。

## 5. 非功能需求

- 单用户数据默认本地保存，AI 密钥只在服务端。
- 常规页面在当前桌面浏览器中响应迅速；流式 Markdown 不按每个 token 同步重排。
- 页面充分使用空间，同一视觉组卡片保持对齐；移动端转为单列，不用固定空白补高度。
- 所有长任务可中止、可显示真实进度，错误使用可行动的中文描述。
- 普通请求必须有明确超时；键盘用户可跳过重复导航，对话框必须管理焦点并在关闭后回到触发元素。
- 生产构建默认不公开源码映射，并以自动预算约束首屏、CSS、常规分块、懒加载大依赖和总资源体积。
- 部署必须持久化数据目录、支持健康检查和备份；公网访问必须有外层身份认证。

## 6. 不做的事情

- 不用固定每日计划替代用户自主选择。
- 不把阅读完成自动当成掌握。
- 不把 AI thinking 当作事实、答案依据或用户笔记。
- 不为没有实际任务的“项目”显示虚假时长。
- 不生成空批次、泛化复盘或无法由系统/AI 验收的路线任务。
- 不实现多用户、公网账号或协作权限，除非另立需求和安全设计。
