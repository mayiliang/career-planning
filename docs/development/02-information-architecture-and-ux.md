# 信息架构与视觉交互规范

## 1. 设计命题

产品主题是“个人技术航海图”，不是普通企业后台。页面的单一任务是：让用户知道自己现在在哪里、下一步往哪里走、是否真的通过了验证。

界面采用“冷静的技术制图桌”方向。唯一醒目的视觉签名是知识图谱节点的双层进度环：内环代表自评掌握，外环代表严格考核；只有复测通过，外环才闭合。其他区域保持安静、精确，不使用装饰性大标题、无意义渐变卡片或重复导航。

## 2. 全局信息架构

```text
今日
├── 今日计划
├── 待复测
├── 即将面试
└── 快速记录

知识
├── 知识图谱
├── 知识清单
├── 学习工作区
└── 考核中心

计划
├── 学习日历
├── 16 周计划
├── 日/周复盘
└── 统计

求职
├── 岗位看板
├── 求职活动
├── 面试记录
└── 项目与简历资产

系统
├── 内容导入
├── 模型配置
├── 备份恢复
└── 数据诊断
```

桌面端使用单一左侧导航。移动端使用底部四项导航：今日、知识、计划、求职；系统入口放在个人菜单中。

## 3. 视觉 Token

### 颜色

| 名称 | 值 | 用途 |
| --- | --- | --- |
| Draft Ink | `#172033` | 主文字、深色图谱节点 |
| Blueprint | `#315C87` | 链接、焦点、当前路径 |
| Cool Sheet | `#EEF3F7` | 页面背景 |
| Moss Proof | `#4E7C65` | 已掌握、完成 |
| Amber Review | `#D89A3A` | 待复测、需要关注 |
| Redline | `#B94A48` | 未通过、风险、破坏性操作 |

颜色不是唯一状态表达。所有状态同时使用文字、图标、线型或进度环。

### 字体

- 展示标题：`LXGW WenKai`，仅用于页面主命题、领域名称和重要学习摘录。
- 正文与操作：`Noto Sans SC`。
- 编号、分数、代码与数据：`IBM Plex Mono`。
- 字体文件本地打包，不依赖运行时 CDN。

### 形状与密度

- 常规圆角 8px，图谱节点允许圆形或胶囊形。
- 卡片只在确有分组边界时使用；优先用留白、细线和网格组织。
- 阴影只用于浮层和拖拽态，不给所有模块加阴影。
- 8px 空间基线，正文行高不低于 1.65。

## 4. 桌面布局

```text
┌──────────┬──────────────────────────────────┬───────────────┐
│ 左侧导航 │ 主工作区                         │ 上下文抽屉    │
│  72/224  │ 今日 / 图谱 / 日历 / 岗位看板    │ 节点详情      │
│          │                                  │ 笔记与操作    │
└──────────┴──────────────────────────────────┴───────────────┘
```

- 导航可在 72px 图标模式与 224px 展开模式间切换。
- 上下文抽屉宽 360-440px，可固定或关闭。
- 主工作区最大宽度只限制阅读页面；图谱与日历使用全部可用空间。
- 页面开始位置直接展示当前对象、状态和主操作，不放装饰性欢迎条。

## 5. 核心页面

### 5.1 今日页

```text
今天 · 7 月 13 日 周一
────────────────────────────────────────
09:30  TS-02 联合类型与穷尽检查   [开始学习]
14:00  gungnir-web 状态建模实战   [记录产出]
19:30  杭州岗位采集               [打开岗位]

待复测 2      本周完成 7/12      面试 1
────────────────────────────────────────
今日复盘输入区
```

- 首屏中心是时间顺序，不是统计卡片墙。
- 已完成项目折叠但可展开查看证据。
- 拖延或跳过必须要求选择原因，避免静默丢失。

### 5.2 知识图谱

- 默认通过脑图分层显示 5 条主干、15 个领域，避免 132 个知识点同时造成噪声。
- 节点双环：内环自评，外环严格考核；待复测外环为琥珀虚线。
- 依赖边为实线，关联边为细虚线，项目应用边按需开启。
- 聚焦某节点时，只突出它的前置、后续、关联计划和技能缺口。
- 图谱变更使用 180-240ms 位移动画；尊重 `prefers-reduced-motion`。

### 5.3 知识详情与学习工作区

```text
TS-02  联合类型、收窄、never 与穷尽检查
[自评已掌握] [参加首次考核]
────────────────────────────────────────────
学习内容 / 我的笔记 / 项目证据 / 考核历史

正文阅读区                    今日目标与下一步
                              - 完成官方资料
                              - 写状态模型
                              - 明日可考核
```

- 状态按钮保持一致命名，结果提示使用“已保存”“初试通过”等明确文案。
- 外部资料在新标签打开；站内保存用户的阅读进度和最后位置。
- 空笔记显示“记录一个能在项目中复用的结论”，不显示泛化鼓励语。

### 5.4 考核页

- 顶部只显示知识点、考核类型、剩余时间、保存状态和交卷。
- 答题时隐藏全局导航，减少误操作；允许明确退出并保留草稿。
- 左侧题号导航，中间题目与答案，右侧显示题目要求，不展示资料。
- 提交后先展示确定性测试，再展示模型评分和引用证据。
- 不用单一总分掩盖否决项；否决项始终在结果顶部。

### 5.5 学习日历

- 月视图看节奏，周视图做排期，日视图执行，议程视图做复盘。
- 学习、考核、求职使用图标和边框线型区分，不只用颜色。
- 日期格显示 `完成项/计划项`，不使用只鼓励连续天数的火焰图标。
- 点击空白时间创建事件；拖拽后立即保存并提供撤销。

### 5.6 求职看板

- 列为岗位状态，卡片只显示公司、岗位、薪资、下一动作和截止日期。
- 技能缺口以知识编号标签展示，点击直接打开知识详情。
- 岗位详情中的时间线统一记录投递、沟通、面试和结果。
- 面试复盘保存后，明确提示将哪些知识点加入了学习待办。

## 6. 空状态、错误与反馈

- 没有今日计划：显示“从 16 周计划生成今天的任务”按钮。
- 模型未配置：考核可以编辑和保存，但交卷按钮说明“配置模型后评分”。
- 模型评分失败：保留答案和确定性得分，显示重试与查看原始错误。
- 导入冲突：逐条显示来源版本和本地版本，不自动覆盖用户数据。
- 数据库错误：停止写入，显示备份路径和诊断操作，不继续假装保存成功。

## 7. 响应式与可访问性

- 1440px：三栏；1024px：上下文抽屉覆盖；小于 768px：单栏与底部导航。
- 图谱在手机端提供同步的列表路径视图，不能要求精确拖拽节点。
- 所有交互可用键盘完成，焦点样式使用 Blueprint 2px 外框。
- 图谱节点提供可访问名称、状态和相邻节点列表。
- 考核计时不应强制自动交卷；时间到后允许保存并标记超时。
- 对比度满足 WCAG AA；状态不依赖颜色；动画支持减少动态效果。

## 8. 文案规则

- 从用户可控制的对象命名：使用“保存笔记”“参加考核”“安排复测”。
- 一个动作全流程使用同一名称：按钮“交卷”，结果“已交卷”。
- 错误说明发生了什么和下一步，例如“模型返回格式不符合评分协议，可重新评分；你的答案已保存”。
- 不使用“太棒了”“继续加油”等模板化填充文案替代具体反馈。
